# INT-001 个人知识库 Web 端 MVP — 入口登记

## 原始表达（可回放，未改写）

> 我想做一个个人知识库的应用，就像 Obsidian 一样，先做 web 端 MVP，个人使用，功能有写入 / 查看知识库列表 / 知识库图谱（星球形状，点击弹框显示知识库）。
>
> 项目目录用 D:\project\_qoder_trials\kb-app-20260923（目前是空目录），所有产物和代码都放在这个目录里，不要改动这台机器上的其他目录。

## 目标（FACT：来自原始表达）

- 面向个人使用的知识库应用，首个版本为 Web 端 MVP。
- 三个候选能力：写入、查看知识库列表、知识库图谱（星球式呈现，点击星球弹框展示该知识库）。
- 对标物：Obsidian（作为认知锚点，不等于功能等价的授权范围）。

## 角色与场景

- `FACT` 单一角色：个人使用者本人（原始表达明确「个人使用」）。
- `INFERENCE` 场景为个人日常记录与回顾：写下一条知识 → 在列表里找回 → 在图谱里按关联发现。
- `ASSUMPTION` A1：单机/本地运行即满足验收，不含多人协作、账号体系与权限分级。
- `ASSUMPTION` A2：数据由使用者本人产生，MVP 不做导入导出、同步与备份。

## 约束（FACT）

- 全部产物与代码只落在 `D:\project\_qoder_trials\kb-app-20260923`；不改动本机其他目录。
- MVP 只做 Web 端形态（原始表达明确）。

## 非目标（暂定，待确认）

- 多人协作、评论、共享链接；插件生态；移动端；桌面端；发布上线与运维（默认终点=本地可运行的可验收结果，未获授权不做发布阶段）。

## 未知项（OPEN，影响范围）

- `OPEN-1` 「知识库」在数据语义上指什么层级：一个库（内含多条知识）还是单条知识本身？图谱上的一个星球对应哪一层？
- `OPEN-2` 「写入」的交互形态：自由 Markdown 长文编辑 / 结构化短条目 / 对话式快速记录。
- `OPEN-3` 星球之间的连线（关联）从何而来：手动指定 / 由标签或引用自动生成 / MVP 阶段先不连线。
- `OPEN-4` 「点击弹框显示知识库」的展示内容层级：只显示摘要，还是要能继续下钻到条目内容与相邻关联。
- `OPEN-5` 验收终点：本机跑起来自己用即可，还是需要可给别人访问的地址（后者属于发布，需另行授权）。

## 研究命题（不由用户作答，待需求方向确认后按 oss-research-policy 投入）

- R1 星球式知识图谱的可视化实现路线与成熟开源做法（渲染、大规模节点、交互）。
- R2 Markdown 编辑与本地存储的常见实现取舍。
- R3 Obsidian 的 graph / vault / note 概念模型，用于校准上表的层级语义与功能全景。
- R4 个人知识库的关联建模方式（双向链接、标签、引用）。

> 以上均属技术选型与外部证据域，`ASSUMPTION` 未经确认不作为下游输入；R1/R2 在需求方向 `ACCEPTED` 前不启动（资源投入门禁）。
