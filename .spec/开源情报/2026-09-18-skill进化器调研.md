## 发现清单

### 1. 「不预载技能，长出来」——任务结晶成 skill（P1 · 泳道 A · 需改造）
- 出处：lsdefine/GenericAgent（14.2K★）— README「Self-Evolution Mechanism」+ `memory/` 目录
- 优秀点：设计哲学「don't preload skills, evolve them」；每完成一个新任务自动把执行路径结晶为 `memory/*_sop.md`（+helper 脚本），下次同类任务一行调用；3K 行种子长出个人 skill 树，<30K 上下文窗口
- 建议落点：新进化 skill 的**产出物形态**——进化产出对齐本仓 SKILL.md 标准格式，不另造格式；其「产物是数据库不是报告，遗漏即损失」原则写进产出约定
- 证据：`[新 Task] → 自主探索 → 结晶成 Skill 写入 memory → 下次直接召回`

### 2. 会话显著点挖掘的工程化判据（P0 · 泳道 A · 直接搬）
- 出处：lsdefine/GenericAgent — `memory/L4_raw_sessions/salient_mining_sop.md`
- 优秀点：把「从历史会话挖什么」写成了可执行判据——①增量扫描（增量标记，只扫新 session）；②持久知识层（读-更新-写回）+ 追加式事件列表；③提取标准明确到「标记什么/不标记什么」（情绪事件只标语气波动不标内容；持续活动 vs 已消失事项必须二选一归类）；④证据标准（系统里的被动出现不构成证据，不能从「存在某 SOP」推断用户在做某事）；⑤坑点直言「关键词扫描看不到情绪与习惯，必须读原文」
- 建议落点：进化 skill 的「偏好/行为习惯挖掘」模式核心；也可反哺 Skill-Optimizer 模式②（挖聊天）——现在缺的正是这种判据级 SOP
- 证据（坑点原文）：「用户消息的含义不在关键词里，在语气和上下文里。脚本扫描只能看到主题，看不到情绪、看不到习惯……必须阅读原文。」

### 3. 完整 skill 进化管线 + 五条护栏（P0 · 泳道 A · 需改造）
- 出处：NousResearch/hermes-agent-self-evolution（5.4K★）— README + PLAN.md
- 优秀点：六步优化环「选目标 → 建评测集（真实会话挖掘 or 合成）→ 包装 → 优化器 → 对比评估 → 部署」；**评测数据从真实会话（sessiondb）挖**，正是「从运行过程收集」；五条护栏：全测试通过 / skill ≤15KB / 不破坏缓存 / 语义不漂移 / 一律走 PR 人工审核绝不直推；目标分层（Tier1 skill 文本 = 最高价值最低风险）
- 建议落点：新进化 skill 的主流程骨架 + 护栏清单；「语义不漂移」「人工确认后落地」与本仓「只审不改/确认后交 Skill-Optimizer」约定天然对齐
- 证据：`Guardrails: 1.Full test suite 2.Size limits 3.Caching compatibility 4.Semantic preservation 5.PR review — never direct commit`

### 4. 反思式进化：读轨迹而非看分数（P1 · 泳道 A · 仅启发）
- 出处：gepa-ai/gepa（6.6K★，ICLR Oral）— README
- 优秀点：与 RL 把轨迹坍缩成标量奖励不同，GEPA 让 LLM 读完整执行轨迹（报错/推理日志）诊断「为什么失败」再定点变异；生产实证：coding agent 经 auto-learned skills 从 55%→82%
- 建议落点：进化 skill 的「诊断」环节铁律——分析 skill 运行问题必须读轨迹原文（日志/会话记录），禁止只凭结果好坏下结论
- 证据：`reads full execution traces to diagnose why a candidate failed and propose targeted fixes`

### 5. 偏好作为一等公民 + 新建/合并/跳过三决策（P1 · 泳道 A · 需改造）
- 出处：volcengine/OpenViking（38K★）— README
- 优秀点：`viking://user/{id}/memories/preferences/`（writing_style、coding_habits）把用户偏好做成一等公民目录；会话 commit 后后台提取，**候选记忆与既有记忆比对后三选一：新建/合并/跳过**；L0 摘要/L1 概览/L2 全文按需加载；LoCoMo 实证 24–57%→80–83%
- 建议落点：进化 skill 的偏好库存储形态——纯 markdown 目录即可（不引 DB）；「新建/合并/跳过」去重决策直接搬
- 证据：`candidates are compared with existing memories for creation, merging, or skipping`

### 6. 会话捕获→压缩→回注 + 按月追加式感知日志（P2 · 泳道 A · 需改造）
- 出处：thedotmack/claude-mem（94K★）— README
- 优秀点：自动捕获 tool 使用观察→语义压缩→未来会话可检索；awareness push 把高价值观察（decision/bugfix/security_alert）按日期追加进宿主已有的 `memory/log/YYYY-MM.md`——「不侵入、只追加、宿主自己会重读」的轻集成设计
- 建议落点：skill 运行中问题埋点的补充形态——现有 `issue/<skill>/<日期>/` 之外，可加按月追加的信号日志供进化 skill 定期消化（形态待拍板，避免双轨混乱）
- 证据：`needle observations are appended as dated lines into that bot's memory/log/YYYY-MM.md`

### 7. 可审计进化：进化留痕 + 策略档位 + git 回滚（P1 · 泳道 A · 仅启发）
- 出处：EvoMap/evolver（9.1K★）— README + SKILL.md
- 优秀点：每次进化写 EvolutionEvent 进 `./memory/` 审计；进化策略档位（balanced/innovate/harden/repair-only…）；强依赖 git 做回滚与爆炸半径计算，solidify 失败自动 stash 回滚；其论文结论「skill 文档是稀疏不稳定控制信号」值得警惕但不必照搬 Gene 概念
- 建议落点：进化 skill 必须带进化台账（改了什么/依据哪条信号/如何回滚——git 天然支持）；策略档位简化为 保守(只建议)/标准(确认后改)/激进(自动改+事后报) 三档
- 证据：`It writes an EvolutionEvent into ./memory/ for audit` / `Rollback strategy on solidify failure: stash`
