# frontend-dev — 前端实现

## 何时用

- `task.md` 的 AC 与 `design.md` 的页面/接口就绪，进入前端实现。
- 输入：task.md、design.md、原型（结构基线）、设计稿与 design-system（视觉基准，有则）、现有代码。
- 环境前置：浏览器工具可用，能真实渲染并截图；全无则停等，不拿静态比对冒充视觉证据。
- 不适用：方案未定交 [tech-design](../tech-design/SKILL.md)；全量测试交 [auto-test](../auto-test/SKILL.md)；缺陷修复交 bug-fix。
- 开发期零选型：框架/组件库/请求方式只来自 design.md 或现有基线。

## 交付物

- 代码：按 AC 逐页面/功能点实现；组件按现有结构抽离（复用 ≥2 处才抽）；一个功能点一提交，提交信息可追溯 AC。
- 自测证据：写进 `.spec/tasks/<YYYY-MM-DD>-<slug>/test-report.md` 的「开发自测」段（auto-test 后续在同一文件补全量报告）：build/test/lint 输出 + 每页截图（设计稿或原型与实现）+ 关键状态截图。
- 契约对齐清单：页面取数/提交与 design.md 接口逐一对应；缺口显式登记，不静默造字段。
- 不交付：需求/方案改动、评审报告、验收结论；评审与验收见 [review](../review/SKILL.md)、[acceptance](../acceptance/SKILL.md)。

## 验收判据

- AC 覆盖：每条前端 AC 有页面/交互实现 + 至少一条测试或可复现操作步骤。
- 结构对应：区块、布局、交互与原型逐块对应；有设计稿时视觉值（色/字号/间距/圆角）对 design-system 或设计稿。
- 状态覆盖：空、加载、错误、无权限、超长文本、大数据量按 AC 与方案覆盖，无布局破碎。
- 契约一致：请求路径/字段/错误处理与 design.md 一致；共享类型只引用不重定义。
- 门禁全绿：install/typecheck/lint/test/build 实际通过，贴输出；浏览器控制台无未处理错误。
- 交互可用：主流程可走通，失败有提示，键盘可操作（方案要求时）。
- 无硬编码：接口地址、文案、颜色、尺寸走配置与 token。
- 无未登记 TODO、占位交互或假数据兜底。

## 停等点

1. 设计稿缺失或与原型/AC 冲突，视觉基准无法确定。
2. 接口契约冲突或字段缺口：design.md 与后端不一致、页面需要但契约没有。
3. 浏览器工具全无，或关键页面无法真实渲染/截图。
   其余默认「按现有规范裁决 + 记录假设 + 继续」。

## 证据要求

- 截图：真实运行页面截图，标页面、状态与时间；与设计稿并排是关键页的必须项。
- 命令输出：build/test/lint 原文，附环境与版本；控制台错误导出留证。
- 还原差异：可接受差异与必须修正分开列，必须修正的修完再交。
- 契约核对：逐条对齐记录，缺口标处置。
- 旧截图、设计稿本身、自述「看起来一样」= 未验证。
