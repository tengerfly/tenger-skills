# 评审（review）

> 规则唯一事实源：[shared/review-contract.md](../../shared/review-contract.md)。本文只写怎么做，不重复定义。
> 硬约束：只审不改、隔离评审、判据 + 证据、最多 3 轮。缺陷检出清单：[bug-patterns/README.md](../../bug-patterns/README.md)。

## 何时用

- 标准/完整档任务交付前：独立评审代码或交付物。
- 轻量档需要一次快速评审时（新上下文，可不出正式评审归档）。
- 触发词：评审、审查、走查、检查契约、交付前把关。
- 不适用：写代码/改代码（归 dev Skill）、跑测试（auto-test）、最终签收（acceptance）。
- 前置输入：任务与范围、AC、技术方案/契约、测试证据、被审对象路径与 commit。
- 判据缺失先补输入再开审：没 AC、没测试证据、版本不明都不审。
- 批次：单批只审一端（如只审后端）；完整档可拆前端/后端/契约多个评审单元。

## 交付物

- `review-package.md`：评审包，派发前写好，落 `.spec/tasks/<日期>-<slug>/`。
- `review-report.md`：评审报告，同目录；模板见 [templates/review-report.md](templates/review-report.md)。
- 报告六节固定，问题清单并入 §4，不另建第二份清单。
- 建议补丁只写进报告（仅 P0 附），不落盘源码。
- 结论：ACCEPT / FIX / REJECT 三值之一。

评审包至少含：任务与档位、被审对象（路径 + commit + sha256）、判据（AC/技术方案/测试证据）、边界、上轮已确认项、输出契约。

## 验收判据

- 报告六节齐全；§5 结论是本轮三值之一，与残留问题一致。
- §0 隔离信息四项齐全：评审者 id、上下文类型、输入清单（含 sha256）、时间。
- 每条问题有位置 + 证据 + 修复判据；无出处、无判据的条目为 0。
- AC 逐条有结论；可运行性四项（install/typecheck/test/lint）有结果或写明未取证原因。
- 契约专项写明比对范围与接口条数，不只写「已检查」。
- P0/P1 清零才可 ACCEPT；P0 残留只能 REJECT。
- 零问题也写了覆盖边界：查了什么、没查什么、残余风险。
- 缺陷模式库已逐条对照，报告有对照记录。

## 停等点

1. 无独立评审能力：既无 fresh 子代理也无新会话 → 停，要隔离能力；不许自己读一遍当评审。
2. 判据缺失：无 AC / 无技术方案 / 被审对象版本不明 → 停，先补输入或由 owner 明确降档。
3. 完整档缺 owner 签收或回滚验证 → 停，等 owner 补；不得代签。

其余（范围外发现、修复方式分歧、小瑕疵）默认裁决 + 记账 + 继续。

## 证据要求

- 只认：可复现命令与输出、测试报告、构建产物、真实运行/截图、日志、文件 sha256。
- 不认：模型自述、口头描述、旧截图/旧输出、子代理「已通过」的汇报。
- 静态验证贴命令 + 退出码；跑不了标「未取证（原因）」，不得写「通过」。
- 评审包与被审对象用 sha256 标定版本，报告写明输入清单。
- 每条结论后挂证据路径。

## 评审流程

0. 判档：轻量/标准/完整；拿不准往高一档，写进报告。
1. 派发：按 [templates/review-package.md](templates/review-package.md) 建包 → 派 fresh 子代理或新会话 → 评审者只拿包。完整档多单元：每单元独立上下文、互不可见，汇总单独做。
2. 判据核对：AC 逐条 → 契约三方比对 → 可运行命令 → 安全数据 → 清理 → 性能边界 → 缺陷模式库逐条。
3. 证据核对：命令/产物/截图/日志逐项核，未取证项单列。
4. 问题分级：P0/P1/P2，每条带位置、成因、修复判据、归因。
5. 出结论：三值之一，写覆盖边界与残余风险。
6. 复核：修复后只验本轮已确认项，最多 3 轮。

- 只审不改：不改源码/方案/配置；发现 skill 问题转 issue 卡。
- 报告落点：`.spec/tasks/<日期>-<slug>/review-report.md`。
- 3 轮规则与残留处置按契约；不自动开第 4 轮。
- 全流程不读产出会话记录，不参考自检结论。
- 出结论前自检：有没有残留 P0/P1、证据是否全在本轮、隔离记录是否齐。

## 结论与处置

| 结论 | 条件 | 下一步 |
|---|---|---|
| ACCEPT | 无 P0/P1、AC 全过、证据齐、隔离齐 | 转验收 |
| FIX | 有 P1/P2 残留、P0 已清 | 产出方按清单修，修完只验本轮 |
| REJECT | P0 残留 / 证据缺失 / 隔离不成立 | 修复或补证据后重审，不得放行 |

- P0 残留一律 REJECT，不得「先放行后补」。
- P1 残留不自行 ACCEPT；owner 明确签收风险才可转 ACCEPT，并由验收登记遗留风险。
- 3 轮后：P0 → REJECT；P1 → FIX + 升级 owner 决策；P2 可留并登记。
- 评审通过 ≠ 可交付；最终交付结论归验收。
- 结论与问题数、证据一一对应，写不出依据就不给 ACCEPT。
