# auto-test：验收测试与修复闭环

> 铁律 1：证据先于声明——没有本次实测的命令 / 输出 / 截图，不许说「通过」「已修复」。
> 铁律 2：分层短路——L0 不过不跑 L1，L1 不过不跑 L2；token 只花在确定性检查之后。
> 铁律 3：真实优先、mock 兜底——mock 了什么写进「覆盖边界声明」；核心链路整体 mock = 零覆盖。

## 何时用

- 触发：AI 写完代码要验收 / 回归 / 复测；要跑 E2E、找 bug；修复后 fresh 回归；交付前要测试报告。
- 输入：代码与启动命令（先读 README / 脚本 / CI，仍不确定就问，不猜）、验收基准（AC / PRD，缺则标「假设」）、上一轮报告（有则只跑失败项 + 全量冒烟）。
- 不适用：需求不合理（回 requirements）、代码质量评审（交 review）、纯方案问题（回 tech-design）。

## 交付物

产物放被开发项目 `.spec/tasks/<YYYY-MM-DD>-<slug>/`：

- `test-report.md`：①可复现声明（命令 / 环境 / 数据 / 版本）②分层结果表 ③覆盖范围与边界 ④缺陷清单（P0/P1/P2 + 证据）⑤结论与下一步。
- `evidence/`：命令输出、截图、console / network 日志；文件名带用例号。
- 修复任务卡：每条 P0/P1 一张（现象 / 复现步骤 / 期望 vs 实际 / 证据 / 关联用例）。
- 问题卡：测试暴露的 skill / 流程问题写本仓 `issue/NNN-slug.md`（模板 [000-template.md](../../issue/000-template.md)），规则见 [issue-loop.md](../../shared/issue-loop.md)。
- 回归：新一轮报告覆盖上一轮，不沿用旧截图与结论。

## 验收判据

- L0 五条全绿：install → typecheck → lint → 单测 → build；每条有命令、退出码、输出尾部。
- L1 关键接口通过：状态码 / 结构 / 关键字段；断言前先 GET 一次真实响应，不凭想象写字段。
- L2 主链跑通：真实浏览器或真实 API；关键状态用注入构造前置；三态（加载 / 空 / 错误）必测；有设计稿才做视觉抽查。
- 覆盖边界声明非空：覆盖什么 / 未覆盖什么 / 残余风险；零缺陷也必须写。
- 缺陷与证据成对：P0 立即修、P1 本轮修、P2 排队；无证据的缺陷不算数。
- L3/L4 未命中信号就写「本轮未跑」，不许假装跑过。
- 结论只有两种：全绿 → 交 review；有 P0/P1 → 修复卡 + fresh 回归。

## 停等点

- 启动命令 / 环境 / 凭证定不下来：停下问，不猜命令、不硬跑。
- 要打真实外部链路（付费、生产写入、发通知）：先要授权与数据隔离方案。
- L2 用例范围与 mock 方案：确认后执行（回归模式跳过）。

## 证据要求

- 只认：可复现命令 + 输出、测试报告、构建产物、真实运行截图、console / network 日志、文件 sha256。
- 不认：模型自述、「应该没问题」、旧截图、人工勾选清单。
- 失败也是证据：失败的命令、截图、日志必须进报告，不许一句话带过。
- 每条结论可回查：报告里的命令能被人重跑。

## 分层门禁

| 层 | 查什么 | 何时跑 | 失败处置 |
|---|---|---|---|
| L0 确定性 | install / typecheck / lint / 单测 / build | 每次必跑 | 立即停，出修复卡，不进上层 |
| L1 契约 | 关键接口状态码 / 结构 / 关键字段 | L0 绿后 | 停止，出修复卡 |
| L2 主链 | 真实 E2E + 三态 + 慢接口分档（>1s / >3s / >5s 记录） | L0/L1 绿后 | 出修复卡 + 截图 |
| L3 探索性 | 乱点乱填、非常规路径 | 按需 | 只出报告，不阻断 |
| L4 专项 | 负载 / 压力 / 稳定、安全扫描、兼容 / 无障碍 | 命中需求信号才跑 | P0 才阻断 |

浏览器或真实链路不可用：报告写「未测 + 原因 + 补齐步骤」，不拿读代码冒充运行；L4 跑前确认成本与授权。

## 修复闭环

报告有缺陷 → 出修复任务卡 → 交编码方修复（fresh 上下文，不带本轮测试结论）→ 全量回归（不是只跑失败项）→ 全绿收口 / 计数 +1。

- 轮次上限 3；超限停下，输出震荡分析（哪两个缺陷在互相打架），交用户裁决。
- L0/L1 的失败，任何 AI 判断无权覆盖。
- 每轮都是新证据；回归执行者只拿 AC + 用例 + 当前代码。
- 修完后原失败用例 + 受影响用例必须同轮通过。
- 可运行性问题定位交 [bug-fix](../bug-fix/SKILL.md)；有预防价值的缺陷模式沉淀看 [bug-patterns/README.md](../../bug-patterns/README.md)。
