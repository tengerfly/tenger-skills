# workflow — 唯一入口

## 何时用

- 用户提出任何软件任务（新功能、迭代、Bug、重构、发布、巡检），且没点名专业 Skill。
- 任务跨多个阶段，需要判断「下一步做什么、产物放哪、什么时候停」。
- 不确定任务大小、该走哪条路径。

前置输入：项目路径、目标与终点、允许/禁止范围、已有材料；缺关键项按第 5 类硬停问一次。

先判三档（判不了按标准；三档的完整判据与结论三值见 [review-contract](../../shared/review-contract.md)）：

- 轻量：文案/样式/单文件小改 → 自检 + 1 次快速评审。
- 标准：一般功能开发 → 独立评审 + 测试证据 + 验收清单。
- 完整：生产/发布/迁移/权限/资金 → 标准全部 + owner 签收 + 回滚验证。

## 交付物

主链：需求 → 方案 → 开发 → 测试 → 评审 → 验收 → 交付。轻量可跳方案与测试文档，但不跳验收。

| 步 | 调度 | 产物（落在任务工作区） |
|---|---|---|
| 需求 | requirements | `task.md` 里的 AC 清单 |
| 方案 | tech-design | `design.md` |
| 开发 | backend-dev / frontend-dev | 代码 + 自测证据 |
| 测试 | auto-test | `test-report.md` |
| 评审 | review | `review-report.md` |
| 验收 | acceptance | `acceptance-report.md` + 证据包 |
| 交付 | 本 Skill 收口 | 结论、遗留风险、loop-log 一行 |

- 任务工作区：被开发项目内 `.spec/tasks/<YYYY-MM-DD>-<slug>/`；`task.md` 必建，其余按档位按需。
- 每个节点交接一句话状态卡：当前步骤/Skill、产物路径、证据、待决事项、下一步。
- 本 Skill 只判档、排序、交接、收口，不代做专业 Skill 的产物。

## 验收判据

- 档位判定有命中依据，不是「感觉不大」。
- 每个节点有产物与证据路径；跳过的节点写「跳过 + 依据」。
- 交付前最后一步是 acceptance；结论必须为 ACCEPT 才算完成，DoD 与三值口径见 [acceptance-contract](../../shared/acceptance-contract.md)。
- 业务任务产物只留在真实项目 `.spec/tasks/`，本仓不建 `.spec/`。
- 最终交接：结论、证据路径、遗留风险、回滚方式、下一步，缺一项不算交付。

## 停等点

除以下五类硬停外，一律裁决 + 记账 + 继续：

1. 不可逆或破坏性：删除、覆盖已批准基线、数据迁移、重置。
2. 安全敏感：认证授权边界、资金与计费、敏感数据、外部凭据。
3. 本仓之外的副作用：push、发布部署、改外部仓、付费调用。
4. 关键产品决策：范围、定位、目标用户、MVP、验收口径的实质变更。
5. 无路可走：缺关键输入且无法推断。

裁决记一行：`Ruling: 决定 — 理由 — 错了的代价 — 回退方式`。轻量写进 `task.md`；标准/完整写进任务工作区。

## 证据要求

- 只认可复现物：命令与输出、测试报告、构建产物、真实运行/截图、日志、文件 sha256。
- 模型自述、口头描述、旧截图 = 未验证。
- 每次交接写证据路径，不写「已验证」四个字。
