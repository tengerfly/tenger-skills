# backend-dev — 后端实现

## 何时用

- `task.md` 的 AC 与 `design.md` 的接口/表结构就绪，进入后端实现。
- 输入：task.md、design.md、现有代码与测试、[bug-patterns](../../bug-patterns/README.md) 相关模式。
- 不适用：方案未定交 [tech-design](../tech-design/SKILL.md)；全量测试与证据编排交 [auto-test](../auto-test/SKILL.md)；缺陷修复交 bug-fix。
- 开发期零选型：技术栈只来自 design.md 或现有基线；都不足以开工时停等，不在实现中重选。

## 交付物

- 代码：按 AC 逐功能点实现；一个功能点一提交，提交信息可追溯到 AC。
- 自测证据：写进 `.spec/tasks/<YYYY-MM-DD>-<slug>/test-report.md` 的「开发自测」段（命令、输出摘要、覆盖的 AC 与用例名；auto-test 后续在同一文件补全量报告）。
- 契约对齐清单：实现与 design.md 接口逐条对应；有偏差显式登记，不静默自造字段。
- 不交付：需求/方案改动、评审报告、验收结论；评审与验收见 [review](../review/SKILL.md)、[acceptance](../acceptance/SKILL.md)。

## 验收判据

- AC 覆盖：每条后端 AC 有实现 + 至少一条自动化测试，能指出测试文件与用例名。
- 关键路径测试先行：先有失败测试再实现，提交顺序或测试记录可证。
- 门禁全绿：install/typecheck/lint/test 实际通过，贴输出。
- 契约一致：接口路径/字段/错误码/分页/枚举与 design.md 一致，无自造字段。
- 边界守住：接口层不含业务与数据访问逻辑；未直接访问其他服务的库。
- 异常路径：失败响应、重复提交、并发按方案实现并有测试（方案要求时）。
- 迁移可回滚：脚本可重复执行，回滚步骤已验证。
- 无未登记 TODO、占位实现或注释掉的代码。

## 停等点

1. 契约冲突：AC、design.md 与现有代码/前端调用不一致，或方案缺字段。
2. 关键业务规则、权限或数据归属不明，方案未覆盖且影响实现。
3. 需改公共接口、共享类型、跨模块数据迁移等会波及其他任务的动作。
   其余默认「按现有代码风格裁决 + 记录假设 + 继续」。

## 证据要求

- 命令输出：typecheck/lint/test 原文，附环境与版本；失败即证据，不删不藏。
- 测试映射：测试名与 AC 编号逐一对应；覆盖率只在方案要求时给。
- 契约核对：逐条对照清单或脚本输出，标出偏差与处置。
- 迁移证据：重复执行记录、回滚演练记录（涉及数据库时）。
- 提交证据：commit hash 与 AC 对应表。
- 自述「已完成 / 应该没问题」= 未验证。
