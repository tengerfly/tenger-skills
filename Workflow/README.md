# Workflow —— 全流程开发编排 Skill

> 状态：✅ 定稿
> 定位：只调度、记账、守门，不产出业务文档。原则：一条链，任意起点，逐步推进，随时可停。
> 链外修复闭环：`Bug-Fix` 不入主链、独立触发——⑭ 测试发现的可运行性问题转 `Bug-Fix`（定位→方案→开发→回归），修复沉淀入源仓库 `bug-patterns/` 集中池反哺方案/开发 skill。

## 一、核心模型

```
①竞品 → ②PRD → ③PRD评审 → ④原型 → ⑤原型评审 → ⑥UI/UX → ⑦UI/UX评审
→ ⑧TDD → ⑨FTDD → ⑩方案评审 → ⑪后端 → ⑫前端 → ⑬代码评审 → ⑭测试
```

| 参数 | 默认 |
|---|---|
| 起点 | 用户点名或按 .spec/ 推断（须确认） |
| 终点 | 不点名 = 只跑起点节点 |
| 跳过 | 用户随时说跳过 |

每节点完成 → 回填 PIPELINE → 交接摘要 → 停下等用户。

硬串行：⑧→⑨、⑪→⑫。评审节点（③⑤⑦⑩⑬）：已确认=0 放行，否则回修改方（上限 3 轮）。

## 二、节点速查（要点）

每节点前置缺失即阻塞；浏览器硬依赖 ⑤⑦⑨⑫⑭、软检测 ⑧⑩；⑥ Superdesign 三件套硬依赖、⑥⑦ 可选。⑭ 发现可运行性问题 → 转 `Bug-Fix`。详见 SKILL.md。

## 四、快速上手

- 从零开发 → ①→⑭；有 PRD 走后续 → ④→⑭；只点名某节点 → 只跑该节点。
- 想改流向直接说「跳过 XX / 从 X 开始 / 继续」。
