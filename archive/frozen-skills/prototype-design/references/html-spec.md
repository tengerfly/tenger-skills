# 低保真 HTML 原型实现规范

> 用途：规定低保真 HTML 原型的文件组织、跳转方式、极简配色、可点击交互，保证产出可运行、可快速验证逻辑。

---

## 一、文件组织

- 每个**独立页面**一个 HTML 文件（以步骤 3 布局清单 Gate 的清单为准），命名语义化：`index.html`（入口）、`list.html`、`detail.html`、`publish.html` 等；
- 弹框 / 抽屉 / 表格 / 卡片 / 页内区块**不单独成文件**，内嵌在宿主页面中实现（原生 JS 控制显隐）；
- 所有文件放在 `.spec/原型/` 同一目录下，便于相对路径跳转；
- 附 `布局清单.md`（载体划分）与 `README.md`（使用说明）。

## 二、页面间跳转（可点击闭环）

- 用真实 `<a href="detail.html">` 链接实现跳转，禁止用无意义的 `#` 占位；
- **闭环要求**：每个页面都要能「进来」（有入口链接指向它）且能「出去」（有返回 / 下一步链接），断头或孤立页面即缺陷；
- 列表项、按钮、卡片等可点击元素，都接真实链接或说明跳转目标。

## 三、极简配色（低保真基调）

每个 HTML 文件用一套极简的 CSS 变量，由 AI 根据产品定位自动定一个**单一主色**做点缀，其余用中性色。**不沉淀独立 token 文件、不单独让用户选配色**：

```css
:root {
  --c-bg: #f7f7f8;        /* 页面背景（中性浅灰） */
  --c-surface: #ffffff;   /* 区块/卡片面 */
  --c-border: #e5e5e6;    /* 描边 */
  --c-text: #1f1f1f;      /* 正文 */
  --c-text-2: #6b6b6b;    /* 辅助文字 */
  --c-primary: #0f766e;   /* 单一主色（AI 按产品定位定一个） */
  --c-danger: #dc2626;    /* 危险/错误（仅按需） */
}
```

- 全站共用同一套变量；配色只为「区块可读、层级分明」，**不做视觉精修**。

## 四、可点击交互

- 静态可点击元素用 `<a>` 跳转页面；
- 页内交互（Tab 切换、弹框/抽屉开关、表格筛选、表单校验提示）用少量原生 JS 实现，不引第三方框架；
- 交互要有真实反馈：按钮点击后跳转或状态变化，不能是「死按钮」。

## 五、内容要求

- 界面文案用**真实业务文案**（来自 PRD 的需求描述），不用占位符 Lorem、不用「某某某」「测试数据」式假文案；PRD 未定义的用贴合定位的示例文案；
- 图标用简单内联 SVG 或纯文字，**不用 emoji**。

## 六、端类型布局规范（强制）

端类型在流水线步骤 2 与用户确认，决定页面布局规范：

| 端类型 | 视口 / 布局 | 导航交互 | 交付形态 |
|---|---|---|---|
| Web 端 | 桌面宽度（如 1280px 容器） | 侧边栏 / 顶部导航 | 单套 `*.html` |
| 移动端 | 375px 视口、触控间距 | 底部 Tab / 顶部返回 | 单套 `*.html` |
| 双端同步 | 由用户二选一（见下） | 各自按端匹配 | 见下 |

- **优先 Web 端**：用户未明确时，推荐并默认按 Web 端产出；
- **双端同步由用户选择，不代拍板**：
  - **两套独立原型**：Web / 移动各一套，交互与布局各自定制，交付 `web/` 与 `mobile/` 两个子目录；
  - **一套响应式布局**：同一套页面用媒体查询断点适配多端，交付单套 `*.html`；
- 移动端注意触控目标尺寸、底部 Tab 拇指区，Web 端注意信息密度与多栏布局。

## 七、交付自检

- [ ] 每个独立页面都有对应 HTML 文件（弹框/抽屉/表格/卡片内嵌宿主页）；
- [ ] 页面间跳转闭环，无断链、无孤立页；
- [ ] 全站共用同一套极简 CSS 变量，配色统一；
- [ ] 文案真实可感，无 Lorem 占位、无 emoji 图标；
- [ ] 无过度视觉精修（无渐变、光斑、玻璃拟态、重阴影）。
