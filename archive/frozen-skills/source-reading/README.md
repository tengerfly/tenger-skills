# Source-Reading（源码导读）

给定一个 GitHub 仓库，产出帮你**快速学习源码**的导读文档：流程图给全局感，关键点用大白话讲透（干什么 + 为什么这么设计），大仓库自动拆成多章节、按学习动线排序。

## 快速开始

```
帮我学习 vuejs/core 的源码
用 Source-Reading 导读 facebook/react，先出章节规划
导读 axios 源码，只看拦截器这条线
```

## 产出

落盘 `<工作区>/.spec/源码学习/<owner>__<repo>/`：

- `00-总览.md` —— 架构总图 + 学习动线（先读哪章后读哪章）+ 上手建议
- `01-*.md` … `NN-*.md` —— 逐章：本章位置 → 前置知识 → 核心问题 → 主线流程图 → 关键点讲解（带 `文件:行号` 锚点）
- `章节规划.md` —— 大仓的拆章方案留档
- `导读.md` —— 小仓或批量/点名「一份文档」时的单文档多章节形态
- `大纲.md` —— ④ 大纲先行留档（章节 + 功能点清单 + 命题清点结论），成文按纲填充、复核对纲

## 四条命根子

通俗（说人话）· 不啰嗦（每点 ≤5 句）· 逻辑清晰（一条主线走到底）· 前置铺垫（不懂的概念先补，链接核实过才给）

## 边界

- 只读不写：绝不改源码仓库
- 竞品/选型调研 → `Competitive-Analysis`
- 借开源实践反哺自有 skill → `OSS-Radar`
