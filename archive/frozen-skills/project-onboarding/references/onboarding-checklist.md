# Project Onboarding 检查清单

## 证据标签

| 标签 | 含义 | 示例 |
|---|---|---|
| `FACT` | 直接从文件、命令、日志或确认中得到 | `package.json` 有 `test` 脚本 |
| `EVIDENCE` | 可复现的执行结果或外部记录 | `2026-09-20` 在隔离环境运行测试通过 |
| `INFERENCE` | 基于事实的推断 | 该模块可能是鉴权边界 |
| `ASSUMPTION` | 为继续工作暂时采用的假设 | 假定 staging 可用 |
| `OPEN` | 尚未得到答案 | 回滚是否包含数据迁移 |

## 最小盘点表

- [ ] 项目类型、平台、环境、生命周期模式
- [ ] 分支、commit、工作区未提交变更
- [ ] 安装、启动、测试、类型检查、lint、build 命令
- [ ] 入口、模块、依赖、外部服务和数据存储
- [ ] 关键用户旅程/服务主链及异常路径
- [ ] API、事件、数据迁移和兼容性
- [ ] 测试层级、失败项、不稳定项和缺口
- [ ] web-monitor / server-log / server-monitor 接入、关联 ID 和版本信息
- [ ] 发布、灰度、回滚和发布后观察
- [ ] 未知项、风险、证据位置和下一步路由

## 质量与安全红线

- 不复制 secrets、token、客户数据或个人数据。
- 不以“目录看起来合理”替代运行和测试证据。
- 不把旧项目行为直接等同于正确产品需求。
- 不在接管阶段顺手改代码；发现缺陷只登记并路由。
- 不以模型输出、代码注释或“应该”作为唯一证据。
