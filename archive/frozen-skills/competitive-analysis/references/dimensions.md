# 五层分析维度详表

> 竞品分析时五层全做，每层内根据调研目标选重点子维度。每个子维度标注「分析要点」和「数据来源」。

## ① 市场趋势

| 子维度 | 分析要点 | 数据来源 |
|--------|---------|---------|
| 市场规模与增速 | 赛道整体规模、年增长率，判断天花板 | 行业报告（艾瑞 / IDC / Gartner） |
| 增长驱动因素 | 技术、需求、政策等推动增长的原因 | 行业报告、科技媒体 |
| 技术演进方向 | 行业技术趋势（如 AI 化、移动化） | 科技媒体、行业报告 |
| 政策与合规 | 监管、牌照、数据合规要求 | 官方政策、媒体报道 |
| 竞争格局 | 市场集中度、头部玩家及份额 | 行业报告、数据工具 |

## ② 竞品优缺点

| 子维度 | 分析要点 | 数据来源 |
|--------|---------|---------|
| 定位 | 目标人群 + 核心主张（一句 slogan） | 官网、产品介绍 |
| 核心功能覆盖度 | 主要功能有哪些、覆盖多广 | 官网、亲自体验 |
| 强项 / 短板 | 相对优势与明显不足 | 评测、用户评论 |
| 定价与付费模式 | 价格档位、免费 / 付费 | 官网、应用商店 |
| 用户口碑 / 评分 | 评分、好评 / 差评点 | 应用商店、社区 |
| 用户规模 / 市场份额 | 下载量、活跃用户、份额 | 数据工具、财报 |

## ③ 用户痛点

| 子维度 | 分析要点 | 数据来源 |
|--------|---------|---------|
| 目标用户画像 | 谁在用（年龄、身份、场景） | 产品定位、社区 |
| 核心使用场景 | 用户在什么情况下用 | 评论、使用场景 |
| 痛点与抱怨 | 用户不满、投诉集中在哪 | 应用商店差评、社区 |
| 未满足需求 | 用户想要但没有的功能 | 评论「希望有 XX」、社区 |
| 现有替代方案 | 用户现在用什么解决 | 社区、竞品分析 |

## ④ 商业模式

| 子维度 | 分析要点 | 数据来源 |
|--------|---------|---------|
| 收入模式 | 订阅 / 免费增值 / 广告 / 抽成 | 官网、财报 |
| 定价策略 | 价格档位、锚点、促销 | 官网、应用商店 |
| 成本结构 | 主要成本（AI 产品尤其算推理成本） | 财报、行业分析 |
| 获客与增长 | 渠道、投放、增长策略 | 财报、媒体报道 |
| 变现 / 盈利 | 是否盈利、变现能力 | 财报、融资信息 |

## ⑤ 技术可行性

| 子维度 | 分析要点 | 数据来源 |
|--------|---------|---------|
| 技术选型 | 自研 vs 接 API、用了什么技术 | 招聘信息、技术博客 |
| 数据与资源 | 知识库、数据源、训练数据 | 技术博客、招聘信息 |
| 关键能力 | RAG / 多模态 / 实时性等 | 产品体验、技术文档 |
| 性能与体验 | 延迟、准确率、稳定性 | 评测、用户评论 |
| 技术壁垒 | 专利、算法、数据壁垒 | 专利库、技术分析 |
