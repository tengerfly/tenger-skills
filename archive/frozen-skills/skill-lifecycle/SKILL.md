# Skill 个性化迭代闭环

## 问题记录与恢复（执行必需）

发现失败、阻塞或用户纠正，在下一安全节点按 `references/record.md` 记录；根因未明也保留事实。恢复/交付前回读维护上下文与未决问题，context.md 作为唯一索引，详情保留原 ID，不重复建池。只记录不构成修改授权；写失败明确未落盘。

## Purpose
以一个目标 Skill 为维护对象，让真实问题和明确偏好变成可验证的小步改进；最终产物是可使用、可复制的目标 Skill。只编排本包内的创建、记录和迭代方法，不要求其他 Skill 或工程体系。

## Trigger
用户明确要求独立 Skill 的创建/接管、记录反馈、迭代或个性化交付时使用。已有维护体系只读参考；除非用户选择本包接管，不再另建一套问题池。只要求记录，不进入修改模式。

## Inputs
目标用途或已有源码、用户授权的可写源码与维护目录、真实任务/失败证据、适用人群和当前请求模式。用户不知道全部细节时帮助澄清，不要求预先写好规范；只读取本次授权材料。

## Preconditions
先确认目标 Skill 与使用者范围，区分源码、安装副本和工具包自身。记录目录按使用者/目标隔离，首次采用 [维护上下文模板](assets/context-template.md)；未指定路径可提出当前工作区下的目标源码目录和独立维护目录，遵守宿主写入权限，不猜测安装缓存是源仓。

## Responsibilities
- 创建/接管：一句话职责、触发边界、最小可用指令与真实验收场景。
- 记录：保存已观察事实、出处、版本和下一步；不顺便改 Skill。
- 迭代：诊断来源、提出最小方案、确认后执行、复验和回退记录。
- 交付：输出可用 Skill 与范围内证据，隔离私人维护数据。

## Non-goals
不后台监听所有聊天，不自动画像或自我改写；不把一次抱怨推广为永久规则；不收集秘密或无关私人信息；不修改业务代码或其他 Skill，不默认安装、同步或上传。不因没有优化器/测试引擎而要求安装其他 Skill。

## Procedure
1. **显示状态**：目标、当前模式（创建/接管、记录、诊断待确认、修改待验证、已验证/阻塞）、本轮终点、待用户决定项和下一步；恢复时回读维护上下文与未决问题，不能只靠聊天记忆。
2. **按模式读取**：创建或接管读 [创建方法](references/create.md)；反馈只读 [问题与偏好记录](references/record.md)；要求改进读 [迭代与验证](references/iterate.md)。不因流程完整而强迫每次从头执行。
3. **按授权执行**：只记录不改规则；迭代方案有逐项来源、适用边界、影响与回退方式。用户明确批准本轮具体改动后才改源码，已有明确授权不重复索要确认；扩大范围或冲突则重新确认。
4. **验证与交付**：实际执行可用的自动化检查和场景回放，保留命令/结果与未验证项。无工具/模型运行能力时标未验证，不用静态阅读冒充行为回归。分享时读 [独立使用与分享](references/portability.md)。
5. **收尾/暂停**：更新唯一维护上下文，列改动、证据、未决项、下一动作；不伪造后台进度。

## Outputs
创建模式交付目标 SKILL.md 及必要资源；记录模式交付问题/偏好条目；迭代交付目标文件差异、[迭代记录](assets/iteration-template.md)、验证结果与回退定位。源码、记录和分享包分离，未请求的模式不执行。

## Evidence
诊断必须读取授权原始证据，不仅看二手摘要。区分事实、推断、建议、用户决定；每次变更回链问题/明确请求及确认。测试的版本与结果可追踪，复制或文件生成不能作为行为效果证据。

## Gate
这是维护结果而非工程发布审批：PASS 仅针对已执行且满足约定的验证范围；关键输入/权限缺失或必要验证未执行为 BLOCKED。问题修复待验证保持未决，结构检查 PASS 不得覆盖行为 BLOCKED。工具包不授予宿主流程批准权。

## Failure Route
写入失败说明未落盘并给脱敏待记录内容；来源缺失保持待分析；偏好冲突展示旧/新规则并等待选择；复验失败回到该轮问题，连续三轮未解决同一阻塞就暂停自动修改，汇报原因与人工选项，不扩大重写或强行关闭问题。

## Downstream Contract
目标 Skill 必须自包含其运行所需资源，不依赖本维护工具才能完成本职任务。新 Skill 中的反馈规则能独立记录事实，但不会擅自修改自身。接收方只得到明确选定的文件，不携带原用户维护历史；本包不写宿主工程状态。

## State Changes
只更新用户指定维护目录中的 context.md、问题详情、偏好与迭代记录；阶段变化保持路径、源码版本、未决问题和下一步一致。记录详情是事实源，context.md 仅作定位，不重复复制原始证据。只读审查不写状态；恢复信息冲突先说明未知，不猜测已完成。
