## 现象

- 分发入口只有 `scripts/sync-skills.sh`（依赖 Git Bash + tar）与 `scripts/link-skills.sh`（Windows mklink /J），macOS/Linux 或未装 Git Bash 的机器没有可用安装方式；也没有「导出可带走包」入口。
- 本机实测（2026-10-18 23:00）：
  - `~/.dsh/skills/auto-test/SKILL.md` 与源仓 `Test/auto-test/SKILL.md` 内容不一致（源仓 2026-10-18 18:34 已改，副本仍是 2026-10-17 19:54 拷贝；2 个文件漂移）；
  - `~/.codebuddy/skills` 还是旧拷贝（手册称该宿主已停用并「skills 已删除」，与磁盘不符）；
  - `~/.zcode/skills` 只有第三方 superpowers skill，仓内 45 个 skill（46 个注册项中 1 个为外部引用层 skill-knowledge，无 SKILL.md）一个都没有（手册称 zcode 是默认在用宿主）；
  - 没有任何「副本 vs 源仓」的机械比对入口（sync-skills 只能逐目标临时跑）。
- 影响：在本机其他宿主/新机器上「直接使用」会读到旧版或读不到；行为验收可能测到与源仓不同的版本。

## 跟踪与证据

- 原问题 ID / 来源：新增；关联历史 issue/WorkFlow/2026-09-23 系列「仓库已修、生效副本仍旧」
- 发现时间 / 相关步骤：2026-10-18 23:00 本轮体系修复；证据 = 文件哈希比对（.dsh 副本 vs 源仓）、目录列表（.zcode/skills）
- 责任方 / 下一动作 / 修复判据：新增跨平台安装器并同步在用宿主；判据 = 临时目录（模拟另一台机器）安装后全部 refs 可解析、--check 无漂移；本机各在用宿主 --check 无漂移。
- 根因与归属：已确认——分发机制按 Windows 单机场景长出来，没有跨平台安装/校验入口；宿主安装动作靠人记，缺机械核对。
- 复核证据 / 未验证项：跨机器（macOS/Linux）未实测；本轮以 Windows 上「临时目录安装 + --check」代替，并在报告中如实标注。
- 回退方式：删除新增安装器文件/停止同步即可；宿主副本可重新用旧脚本生成。

## 期望 vs 实际

- **期望**：任意机器 git clone 后一条命令（`python scripts/install-skills.py --target <宿主>/skills`）完成安装；`--check` 可机械回答「副本是否等于源仓」；`--export` 可导出可带走的 self-contained 包。
- **实际**：只有两套 Windows 专用做法；副本漂移不可机械发现；三个宿主状态互不一致且与手册描述不符。

## 修复方向

1. 新增 `scripts/install-skills.py`（仅标准库、跨平台）：--target/--dry-run/--check/--list/--export，shared 三落点，跳过链接，排除派生目录。
2. 新增 `scripts/tests/test_install_skills.py`，纳入回归。
3. 用安装器同步在用宿主（.dsh / .qoder-cn / .zcode / .codebuddy 按实际状态处理），并跑 --check 记录结果。

**本轮实测（2026-10-18 23:28–23:32）**：安装器一次写入 4 个目标（new=4212 / updated=249 / unchanged=2745 / linked=47 跳过）；随后 `--check` 四目标全部 `drift=0`（codebuddy 2362 files、dsh 2362、qoder 160+46 linked、zcode 2322+1 linked），合计 `RESULT: PASS（安装副本与源仓一致）`。qoder 的 46 个 junction 与 zcode 容器级 shared junction 按设计跳过、未写入。
4. 手册 §3.1 改写为「跨平台安装器为默认，junction 为 Windows 免同步加速」，删掉过期宿主描述。
