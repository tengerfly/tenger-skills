# Skill 维护闭环无法独立复制

- 来源：2026-09-22 用户要求抽离创建、记录问题、迭代与个人化交付的方法，放入 Skill/ 供他人复制使用。
- 状态：处理中（独立包及自动验证完成；真实模型闭环待验证）。
- 事实：Other/Skill-Optimizer 和 Other/Skill-Evolver 依赖本仓共享契约、其他 Skill、集中问题/偏好池，正文还包含固定源仓磁盘路径。直接复制现有目录不能满足独立使用要求。
- 期望：复制一个目录即可获得完整维护规则和模板，接收方自行建立个人目标 Skill 与记录，不携带原用户数据。
- 归因边界：这是当前复用方式的限制，不推断原仓内维护功能失效。
- 修复范围：新增 Skill/skill-lifecycle，保留原工程体系入口；不搬运问题池和偏好库、不安装或同步。
- 验收判据：包内资源引用闭合；在仓库外临时目录、禁用 site-packages 后可运行标准库自检与回归；目标模板带独立反馈钩子；记录/确认/修改/验证/分享职责与授权清晰。
- 已实现：入口、四个方法引用、六个模板、只读结构检查、12 项自动化回归；注册与文档导航已更新。
- 未验证：模型实际创建→反馈→诊断→确认→改写→行为复验，以及不同宿主中的自动发现/安装。静态校验不能证明这些效果。
- 下一步：运行独立复制测试与全仓回归，保存结果；真实模型验证另行明确范围后执行。
