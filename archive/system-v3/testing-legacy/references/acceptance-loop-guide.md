# 验收闭环指南

> 目的：让机器自动拦错，改掉 Agent「写完宣布完成」的模式；测试时同时核查闭环是否到位。

## 一、代码层闭环（成本由低到高）
typecheck → lint → 单测 → build → e2e。错误越晚发现代价越高，计划按此排序。

## 二、hooks 让闭环必然发生
- CLAUDE.md 是软约束；hook 到点必执行。
- 第一层：PostToolUse（Edit|Write）后自动 lint，报错回灌 Agent。
- 第二层：新功能完成后强制 build + e2e，全绿才算做完。
- 测试发现项目缺 hooks/强制验证 → 记 P1（验收闭环不闭环）。

## 三、checklist 定义合格
- 工具只答单维对错；综合合格需显式 checklist（如：无 >500 行模块；禁 emoji 图标；无重复函数；不吞异常；新增接口有校验；用户输入防 XSS）。
- 清单会长：先写 5~6 条，之后每次翻车沉淀一条。

## 四、验收标准前置
- 派活时给核心目标 + 关键验收；Agent 动手前自行补边界/异常/机器检查，生成任务级验收标准，完成后照同一标准自检打回。
- 与零臆断同源：验收只能来自 PRD AC 或显式清单，不凭空编。

## 五、UI 视觉层
代码闭环罩不住 z-index 遮挡、长文本溢出、对比度塌陷等真实渲染问题；需加视觉闭环（见 style-test-guide）。
