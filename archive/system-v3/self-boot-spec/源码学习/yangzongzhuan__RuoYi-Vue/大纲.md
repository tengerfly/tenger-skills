## 逐章功能点清单（锚点均出自本次克隆）

### 章1 全局架构与一次请求动线
- 六模块职责与依赖：pom.xml:177-182（admin 聚合启动 / framework 安全与切面 / system 业务 / common 工具 / quartz 定时 / generator 代码生成）
- 一条主线：GET /system/user/list 从 CORS→JWT 过滤器→授权规则→Controller→Service→Mapper→统一返回（SecurityConfig.java:100-117、SysUserController.java:59-61、SysUserMapper.xml:86）
- 统一返回 AjaxResult = code/msg/data 三键的 HashMap（AjaxResult.java:13,18-24）
- 全局异常分级处理（GlobalExceptionHandler.java:35,58,96）
- 分页：PageHelper.startPage 用 ThreadLocal 吃掉下一条 SQL（PageUtils.java:18-25）

### 章2 认证：登录到 token 的双层设计
- 登录主线：验证码（Redis 校验）→ authenticationManager.authenticate → 异步记登录日志 → 发 token（SysLoginService.java:63-100、115-116）
- 密码比对：BCryptPasswordEncoder bean（SecurityConfig.java:123-127）
- JWT 双层设计：JWT 里只有 uuid+用户名，LoginUser 全量在 Redis（TokenService.java:63-84、115-126、150-156）
- 滑动续期：距过期 <20 分钟自动刷新 Redis TTL（TokenService.java:134-142；application.yml:96-102 有效期 30 分钟）
- 过滤器装填身份进 SecurityContext（JwtAuthenticationTokenFilter.java:34-42）
- 登出=删 Redis 键，因此可服务端踢人（TokenService.java:100-107；LogoutSuccessHandlerImpl.java:47；SecurityConfig.java:111）

### 章3 鉴权：RBAC 与按钮权限
- RBAC 五表关系（sys_user:42 / sys_role:105 / sys_menu:134 / sys_user_role:268 / sys_role_menu:285，行号均指 sql/ry_20260417.sql）
- 权限字符的源头：sys_menu.perms，菜单三类型 M 目录/C 菜单/F 按钮（DDL + insert 样例 167、191 行）
- 登录后权限集合的组装：按角色聚合 menu perms，admin 全量（SysPermissionService.java:58-84）
- 接口鉴权机制：@PreAuthorize("@ss.hasPermi(...)") 调 @Service("ss") 的 PermissionService（SysUserController.java:59；PermissionService.java:18-40）
- 超管短路：roleKey=admin 直接过（PermissionService.java:102）
- 前端配合：v-hasPermi 无权删 DOM（RuoYi-Vue3 src/directive/permission/hasPermi.js:8-21）；路由守卫+动态路由（src/permission.js:21-23）

### 章4 数据权限：行级过滤
- 定位：功能权限管「能不能调」，数据权限管「调出来有哪些行」
- @DataScope + @Before 切面入口（DataScopeAspect.java:35-40）
- 五种范围→SQL 策略：1 全部(清空条件break)/2 自定(sys_role_dept 子查询)/3 本部门(等值)/4 本部门及以下(find_in_set ancestors)/5 仅本人(user_id)（DataScopeAspect.java:90-127；Constants.java:177-202）
- 落地点：拼好的 SQL 放 params.dataScope，mapper XML 用 ${params.dataScope} 吸收（DataScopeAspect.java:137-145；SysUserMapper.xml:86,103,121）
- 防注入：进切面先 clearDataScope 清掉外部传入的 params.dataScope（DataScopeAspect.java:38、148-150）
- 树形铺垫：sys_dept 的 parent_id + ancestors 祖级链（sql/ry_20260417.sql:5-8）
- 接口外兜底：checkUserDataScope/checkDeptDataScope（SysUserController.java:107、127-128）

### 章5 表设计思想与工程化横切
- 通用字段规范：create_by/create_time/update_by/update_time/remark、status char(1)、del_flag 逻辑删 0/2、auto_increment 预留（sys_user DDL sql/ry_20260417.sql:42-63；sys_dept:5）
- 树形两件套：parent_id（邻接表）+ ancestors（祖级链空间换时间）（sql/ry_20260417.sql:5-8）
- 字典表对：sys_dict_type:449 / sys_dict_data:480（类型与数据分离）
- 代码生成器：gen_table:668 / gen_table_column 存表与列元数据→产出 java/vue/sql（ruoyi-generator 模块）
- 异步日志：AsyncManager 延迟 10ms 的 ScheduledExecutorService（AsyncManager.java:19、43-45）+ @Log 切面 @AfterReturning 入队（LogAspect.java:70、128）
- 定时任务：quartz 模块 + sys_job/sys_job_log（sql/quartz.sql）
- 接口限流：@RateLimiter 注解 → Redis+Lua 脚本计数（RateLimiterAspect.java:53-64）
- 多数据源：@DataSource(MASTER/SLAVE) 注解 + 切面切换（DataSource.java:22-27；DataSourceType.java:13；DataSourceAspect.java:26）
- 事务边界：@Transactional 收在 service impl 层（SysUserServiceImpl.java 等 5 处）

### 章6 收束：进阶映射与局限
- 三层权限模型：功能（接口）/按钮（UI）/数据（行）——RuoYi 一套 RBAC 全覆盖
- 会话双层：JWT 无状态表象 + Redis 有状态内核 = 可扩容又可踢人
- 约定先行：表规范→代码生成器→团队统一产出
- 横切归位：日志/限流/数据权限/多数据源全在切面与过滤器，业务方法保持干净
- 局限：无 MQ（pom 无 rabbit/kafka/rocketmq/amqp，已核实）、单库无分库分表、无检索中间件 → 引出 mall
