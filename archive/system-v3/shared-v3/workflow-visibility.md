# 流程可见性与用户控制

适用于总编排、领域编排和原子 Skill 的交接。只增加可见性，不增加审批层或新的状态机。

## 何时告诉用户

- **开工/恢复**：展示本次目标、强度及原因、终点、拟走阶段、复用/跳过项与依据、当前步骤和下一动作；不能只说“开始处理”。
- **阶段开始与交接**：说明现在调用哪个 skill、为什么调用、输入/输出是什么；结束后说明完成内容、证据/文件位置、Gate 或剩余限制、下一步。
- **等待确认/阻塞/路线变化**：立即说明停在哪里、为什么、影响、谁需要提供什么、可选处理和恢复条件。不要把等待用户写成仍在执行。
- **长阶段**：完成有意义的子步骤时简报进度，不逐条播报工具调用，不虚构实时后台进度、百分比或预计完成时间。
- **结束/暂停**：列已完成、未执行/未验证、待决定事项和明确恢复入口。

## 状态卡（每次简短更新）

目标/终点：…
路径：接管 → 需求 → 设计 → 实现 → auto-test（本次不用的阶段标不适用并说明）
当前位置：阶段名称 / skill；已完成 …；待执行 …
状态：执行中 / 等待你确认 / 阻塞 / 已完成（人类可读展示，不是新增正式状态）
本步产物与证据：路径、版本、实测或研究引用
待你决定：具体问题、选项及影响；没有则写无
下一步：动作、执行方、前置条件

正式流程同时展示 workflow.yaml 的 state、gate、allowDownstream；中文状态不得冒充注册状态。“产物已写”不等于“已批准”，“未执行/不适用”不等于“通过”。

**状态卡是工作单元交付物（硬门禁），但不是停等**：每完成一个可验收结果必须输出一张状态卡（当前位置/本步产物/下一步/需你决定），**未输出不得开始下一个工作单元**；卡片输出后，若下一单元仍在已批准范围内，可直接推进，不必等「继续」。用户只回「继续」时，默认推进当前单元的剩余部分；超出已批准范围才重新确认范围与终点。任何一次静默的工作单元切换都视为流程偏离，应停下补卡。裁决与停等口径见 `shared/ruling-policy.md`。

## 持久化与单一事实源

正式当前状态只以 `.spec/workflow.yaml` 为准，沿用 executionId、currentSkill、state、gate、allowDownstream、artifactRefs、evidenceRefs、decisionRefs、nextAction、revision、updatedAt。每次交接按合法状态转移同步，历史原因及阶段计划保存在本次 execution 摘要中；展示是这些记录的视图，不再维护第二套状态。

**任务级状态单一事实源**：评审/测试任务清单的「状态」列是唯一状态载体，按状态机流转（`待确认 → 已确认/已忽略 → 已修复`），修复/裁决说明写在「说明」列，不得另建第二个状态表。若已存在「状态列 + 裁决记录」两处，必须**同一批次**更新两者；只改一处即属状态漂移，换会话后读到旧状态会误导执行方（knowledge-bases 原型评审曾因此三处状态不一致）。

**换会话/换编辑器对账**：恢复时除读 workflow.yaml、manifest、traceability 外，还要读任务清单与裁决记录，并抽查实际产物文件。发现多处状态不一致（如 workflow 已 `PASS` 但任务清单仍「待确认」）时，以 `workflow.yaml` + 实际产物文件证据为准，标出并修正 stale 文件，不得把 stale 状态当当前真相。

**代码面续做对账**：控制文件与 manifest 只能证明「产物」进度，不能证明「实现」进度——若 workflow.yaml 的 state 已过 `TECH_DESIGN_APPROVED`（或 nextAction 仍停在技术设计/评审），但工作区已有实现代码、测试或构建产物：以代码与测试实跑结果为准重建状态（通常为 `DEV_IN_PROGRESS`），补 `PROJECT.md`/`PLAN.md` 与 dev 节点 trace（`tsr node-start --node backend-dev|frontend-dev`），并在恢复说明中标注 stale 控制文件；禁止把过期状态当「开发尚未开工」而重跑已完成阶段。反向不一致（state 已到 DEV/TEST 而工作区无对应代码）同样是对账失败，需停下查因。

**无 git 项目的恢复**：项目无 git 仓库时，先在允许写范围内 `git init` + 提交基线（不 push、不改远端），再继续；否则按提交定位改动、一功能点一提交与回滚基线都无法执行，恢复后应把这个缺口如实登记。

轻量任务复用会话/已有任务摘要，不为看板补建正式文件。暂停或跨会话时按 execution-profiles.md 持久化；恢复先回读状态、相关产物、决策与未决问题。缺失/冲突时明确“状态未知/待核验”，不猜测完成。

用户问“到哪一步/完整流程/为什么跳过/还缺什么”时先回答再继续。用户要求暂停则保存进展后停止；调整范围须展示影响并在原决策处确认，不暗中扩展。确认聚焦定位、范围、风险、发布等决策，不要求每个确定的低风险动作都说“继续”。

可用 `python scripts/workflow_status.py --project-root <项目路径>` 只读查看持久状态；它不是调度器或 Gate 校验器。
