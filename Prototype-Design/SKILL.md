# 低保真原型设计稿生成 Skill

> 把 PRD 快速可视化为可点击的低保真 HTML 原型，验证需求是否闭环。不写需求、不评审需求、不做视觉精修。

## 一、角色与原则

**角色**：产品原型工程师。

1. **原型是验证逻辑的工具**：目标是让需求闭环、业务逻辑一目了然。
2. **零加戏**：只画 PRD 明确的元素与文案；确需补充必须标 `【设计假设】` 并经用户确认。
3. **最快产出**：不走风格确认、不沉淀 token、不去 AI 味精修；精力全放布局与交互。

## 二、适用范围

- 适用：已有 PRD，生成原型/低保真/交互/页面原型；需求定稿后开发前快速验证。
- 不适用：写需求（PRD-Design）；评审需求（PRD-Review）；高保真视觉/营销素材/Logo。

## 三、流水线

```
输入 → 解析 PRD → 端类型确认 → ◉ 布局清单 Gate → 生成 HTML → ◉ 闭环检测 Gate → 落盘归档 → 按反馈回写清单
```

1. **解析 PRD**：
   - 检查 `.spec/原型评审/任务清单.md`：有 `已确认` 且修改方为 `Prototype-Design` 的任务逐条纳入本次修复；无则按全新绘制。
   - 多文件改动（script/数据/弹框链/交互）落盘前按 `references/iteration-regression-guard.md` 跑 Regression Gate（console 零错误 + 动态内容 DOM 断言 + 关键态截图人工核验）。
   - 自行提取产品定位、用户画像、核心主流程、页面/功能素材；不逐项问用户。
   - PRD-Design 产出优先读 `PRD速查表.md` 建索引；页面/视图素材从速查表 + 各模块 §3.1 提取；细节按锚点回 NN_xxx.md。
   - PRD 的「页面」≠ 原型独立页面：载体划分留给步骤 3，本步只收集素材不拍板。

2. **端类型确认**：问 Web/移动/双端同步，推荐并默认 Web；选双端再问「两套独立原型」还是「一套响应式」，由用户决定。

3. **布局清单 Gate（核心，强制）**：
   - AI 基于 PRD 推导《布局清单》（载体类型 / 名称 / 内容 / 宿主页面 / 入口 / 出口 + 页面跳转），按 `assets/layout-inventory-template.md` 呈现。
   - 载体开放：页面/弹框/抽屉/表格/卡片/列表/表单/页内区块/Tab。判定依据：信息量与操作复杂度（轻量/短表单 → 弹框；重内容/多步骤/高频 → 独立页；需保留上下文 → 弹框/抽屉；数据罗列 → 表格）、端类型习惯。
   - 用户确认增删后才生成原型；PRD 页面不得静默丢弃，不做须写明原因。
   - 后续改载体划分 → 回本步骤重出清单并重新确认。

4. **生成低保真 HTML**：按 `references/html-spec.md`；独立页一个 HTML，弹框/抽屉等内嵌宿主页，页面间真实链接跳转；极简中性色 + 单一主色 + 三级字号层级；双端按步骤 2 方案产出（`web/`+`mobile/` 或单套响应式）。

5. **逻辑闭环检测 Gate（强制）**：按 `references/completeness-check.md` 自检 6 项（载体完整/防加戏/跳转闭环/状态覆盖/端类型匹配/假设标注），全绿才落盘。

6. **落盘归档 + 回写**：
   - 落盘 `.spec/原型/`：`布局清单.md`（核心产物）+ `README.md` + 各 HTML。
   - 回填评审任务清单：归本 skill 的 `已确认` 任务改 `已修复` 并写修改说明；未处理项保留并注明原因。
   - 用户看原型后的调整 → 改原型并**同步回写布局清单**，清单 ↔ 原型保持一致。

## 四、布局清单生成法

| 载体 | 适用（参考） |
|---|---|
| 独立页面 | 重内容/多步骤/高频/需独立导航位 |
| 弹框 | 轻量查看、短表单、确认类、保留上下文 |
| 抽屉 | 中等信息量侧栏编辑/详情（Web） |
| 表格 | 数据罗列/批量展示 |
| 卡片 | 信息聚合单元/列表项 |
| 列表/表单 | 结构化展示/录入 |
| 页内区块/Tab | 信息量小、与宿主强相关 |

- 同一 PRD 页面在不同端可映射不同载体。
- 清单每个载体/入口必须在 PRD 有出处；无依据不列；必要补充标 `【设计假设】`。
- AI 先推荐，用户确认后才生成原型。

## 五、低保真视觉规范

**做**：极简配色（白/浅灰 + 深灰文字 + 单一主色点缀）；标题/正文/辅助三级字号；边框/浅底区分区块表达真实信息架构；用 PRD 真实文案，不用 Lorem/假数据。

**禁止**：沉淀 Design Token、写 style-guide；多套风格/配色精修；emoji 当图标（用简单 SVG/文字）；装饰渐变/光斑/玻璃拟态/重阴影；追求高保真视觉打磨。

## 六、交付结构

```
.spec/原型/
├── 布局清单.md   # ★核心产物
├── README.md     # 端类型 + 跳转关系 + 主流程覆盖
├── index.html    # 入口页
├── <页面2>.html
└── ...
```

语义化命名；跳转链接一一对应；双端按选定方案组织 `web/`+`mobile/` 或响应式单套。

## 七、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 未确认端类型直接生成 | 先步骤 2，默认 Web |
| 交互模式与端不匹配 | 端类型适配（移动端不做侧边栏等） |
| 未过布局清单 Gate | AI 推荐 + 用户确认后才生成 |
| PRD 页面照单全收全做独立页 | 布局清单拆出弹框/抽屉/表格/卡片 |
| 回到高保真 | 只做极简配色 + 字号层级 |
| 断链 | 入口接真实 `<a>`，可点击闭环 |
| 凭空加按钮/提示 | 零加戏；必要标假设并经确认 |
| 未跑闭环检测就产出 | completeness-check 6 项全绿才落盘 |
| 重构后动态空白/交互全死 | 同名符号冲突先全文检索清理；跑 Regression Gate |
| 调整原型未回写清单 | 清单 ↔ 原型必须一致 |
