# 页面 / 弹框载体映射清单（信息载体确认 Gate）模板

> 用途：`Prototype-Design` 步骤 3「信息载体确认 Gate」产出物的实现模板。
> 目标：把 PRD 罗列的「页面」逐一映射到原型真实载体（独立页面 / 弹框 / 抽屉 / 页内区块），让用户在选风格前明确「到底几个独立页、几个弹框」，防止「PRD 十页、原型三页」的错位被漏掉或拍脑袋决定。
> 铁律：清单确认前不进入风格澄清；确认后 wireframe / 高保真的页面文件以此为准。

填写要求：

- PRD 页面**一行不漏**——哪怕结论是「并入某页」或「不做」，也要有行可查并写明原因；
- 载体四选一：`独立页面 / 弹框 / 抽屉 / 页内区块`；
- 独立页面数 = 导航位来源；弹框 / 抽屉必须写明宿主页面，禁止无宿主悬空。

## 三、载体判定依据（推导时引用，向用户解释用）

| 载体 | 适用情形 |
|------|---------|
| 独立页面 | 重内容 / 多步骤 / 高频访问 / 需要独立导航位 |
| 弹框 | 轻量查看、短表单、确认类操作、需保留宿主上下文 |
| 抽屉 | 中等信息量的侧栏编辑 / 详情（Web 端常见） |
| 页内区块 | 信息量小、与宿主强相关，不值得单独交互单元 |

- 端类型影响形态：Web 偏模态框 / 抽屉；移动端偏全屏页 / 底部弹层——同一 PRD 页面在不同端可能映射不同载体。

## 四、呈现与确认规则

- 呈现「载体映射清单 + 跳转关系」后，请用户明确确认「页面/弹框划分无误」；有异议 → 就地增删调整 → 重新确认；
- **放行约束**：确认通过后才进入风格澄清；风格提案的导航结构与页面举例、wireframe、高保真的 HTML 文件清单均以本清单为准；
- 后续改载体划分（页面变弹框或反之）→ 回步骤 3 重出清单并重新确认，禁止绕过 Gate 直接改高保真。

## 五、红线

1. PRD 页面不允许静默丢弃：不做的必须写明原因（并入某页 / 超出核心闭环）；
2. 弹框必须有宿主页面与触发入口，禁止无宿主、无入口的孤儿弹框；
3. 独立页面数以本清单为准，风格澄清与 wireframe 不得再按 PRD 字面页数想象。
