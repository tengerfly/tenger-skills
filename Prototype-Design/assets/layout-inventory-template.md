# 布局清单模板（布局清单 Gate）

> 用途：`Prototype-Design` 步骤 3「布局清单 Gate」产出物的实现模板。
> 目标：由 AI 基于 PRD 推导一份《布局清单》——把 PRD 罗列的「页面/功能」逐一映射到真实载体（独立页面 / 弹框 / 抽屉 / 表格 / 卡片 / 列表 / 表单 / 页内区块…**载体类型开放，不穷举**），作为生成原型布局的**主要依据**，也作为后续 UI 设计阶段「页面有几个、弹框有几个」的输入。
> 铁律：清单经用户确认后才生成原型；清单 ↔ 原型必须一致。

- PRD 页面/功能**一行不漏**——哪怕结论是「并入某页」或「不做」，也要有行可查并写明原因；
- **载体类型开放**：上表只是常见示例，实际按 PRD 内容判断，可增补（如列表、表单、页内区块、Tab、步骤条、提示气泡等）；
- 独立页面数 = 导航位来源；弹框/抽屉/表格/卡片等必须写明宿主页面，禁止无宿主悬空。

## 三、载体判定依据（推导时引用，向用户解释用）

| 载体 | 适用情形（参考） |
|------|----------------|
| 独立页面 | 重内容 / 多步骤 / 高频访问 / 需要独立导航位 |
| 弹框 | 轻量查看、短表单、确认类操作、需保留宿主上下文 |
| 抽屉 | 中等信息量的侧栏编辑 / 详情（Web 端常见） |
| 表格 | 数据罗列 / 批量展示 |
| 卡片 | 信息聚合单元 / 列表项展示 |
| 页内区块 / Tab | 信息量小、与宿主强相关 |

- 端类型影响形态：Web 偏弹框 / 抽屉；移动端偏全屏页 / 底部弹层——同一 PRD 页面在不同端可能映射不同载体。

## 四、呈现与确认规则

- AI 先推荐《布局清单 + 跳转关系》，请用户明确确认「载体划分无误」；有异议 → 就地增删调整 → 重新确认；
- **放行约束**：确认通过后才生成原型；原型 HTML 文件清单以本清单为准；
- 后续改载体划分（页面变弹框或反之）→ 回步骤 3 重出清单并重新确认，禁止绕过；
- **清单 ↔ 原型一致**：用户调整原型后，必须同步回写本清单。

## 五、红线

1. PRD 页面/功能不允许静默丢弃：不做的必须写明原因（并入某页 / 超出核心闭环）；
2. 弹框/抽屉/表格/卡片必须有宿主页面与触发入口，禁止无宿主、无入口的孤儿载体；
3. 独立页面数以本清单为准，生成原型不得再按 PRD 字面页数想象。
