# Prototype-Design —— 高保真 UI 原型生成 Skill

> **状态**：✅ 定稿
> **定位**：把 PRD 变成高保真、可点击、去 AI 味的 HTML **UI** 原型，当作正式 UI 设计稿来做。

## 一、这是什么

一个把已写好的 PRD 需求文档，转化成**高保真 HTML 可交互 UI 原型**的 Skill。它不写需求、不评审需求，只负责"把需求可视化"——以**高级 UI/UX 专家**的身份，让产品定位、信息架构、交互流程在浏览器里一目了然、精致可感。

**核心能力**：
1. 从 PRD 提取产品定位，据此推导设计方向；
2. **页面/弹框载体先确认**：把 PRD 罗列的页面映射为原型载体（独立页面 / 弹框 / 抽屉 / 页内区块）+ 跳转关系，用户确认后才选风格（防「PRD 十页、原型三页」错位）；
3. 苏格拉底式询问用户设计风格 / 交互模式（无偏好则推荐三套差异化方案，导航结构落在已确认页面上）；
4. **在设计任何页面前，先沉淀完整的样式规范（Design Tokens + 组件规范）**，作为全站唯一视觉底座；
5. 对已确认页面做**防漏 + 防加戏**双向完整性判断（只画 PRD 要求的元素与文案，杜绝无依据的按钮/提示/装饰），严格套用样式规范生成可点击跳转的高保真 HTML UI 原型；
6. 全程去除 AI 模板感 + **简洁大方基调**，让原型像真实设计师的手笔（少装饰、按钮克制、零加戏）。
7. **布局骨架先行确认**：确认页面清单后先出极简 HTML 线框，供用户确认布局再生成高保真（防布局返工）。

## 二、核心设计

| 项 | 决定 |
|----|------|
| 名称 | `Prototype-Design` |
| 角色 | 高级 UI/UX 专家 + 前端原型工程师 |
| 输入 | 用户指定 PRD 文件路径，或直接粘贴内容 |
| 产出形式 | 高保真 HTML UI + 可点交互（真实配色排版 + 点击跳转） |
| 样式规范 | 设计前先沉淀 Design Tokens（色彩/字体/间距/圆角/阴影）+ 组件规范 |
| 交付范围 | 独立页面集（步骤 3 载体清单定稿，聚焦闭环；弹框/抽屉随宿主页交付） |
| 三套方案 | 视觉 + 交互组合（每套 = 配色 + 排版 + 交互模式 + 理由） |
| 去 AI 味 | 仅视觉设计（避免模板感） |
| 端类型 | Web 端 / 移动端 / 双端同步（优先 Web 端） |
| 产出门禁 | 页面完整性检测（8 项全绿才产出，含冗余元素检测 + 样式规范一致性） |
| 载体确认 | 步骤 3 信息载体确认 Gate：PRD 页面 → 独立页/弹框/抽屉/页内区块映射 + 跳转关系，用户确认后才进风格澄清 |
| 布局确认 | 高保真前先出极简 HTML 线框过步骤 6 Wireframe Gate，确认后才生成 |

## 三、流水线全景

```
输入 PRD ──► 解析定位 ──► 端类型确认(优先Web) ──► ★信息载体确认Gate(页面vs弹框映射+跳转关系) ──► 风格澄清(一次一问) ──► 锁定风格 ──► 沉淀样式规范 ──► 页面完整性判断+假设标注 ──► ★页面布局骨架确认(Wireframe Gate) ──► 生成 HTML ──► 完整性检测 Gate ──► 落盘 .spec/原型/
```

## 五、快速上手

1. 触发方式：把 PRD 文件路径（或粘贴 PRD 内容）发给我，说"帮我生成原型图"；
2. Skill 会先提取产品定位，然后问你做哪端（Web / 移动 / 双端，优先 Web）；
3. **先跟你确认页面与弹框清单**：哪些 PRD 页面做独立页、哪些用弹框/抽屉承载，确认后才继续；
4. 接着问你风格偏好（一次只问一个问题），无偏好则推荐三套差异化方案；
5. **锁定风格后，先沉淀样式规范（Design Tokens + 组件规范）供你确认**；
6. **先出极简 HTML 线框（Wireframe）供你确认布局**，不满意就地调整，确认后才做高保真；
7. 严格套用样式规范生成可点击 HTML UI 原型，经完整性检测通过后落盘到 `.spec/原型/`。

## 六、去除 AI 味的核心要义

AI 生成界面的典型"模板感"：紫蓝渐变背景、emoji 当图标、hero 大标题 + 三卡片、装饰性光斑、大面积留白。本 Skill 通过一套负面清单 + 替代做法（详见 `references/anti-ai-visual-guide.md`），让原型配色贴合产品定位、信息密度贴近真实应用、图标用 SVG 不用 emoji，整体气质像专业设计师产出。
