# Prototype-Design —— 低保真原型设计稿生成 Skill

> **状态**：✅ 定稿（2026-09-04 推倒重做）
> **定位**：把 PRD 快速变成**低保真、可点击、可交互的 HTML 原型设计稿**，用来验证 PRD 需求闭环与业务逻辑是否正确，并为后续 UI 设计阶段提供布局依据。**不再是高保真 UI 设计稿。**

## 一、这是什么

一个把已写好的 PRD 需求文档，快速转化成**低保真可交互 HTML 原型设计稿**的 Skill。它不写需求、不评审需求，只负责「把需求快速可视化」——核心目标是让用户**快速确认 PRD 需求闭环、业务逻辑正常**，而不是产出精美的视觉稿。

**核心能力**：
1. 从 PRD 提取产品定位与用户背景，据此推导布局；
2. **布局清单先行**：AI 推荐一份《布局清单》（载体类型开放：页面/弹框/抽屉/表格/卡片/列表/表单…），经用户确认后作为原型布局的主要依据；
3. 确认端类型（Web / 移动端，优先 Web）；
4. 以最快速度生成可点击、可交互的低保真 HTML 原型（极简中性色 + 单一主色点缀 + 基础字号层级，不精修视觉）；
5. 逻辑闭环检测（6 项）通过后才产出；
6. 用户看原型调整 → 同步回写《布局清单》+ 业务逻辑闭环。

## 二、核心设计

| 项 | 决定 |
|----|------|
| 名称 | `Prototype-Design` |
| 角色 | 产品原型工程师 |
| 输入 | 用户指定 PRD 文件路径，或直接粘贴内容 |
| 产出形式 | 低保真 HTML 原型 + 可点交互（极简配色，不做视觉精修） |
| 核心产物 | 《布局清单》——载体划分（页面/弹框/抽屉/表格/卡片…），供后续 UI 设计阶段用 |
| 端类型 | Web 端 / 移动端 / 双端同步（优先 Web 端） |
| 产出门禁 | 逻辑闭环检测（6 项全绿才产出） |
| 布局确认 | 步骤 3 布局清单 Gate：AI 推荐 + 用户确认后才生成原型 |

## 三、流水线全景

```
输入 PRD → 解析定位 → 端类型确认(优先Web) → ★布局清单Gate(AI推荐+用户确认) → 生成低保真原型 → 逻辑闭环检测Gate → 落盘 .spec/原型/ → 用户调整回写清单(闭环)
```

## 五、快速上手

1. 触发方式：把 PRD 文件路径（或粘贴 PRD 内容）发给我，说「帮我生成原型图」；
2. Skill 先提取产品定位，然后问你做哪端（Web / 移动 / 双端，优先 Web）；
3. **AI 推荐一份《布局清单》**（页面/弹框/抽屉/表格/卡片等载体划分），你确认或调整；
4. 确认后，以最快速度生成可点击、可交互的低保真 HTML 原型；
5. 你看原型调整 → AI 同步回写《布局清单》+ 业务逻辑闭环；
6. 逻辑闭环检测通过后落盘到 `.spec/原型/`。

## 六、为什么从高保真改到低保真

高保真原型需要先确认风格、沉淀 Design Token、做视觉精修、去 AI 味，这一整套流程让「确定 PRD」的过程被显著拉长。而原型设计这一步的真实目标是**把 PRD 可视化，验证需求闭环与逻辑正常**——低保真就完全够用。因此砍掉所有视觉精修环节，只保留「布局 + 交互」，让用户用最短时间确认「整体逻辑 OK」。
