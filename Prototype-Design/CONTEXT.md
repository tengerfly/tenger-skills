# Prototype-Design 决策日志（CONTEXT）

> 术语对齐源 + 决策日志。概念须与 SKILL/templates/references 一致；敲定即更新；D-xx 递增。

## 一、定位

把 PRD 快速可视化为低保真、可点击、可交互的 HTML 原型；目标是验证需求闭环与业务逻辑，为 UI 阶段提供布局依据。不是高保真 UI。

## 二、术语表

| 术语 | 定义 | 排除 |
|---|---|---|
| 布局清单 | 载体划分清单（载体/名称/内容/宿主/入口/出口 + 跳转），原型与 UI 设计的输入 | 不是页面清单；不含区块级拆解 |
| 载体 | PRD 页面/功能的落地形态：页面/弹框/抽屉/表格/卡片等，开放不穷举 | 不只指独立页面 |
| 布局清单 Gate | AI 推荐 → 用户确认后才生成原型 | 不是生成后确认 |
| 低保真原型 | 极简中性色 + 单一主色 + 基础字号层级，可点可交互 | 不是高保真稿，也不是纯灰白线框 |
| 零加戏 | 只画 PRD 明确的；补充必须有据、标假设、经确认 | 不是禁止补充 |
| 闭环回写 | 改原型同时改布局清单，保持清单↔原型一致 | 不是单向改原型 |
| 逻辑闭环检测 | 6 项门禁：载体完整/防加戏/跳转闭环/状态/端类型/假设 | 不是视觉质量检测 |
| 案例库 | case-library/：prototyping-methods + prototyping-tools + 动作型范本 | 只补方法论/反模式/范本，不改变低保真定位 |
| 生命周期状态 | 原型内置 persona 切换（new/active/power、empty/busy），换数据不换外壳 | 可反哺闭环检测，非强制引入 |
