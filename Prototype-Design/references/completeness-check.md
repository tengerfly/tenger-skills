# 页面完整性与产出检测门禁

> 用途：两件事——① **设计阶段**对 PRD 页面信息不完整处做判断（保证页面原型完整）；② **产出前**执行自检，检测通过才允许产出原型。

---

## 一、设计阶段：页面完整性判断

在步骤 3 信息载体确认 Gate 定稿页面/弹框清单后、进入布局设计前，对每个已确认页面逐一判断 PRD 是否提供了足够信息，缺什么补什么：

| 判断维度 | 检查点 | 不完整时的处理 |
|---------|--------|---------------|
| 入口 | 从哪个页面 / 导航进入 | 能推导则补全，否则标 `【待确认】` |
| 出口 | 办结后流向哪里 | 同上 |
| 功能区块 | 页面有哪些功能区、各承载什么内容 | 能推导则补全，否则用合理设计补全并标 `【设计假设】` |
| 状态覆盖 | 空态 / 加载 / 成功 / 失败 / 边界是否都定义 | 缺失状态用合理设计补全并标 `【设计假设】` |
| 关键交互 | 触发 → 反馈 → 流向是否明确 | 同上 |
| 冗余元素 | 页面是否出现 PRD 未要求的按钮/提示文案/区块/装饰 | 无依据的**删除**；确属必要补充的标 `【设计假设】` 并随骨架页确认 |

**不完整处理铁律**：
- 能从 PRD 其他部分推导的 → 推导补全，不标注；
- PRD 确实没有、属于设计自由度的 → 用合理设计补全，标 `【设计假设】`；
- PRD 缺失且影响业务正确性的 → 标 `【待确认】`，列为风险项（不阻塞原型产出，但在 README 中显式提示）。

**防加戏铁律（与完整性判断同等重要）**：判断不仅要查"缺"，也要查"多"——凡 PRD 无出处的按钮、提示文案、区块、装饰元素，**一律删除**；确属必要补充（如空态兜底、必要操作入口）才可保留，且必须标 `【设计假设】` 并随 wireframe 让用户确认，禁止静默保留。

## 二、产出前检测规则（Gate，全部通过才产出）

生成 HTML 后，逐条自检，**任一不通过即返工**，全部通过才允许落盘：

| 编号 | 检测项 | 通过标准 | 不通过处置 |
|------|--------|---------|-----------|
| CK-1 页面完整 | 步骤 3 确认的每个独立页面都有对应 HTML 文件（弹框/抽屉内嵌宿主页面，不单独成文件） | 无遗漏、无多余 | 补生成或删除 |
| CK-2 跳转闭环 | 页面间跳转无断链、无孤立页（入口 / 出口成对），弹框有宿主页面且打开/关闭成对 | 每页有入口且有出口 | 补链接 |
| CK-3 状态覆盖 | 每页空态 / 加载 / 成功 / 失败 / 边界都处理 | 五态齐全 | 补状态 |
| CK-4 端类型匹配 | 布局与确认的端类型一致（Web 桌面 / 移动 375px / 双端按用户选定方案） | 与步骤 2 确认一致 | 返工布局 |
| CK-5 反 AI 味 | 无 emoji、无紫蓝渐变、无光斑、无模板结构 | 对照 anti-ai-visual-guide 自检全绿 | 返工清除 |
| CK-6 样式规范一致 | 全站严格套用沉淀的 `style-guide.md` 的 token 与组件规范 | 配色/字号/间距/圆角/阴影/组件与规范一致，无另起炉灶 | 返工对齐 |
| CK-7 假设标注 | 所有 `【设计假设】` 已标注，`【待确认】` 已在 README 提示 | 无遗漏 | 补标注 |
| CK-8 冗余元素检测 | 页面无 PRD 未要求的按钮/提示文案/区块/装饰（零加戏），无过度设计 | 每个按钮/文案/区块都能在 PRD 找到出处 | 删除冗余或补【设计假设】 |

**门禁裁决**：`✅ 通过` = 8 项全绿；任一 `❌` = 就地返工后重检，通过才产出。
