# 原型设计方法学（Prototyping Methods）

> 用途：布局清单 Gate 与闭环检测时的理论参考。⚠️ 本 Skill 定位低保真，分级只作「当前阶段该出哪级」的参考。

---

## 一、保真度分级（参考，不改本 Skill 定位）

| 目的 | 保真度 |
|---|---|
| 测想法 | 低保真（本 Skill 默认） |
| 测流程 | 中保真 |
| 测交互/就绪 | 高保真 |

- 四级原型法（纸面/低/中/高）：每级耗时、工具、适用阶段，按阶段选保真度。

## 二、快速原型三阶段

- Prototype → Review → Refine：先出可点击原型 → 评审 → 按反馈迭代。

## 三、常见反模式（「不要做」清单）

- 过早高保真；用 lorem 忽略真实内容；孤立作业不协作；跳过标注；不做用户测试；把原型当最终交付物。

## 四、可用性测试

- 5–8 用户任务测试、Think Aloud；指标：完成率/时长。
- 原型交付前验证「需求是否闭环、业务逻辑是否一目了然」。

## 五、AI 角色边界

- AI 适合「空白到初稿」，**不能替代确认业务规则/数据/权限/异常**（对应本 Skill 零加戏铁律 + 标【设计假设】）。

## 六、生命周期状态（kurenn 黄金范式，可反哺）

- **换数据，不换外壳**：原型内置 persona 切换（如 `new/active/power` 用户成长阶段、`empty/busy` 数据负载），切换时姓名/计数/列表真实变化。
- 每个按钮/弹窗/标签页/筛选器真正可用；含 loading/toast/empty/skeleton/404。
- 价值：评审者看到的是产品在不同阶段/数据状态的真实样貌，而非静态截图。

> 出处：Interaction Design Foundation、墨刀 7 步、kurenn/claude-prototype。
