# Prototype-Design —— 低保真原型生成 Skill

> 状态：✅ 定稿（2026-09-04 低保真重做）
> 定位：把 PRD 快速变成可点击、可交互的低保真 HTML 原型，验证需求闭环与业务逻辑，为 UI 阶段提供布局依据。不做高保真视觉。

## 一、能力

1. 从 PRD 提取产品定位、用户与主流程。
2. 布局清单先行：AI 推荐载体划分（页面/弹框/抽屉/表格/卡片等），用户确认后生成。
3. 竞品布局参考：推导清单前尽力检索同类产品公开布局作为依据，出处标注在布局清单备注列（无强相关竞品则跳过并注明）。
4. 确认端类型（Web / 移动 / 双端，优先 Web）。
5. 快速生成低保真 HTML：极简中性色 + 单一主色 + 基础字号层级。
6. 逻辑闭环检测 6 项全绿才产出。
7. 用户调整后同步回写布局清单。

## 二、核心设计

| 项 | 内容 |
|---|---|
| 角色 | 产品原型工程师 |
| 输入 | PRD 路径或粘贴 |
| 产出 | 低保真 HTML + 布局清单 |
| 端类型 | Web / 移动 / 双端（优先 Web） |
| 门禁 | 布局清单 Gate + 逻辑闭环检测（6 项） |

## 三、流程

```
输入 PRD → 解析 → 端类型确认 → ★布局清单 Gate（含竞品布局调研 + AI 推荐 + 用户确认）
→ 生成低保真原型 → 逻辑闭环检测 → 落盘 .spec/原型/ → 调整回写清单
```

## 五、快速上手

1. 给 PRD 路径或内容，说「生成原型」。
2. 回答端类型（默认 Web）。
3. 确认 AI 推荐的布局清单。
4. 生成后可点原型；调整会同步回写清单。
5. 闭环检测通过后落盘。

## 六、为什么低保真

高保真流程（风格确认/token/视觉精修）拖慢需求确认；本步目标是可视化 PRD、验证逻辑，低保真已够用。
