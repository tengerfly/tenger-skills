# 布局清单消费契约（Layout Inventory Contract）

> **契约方**：`UI-UX-Design`（消费方）；**生产方**：`Prototype-Design`（重构版，低保真流水线）。
> **Q1 对齐结论（2026-09-04，D-10）**：Prototype-Design 的《布局清单》为**载体级**（页面/弹框/抽屉/表格/卡片/列表/表单…载体类型开放不穷举），**页内区块结构由低保真原型 HTML 实物承载**（其「清单↔原型一致」红线保证两者一致）。因此本 skill 消费**双输入**：布局清单定「有哪些载体」，低保真原型定「每页区块怎么摆」。

## 一、输入物与来源（双输入 + 佐证）

| 输入 | 来源 | 回答什么 |
|---|---|---|
| PRD | `.spec/PRD/V1/`（若为 PRD-Design 产出，先读 `PRD速查表.md` 建索引） | 文案 / 字段 / 业务规则（文案保真的一字不差基准；逐字级细节按锚点回模块原文） |
| **布局清单.md** | `.spec/原型/`（Prototype-Design 步骤 3 产出） | **载体划分**：每个 PRD 页面/功能 → 页面/弹框/抽屉/表格/卡片/列表/表单/页内区块/Tab… + 宿主页面 / 入口 / 出口 |
| **低保真原型 HTML** | `.spec/原型/*.html` | **页内区块结构实物**：每页从上到下有哪些区块、组件形态、交互 |
| 原型 README.md | `.spec/原型/` | 端类型 / 跳转关系 / 产物说明（佐证） |

## 二、消费校验规则（步骤 2 逐项核对，缺一阻塞或问用户）

1. 布局清单中 PRD 页面/功能**一行不漏**（并入或不做的必须有行且有原因）；
2. 弹框 / 抽屉 / 表格 / 卡片等非页面载体必有**宿主页面 + 触发入口**（禁止孤儿载体）；
3. 跳转关系**闭环**（有进有出，无断链）；
4. 低保真原型 HTML 文件清单 = 布局清单中独立页面集合（清单↔原型一致）；
5. **端类型与导航结构**：从低保真原型 HTML 布局特征读取（侧边栏/顶部导航 = Web；底部 Tab = 移动端），读不出或歧义 → 问用户，不猜测；
6. 文案以 PRD 为基准（布局清单/原型中的文案如与 PRD 冲突 → 回 Prototype-Design，不擅自改）。

## 三、区块结构提取规则（布局清单不含区块级 → 本 skill 提取）

- 逐页读低保真原型 HTML，按视觉顺序提取区块行：**区块名 / 组件类型 / 内容要素 / 关键交互**；
- 组件类型**对齐布局清单的载体枚举**（页面/弹框/抽屉/表格/卡片/列表/表单/页内区块/Tab…开放不穷举），不另造名词体系；
- 提取产物写入**设计任务清单**（`design-task-list-template.md`）；
- **只翻译、不改动**：提取是「结构→设计语言」的翻译，区块增删移 = 布局改动 → 触发布局零改动铁律，回 Prototype-Design（走其「清单↔原型一致」回写机制）。

## 四、红线

1. **布局零改动**：布局清单（载体级）+ 低保真原型（区块级）共同构成结构真相源，视觉阶段禁止增删移任何区块/元素；
2. 结构问题（载体划分错、区块缺失、交互断点）→ 回 Prototype-Design 修复后重出，禁止视觉阶段顺手改；
3. 缺布局清单或缺低保真原型 → 阻塞，请用户先跑/补跑 Prototype-Design；禁止凭 PRD 脑补结构；
4. 本契约为消费方定义（D-02）；若 Prototype-Design 未来升级布局清单粒度（如增设区块级），两边同步确认后修订本契约。
