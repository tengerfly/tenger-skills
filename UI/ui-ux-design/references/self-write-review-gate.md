# B 路径设计检查（唯一检查记录）

只用于 AI 自写；A 路径继续使用 `design-review-gate.md`，不改变其调用与交付。本文件与 `self-write-sop.md` 配套，不重复套用 A 门禁、云端导入格式或旧的审美零容忍表。

## 1. 范围和基线

先确认本次文件/状态/视口、需求版本、结构基线与 design-system。轻量局部修改检查变更区域、相关交互及受影响全局样式；共享 token/组件改动需覆盖其消费者，不以“只改一行”省掉回归。新多页设计覆盖全部交付页及关键状态。

## 2. 检查表

| 检查 | 判据 | 证据 |
|---|---|---|
| 需求/结构 | 相关区块、载体、入口/出口、状态与确认基线一致，没有业务增删 | 需求条目、结构对照与实际页面 |
| 文案/数据 | **① 类已批准文案原样保留**（判据见 `self-write-sop.md` §二 保真范围限定）；**② 类原型说明层在界面可见层命中数 = 0**（`U-xxx`／`【设计假设】`／`台账 §x`／`AC-Mxx`／`PRD 未写`／`示意·走查占位`／元信息徽标／演示切换条／清单对照块）；**③ 类原型口语有重写记录**；样例与占位明确；无杜撰指标 | 源条目与 HTML 对照；不得因 em-dash/长 CTA 而拒绝已批准文案；② 类须给**渲染后可见层扫描结果**（命中清单 + 计数），源码 grep 不能证明"不可见" |
| 视觉规范 | 实际视觉决策对应语义 token；已有产品保持一致；新方向的例外有确认依据 | design-system 引用、源码及渲染 |
| 可用性 | 导航和按钮可达；键盘操作与焦点清晰；表单标签/错误关联；本次状态完整 | 实际点击/键盘/状态检查；源码只能证明静态部分 |
| 渲染 | 目标视口无遮挡、非预期溢出、资源缺失；文字可读；页面无影响功能的运行错误 | 对应文件版本、视口、截图与控制台/交互结果 |
| 链接/依赖 | 本地链接解析后在交付目录内且目标/锚点存在；外部依赖与运行条件明确 | 本地目标检查及真实导航；无条件时外链标未验证 |
| 动效（存在时） | 有目的、对齐 token、不阻塞操作、reduced-motion 下可用 | CSS/脚本检查与必要的实际交互 |
| **跨页不变量（多页交付必查）** | 先按 `assets/design-system-template.md` §5.11 **分角色**再核：**〔全局导航外壳〕**（承载跨页一级入口的顶栏/侧栏）全站同宽、同左缘、同内距，**限宽页不得把它随内容档位一起居中缩窄**——`max-width` 落在含导航外壳的页框/根容器＝缺陷；**〔页内标题栏〕**（只含本页 h1/页头、不承载跨页导航）与该页主内容列同宽、同中心、左缘差 ≤2px；**禁主列内再套一层不同中心的限宽列**（三类豁免见本节末）；**宽度档位**须 token 化并登记档位表与出处——档位本身才是 token 化对象，组件内部排版行宽与栅格列轨不在此列（口径见 `self-write-sop.md` §三）；1440 与 1920 两档视口下放大规则一致，不得某页不跟随 | 逐页实测三值并横向比对：**导航外壳逐页 `getBoundingClientRect().x/width` 必须跨页全等**；页内标题栏内容行内缘取 `getComputedStyle(标题栏).paddingLeft/Right`，主内容列与跨视口宽度取 `getBoundingClientRect`（x / width / 中心）；**源码里有 §5.11 规范文字不算证据**，必须有测量值或截图 |
| 交付一致 | README 与本地版本、需求和 token 对账一致，无云端旧稿问题 | 文件版本/指纹与本次检查记录 |

颜色/字体/装饰的默认建议用于改进，不独立构成缺陷。Aurora、多字体等已批准风格不因“非克制”自动失败；仍须满足可读性、交互和业务约束。不要把主观“AI 味”当硬门槛。

**跨页不变量的三条硬约束**：

1. **不得以"规范里写了"代替实测**。`design-system.md` 有页面宽度分层一节 ≠ 稿件遵守了它；本行只有拿到逐页测量值才能标「已验证」，否则标「未验证」并写入交付边界。
2. **宽度不一致按跨页共性问题处理**，不逐页开单——收敛方案（顶栏随内容列收窄 / 内容列左对齐到 logo / 全站收敛到少数档位）属**设计方向决策**，必须交用户裁决后再改，不得在视觉阶段自行统一。
3. **〔上一项目的裁决不可照搬〕**（2026-10-12 由 knowledge-bases 用户走查指出）"顶栏随内容列收窄"是 travel-agent 2026-09-24 的**已批准收敛方案**，其成立前提是那儿的顶栏为**页内标题栏**。本产品顶栏是**唯一全局导航外壳**（无侧栏），沿用同一方案会做出"跨页导航宽度跳变"的缺陷——同一条判据在两个项目里指向相反的正解。**登记收敛方案时必须连同其成立前提（角色）一起登记**，跨项目复用前先重判角色。

**二次窄列的三类豁免**（全站唯一枚举，同 `../../ui-ux-review/references/rendered-quality-checklist.md` §七「三类不算命中」；A 路径设计门禁 §五 校验方法回指该枚举；不得各处各自增删）：

1. 已登记为栅格列轨的内层列；
2. 组件内部排版行宽（如 `max-width: 44ch` 类可读性约束）——依 `self-write-sop.md` §三「尺寸规则、布局比例和原生浏览器必要值不机械当成待新增的品牌 token」；
3. 注释层样张框（仅示意用途、不属交付页）。

## 3. 结果与停止

- 每项标 **已验证 / 不适用（附理由）/ 未验证 / 缺陷**，并写证据。只勾选真实验证项；无动画可不适用，无浏览器的视觉检查只能未验证。
- 同一次检查记录被 pre-flight、README 和交接引用，不重复全量走查。第一版检查通过可以交付；有缺陷才修复，并复核受影响项。
- 默认一次检查加一次修复复核；仍有问题就停止并报告，不因为上限而自动放行，不为得到全勾伪造截图/版本。
- 浏览器不可用可交付“待视觉验收”的草稿，源码检查不能证明视觉正确。不执行 `get-design` 作为 B 的替代检查。
- 轻量独立结果不写正式 Gate/状态。正式交接依照仓库根 `../../../shared/gate-policy.md`：验收所需证据缺失或 P0/P1 未处理不能 PASS；例外必须真实授权并带完整补证计划。已有评审任务仍由原评审方复核。
