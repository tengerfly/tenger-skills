# AI 自写设计稿 SOP（B 路径）

仅用于用户指定自写或 A 路径不可用后的本地设计稿生成。**B 的完整流程与检查以本文件及 `self-write-review-gate.md` 为准**；不继承云端导入格式、A 的三套方案必选、逐字审美禁令或云端回传步骤。Superdesign 的 SOP、门禁、模板及调用行为不变。

融合来源沿用本地 2026-09-20 OSS-Radar 记录；这是按本项目职责改编后的方法，不是任何上游 Skill 的逐字规范。吸收设计意图与审美纪律（frontend-design / taste-skill）、有界检查（impeccable / design-taste）、目的驱动动效（emil）、可访问交互与真实渲染（vercel / avoid-ai-design），不把所有来源的偏好叠成硬禁令。

## 一、先判断任务，而不是先选三套风格

读取仓库根 `shared/execution-profiles.md` 与 `shared/requirements-context.md`；只加载本次相关的需求、结构与视觉基线。

| 任务 | 处理方式 |
|---|---|
| 新设计且方向未定 | 确认产品/受众/核心任务，必要时提出差异化方向；默认文字+色板，不先生成多版 HTML；数量按用户需要与预算，不固定三套 |
| 新页面/已有产品延展 | 继承已确认的品牌、Token 和组件，不重新选风格；先识别确有缺口的规范 |
| 局部修改 | 只改用户指定区域及必要关联项，复用现有稿，不整页 replace；不重新搜风格、不重新跑全站门禁 |

在风格探索**之前**确定页面目的：Persuade（说服/营销）、Operate（任务操作）、Read（阅读理解）、Experience（内容体验）。目的影响密度与动效，不要求每页都制造新记忆点。

### 输入与停止条件

- 结构基线优先用已确认布局清单与原型；轻量局部任务可用现有页面/HTML加用户确认的变更清单，记录入口、区块、状态、跳转。不能用“没原型”强迫小改动补整套原型，也不能擅自发明未知结构。
- PRD 文案/规则按相关条目取原文；无 PRD 的 Demo 用已确认目标与验收点。未知业务行为/关键文案先问，不编造数据或批准。
- 视觉基线优先用现有 `design-system.md`。没有规范时先提出覆盖本次需要的 token 与方向；用户已明确指定或授权自行选择的部分不重复询问。未确认且未授权决定的关键方向不能被模型自批为已确认。
- 既有规范/已批准文案与新要求冲突时记录差异并澄清，不用美学规则偷偷覆盖产品事实。
- 浏览器可用则真实渲染；不可用可以生成草稿和源码检查，必须标“待视觉验收”，不能视为视觉通过。

## 二、统一规则优先级

| 层级 | 内容 | 行为 |
|---|---|---|
| 必须满足 | 授权/安全；已确认业务、文案、结构和跳转；本次已批准视觉基线；交互可达、真实证据 | 冲突先澄清；不得用风格或预算豁免 |
| 默认建议 | 克制阴影/装饰、少而有意义的强调、清晰排版、一意图同措辞、避免无来源营销数字 | 服务具体任务，不是自动阻塞条件 |
| 风格选择 | 多色/渐变、衬线、多字体、复古纹理、表达强度 | 仅按已确认方向启用，写清理由和 token，不按另一种风格的偏好判失败 |

**文案保真**：已批准文案原样保留，包括 OK、长按钮标签和标点。文案改进只能提建议，获确认后更新唯一需求源/变更记录，再改页面。新文案有确切授权时可起草并标来源。没有 em-dash 零容忍、CTA 三词限制或强制单行截断业务含义的规则。

**一致性与独特性**：新品牌探索检查是否无理由套模板；同产品延展检查是否一致。不强制换颜色/字体来证明独特，不用“像不像 AI 做的”作为不可证伪的放行门槛。

**结构保真**：不增删业务区块、不改入口/出口与业务顺序；响应式重排应保持信息/导航完整。发现结构问题输出建议回结构设计方，不在视觉阶段擅改。

## 三、设计计划与规范（只写必要差异）

用几行记录：页面目的、受众核心任务、使用的颜色/字体/密度 token、继承/新增组件、是否需要动效及理由。旧页面小改只记录变更点，不重复写每页完整计划。

新方向可按需读 `self-write-style-options.md` 与相关案例；已有规范不强制外部研究。确需外部参考时实抓、确认可达/许可，失败如实标无命中，不编造提取值；不依据 star 数量判质量，不擅自安装或运行未核验包。

`design-system.md` 放在 `.spec/设计稿/`，沿用既有模板的章节定位，尤其 §5 状态/组件、§6 动效、§7 CSS token 汇总，确保下游仍能消费。已有规范只更新经确认的必要增量；轻量 Demo 可精简章节内容，不凭空补复杂组件。规范外新增视觉值先登记用途并按授权确认，不能让页面与规范各自演化。尺寸规则、布局比例和原生浏览器必要值不机械当成待新增的品牌 token。

## 四、本地生成契约（不套云端导入格式）

1. 可直接浏览的完整 HTML 文档，语义结构清楚；页面可滚动，不强制单屏。目录与文件名延续现有交付约定。
2. 优先复用现有 CSS/组件/图标；允许原生 CSS、已有 Tailwind、class 放在 body、合理多容器以及项目既有 SVG。不强制 CDN、Iconify 或安装新框架；外部依赖缺失要说明，不宣称离线可用。
3. 页面/锚点导航用真实链接或符合语义的等价组件；同目录相对链接合法。解析后的本地目标必须在交付根目录内，锚点真实存在；禁 `javascript:` 链接、死链和假按钮。动作按钮保留键盘操作与状态反馈。
4. 所有本次视觉决策对齐 design-system 语义 token，状态色不受“唯一强调色”限制；已批准多色风格也不受该默认偏好限制。
5. 图像/数据有出处；Demo 占位内容明确标样例且不冒充业务事实。缺少素材列明位置与限制，不以未提供的素材冒充完成。保留替代文本、焦点、表单标签与错误关联。
6. 覆盖本次需求涉及的加载/空/错误/禁用等状态，不为每个简单静态页机械增加十种状态。窄屏不得丢失核心内容与操作，长文案不得因“美观”截掉必要含义。

## 五、动效决策（按需）

依次问：是否必要、服务何种状态/空间/反馈、使用哪个已确认曲线、需要多长。回答不出目的就不加。

- 优先低成本 transform/opacity；颜色、焦点、必要高度过渡可以按场景使用，不用“只准两个属性”破坏交互反馈。
- 列明 transition 属性，不用 `transition: all`。曲线与时长来自规范；通常微交互短、弹层略长，具体取值服从既定规范与可用性，不用字符串 grep 把 `ease-in-out` 当成 `ease-in`。
- 键盘操作不增加装饰性等待，不移除必要的状态/焦点反馈；不硬性规定所有键盘触发都不能动画。交互不得依赖动画完成才能使用。
- 尊重 `prefers-reduced-motion`；减少/关闭非必要运动，保留可理解的状态变化。不要给所有元素统一强加按压缩放。

## 六、生成、验证、修复（有界）

**未经验证的第一版不能作为完成稿；验证通过的第一版可以交付。** 新多页方向先做代表性主流程页，经确认再延展；旧方向局部修改不重复进行风格确认。

1. 生成/局部修改后，以 `self-write-review-gate.md` 建一份检查记录；渲染与检查覆盖本次页面/状态。响应式页面检查桌面与窄屏；明确只有单端的任务按实际端型，不强制无关视口。
2. 发现问题时一次列齐，记录问题、修改与原因；批量修复后复核受影响项及必要回归。不每修一条都重跑全站。
3. 默认一轮检查加一次修复复核；首轮通过不制造第二版。未收敛则停止打磨，说明剩余缺陷、影响和下一步，请用户决定范围/预算；不会因达到上限自动放行。
4. pre-flight、README 与下游交接复用本轮证据，不再做一遍相同全量检查。源文件变化后相关证据失效，必须复核。
5. 结论区分源码可证、渲染实测与未验证推断。无浏览器时不勾视觉检查，交付仅为待验收草稿。

正式独立 UI-UX-Review 按流程或用户要求调用，发现问题按共享 Gate/anti-deadloop 处理；轻量任务不自动追加独立评审 Skill。但已有评审任务的修复必须由原评审方复核，不得自销问题。

## 七、交付与恢复

本地 `.spec/设计稿/` 是稿源，无 `.superdesign/` 工作副本，不调用 create/import/get-design。本地相对链接与宿主弹框保持可达。采用 git diff/用户允许的版本副本记录变更，不擅自 commit、覆盖或回退用户修改。

B 路径 README（局部续做只更新相关行）记录：
- 稿源 = AI 自写（B）；文件版本/内容指纹；新设计/延展/局部修改与范围；
- 需求上下文引用、结构基线、已确认视觉规范及 §7 token 对账；
- 页面/状态/跳转与素材或运行依赖；
- 唯一一份检查记录：检查项、证据、结果（已验证/不适用并说明/未验证/缺陷）；
- 已批准风格选择与理由、尚未批准的建议；
- 未验证项、缺陷、下一动作；草稿明确“待视觉验收”。

轻量只交付本次结果与证据摘要，不伪造 Gate。标准/完整要正式交接时遵循原 Envelope/manifest/批准契约；结果满足验收方可通过，缺少视觉验收或残留缺陷不能静默 PASS，CONDITIONAL 必须真实授权。下游需另做批准流程时复用本地结果，不回头重做云端稿。
