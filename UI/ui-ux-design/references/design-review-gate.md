# 质量门禁检查表（Design Review Gate）

> 用途：UI-UX-Design 步骤 8。**全绿才放行归档**；任一 ❌ 按迭代路由修正后重检，禁止带病归档。
> 原则：只对照客观来源（布局清单 / design-system.md / PRD）判定，不凭感觉。

## 一、布局零改动（对照物：布局清单 / 设计任务清单）

- [ ] 独立页面清单与布局清单一一对应（无多页、无少页、无改名错位）；
- [ ] 每页区块结构逐项一致：区块数量、类型、位置关系（导航/侧栏/操作区/数据区…）；
- [ ] 组件类型一致：表格还是列表、几个统计卡、几个 Tab，不多不少；
- [ ] 弹框 / 抽屉宿主挂载一致（宿主页、触发入口、数量）；
- [ ] **入口→目标载体闭环（含下拉/菜单内入口项）**：凡设计稿里「点了该去某弹框/页面/动作」的入口（含头像菜单「设置」这类下拉项），必须可到达其对应载体（弹框专稿/页面稿/动作），不得做成无动作 button 或死链——独立成稿的弹框（如弹框专稿）其触发入口必须用可达链接指向对应稿；
- [ ] 跳转关系一致：入口按钮 → 去向与布局清单站点地图逐条对上（`<a>` 链接无断链）；
- [ ] 无「设计需要」新增的区块 / 按钮 / 提示 / 装饰；
- **校验方法**：逐页打开导出 HTML，与设计任务清单逐行核对；区块数用 DOM 计数，跳转逐链接点验。

## 二、规范一致性（对照物：.superdesign/design-system.md）

- [ ] 页面 `:root` 的 CSS 变量与 design-system.md §7 Token 汇总一致（无缺项、无私改值）；
- [ ] 抽查色值：页面里出现的一切颜色都能在 token 中找到出处（grep `#[0-9a-fA-F]{3,8}` 与 token 表比对，允许的例外：token 本身派生的透明度写法）；
- [ ] 字号 / 字重只用 §2 排版定义的层级；
- [ ] 间距符合 4px 网格（§3）；
- [ ] 组件样式符合 §5 组件规范（按钮三态、表格行高、弹框结构、badge 配色…）；
- [ ] 图标风格统一（线性 1.5px，同源图标集，无 emoji）；
- [ ] **动效合规**：强度档与 §6 一致；时长取自 §6 档、曲线取自 §7 token（无内置默认值直写、无 ease-in、常规 UI 动效 <300ms、弹层 / 抽屉类按档放宽）；无答不出目的的动画（判据 `references/motion-design-guide.md`）；
- [ ] 布局清单/原型中涉及界面状态（空/错/加载/禁用/断网等）的页面：对应状态稿已产出且符合 design-system §5.10 状态规范；
- **校验方法**：`get-design` 导出后 grep 色值/字号，与 token 表机械比对 + 关键组件目检 + 状态稿逐状态目检。

## 四、文案保真（对照物：PRD（先读 `PRD速查表.md` 建索引，逐字比对按锚点回原文）/ 布局清单内容要素）

- [ ] 界面文案与 PRD / 布局清单**一字不差**（按钮、列名、字段名、提示语）；
- [ ] 无杜撰 Toast / 引导 / 说明文案；
- [ ] 无无出处操作入口；
- [ ] 【设计假设】标注（若步骤 2 有假设）均已用户确认；
- **校验方法**：文案逐字比对（重点：列名、表单标签、按钮组）。

## 五、布局基线与全站组件不变量（Cross-Page Layout Baseline · 一类问题，2026-09-05 沉淀）

> 类别：这类问题的共同点是——**页面基础布局策略（顶栏/内容列宽度与关系、全局组件是否恒定）在生成阶段被自由发挥、或在修改阶段被连带改坏**。典型症状：① 已定稿全局组件（顶栏/导航/头像）因某页面需求被逐页改宽改位；② 顶栏内容列宽与页面内容列宽不一致（上下宽度错位）；③ 限宽值被当死值锁死、大屏不响应。属**步骤 4 风格决策 Gate 定方向、步骤 5 设计规范 Gate 落 §5.11 就应向用户拍板确认的范围**，步骤 6/8 与 UI-UX-Review 均须核对。案例：`.spec/设计评审/沉淀_评审盲区复盘_导航换行与大屏铺开.md`（学径项目）。

### A. 全站组件不变量（跨页恒定，禁止 per-page 漂移）
- [ ] **全局组件（顶栏/导航/头像/页脚等）一旦用户拍板定稿 → 全站每页实现恒定**（相同容器宽度、相同内部三段式、相同激活态）；需求变更只针对「内容区」时**不得连带改全局组件**；
- [ ] 顶栏内部版式恒定：品牌（icon+slogan）贴左 → 导航组与头像靠右 → 头像在列最右端（brand 用 `mr-auto`）；导航不许漂在正中或逐页不同位置；
- [ ] 顶部导航条宽度策略全站同一档（全宽 or 固定居中列），不因该页内容区是「限宽/全宽」而异宽。

### B. 页面宽度分层（先拍板再生成）
- [ ] 每页归属明确一档：限宽居中页（顶栏内容列 **=** 内容主列同宽居中，报纸式上下对齐）或 全宽铺满页（内容区铺到最左/最右，与顶栏不必同宽）；
- [ ] 页面归属清单、顶栏列宽、内容列宽在生成前与用户确认并写入 design-system（§5.11 页面宽度分层）；
- [ ] 限宽页内容主列**禁止内部二次窄列**（如 `w-[70%]` 内嵌使内容实际宽度 ≠ 顶栏列宽）。

### C. 响应式列（限宽值是「当前屏基准」，非死值）
- [ ] 限宽列用统一响应式工具类实现：`width:100%; max-width:Npx; margin-inline:auto` + 大屏断点放大（如 ≥1536 → N2），禁止单一 `max-w-[Npx]` 死锁、禁止不同页写法不一致；
- [ ] 设计稿交付须含宽屏（≥1440/1920）截图，证明大屏下列宽按断点放大且仍居中。

> **校验方法**：grep 全局组件容器 class 是否全站一致、限宽页内容主列与顶栏是否同一容器 class——**grep 与宽视口截图目检只能证「写法相同」，不能证「实测宽度对齐」，不得单独作为通过依据**；须按 `../../ui-ux-review/references/rendered-quality-checklist.md` §七 用真实浏览器逐页实测三值（顶栏内容行内缘 / 主内容列 x·width·中心 / 1440 与 1920 两档主列宽）并横向比对，判据为同宽、同中心、左缘差 ≤2px、宽屏放大规则全站一致；三类豁免同 §七 唯一枚举。发现「只改了某页的全局组件」一律打回。

## 六、稿源同步核验（一类问题，2026-09-05 沉淀 · 学径案例）

> **〔A〕Superdesign 云端路径**适用下述云端核验；**〔B〕AI 自写路径**无云端稿，本项替换为：〔B〕**本地渲染核验**——① 每页 HTML 浏览器渲染无报错且截图与源码一致；② README 稿源标注「AI 自写 + git 版本（或 `.v<n>` 副本号）」，用户评审入口 = 本地文件/本地服务（无「云端旧稿」问题）；③ 关联稿互链（宿主入口→弹框/页面稿）在本目录内可达。
>
> 类别（〔A〕）：**本地 .spec/设计稿/*.html 与云端草稿（评审/宿主入口指向 `p.superdesign.dev/draft/<id>`）版本不同步**——本地直编/迭升已是新版但未 `import-design-draft` 回传，云端仍是旧稿；用户从可点击入口看到旧稿，误判「模块没生成/遗漏」。属放行前必查项（本 skill 步骤 8/9 与 UI-UX-Review 均须核对）。
> 案例：学径 LearnPath 设置弹框迭升 V1.4（模型管理/Skill/MCP/偏好设置）——本地 dialogs-settings.html 已直编五分类并截图存证，但云稿 49eb9f4c 仍为 v1（仅标签管理），README 标「待 import 回传」即当定稿搁置；用户从首页云稿点「设置」进入看到旧稿。

### 闭环流程（每次更新云端都最新 · 用户拍板 2026-09-05）
1. **本地完成 → 自动本地打开给用户确认**：起本地静态服务 / 打开渲染稿，请用户确认「没问题」（确认入口=本地最新稿，不是旧云稿）；
2. **确认 OK → 立即回传云端**：`import-design-draft --into <draftId>` 同一轮内完成，不留「本地新/云端旧」中间态；
3. 回传后 `get-design` 核 version 递增，README 稿源对照同步为已回传版本。

### 必查项
- [ ] 本轮凡改动过 `.spec/设计稿/*.html` 的稿 → 已本地打开请用户确认 + 均已 `import-design-draft --into <draftId>` 回传云端（不得只有本地改动）；
- [ ] 回传后 `get-design` 核验云端 version 已递增为最新，非旧版缓存；
- [ ] 迭升新增分类/面板/区块时 → 宿主页入口链接指向的目标云稿内容确为最新（用户点「设置/…」进去看到的是新稿）；
- [ ] 归档 README 稿源对照表状态列如实：凡写「待回传/本地直编」＝未闭环，禁止当作定稿交付；全部回传后才可标定稿。

## 七、放行规则

1. **六查**全绿（一~四 + §五布局基线与全站组件不变量 + §六稿源同步核验）→ 归档（〔A〕`get-design --output` 导出；〔B〕本地文件核对路径命名）+ README 门禁记录表打勾；
2. 任一 ❌ → 判定修正路由（branch / replace / 直编）→ 修正 → 重检该项及关联项；
3. 同一问题 3 轮不收敛 → **强制清零 P0 后直接放行**，残留 P1 记入 PIPELINE 遗留问题，全程留痕并告知用户（评审死循环对策：轮次上限，定义见仓库根 `../../../shared/anti-deadloop.md` §二.3）；
4. 门禁结果记入 `.spec/设计稿/README.md` §四（可追溯）。

## 2026-10-10 增补 · 四类反向清点（knowledge-bases 设计稿评审闭环反哺）

第一轮自查「六查全绿」被独立复审推翻四条，共同特征是**只做正向核对、不做反向清点**。生成与自检阶段必须补跑：

1. **载体总数反向清点**：`grep -c 'class="modal"'`、`role="dialog"`、抽屉容器数，与布局清单登记数**双向**相等；不等即逐个定位是漏做还是自造。**只核对「清单要求的载体在不在」检不出自造载体**（案例：自造第 8 个弹框 + 5 句无出处文案）。
2. **跨页路由等值性**：收集全部稿的 `#go-*` 出口 → 归一（目标页, frag）→ 在 iframe 内以该 hash 打开目标页 → 读**可见 h1** 与 frag 语义比对；同时确认目标页监听 `hashchange`。不等值会呈现**相邻状态的满页真实内容**，不报错不空白，是最高危的静默缺陷。
3. **演示文案双扫描道**：标记文本道（含 `display:none` 节点）扫「演示/模拟/原型略/原型简化/原型占位」+ 演示区块串泄漏道（从原型 `.demo-bar`、「当前视角」区块取串在稿内全文匹配）。**扫描前整体剔除 `<script>` 会让运行时注入文案与藏匿节点双双逃检**；`<script>` 内的 toast 串另立规则（去「演示：」「演示原型：」前缀，纯演示句加注释并入下游交接）。
4. **token 用途列与声明-消费**：色值/字号在 §7 白名单内 ≠ 合规，还要对照「允许出现处」列核使用部位；并核 `:root` 声明的 token 是否被 `var()` 实际消费（0 次消费即声明-实现脱节，下游对账会假绿）。

**配套纪律**：评审裁决产生的文案偏离（删演示括注、按 PRD 改词、补区块名）必须进**偏离登记表**（如 `.superdesign/copy-deviations.json`，带 T-xx 依据），量具输出显示「已豁免 N 条」——不得为过检回改已批准文案，也不得静默放宽判据。
