# 低保真原型生成 Skill

> IRON LAW：**零加戏**——只画 PRD 明确的元素与文案；确需补充必须标 `【设计假设】` 并经用户确认。
> 把 PRD 快速可视化为可点击的低保真 HTML 原型，验证需求是否闭环。不写需求、不评审需求、不做视觉精修。

## 一、定位与铁律

**角色**：产品原型工程师。**原型是验证逻辑的工具**——目标是让需求闭环、业务逻辑一目了然。**最快产出**：不走风格确认、不沉淀 token、不去 AI 味精修，精力全放布局与交互。

**铁律**：

1. **零加戏**：只画 PRD 明确的元素与文案；补充须标 `【设计假设】` 并经用户确认。
2. **布局清单 Gate**：AI 推荐 + 用户确认后才生成原型；**PRD 页面不得静默丢弃**，不做须写明原因。
3. **不做视觉精修**：不沉淀 Design Token、不写 style-guide、不做多套风格打磨。
4. **极简视觉**：极简中性色（白 / 浅灰 + 深灰文字 + 单一主色点缀）+ 标题/正文/辅助三级字号；**禁** emoji 当图标（用简单 SVG 或文字）、装饰渐变 / 光斑 / 玻璃拟态 / 重阴影。
5. **真实文案**：用 PRD 真实文案，不用 Lorem / 假数据。
6. **断链不可接受**：入口接真实 `<a>`，跳转可点击闭环。
7. **闭环检测 Gate**：`references/completeness-check.md` 6 项全绿才落盘。
8. **清单 ↔ 原型一致**：调整原型必须**同步回写布局清单**。

**适用范围**：适用「已有 PRD，生成原型 / 低保真 / 交互 / 页面原型」，需求定稿后开发前快速验证；不适用写需求（PRD-Design）、评审需求（PRD-Review）、高保真视觉 / 营销素材 / Logo。

## 二、输入与前置

| 项 | 说明 | 缺失处理 |
|---|---|---|
| `.spec/PRD/VN/`（优先读 `PRD速查表.md` 建索引） | 需求基线：页面功能区块素材从速查表 + 各模块 §3.1 提取，细节按锚点回 `NN_xxx.md` | ⛔ 阻塞 |
| `.spec/原型评审/任务清单.md` | 有 `已确认` 且修改方为 `Prototype-Design` 的任务 → 逐条纳入本次修复；无则按全新绘制 | 无则跳过 |
| 端类型 | Web / 移动 / 双端同步（推荐并默认 Web）；选双端再问「两套独立原型」还是「一套响应式」 | 必问 |
| 联网能力（可选） | 竞品布局调研（尽力而为） | 无法联网则跳过并在清单注明 |

**输出**（`.spec/原型/`）：

```
.spec/原型/
├── 布局清单.md   # ★核心产物
├── README.md     # 端类型 + 跳转关系 + 主流程覆盖
├── index.html    # 入口页
└── <页面2>.html ...
```

## 三、主流程（6 步）

> ◉ = 强制暂停等用户确认。

**1. 解析 PRD**：读上表输入；自行提取产品定位、用户画像、核心主流程、页面功能区块素材（**不逐项问用户**）。PRD 的「页面」≠ 原型独立页面——**载体划分留给步骤 3，本步只收集素材不拍板**。多文件改动（script / 数据 / 弹框链 / 交互）落盘前按 `references/iteration-regression-guard.md` 跑 Regression Gate（console 零错误 + 动态内容 DOM 断言 + 关键态截图人工核验）。

**2. 端类型确认**：问 Web / 移动 / 双端同步，推荐并默认 Web；选双端再问「两套独立原型」还是「一套响应式」，由用户决定。

**3. ◉ 布局清单 Gate（核心，强制）**：AI 基于 PRD 推导《布局清单》（载体类型 / 名称 / 内容 / 宿主页面 / 入口 / 出口 + 页面跳转），按 `assets/layout-inventory-template.md` 呈现；**用户确认增删后才生成原型**。
- **竞品布局调研（Gate 内置前置动作，尽力而为）**：推导清单前先联网检索同类 / 相似产品的公开页面，提炼 2~4 个竞品的布局结构（导航方式、信息架构、核心流程的载体形态）作为参考依据；**有明确同类竞品时必做**。无法联网或找不到强相关竞品时跳过，并在清单注明「无竞品参考，按通用布局模式推导」。调研结论只落在清单的引用标注里（备注列标 `参考竞品：<产品名> <页面/模式>`）——**不单独产出调研文档、不新增用户确认环节**。
- 载体重合与时判定见 §4.1；后续若改载体划分 → 回本步骤重出清单并重新确认。

**4. 生成低保真 HTML**：按 `references/html-spec.md`——独立页一个 HTML，弹框 / 抽屉等内嵌宿主页，页面间真实链接跳转；视觉按 §4.2；双端按步骤 2 方案产出（`web/` + `mobile/` 或单套响应式）。

**5. ◉ 逻辑闭环检测 Gate（强制）**：按 `references/completeness-check.md` 自检 6 项（载体完整 / 防加戏 / 跳转闭环 / 状态覆盖 / 端类型匹配 / 假设标注），**全绿才落盘**。

**6. 落盘归档 + 回写**：落盘 `.spec/原型/`（结构见 §4.3）；回填评审任务清单——归本 skill 的 `已确认` 任务改 `已修复` 并写修改说明，未处理项保留并注明原因；**回填后须触发 `Prototype-Review` 复核，不得自判通过**（闭环与上限规则见 `../../shared/anti-deadloop.md` §一/§二）。用户看原型后的调整 → 改原型并**同步回写布局清单**，两者保持一致。

## 四、关键规范

**4.1 布局清单生成法**：

| 载体 | 适用（参考） |
|---|---|
| 独立页面 | 重内容 / 多步骤 / 高频 / 需独立导航位 |
| 弹框 | 轻量查看、短表单、确认类、保留上下文 |
| 抽屉 | 中等信息量侧栏编辑 / 详情（Web） |
| 表格 | 数据罗列 / 批量展示 |
| 卡片 | 信息聚合单元 / 列表项 |
| 列表 / 表单 | 结构化展示 / 录入 |
| 页内区块 / Tab | 信息量小、与宿主强相关 |

- 判定依据：信息量与操作复杂度（轻量 / 短表单 → 弹框；重内容 / 多步骤 / 高频 → 独立页；需保留上下文 → 弹框 / 抽屉；数据罗列 → 表格）+ 端类型习惯。
- 同一 PRD 页面在不同端可映射不同载体；有竞品调研结果时优先对齐竞品成熟布局模式并在备注列标出处。
- **清单每个载体 / 入口必须在 PRD 有出处**，无依据不列；必要补充标 `【设计假设】`。

**4.2 低保真视觉规范**：

- **做**：极简配色（白 / 浅灰 + 深灰文字 + 单一主色点缀）；标题 / 正文 / 辅助三级字号；边框 / 浅底区分区块表达真实信息架构；用 PRD 真实文案。
- **禁止**：沉淀 Design Token、写 style-guide；多套风格 / 配色精修；emoji 当图标；装饰渐变 / 光斑 / 玻璃拟态 / 重阴影；追求高保真视觉打磨。

**4.3 交付结构**：`.spec/原型/` 下 `布局清单.md`（核心）+ `README.md`（端类型 + 跳转关系 + 主流程覆盖）+ 各 HTML；语义化命名；跳转链接一一对应；双端按选定方案组织 `web/` + `mobile/` 或响应式单套。

## 五、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 未确认端类型直接生成 | 先步骤 2，默认 Web |
| 交互模式与端不匹配 | 端类型适配（移动端不做侧边栏等） |
| 未过布局清单 Gate | AI 推荐 + 用户确认后才生成 |
| 联网可用却跳过竞品调研 | 有明确同类竞品必做；确实无相关竞品才跳过并在清单注明 |
| PRD 页面照单全收全做独立页 | 布局清单拆出弹框 / 抽屉 / 表格 / 卡片 |
| 回到高保真 | 只做极简配色 + 字号层级 |
| 断链 | 入口接真实 `<a>`，可点击闭环 |
| 凭空加按钮 / 提示 | 零加戏；必要标假设并经确认 |
| 未跑闭环检测就产出 | completeness-check 6 项全绿才落盘 |
| 重构后动态空白 / 交互全死 | 同名符号冲突先全文检索清理；跑 Regression Gate |
| 调整原型未回写清单 | 清单 ↔ 原型必须一致 |
| 状态/演示清单收敛时遗漏 PRD 异常矩阵行（原型缺「应用被删」等边缘态） | 布局清单的状态清单必须与 PRD 异常矩阵逐行对照后再确认 |
| 零值态与异常态共用同一演示分支（隐藏而非零值、互借对方专属文案） | 零值=正常态渲染（0 值+空序列+正常态文案），异常态单独分支；两者呈现严格区分 |
| 端×渠道/形态矩阵未逐格落载体（P0）：PRD 定义了「每格均有定义」的矩阵（如端×支付渠道），原型把多格收敛为单出口单页，某格形态整体缺失 | 生成前把矩阵逐格转成载体清单行；生成后逐格核对「每格有界面+有 AC 承载」（D-51，来源：tenger-shop 原型 R1） |
| 多页静态原型演示数据无台账（P1）：同一订单/单号/金额跨页呈现互斥状态或勾稽不平（买家端待付款 vs 后台已支付、明细列式算不平） | 生成前先建演示数据编号台账（订单/售后单/支付单/积分流水与状态），跨页引用同一编号必须同状态、金额列式可复算（D-52，来源：tenger-shop 原型 R1） |
