# 修复任务卡模板（BUG Card）

> 每条 P0-P2 缺陷一张卡，存 `任务卡/BUG-<日期>-<序号>.md`。机器可读、AI 可执行；修复 agent 只拿这张卡 + 必要上下文，不拿测试过程。

```markdown
# BUG-<日期>-<序号>【P0/P1/P2】<一句话标题>

| 字段 | 内容 |
|---|---|
| 级别 | P0（阻断）/ P1（严重）/ P2（一般） |
| 类型 | 功能 / 样式 / 性能 |
| 位置 | {{页面 / 模块 / 路由}} |
| 关联用例 | TC-{{xxx}} |
| 发现轮次 | run-{{日期}}-R{{n}} |

## 现象
{{一句话：什么页面、做了什么、应该怎样、实际怎样}}

## 复现步骤（可直接照做）
1. {{前置：执行 {{seed/mock 命令}} 或 已处于 {{状态}} }}
2. {{操作}}
3. {{操作}}

## 期望 vs 实际
- 期望：{{来源：AC-Mxx-nnn / 设计稿 / 契约}}
- 实际：{{实测结果}}

## 证据
- 截图：evidence/screenshots/{{xxx}}.png
- console：evidence/console/{{xxx}}.log（关键报错：`{{错误行}}`）
- 网络：evidence/network/{{xxx}}.har（关键请求：`{{方法 路径 → 状态码}}`）
- 定位线索：{{改动 diff 涉及文件 / 报错指向的模块}}（只给方向，不下结论）

## 回归验收标准（机器判读）
- [ ] 按上述复现步骤执行后：{{可自动断言的结果}}
- [ ] {{相关联的不可回归项，如「订单列表原有功能不受影响」}}

## 修复记录（修复方回填）
| 轮次 | 修复说明（commit） | 回归结论 |
|---|---|---|
| R{{n}} | {{}} | {{Pass / Fail + 新证据}} |
```

**写卡禁令**：不带测试方的修复方案结论（给方向不给药方）；不带对开发者的情绪评价；不省略证据只写文字。
