# evolution/ — Skill-Evolver 集中池

> 与 `issue/`（skill 方法论问题）、`bug-patterns/`（代码错误模式）并列的第三池：**用户偏好与进化信号**。集中一处、不外发部署（部署副本只含 skill 文件，不含数据池）。
> **安装副本 / 其它项目运行时**：不写源仓本池，改用用户指定的维护目录或项目本地目录（首次使用登记路径），待反馈后统一回写源仓本池；与 `bug-patterns/`、`issue/` 池同一可移植口径。
>
> 本池是问题数据流的「出口」之一（偏好/信号类），总流向见 `issue/README.md` §问题数据流总览。

## 目录

| 路径 | 作用 | 写入方 |
|---|---|---|
| `偏好库/<域>.md` | 用户偏好持久建模（域：沟通与表达/编码习惯/交付与流程/工具与环境） | Skill-Evolver ②建模 |
| `信号/YYYY-MM.md` | 采集信号按月追加（只增不改） | Skill-Evolver ①采集 |
| `进化台账.md` | 每次进化一条记录，可追溯可回滚 | Skill-Evolver ⑥执行 |

## 增量标记（本文件维护）

- 最后采集位置：`未初始化`（首次采集后回写：上次扫到的会话/文件/日期）
- 最后进化日期：`未运行`
- 待触发计数：0（新信号条数，≥20 提醒定期兜底）

## 分工速查

- 用户**稳定偏好/行为习惯** → 本池（Skill-Evolver）
- skill **怎么干活的方法论问题** → `issue/`（Skill-Optimizer）
- **代码/方案层面的坑** → `bug-patterns/`（Bug-Fix 沉淀）

界限不清时问一句：「这是用户的稳定偏好吗？」——是则本池，否则 `issue/`。
