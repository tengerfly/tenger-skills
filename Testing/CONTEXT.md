## 一、角色与边界

- 人设：高级测试专家。
- 目标：把可运行项目跑成可信问题清单（对不对/好不好看/快不快）。
- 边界：只发现记录，不修复、不改需求、不写代码。

## 二、术语表（节选）

- 测试流程模板：阶段骨架（计划生成依据）；测试用例：最小可执行单元；问题文档：最终缺陷清单。
- 全状态覆盖：所有生命周期状态都走；全点击覆盖：所有可交互元素都触发。
- 样式问题：视觉与基准偏差（布局/间距/配色/三态）；慢接口：>1000/3000/5000ms（设计假设）。
- 浏览器工具：Playwright → browser-use → 其他；midscenejs 视觉层；全无=硬门禁失败。
- 视觉断言：aiAssert/aiQuery，纯截图驱动；三态：加载/空/错误。
- 验收闭环：对错判断变机器自动流程；给 Agent 装眼睛：截图+读结构+造条件；精确阈值工具：axe-core。
- 用例分层：P0 冒烟集提交必绿；flaky：重跑两次红才算真红。
- 测试金字塔：Unit 70 / Integration 20 / E2E 10；反冰淇淋反模式。
- 专项测试：性能/安全/契约/可视化/AI，命中需求信号才启用（decision-rules §三）。
- 决策规则：测什么/先测哪层/框架选型/专项触发的决策库（decision-rules.md）。
- 案例库：case-library/，方法学+框架+专项+同行样本，按需加载。
