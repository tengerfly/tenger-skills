# 验收闭环指南（Acceptance Loop Guide）

> 权威细则：把「测试」放进「验收闭环」的完整视角——代码层闭环流水线、hooks 保证必然执行、checklist 定义合格、验收标准前置。
> 来源：Vibe Coding 高效能秘籍 第三章（vc-05「让 AI 写功能老是有 bug」）。

---

## 一、核心认知：闭环的价值不止「抓错」

秘籍的核心判断：**「能被机器自动感知并拦下的错误，就永远不该消耗你的注意力。」**

- 测试的真正价值不只是事后抓 bug，而是**把 Agent 的工作模式改掉**：没有闭环时，Agent 写完代码宣布「实现已完成」，对错全靠人来验证；有了闭环，Agent 每改一轮就收到机器反馈（typecheck 报错、lint 报错、测试挂），它自己看报错自己修。**错误的发现与修复在 Agent 的循环内部消化掉，根本到不了人面前。**
- 本 skill 做「项目测试」时，应同时承担「验收闭环是否闭环」的检查职责：不只测「功能对不对」，还要确认「代码层/视觉层的机器验证手段是否到位」。

---

## 二、代码层闭环流水线（成本从低到高）

| 环节 | 验什么 | 何时跑 |
|---|---|---|
| `typecheck` | 类型对不对 | 编辑后即时 |
| `lint` | 代码风格对不对 | 编辑后即时 |
| 单元测试 | 逻辑对不对 | 改完相关代码 |
| `build` | 能否构建 | 新功能完成后强制 |
| e2e 测试 | 端到端流程对不对 | 新功能完成后强制 |

> **铁律：错误越晚发现，修复代价越高**，要让每个错误尽可能在前面的环节暴露。测试计划与测试用例应按此排序组织，优先验证「前置、低成本」的环节。

---

## 三、hooks 让闭环必然发生

CLAUDE.md / AGENTS.md 是**软约束**（Agent 大概率遵守，但没有保证——95% 遵守，5% 漏网）。验证这种事「一次都不能漏」，所以闭环要用 **hooks** 挂载——hook 是代码，到点必然执行，不经过模型的脑子。

| 层 | hook 类型 | 作用 |
|---|---|---|
| 第一层 | `PostToolUse`（matcher: `Edit|Write`） | 每次编辑完文件自动 lint，报错回灌给模型（退出码 2 = 把 stderr 回灌，Agent 自己修） |
| 第二层 | 新功能完成后强制 build + e2e | 两个都绿才算「做完了」，不绿不许宣称完成 |

> 本 skill 测试时发现「项目缺 hooks / 缺强制验证」的，应在测试问题文档中作为 P1 记录（验收闭环不闭环 = 系统性问题），并建议在 CLAUDE.md 固定「改完代码必须跑 lint」、配置 PostToolUse hook。

## 四、checklist 定义「什么算合格」，工具只是执行器

typecheck 验类型、e2e 验流程、截图验视觉——每个工具只回答自己那个维度的「对不对」。但「这次产出合不合格」是**综合判断**，需要一份显式 checklist。典型条目（每个项目按需长出来）：

- 不要出现超过 500 行的模块，超了必须拆；
- 不要用 emoji 当图标，图标一律用项目 icon 组件；
- 不要新增重复的工具函数，写之前先搜现有代码；
- 不要吞错误的空 `catch`，要么处理要么往上抛；
- 新增接口必须有错误处理和参数校验；
- 涉及用户输入的地方必须考虑 XSS。

**关键：清单是长出来的，不用一次写全。** 起手写五六条最在意的，之后每次翻车往里沉淀一条（「上次 Agent 用 emoji 当图标被抓到，加一条」）。

> 本 skill 的「九条铁律」即测试侧 checklist 的起点；执行中发现新的系统性坑，应同步建议用户沉淀进项目 CLAUDE.md。

---

## 五、验收标准前置：把「做完了」变成可执行的定义

通用 checklist 是「每次交付都要执行」的标准；具体功能还有**只属于当前任务的验收标准**（导出文件包含哪些字段、空数据时页面显示什么、重复点击会不会两次下载），必须在每次派活时补齐。

**落地方式**：人给核心目标 + 最重要的几条验收标准，Agent 在动手前**根据需求与代码库自行补全**其余边界情况/异常路径/机器检查，生成一份任务级验收标准；实现完成后沿同一份标准自己跑、自己核对、失败自己打回。

> **验收越能被机器执行，Agent 自治的程度就越高。** 本 skill 的「零臆断」铁律（预期必须有来源）与此同源：预期/验收标准要么来自 PRD AC，要么来自「验收标准前置」生成的显式清单，两者都不允许凭空编。

---

## 六、UI 视觉层：代码闭环罩不住的盲区

typecheck 验类型、测试验逻辑，但「页面长得对不对」只有看到 UI 才能回答——z-index 遮挡、长文本溢出、暗色对比度塌掉，代码每一行都是「对」的，只有真实渲染那一帧是错的。

- 代码层闭环 + UI 视觉层闭环（给 Agent 装眼睛 + Midscene 回归测试），合起来才是完整验收体系；
- 视觉层的方法详见 `style-test-guide.md`（三层看 + 自然语言回归 + 精确阈值）。
