# 测试用例编写规范（Test Case Guide）

> 权威细则：功能用例怎么写、怎么做到「全状态覆盖」与「全点击覆盖」、异常分支怎么补。

---

## 一、用例设计总原则

1. **先计划后执行**：用例必须在执行前一次性生成（填充 `test-case-template.md`），执行中只回填结果，不临时造用例；
2. **预期有来源**：每条用例的「预期结果」必须来自 PRD 的 AC、原型、或后端接口定义，来源写进「关联 AC/页面」列；
3. **可追溯**：功能用例 → `AC-Mxx-nnn`；样式用例 → 原型页面；接口用例 → 后端接口路径；
4. **可判定**：预期要能明确判 Pass/Fail，禁用「大概」「差不多」等模糊预期。

## 二、全状态覆盖方法（功能用例核心）

### 2.1 状态从哪里来

- 从 PRD 各模块文档的 **Mermaid 状态机图** 提取每个业务对象的全量状态与流转边；
- 状态机图缺失时，从模块「场景操作步骤流」与「业务信息清单」反向归纳状态，并标注 `【设计假设】` 请用户确认。

### 2.2 逐状态用例的固定结构

| 状态 | 用例要点 |
|---|---|
| 展示 | 状态标签/文案/配色是否正确、与设计稿一致 |
| 可操作 | 该状态下允许的操作是否正确展示、可用 |
| 流转 | 触发操作后是否正确流转到下一状态、入口是否成对 |
| 终态 | 终态是否不可再流转、是否展示正确 |

### 2.3 覆盖自检清单

```
□ 已从 PRD 状态机提取全量状态列表
□ 每个状态至少 1 条用例（展示 + 操作 + 流转）
□ 每个状态流转边至少触发 1 次
□ 终态已验证不可再流转
□ 状态覆盖 = 100%
```

## 三、全点击覆盖方法（功能用例核心）

### 3.1 元素盘点清单

对每个页面盘点全部可交互元素，分类列出：

| 类别 | 元素示例 |
|---|---|
| 主操作按钮 | 提交 / 保存 / 删除 / 确认 |
| 次操作按钮 | 取消 / 重置 / 导出 / 刷新 |
| 图标按钮 | 编辑 / 删除 / 更多 / 收藏 / 关闭 |
| 链接 | 详情链接 / 面包屑 / 分页 / 页签 |
| 输入类 | 输入框 / 下拉 / 单选 / 复选 / 开关 / 日期选择 |
| 可点击区域 | 卡片 / 表格行 / 图片 / 头像 |

### 3.2 逐元素用例的固定结构

| 验证点 | 说明 |
|---|---|
| 有反应 | 点击后有视觉反馈（弹窗/跳转/状态变化/请求发出） |
| 反应对 | 反馈符合预期（与 PRD/原型一致） |
| 无报错 | 控制台无报错、页面无崩溃 |
| 无死链 | 跳转目标存在、无 404/空白页 |

### 3.3 覆盖自检清单

```
□ 已盘点每页全量可交互元素清单
□ 每个元素至少 1 条点击用例
□ 点击后的副作用（弹窗/跳转/请求）已验证
□ 无法点击的元素已标注原因（权限/前置状态）并登记风险
```

## 四、异常分支覆盖

每页/每模块至少补五类通用异常用例：

| 异常类 | 用例要点 |
|---|---|
| 空数据 | 无数据时展示空态，符合设计稿 |
| 超限极值 | 输入超长/超上限时是否正确提示 |
| 等待过久/中断 | 接口超时/失败时是否有错误提示与重试入口 |
| 重复操作 | 连续点击提交是否防重、不重复产生数据 |
| 无权使用 | 无权限时是否正确拦截或提示 |

> 本业务特有异常从 PRD「异常分支」章节补充。

---

## 五、用例优先级分配

| 优先级 | 分配标准 |
|---|---|
| P0 | 核心主流程、每个状态的主链路、页面主操作按钮 |
| P1 | 次操作按钮、图标按钮、主要页面三态、主要接口性能 |
| P2 | 次要样式、文案、非核心接口、体验优化点 |
