# 测试用例编写规范

## 一、总原则
1. 先计划后执行；执行中只回填结果。
2. 预期必须有来源（AC/原型/接口），写入关联列。
3. 可追溯：功能标 AC、样式标页面、性能标接口路径。
4. 可判定：禁「大概/差不多」。

## 二、全状态覆盖
- 状态源：PRD 模块 Mermaid 状态机（先读速查表定位）；缺失时从步骤流/信息清单归纳并标【设计假设】。
- 每状态用例覆盖：展示（标签/文案/配色）、可操作、流转、终态不可再流转。
- 自检：全量状态列表、每状态 ≥1 条、每条流转边触发、终态验证、覆盖 100%。

## 三、全点击覆盖
- 盘点全量可交互元素：主/次/图标按钮、链接、输入类、可点击区域。
- 每元素验证：有反应（弹窗/跳转/状态/请求）、反应对、无报错、无死链。
- 自检：元素清单、每元素 ≥1 条、副作用已验证、不可点已标原因并登记。

## 四、异常分支
每页/模块至少五类：空数据（空态）、超限极值（提示）、等待/中断（错误+重试）、重复操作（防重）、无权（拦截提示）；业务特有异常从 PRD 异常章补。

## 五、优先级与分层
P0 核心主流程/主链路/主按钮；P1 次操作/图标/主要三态/主要性能；P2 次要样式/文案/非核心接口。

### 冒烟集
- P0 冒烟集每次提交必绿，收敛为统一命令并挂 pre-commit/Husky。
- P1/P2 全量集按模块或发版前跑。
- 资源有限时优先刀刃（冒烟集快速反馈，CI 全量把关）。

### flaky 处理
- 失败自动重跑一次，两次红才真红。
- 十轮红绿摇摆自动标记；先判用例错还是页面坏，需人工介入。
