# Testing —— 项目测试 Skill

> **状态**：✅ 定稿
> **术语与决策基准**：[CONTEXT.md](CONTEXT.md)（术语表 + 决策日志 D-01~D-11）

## 一、这是什么

一个由 **高级测试专家** 人设驱动的标准流程 Skill：依据需求文档（PRD）与 UI 设计稿（原型），**本地启动并自动运行真实项目**做全流程测试，最终交付一份**分级、可复现、有证据**的测试问题文档。

**第一原则**：「全状态覆盖 + 全点击覆盖 + 样式问题必截图 + 慢接口必列出 + 问题必分级可复现。」

## 二、核心特性

1. **三线并行测试**：
   - **功能测试**：每个业务对象的**所有状态**走一遍 + 页面**所有可点击元素**点一遍 + 五类异常分支；
   - **样式测试**：用 **midscenejs** 做 AI 视觉断言，逐页验证布局/间距/配色/字号/三态，发现问题**立即截图**；有 UI 设计稿基准时**内嵌 `Fidelity-Review`** 做 UI 还原度检查（视觉还原 + 交互还原 + 超长文案专项），就地收轻量清单并入问题文档；
   - **接口性能测试**：监听所有接口耗时，**慢接口逐条列出**（路径 + 耗时 + 触发场景）。
2. **测试流程模板驱动**：先按 `assets/test-process-template.md` 生成测试计划，再按 `assets/test-case-template.md` 派生测试用例，最后按 `assets/bug-report-template.md` 汇总问题文档——**先计划后执行，不边测边想**。
3. **浏览器工具分层**：开工硬性预检 **Playwright → browser-use → 其他（如 agent-browser）**（全无即报错等安装，不工作）；功能遍历 + 慢接口监听优先 **Playwright**；样式视觉断言用 **midscenejs**（可选增强，按测试线组合）。
4. **问题分级可追溯**：P0 阻断 / P1 严重 / P2 一般；每条含复现步骤 + 证据；用例标注 `AC-Mxx-nnn`，缺陷反向标注用例号。

## 三、测试流水线全景

```
PRD + 原型 + 项目代码
        │
        ▼
[1] 输入解析 ──► [2] 环境准备(本地启动 + 浏览器工具硬性预检·缺失报错)
        │
        ▼
[3] 生成测试计划 + 测试用例（填充模板）
        │
        ▼
◉[4] Scope Gate（人工确认范围/用例/工具/阈值）
        │
        ▼
[5] 功能测试 ──► [6] 样式测试 ──► [7] 接口性能测试
（全状态+全点击）  （视觉断言+截图）  （慢接口识别）
        └────────────┬────────────┘
                     ▼
        [8] 汇总测试问题文档 ──► [9] 归档 .spec/测试/
```

## 五、快速上手

1. 触发方式：说「帮我测试一下这个项目」「跑一遍项目找 bug」「做 UI 走查」「排查接口慢」；
2. 提供：项目代码位置（目录 + git）+ 启动命令（缺失会问你）+ PRD/原型路径（缺失会退回问你要）；
3. 你将被问一次 Scope 确认（范围 / 用例数 / 工具方案 / 慢接口阈值），确认后自动执行；
4. 交付物：`测试问题文档.md`（分级缺陷清单，可直接交给 `Frontend-Dev`/`Backend-Dev` 返工）。
