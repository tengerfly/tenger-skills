# 测试流程模板（Test Process Template）

> 用途：填充本模板生成 `测试计划.md`。本模板只描述「怎么测」的**阶段骨架 + 门禁 + 每阶段输入/输出/动作**，不含具体用例步骤（用例见 `test-case-template.md`）。
> 每次测试启动时，把本模板复制进 `.spec/测试/测试计划.md` 并逐段填写。

## 四、各阶段动作明细

### 阶段 1：输入解析
- **读需求**：优先读 `.spec/PRD/VN/`（**先读 `PRD速查表.md` 建六大索引**；AC 清单用速查表 §六，断言细节按锚点回模块 §9）；缺失则读用户指定 PRD 路径/粘贴内容；
- **读视觉基准**：优先读 `.spec/设计稿/`（设计稿 HTML + design-system + README）；缺失回退 `.spec/原型/`；再缺读用户指定外部稿（Figma 导出图/截图/HTML）；
- **读代码**：确认项目目录与 git 地址（**用户未提供则必问**），读 `README.md` / `package.json` / 路由配置，梳理页面清单与启动命令；
- **提取测试面**：页面清单 + 每页的业务状态集合 + 可交互元素清单 + 接口清单（从后端 TDD/前端 api 目录提取）。

### 阶段 2：环境准备
- **本地启动**：按项目 README 安装依赖（`pnpm/npm install`）、起本地 dev server（`pnpm dev`）或构建后静态服务（`pnpm build` + `serve`）；确认能通过 `http://localhost:{{port}}` 访问；
- **浏览器工具检测**（见 `references/browser-guide.md`）：检测 Playwright → browser-use → 其他（硬依赖链见 `references/browser-guide.md` 与仓库根 `shared/browser-policy.md`）；midscenejs 为样式视觉断言的可选增强（缺失降级并明示），不在检测链；
- **样式测试环境（可选）**：若启用 midscenejs，安装 `@midscene/web` + 配置模型环境变量（见 `references/style-test-guide.md`）。

### 阶段 3：生成测试计划 + 测试用例
- 把本模板填充为 `测试计划.md`（上面一二三四章）；
- 依据 `assets/test-case-template.md` 生成 `测试用例.md`，覆盖三类：
  1. **功能用例**：每个页面 × 每条业务状态 × 每个可点击元素；
  2. **样式用例**：每个页面 × 三态（加载/空/错误）+ 关键视觉基线（布局/间距/配色/字号）；
  3. **接口性能用例**：每个接口 × 一次调用并记录耗时。

### 阶段 4：Scope 确认 Gate（强制暂停）
- 向用户呈现：测试范围清单 + 测试用例总数 + 浏览器工具方案 + 慢接口阈值；
- **等待用户确认「范围与方案无误」才放行**；有异议回到阶段 1/2 调整。

### 阶段 5：功能测试（全状态 + 全点击）
- **全状态覆盖**：对每个业务对象，按 PRD 状态机逐一构造前置数据并走一遍，记录每个状态的实际表现（见 `references/test-case-guide.md` §状态覆盖）；
- **全点击覆盖**：对每个页面，逐个点击所有可交互元素，验证「点了有反应、反应符合预期、无报错、无死链」（见 §点击覆盖）；
- **异常分支**：空数据、超限、重复操作、无权、接口报错五类异常至少各触发一次；
- 结果逐条回填 `测试用例.md` 的「实际结果」列。

### 阶段 6：样式测试（视觉断言 + 截图）
- 逐页对照 UI 设计稿做视觉断言（midscenejs `aiAssert` / `aiQuery`，或 Playwright `toHaveScreenshot` / browser-use 截图人工比对）；
- **发现样式问题 → 立即截图**，存入 `screenshots/` 并命名 `{{页面}}_{{问题简述}}_{{序号}}.png`；
- 三态（加载/空/错误）逐页验证并截图（见 `references/style-test-guide.md`）。

### 阶段 7：接口性能测试（慢接口识别）
- 用 Playwright `page.on('response')` + `response.timing()`（或 `performance.getEntriesByType('resource')`）监听所有接口耗时；
- 按阈值分类：慢/很慢/严重，逐条记录「接口路径 + 耗时 + 触发场景 + 截图/证据」（见 `references/api-perf-guide.md`）。

### 阶段 8：汇总生成测试问题文档
- 把三类缺陷合并进 `测试问题文档.md`（用 `assets/bug-report-template.md`），分级 P0/P1/P2；
- 每条缺陷必须：现象 + 复现步骤 + 期望/实际 + 严重级 + 截图（样式/性能必附）+ 关联用例号。

### 阶段 9：归档
- 全部落盘 `.spec/测试/`：`测试计划.md` + `测试用例.md` + `测试问题文档.md` + `接口性能清单.md` + `screenshots/`。

## 五、门禁（Gate）

| Gate | 位置 | 通过条件 |
|---|---|---|
| Scope Gate | 阶段 4 后 | 用户确认范围、用例数、工具方案、阈值 |
| 问题文档 Gate | 阶段 8 后 | 每个缺陷都有复现步骤 + 严重级 + 证据；样式/性能缺陷必有截图或耗时数据；P0 缺陷已明确标注 |
