# UI-UX-Review —— UI/UX 设计稿评审

> 定位：对 UI-UX-Design 产出的设计稿做独立第三方复审，兜底其内部门禁自查盲区。只查问题、找成因、给方向；不改设计稿 HTML 或任何对照源。

## 一、评审目标（四维）

1. **载体与结构零改动**：对照布局清单，独立页面、弹框、抽屉、区块、元素、跳转逐项一致（防漏）；无出处的区块/按钮/提示/装饰一律不得出现（防加戏）。结构不对 = 视觉阶段越权改布局，打回。
2. **文案与字段一致性**：对照 PRD/布局清单逐字比对标题、CTA、列名、标签、提示语；不得自行添加多余文案。
3. **视觉规范一致性**：对照 `.spec/设计稿/design-system.md`（权威源 `.superdesign/design-system.md`，缺归档副本时指明），所有视觉值（色值/字号/字重/间距/圆角/阴影/组件/图标）必须有 token 出处，无规范外值；反 AI 味 12 条目检（清单见 `references/visual-spec-consistency-checklist.md`）。
4. **视觉呈现与可交付质量**：真实渲染设计稿 HTML——规范是否落地、逐入口做结构级可点击性验证（真实 `<a href>` 或等价触发；像按钮却点不动 = 缺陷）、控制台报错/死链/遮挡/资源加载失败、关键缺陷截图。
   - 边界：不验真实业务逻辑/数据/弹框开合逻辑；可点击性只到「入口存在且可点、href 去向与站点地图一致」。

## 二、输入与输出

- **输入**：PRD（有速查表先建索引）、布局清单或设计任务清单、design-system 归档副本、设计稿工程（HTML + README）；缺任一方 → 停下提示。
- **输出** `.spec/设计评审/`：四份维度报告、`设计稿评审汇总报告.md`、`任务清单.md`（待确认→已确认→已修复/已忽略）、`screenshots/`（硬性）。

## 三、严重度

> P0/P1/P2 定义与处理口径见仓库根 `shared/anti-deadloop.md` §二；下表为本域典型示例。

| 级别 | 定义 | 处理 | 典型 |
|---|---|---|---|
| P0 | 结构错位、主流程入口不可点、视觉严重偏离规范、核心文案大面积冲突 | 阻断；修复并通过复核 | 布局规定的弹框无入口；跳转全死链；整页配色另起炉灶 |
| P1 | 局部结构偏差、文案逐字不符、规范局部未执行、单入口死元素、控制台报错 | 必须进任务清单，原则上全修 | 文案不同字；少一张统计卡；按钮无 href |
| P2 | 非关键润色、次要视觉建议、边缘渲染瑕疵 | 记录，由用户裁决 | 留白可斟酌；提示可精炼 |

## 四、六大铁律

1. **只审不改**：禁改设计稿 HTML、design-system、PRD、布局清单；唯一产物为 `.spec/设计评审/` 下文件。
2. **成因必写**：每条结合对照源与 HTML 剖析成因（漏读区块、token 被绕过、直编改坏 href、弹框只做静态视觉）；无法推导标「成因未明」，禁臆造。
3. **方向明确**：设计稿问题 → `UI-UX-Design`；布局清单与 PRD 冲突/漏载体 → `Prototype-Design`；PRD 自相矛盾 → `PRD-Design`；口径不一 → `双方协同`。
4. **浏览器工具硬前置**：本 skill 为硬依赖——检测顺序、两级行为与报错文案见仓库根 `shared/browser-policy.md`；任一可用即渲染截图 + 点击验证；全无 → 报错停止，不产出评审文档。
5. **单一事实源**：全量问题去重后只收口 `任务清单.md`，初始全部 `待确认`。
6. **第三方独立兜底**：不采信 UI-UX-Design 门禁的「✅ 已通过」；只认对照源 + 真实渲染独立复核。

## 五、评审流程（7 步）

1. **资产解析与浏览器预检**：读取 PRD、布局清单、design-system、设计稿工程；缺失即停。按铁律 4 预检并记录工具。
2. **建立映射基准**：提取 PRD 页面/文案/跳转、布局清单载体划分、design-system token 速查；产出 `PRD 功能点/布局载体 ↔ 设计稿页面（draftId 版本）` 矩阵。
3. **渲染走查 + 静态源码审查**：静态服务渲染逐页截图，异常处截入 screenshots；逐入口点击验证；静态读 HTML 结构/`<a>`/CSS token/脚本作证据。两条通道独立完成、最后合并互证；不参考生成过程，不轻信内部门禁。
4. **四维对照评审**：分别按 `references/layout-freeze-checklist.md`、`copywriting-consistency-checklist.md`、`visual-spec-consistency-checklist.md`、`rendered-quality-checklist.md` 逐条过筛（每份含查漏+查多）。
5. **四份维度报告**：按 `assets/dimension-review-template.md` 落盘四份报告。
6. **汇总**：按 `assets/summary-template.md` 合并去重、归纳跨页面共性问题（如整批 token 偏差）、统计 P0/P1/P2。
7. **任务清单 + 归档**：按 `assets/issue-list-template.md` 生成任务清单；每条自足可读（出处+现象+成因+方向）、附修复判据、状态 `待确认`、标注修改方；P0/P1 阻断、P2 由用户裁决；逐条确认（要改 → `已确认`；不改 → `已忽略` + 理由）；复核只验本轮清单，不无限新增；轮次上限 3，不收敛即停下交用户。

## 六、防评审死循环

三招（修复判据 / 分级冻结 / 轮次上限 3）与任务清单状态机的定义见仓库根 `shared/anti-deadloop.md`。反复不收敛且暴露方法论问题 → 按第七节上报 `issue/`，交 Skill-Optimizer。

## 七、运行问题埋点

收尾按 `Skill-Optimizer/references/instrumentation-guide.md` 自查上报 `issue/UI-UX-Review/<日期>/<序号>-<标题>.md`（来源=埋点；字段/等级/标签按其规范，模板 `Skill-Optimizer/assets/issue-template.md`；含 Superdesign/UI-UX-Design 侧）。不确定不记，不打断主流程。
