## 三、修改方操作指引（闭环规范）

1. **开工前**：
   - 读取本清单，筛选出 `已确认` 且 `建议修改方` 包含自己的任务条目；
   - 对照「修复判据」明确「修到什么表现算过」，避免改不干净；
2. **修改中**：
   - 按「修改建议方向」执行精准修复，避免引入新缺陷；
   - 设计稿修改遵循 UI-UX-Design 的迭代路由（branch / replace / 直编），不擅自在视觉阶段改布局结构；
3. **收尾回填**：
   - 将对应任务条目的 `状态` 改为 `已修复`；
   - 在 `修改/忽略说明` 栏写明：改动了哪个文件、哪段 HTML/样式/文案，以及具体修改说明。

---

## 四、复核与轮次规范

- 复核仅核对上一轮清单内 `已确认` 项是否按判据修复，不无限新增同级问题；
- P0/P1 未清零不放行；P2 不阻塞，由用户裁决是否本轮修复；
- 回退修复-复核轮次 > 3 仍不收敛 → 停下交用户裁决：接受现状 / 忽略该问题 / 转人工。
