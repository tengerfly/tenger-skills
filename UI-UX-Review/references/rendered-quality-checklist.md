# 视觉呈现与可交付质量检查清单（Rendered Quality & Clickability Checklist）

> 目标：这是设计稿评审与静态审查的**差异化价值**——把设计稿 HTML 真正渲染出来，核验「规范是否落到屏幕上、入口能不能点、有没有渲染缺陷」。前三维度若依赖本维度渲染才能判定的检查项，在本维度执行并交叉引用。
> 对照物：真实渲染结果 + 布局清单跳转关系 + design-system。
> **边界（重要）**：设计稿是视觉稿不是可运行产品。可点击性只验证到「结构级」——入口真实存在且可点、href 去向与站点地图一致；**不要求**真实业务跳转 URL、真实数据、弹框真实开合逻辑（那些是前端代码与测试阶段的事）。

---

## 一、渲染健康（页面能正常打开渲染）

- [ ] **页面可正常渲染**：每个 HTML 能打开且无白屏 / 关键区块渲染失败；
- [ ] **控制台零报错**：渲染无 JS 报错、无资源 404（图片/字体/iconify CDN 加载失败）；
- [ ] **样式完整加载**：Tailwind / 设计系统 CSS 正常注入，非裸 HTML 无样式；
- [ ] **资源可达**：所有图片/图标/字体为可达 URL（`https://` / `data:`），无 file:// / 相对路径坏引用；
- [ ] **无层级遮挡**：弹框/抽屉/下拉视觉区块无被遮挡、无错误置顶；遮罩层级正常（存在时）。

---

## 二、结构级可点击性验证（核心）

> 方法：对照布局清单的跳转关系/入口清单，逐入口在渲染页面上**实际点击**验证。

- [ ] **应跳转入口真实可点**：布局清单规定会跳转的入口（导航菜单、CTA 按钮、行操作、卡片/列表点击区）在渲染 HTML 中是真实可点击元素（`<a href>` 或等价触发元素），点击有反应；
- [ ] **死元素识别**：页面中「长得像按钮/链接但点击无任何反应」的元素（`<div>` 伪装按钮、无 href 的假链接、onclick 空实现）→ 记缺陷；
- [ ] **href 去向与站点地图一致**：点击后目标与布局清单跳转关系一致（`#hash` 占位 + 对应区块存在即可，不要求跨页真实打开）；
- [ ] **弹框 / 抽屉入口存在**：触发入口可点，宿主 HTML 内含对应视觉区块（不要求真实开合，能定位到视觉呈现即可）；
- [ ] **无死链**：所有 `<a href>` 非空、非 `href="#"`、无断链；
- [ ] **无「该点不能点 / 不该点能点」错位**：视觉上像按钮的静态展示元素若不应跳转（如纯展示 chip），无点击误导即可不算问题。

---

## 三、渲染与规范一致性（规范真正落到屏幕）

- [ ] **屏幕上视觉与 design-system 意图一致**：渲染出的配色/字体/间距/组件形态与 design-system 描述一致（防止「代码写了 token，屏幕显示却偏」的情况）；
- [ ] **布局在目标视口无错乱**：Web 在桌面视口、移动稿在移动视口渲染正常，无横向溢出、无区块挤压变形；
- [ ] **响应式断点（若布局清单要求）**：断点行为无致命错乱（可接受差异：视觉稿未精修响应式的次要瑕疵降 P2）；
- [ ] **hover/按压态（若设计稿实现了）**：已实现的交互态无明显错误（如 hover 变一个无关色）。

---

## 四、截图存证

- [ ] **关键缺陷截图**：渲染异常、死元素、层级遮挡、规范偏差等 P0/P1 问题逐条截屏，存 `.spec/设计评审/screenshots/`；
- [ ] **截图命名规范**：`ISSUE-[编号]-[页面名]-[问题简述].png`，报告内相对路径引用。

---

## 五、分级建议

| 情形 | 严重度 |
|---|---|
| 主流程入口无法点击 / 大面积白屏或报错 / 弹框无入口 | P0 |
| 单个入口是死元素 / 局部资源 404 / 单页控制台报错 / 遮挡影响辨识 | P1 |
| 次要渲染瑕疵（hover 小偏差、非关键资源慢）、可接受响应式差异 | P2 |

---

## 六、设计层可用性启发式（Nielsen 十项·主观体验交叉核对）

> 用法：对每个主页面**在渲染结果上**逐项扫「这个设计有没有违背」，把「总觉得哪里不对又说不上来」变成可指认的体验问题；发现项按严重度进问题清单（一般 P1/P2，阻碍完成核心任务判 P0）。它是对渲染/可点击性**客观检查**的主观体验补充，不是替代。

1. **系统状态可见性**：用户能看出当前处于什么状态、操作有没有被响应（选中态/进度/结果反馈是否明显）；
2. **系统与现实匹配**：图标、措辞、隐喻符合用户直觉与业务语言，不是模型发明的抽象表达；
3. **用户控制与自由**：误操作有出口（「取消/关闭/返回」可见），不会把用户困在某一步；
4. **一致性与标准**：同义操作/同层级组件在页面内与整站内形态一致（含按钮层级、图标语义、术语统一，可对照第②维文案）；
5. **错误预防**：高风险操作有防误设计（危险按钮不突出、删除需二次确认的视觉暗示）；
6. **识别优于回忆**：选项/状态直接可见，不要求用户记住上一步才知道下一步；
7. **灵活高效**：高频操作路径短、可达（桌面/移动视口下关键操作不藏）；
8. **美观简洁**：视觉层级清晰、无干扰性装饰，符合 register 语境（brand 敢表达 vs product 克制）；
9. **帮助用户识别诊断恢复错误**：出错界面有明确提示与出路（而非空错误）；
10. **帮助与文档（如页面有说明场景）**：需要解释的界面有就地帮助或清晰引导。

> 判据提示：启发式发现与布局清单/design-system 冲突时以「设计稿自身自洽 + 三源对照」裁决；无法客观指认的「感觉不对」不记问题，只作为给 UI-UX-Design 的可选打磨建议。
