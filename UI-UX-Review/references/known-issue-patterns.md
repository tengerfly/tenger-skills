# UI-UX-Review · 已知问题模式清单（评审方案例库）

> 定位：设计稿评审时**对照检查**的「已知问题模式」沉淀池——历史上出现过、且判断会再犯的一类问题。同类问题再次出现即判为问题。
> 写入方：⑦ 门禁闭环收尾的**沉淀判定**（P0 必录；P1/P2 判断有普遍性再录）；规则见仓库根 `shared/anti-deadloop.md` §五（方向 B · 检出力）。
> 边界：粒度 = **一类问题**（不是单点案例）；必须有可执行的「检出方法」，否则不予收录。

## 记录格式

| # | 模式 | 典型现象 | 检出方法 | 严重度 | 来源 | 日期 |
|---|---|---|---|---|---|---|
| 1 | {{一类问题的命名}} | {{出现时的表现}} | {{怎么查出来：看什么 / 比什么 / 跑什么}} | P0/P1 | {{门禁点 + 原问题出处}} | {{YYYY-MM-DD}} |

字段说明：

- **模式**：一类问题的抽象命名（如「组件局部另起配色、脱离 design-system token」），非单个 case。
- **典型现象**：该模式在设计稿里的可观察表现。
- **检出方法**：评审时如何判定命中（查哪个 token 出处、比对布局清单哪一项、点击哪个入口）——**这是本条的价值所在**。
- **来源**：哪个门禁点、哪次闭环、原问题出处（可回溯）。

## 使用方式

评审执行时在步骤 4（四维对照清单 `layout-freeze-checklist.md` / `copywriting-consistency-checklist.md` / `visual-spec-consistency-checklist.md` / `rendered-quality-checklist.md`）之后，逐条对照本清单过一遍；命中即按本 skill 域界判级入任务清单（结构零改动 / 文案一致 / 规范一致 / 渲染质量与可点击性）。
