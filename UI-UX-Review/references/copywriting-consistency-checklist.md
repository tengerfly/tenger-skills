# 文案与字段一致性检查清单（Copywriting & Field Consistency Checklist）

> 目标：设计稿界面文案与 PRD / 布局清单内容要素逐字一致，无杜撰、无错别字、无表意偏差；同时反查 PRD / 布局清单没要求的文案是否被擅自加进来（防加戏）。
> 对照物：PRD（速查表优先建索引） + 布局清单内容要素。

---

## 一、界面文案逐字对齐

### 1.1 标题与操作文案
- [ ] **页面 / 区块标题**：Header、卡片标题、弹框标题与 PRD 逐字一致（如 PRD 称「退款申请审核」，不得写成「退款详情」或「审核」）；
- [ ] **操作按钮 CTA**：按钮文案严格遵照 PRD 动词语义：「保存」vs「提交」vs「暂存」、「确认」vs「确定」、「通过」vs「驳回」；禁止笼统「OK / 确定」替代具体动作。

### 1.2 数据字段与表单项
- [ ] **字段名（Label）一致**：与 PRD 业务信息清单严格一致（PRD 为「统一社会信用代码」，不得改成「税号」）；
- [ ] **表格列名与顺序**：列名、列顺序与 PRD / 布局清单一致；
- [ ] **状态标签文案**：与 PRD 状态机枚举完全一致（「待复核」不得展示为「处理中」）；
- [ ] **占位符 / 输入提示**：体现 PRD 的格式规范要求，严禁 `input text here` / Lorem 类无意义占位；
- [ ] **Toast / 空态 / 引导文案**：与 PRD 一致或属 PRD 定义的交互反馈，不杜撰。

### 1.3 视觉稿特有：文字转图形与截断
- [ ] **按钮/标签文字未因视觉处理改变语义**：图标按钮有可读文字或 aria-label 表达 PRD 原动作（「查看」不得画个眼睛图标了事）；
- [ ] **超长字段的截断/换行策略**：未造成文案语义断裂（如「删除」「作废」这类危险词被截掉一半）。

---

## 二、真实数据与 Mock 内容

- [ ] **Mock 数据真实自洽**：表格/卡片占位数据符合真实业务场景，字段间逻辑自洽（创建时间不晚于更新时间、金额单位正确），严禁无语义字符 / 乱码 / 假人名占位；
- [ ] **数字单位 / 货币符号**：带正确单位后缀（元 / % / 个）。

---

## 三、冗余文案排查（防加戏）

### 3.1 无依据文案识别
- [ ] **无来源提示文案**：Toast / Banner / 引导 / 说明文案若 PRD 未定义且非必要交互反馈，记为冗余（典型：「操作成功」「温馨提示：请确认信息无误」）；
- [ ] **无依据 CTA**：PRD 未定义的按钮（「导出」「批量删除」「分享」），其文案本身即无出处，一并记问题；
- [ ] **与 PRD 语义冲突**：自加文案与 PRD 矛盾（PRD 无删除功能，设计稿却出现「删除」按钮）升级 P1/P0；
- [ ] **【设计假设】合规**：确需补充的文案若已标 `【设计假设】`，核查是否经用户确认；未标未确认的自加文案一律记问题。

### 3.2 分级建议
| 情形 | 严重度 |
|---|---|
| 核心字段/操作文案与 PRD 冲突、误导操作 | P0/P1 |
| 纯多余、无冲突的提示/引导文案 | P2 |
