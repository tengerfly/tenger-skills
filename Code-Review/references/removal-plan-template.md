# 删除候选与清理计划模板

> 用途：Code-Review「删除候选」专项（后端 M 组 / 前端 M 组）的输出模板。
> 落盘：独立列 `.spec/代码评审/删除候选与清理计划.md`，并在任务清单中引用（修改方 = Backend-Dev / Frontend-Dev）。
> 原则：**只判定与给计划，不代删**——改动归对应 Dev skill；「现在可安全删」与「需延后删」分列。

## 一、优先级

| 级别 | 含义 |
|---|---|
| P0 | 立即清理（安全风险 / 明显成本 / 阻塞其他工作） |
| P1 | 本轮迭代内清理 |
| P2 | 排入后续迭代 |

## 二、现在可安全删除

| 字段 | 内容 |
|---|---|
| 位置 | `path/to/file.ts:line` |
| 理由 | 为什么该删 |
| 证据 | 无引用（`rg` / `grep` 结果）/ 死分支 / 已下线功能 |
| 影响面 | 无 / 低（无活跃消费方） |
| 删除步骤 | ①删代码 ②删测试 ③删配置 / 依赖 |
| 验证 | 跑测试 + 无运行时错误 + 观察日志 |

## 三、需延后删除（须出计划）

| 字段 | 内容 |
|---|---|
| 位置 | `path/to/file.ts:line` |
| 为何延后 | 仍有活跃消费方 / 需迁移 / 需业务方确认 |
| 前置条件 | 开关关闭满 N 天 / 埋点显示 0 使用 |
| 破坏性变更 | 涉及的接口 / 契约变化 |
| 迁移步骤 | 消费方怎么改 |
| 时间与负责人 | 目标迭代 / 负责人 |
| 验证指标 | 错误率 / 调用量等确认安全的指标 |
| 回滚方案 | 出问题怎么恢复 |

## 四、删除前检查清单

- [ ] 全仓搜索所有引用（`rg` / `grep`）
- [ ] 检查动态 / 反射式引用（字符串拼函数名 / 配置驱动）
- [ ] 确认无外部消费方（对外 API / SDK / 文档）
- [ ] 开关埋点已复核（若适用）
- [ ] 测试已同步更新 / 删除
- [ ] 文档已同步
- [ ] 相关人已知会（共享代码）
