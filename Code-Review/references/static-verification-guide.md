# 静态验证命令与取证规程

> 用途：评审流水线步骤 2 的执行依据。用命令证伪"可编译 / 可测试 / 可 lint"。
> 原则：**能跑则跑，跑不了降级并明示「未取证」**；静态验证失败是 P0/P1 证据，验证不可执行只是"未取证"，**不是"通过"**。

## 一、验证范围（前后端分别跑）

| 目标 | 后端代码 | 前端代码 |
|------|---------|---------|
| 依赖可解析 | `pnpm install`（或 `npm install`） | 同左 |
| 类型 / 编译 | `pnpm build` 或 `tsc --noEmit` | 同左 |
| 测试可运行 | `pnpm test` | 同左 |
| 代码规范 | `pnpm lint`（+ `commitlint`） | `pnpm lint` + `stylelint` |

> 命令按仓库实际脚本名执行（`package.json` scripts），上表为通用名。

## 二、执行规程

1. **定位工程根目录**：后端代码目录、前端代码目录各自定位到含 `package.json` 的根；
2. **逐项跑**：install → build/tsc → test → lint，**前端与后端分开记录**，不混；
3. **记录结果**：每项记 `✅ 通过` / `❌ 失败（附关键报错）` / `⚠️ 未取证（原因）`；
4. **失败取证**：`tsc` / `build` / `test` / `lint` 报错时，摘取**首个关键错误**（文件:行 + 错误信息）作为 P0/P1 证据，不贴整屏日志；
5. **降级规则**：
   - 缺依赖 / 无网络安装失败 → 跳过 install 及后续，整块标注「未取证：依赖未安装」；
   - 无执行权限 / 命令被拦截 → 标注「未取证：未授权执行」；
   - 环境缺运行时（Node 版本不符等）→ 标注「未取证：环境不符」；
   - 以上任一情况**不阻塞评审**，转静态读码，报告注明"本项未经命令验证"。

## 三、取证记录模板（写入对应角色文档）

```markdown
### 静态验证结果

| 项目 | 后端 | 前端 | 结论 |
|------|------|------|------|
| install | ✅/❌/⚠️ | ✅/❌/⚠️ | |
| build / tsc | | | |
| test | | | |
| lint | | | |

> 失败关键报错：{{文件:行 + 错误信息}}
> 未取证项及原因：{{原因}}
```

## 四、边界约定

- **不做的验证**：端到端联调冒烟（实际起前后端服务 + HTTP 请求）——归测试流程，本 Skill 只做契约静态比对；
- **静态验证 ≠ 业务正确性验证**：`test` 全绿只说明"测试可运行"，不说明"业务逻辑正确"（业务逻辑正确性归测试流程评审）；
- **结果用途**：`build` / `tsc` 失败 → 至少 P0；`test` / `lint` 失败 → 至少 P1；全部未取证 → 报告显著位置声明"本次评审未做静态验证取证"。
