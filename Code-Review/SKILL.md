# 代码评审 Skill

> 只审不改；接口契约对不上 = 头号目标；问题定位到 `文件:行`，结论可追溯 AC/接口。
> 术语：TDD = 后端技术文档；FTDD = 前端技术文档；AC = PRD 验收标准编号（`AC-Mxx-nnn`）。

## 一、评审对象与输入基线

| 输入 | 角色 | 说明 |
|---|---|---|
| PRD（AC） | 需求基线 | 判断代码漏做/凭空 |
| 原型 HTML | 还原基线 | 前端页面结构还原度（结构基线 = 低保真原型，见 `shared/baseline-terms.md`） |
| 设计稿（可选） | 视觉基准 | 有则以 `.spec/设计稿/` 为准；无则视觉值从原型收敛 |
| TDD | 设计基线 | 后端表结构/接口/模块边界 + 契约源 |
| FTDD | 设计基线 | 前端页面/组件/fetch + 契约源 |
| 后端代码 + 前端代码 + `libs/shared` | 被审对象 | 实际落地工程 |

- 优先读 `.spec/` 已有产出：PRD（先读 `PRD速查表.md` 建索引）、原型、`.spec/TDD/VN/`、`.spec/FTDD/VN/`、代码工程目录；缺失回退到用户指定路径或粘贴内容。
- 代码与文档不同仓时：以 TDD「接口清单」+ FTDD「fetch 对接表」为契约中介做三方比对。

## 二、双评审视角 + 契约专项（立场隔离）

| 视角 | 标准 | 检查 | 不检查 |
|---|---|---|---|
| 后端代码评审 | 对齐 TDD 接口/表结构且内部一致 | 接口实现、数据模型、四层分层、微服务边界、异常/事务 | 前端页面/组件/交互 |
| 前端代码评审 | 对齐 FTDD fetch/原型且内部一致 | api 方法、hooks、组件抽离、还原度、三态 | 数据库、服务端实现 |
| 接口契约一致性 | 前后端接口与共享类型三方一致 | 路径/方法/入参个数与类型/出参字段/错误码/分页/枚举 | 业务逻辑正确性 |

契约命中项归因：前端调了后端没实现的接口 → 后端；后端字段前端没消费 → 前端；两端字段名不一致 → 双方。

## 三、评审重点与域界

**头号目标（P0）**：接口契约不一致，包括入参/出参个数、类型、字段名（`orderNo` vs `order_id`、驼峰 vs 下划线、同义词）、路径/方法、枚举/分页结构、共享类型被绕过各写一份。

**做**：契约一致、可运行性、架构合规、代码质量、安全与数据、六大闭环。

**不做**：业务逻辑正确性（是否算对、边界是否判对，归测试流程）。测试闭环只查「测试可运行 + 测试先行 + 标注 AC」，不评业务覆盖是否充分。

### 六大闭环（代码层）

| 闭环 | 含义 | 典型断点 |
|---|---|---|
| 需求 | 每条 AC 有代码承接 + 测试标注 AC | AC 漏实现；无来源实现；测试未标 AC |
| 流程 | 业务入口→出口代码贯通 | 只创建不查询；只走成功路径；事件无消费 |
| 状态 | 状态机初态/终态/合法流转 | 缺终态；无触发方；状态枚举两端各写 |
| 数据 | 字段产生→传输→消费一致 | 字段未消费/未定义；分页/枚举/时间格式不一致 |
| 异常 | 定义→抛出→捕获→反馈→可恢复 | 空 catch；错误码未分段；缺空/错/加载态；事务未回滚 |
| 测试 | 先行、可运行、标 AC | 先实现后补测试；测试跑不通；无 AC 编号 |

### 五大正确性

1. 可运行性：install → `tsc --noEmit`（或 build）→ test → lint（见 static-verification-guide）。
2. 架构合规：后端四层单向依赖/微服务边界；前端 pages→components→hooks→api、组件抽离。
3. 接口契约一致：路径/方法/入参/出参/错误码/分页/枚举/字段术语双向 + 共享类型单一源。
4. 代码质量：单一职责、无魔法值、注释讲 why + 传参必注、统一响应、配置外置、无密钥硬编码。
5. 安全与数据：入参校验、鉴权、SQL 注入/XSS、金额整数分、事务/幂等/并发。

## 四、评审流水线（8 步）

```
输入 → 解析 → 静态验证 → 双视角并行评审 → 契约专项 → 两份角色文档 → 汇总 → 任务清单 + 用户确认 → 归档
```

1. **输入解析**：定位后端/前端代码与 `libs/shared`、四类文档；抽取 AC 清单、TDD 接口清单、FTDD fetch 表、原型布局清单。
2. **静态验证（取证）**：前后端分别 `pnpm install → tsc --noEmit（或 build）→ test → lint`；跑不了 → 降级静态读码并在报告标「未取证（原因）」；只证伪可编译/可测试/可 lint，不做端到端冒烟。
3. **双视角并行评审**：后端按 `references/backend-checklist.md`、前端按 `references/frontend-checklist.md` 逐条执行；两视角独立产出断点清单，独立上下文（subagent/新会话）互不可见，不参考代码生成过程；条件允许可用不同模型交叉审查。
4. **契约专项**：按 `references/contract-checklist.md` 做前端 fetch ↔ 后端实现 ↔ 共享类型三方比对，逐接口核对；命中项按第二节归因。
5. **两份角色文档落盘**：按 `assets/role-review-template.md` 写 `后端代码评审.md` / `前端代码评审.md` 至 `.spec/代码评审/`；P0 按 `assets/patch-template.md` 附建议补丁（仅代码块，不落盘源码）。
6. **汇总**：按 `assets/summary-template.md` 合并去重，重点标「前后端契约错误」，按 P0/P1/P2 统计。
7. **任务清单 + 用户确认**：按 `assets/issue-list-template.md` 生成任务清单，状态 `待确认`，按归因填修改方（Backend-Dev / Frontend-Dev / 双方）；每条附修复判据；逐条请用户确认（要改 → `已确认`；不改 → `已忽略` + 理由）；P0/P1 阻断、P2 可留后续；复核只验本轮清单，不无限新增；轮次上限 3，不收敛即停止汇报；确认后交对应 Dev skill 修改并回填状态。
8. **归档**：角色评审 + 汇总 + 任务清单全部落盘 `.spec/代码评审/`。

> 防评审死循环三招与任务清单状态机的定义见仓库根 `shared/anti-deadloop.md`，本 skill 只保留上述流程参数，不重复定义。

## 五、静态验证规程（B 档）

- 目标：证伪可编译/可测试/可 lint，不证业务正确性。
- 前后端分别跑，结果分别记入对应角色文档。
- 跑不了 → 降级读码，标注「本项未取证（原因：{{原因}}）」；未取证 ≠ 通过。

## 六、严重度分级（只标注，不设门禁）

> P0/P1/P2 定义与处理口径见仓库根 `shared/anti-deadloop.md` §二；下表为本域典型示例。

| 级别 | 含义 | 典型 |
|---|---|---|
| P0 | 契约对不上无法联调；无法编译/启动；共享类型被绕过 | 入参个数不符；字段名/类型不一致；tsc 报错 |
| P1 | 契约字段命名不一致但类型兼容、错误码缺失、三态缺失、架构越层、测试跑不通 | 缺错误态/空态；跨层调用；test 失败 |
| P2 | 命名不统一、注释缺失/冗余、魔法值、非关键细节 | 中英混用；裸字符串散落 |

## 七、评审铁律

1. **只审不改**：不改源码；P0 补丁只进报告。改代码归 Backend-Dev / Frontend-Dev，经任务清单交接。
2. **定位到代码**：每条标文件/行/接口/字段，引用关键片段。
3. **零幻觉**：结论基于代码与四类文档；区分「缺失（该写没写）」与「越界（写了不该写的）」。
4. **视角隔离 + 独立上下文**：各视角独立评审、独立上下文，互不可见，不参考生成过程；契约归因到责任方。
5. **不设门禁**：只出问题清单，不判通过/不通过。
6. **不评业务逻辑**：业务正确性归测试流程。
7. **成因必写**：写清为何产生（如后端改字段未同步共享类型）；推不出标「成因未明」，禁臆造。

## 八、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 评审时改源码 | 只记问题，补丁进报告 |
| 两视角混写 | 分视角成文，汇总合并 |
| 漏审一端 | 后端/前端两份都要出 |
| 漏契约专项 | 步骤 4 逐接口三方比对 |
| 评业务逻辑 | 归测试流程 |
| 验证跑不了写「通过」 | 标「未取证」 |
| 无出处 | 定位到文件:行/接口/字段 |
| 越界当缺失 | 区分两类分别标注 |
| 无成因 | 补成因，可考才写 |
