# Code-Review —— 代码评审 Skill

> **状态**：✅ 定稿
> **定位**：只审不改（P0 附「建议补丁」，仅写在报告里、不落盘源码）。

## 一、这是什么

一个把 `Backend-Dev` 产出的**后端代码**与 `Frontend-Dev` 产出的**前端代码**，对照需求文档（PRD 的 AC）、原型、后端技术文档（TDD）、前端技术文档（FTDD），以 **后端代码评审 / 前端代码评审** 两个视角 + **接口契约一致性专项** 评审的 Skill。它不改代码，只找出"接口对不上、字段不一致、跑不起来、架构越界"的点，分视角记录，并汇总归档到 `.spec/代码评审/`。

**一句话原则**：审出问题，不改问题；**契约对不上 = 头号目标**；问题定位到 `文件:行`，结论可追溯到 AC / 接口。

## 二、核心设计

| 项 | 决定 |
|----|------|
| 名称 | `Code-Review` |
| 输入 | 后端代码 + 前端代码 + `libs/shared`，以及 PRD（AC）/ 原型 / TDD / FTDD 四类文档（优先读项目 `.spec/` 已有产出） |
| 输出 | 两份分视角评审文档 + 一份汇总报告 |
| 评审视角 | 后端代码评审 / 前端代码评审 / 接口契约一致性专项 |
| 评审重点 | **接口契约一致性（核心）** + 可运行性 + 架构合规 + 代码质量 + 安全数据 + 六大闭环结构 |
| 域界 | 只审不改；P0 附建议补丁（不落盘）；**业务逻辑正确性不评**（交后续测试流程） |
| 门禁 | 不设 Pass / Fail，只列问题清单 + 严重度（P0/P1/P2） |

## 三、评审重点与域界

### 头号目标（P0 优先）

前后端**接口契约对不上**：后端入参 3 个、前端只传 2 个；字段命名 / 类型 / **大小写 / 术语**不一致（前端 `A` 后端 `a`）；路径 / 方法不一致；枚举 / 分页结构不一致；共享类型被绕过、前后端各写一份。

### 做（结构性评审）

契约一致 · 可运行性 · 架构合规 · 代码质量 · 安全与数据 · 六大闭环结构。

### 不做（Out-of-Scope）

**业务逻辑正确性**——某条业务规则算得对不对、边界条件判得对不对，本 Skill 不评，交由后续测试流程。因此「测试闭环」只查**测试可运行 + 测试先行 + 标注 AC 编号**，不评「用例业务覆盖是否充分」。

## 四、评审维度

### 4.1 六大闭环（代码层定义）

| 闭环类型 | 代码层含义 | 典型断点 |
|---|---|---|
| 需求闭环 | 每条 AC 有代码承接 + 测试标注 AC 编号；每段代码可追溯 AC | AC 漏实现；实现无 AC 来源；测试未标 AC |
| 流程闭环 | 业务流程入口→出口在代码中贯通 | 只写创建不写查询；只写成功路径；事件 / 回调无人消费 |
| 状态闭环 | 状态机有初态 / 终态 / 合法流转，无死状态 | 缺终态；流转无触发方；状态枚举前后端各写一份 |
| 数据闭环 | 字段产生→传输→消费全链路一致 | 后端字段前端未消费；前端入参后端未定义；分页 / 枚举 / 时间格式不一致 |
| 异常闭环 | 异常有定义→抛出→捕获→反馈→可恢复 | 空 catch 吞异常；错误码未分段；前端缺空 / 错 / 加载态；事务未回滚 |
| 测试闭环 | 测试先行、可运行、标注 AC（不评业务覆盖） | 先实现后补测试；`pnpm test` 跑不通；用例无 AC 编号 |

### 4.2 五大正确性

| # | 维度 | 核查点 |
|---|---|---|
| 1 | 可运行性（静态验证） | install → `tsc --noEmit` → build → test → lint |
| 2 | 架构合规 | 后端四层单向依赖 / 微服务边界；前端分层 pages→components→hooks→api / 组件抽离铁律 |
| 3 | 接口契约一致（核心） | 路径 / 方法 / 入参个数与类型 / 出参字段 / 错误码 / 分页 / 枚举，双向 + 共享类型单一源 |
| 4 | 代码质量 | 单一职责、无魔法值、注释讲 why + 传参必注、统一响应、配置外置、无密钥硬编码 |
| 5 | 安全与数据 | 入参校验、鉴权、SQL 注入 / XSS、金额整数分、事务 / 幂等 / 并发 |

## 五、评审流水线

```
输入解析（代码 + 四类文档）──► 静态验证（install/tsc/build/Test/lint）──► 双视角并行评审
        ──► 接口契约一致性专项核查 ──► 两份角色文档落盘 ──► 汇总去重 ──► 生成任务清单 + 用户确认 ──► 归档到 .spec/代码评审/
```

1. **输入解析**：定位后端代码 / 前端代码 / `libs/shared` + PRD / 原型 / TDD / FTDD；识别 AC 编号与接口清单；
2. **静态验证**：按 `static-verification-guide.md` 分别对前后端跑命令取证；跑不了则降级为静态读码并明示「未取证」；
3. **双视角并行评审**：后端按 `backend-checklist.md`、前端按 `frontend-checklist.md` 逐条找断点；
4. **接口契约一致性专项**：按 `contract-checklist.md` 三方比对接口，命中归因到后端 / 前端 / 双方；
5. **两份角色文档**：`后端代码评审.md` / `前端代码评审.md`；
6. **汇总**：去重合并，标出「前后端契约错误」共性项，生成 `代码评审汇总报告.md`；
7. **生成任务清单 + 用户确认**：把问题逐条落进 `任务清单.md`（状态=待确认），按归因标好修改方，请用户逐条确认要改还是不改；
8. **归档**：全部落盘到 `.spec/代码评审/`，任务清单交对应 Dev skill 后续按清单修改。

## 七、严重度分级

| 严重度 | 含义 | 典型情形 |
|--------|------|---------|
| **P0 致命** | 接口契约对不上导致无法联调；代码无法编译 / 启动；共享类型被绕过各写一份 | 后端入参 3 个前端传 2 个；字段名 / 类型不一致；`tsc` 报错 |
| **P1 重要** | 契约字段命名不一致但类型兼容、错误码分段缺失、前端三态缺失、架构越层、测试跑不通 | 缺错误态 / 空态；跨层调用；`pnpm test` 失败 |
| **P2 建议** | 命名不统一、注释缺失 / 冗余、魔法值散落、非关键细节缺失 | 术语中英混用；裸字符串散落 |

> 本 Skill **不做通过 / 不通过的裁决**，只输出问题清单。是否修改、由谁修改，交给用户决策。
