# 超长文案 / 样式错乱专项指引（Overflow Probe Guide）

> 背景：设计稿通常用「理想短文案」排版，页面很好看；真实开发接入业务数据后，文案往往更长（标题/表格列/列表项/按钮/表单值/提示语/长链接/长数字等），导致实现页样式错乱。
> 专项使命：**用「真实业务文案 + 比真实更长的极端文案」替换实现页的动态文本位，截图验证样式是否崩坏**——设计稿好排版、实现页崩了 = 健壮性问题，必须记录并给出修改建议。
> 归属：本专项是「边界状态造条件」三类之一（秘籍 vc-06 第三关）——**长文案 / 暗色模式 / 窄屏**。暗色对比度与窄屏错位已在 `visual-checklist.md` §三（axe-core 对比度）与 §八（暗色/窄屏）覆盖，本指南专吃「长文案撑崩」这一支；三类都是「正常数据/默认视口下不触发，必须主动造条件才暴露」的健壮性问题。

---

## 一、识别动态文本位

先盘点实现页中所有**内容可变**的文本位（数据驱动文本，非写死的静态标签）：

| 文本位 | 典型风险 |
|---|---|
| 标题/卡片标题 | 两行/超长折行挤压布局 |
| 按钮（表格行操作/弹框按钮） | 文案变长按钮被撑大/换行 |
| 表格列 | 单元格文字溢出、列宽失真、表格横向撑破容器 |
| 列表项/卡片正文 | 折行遮挡、卡片高度跳动 |
| 表单值/下拉选中值 | 过长值挤出容器、遮挡其它字段 |
| 标签/tag/状态 | 多字标签折行、超出胶囊 |
| 提示语/校验文案 | 长提示覆盖遮挡 |
| 数字/金额/单号 | 无省略的长串横向溢出（尤其表格/卡片） |
| 面包屑/导航 | 长名称溢出截断异常 |

## 二、替换文案构造

每个文本位准备 **2 类输入**替换后截图：

1. **真实业务文案**：从 PRD（先读 `PRD速查表.md` 定位到业务信息清单）/ 接口 mock / 真实数据中取该字段能出现的最长样例；无真实来源时用贴近业务的合理长文案；
2. **极端长文案**（压力测试）：比真实更长——
   - 连续无空格长单词/长数字串（触发不折行横向溢出）：如 `XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX`；
   - 中文长句（触发纵向折行）：如「这是一个用于测试极端超长中文文案是否会撑破当前容器布局的说明性长句子……」；
   - 带标点/空格混合长文本；
   - 长 URL / 邮箱 / 单号。

> 构造文案时标注【设计假设】说明取法；替换范围与样例先经用户确认（Scope Gate），确认后统一执行。

## 三、判定标准（什么算问题）

| 现象 | 判定 | 说明 |
|---|---|---|
| 溢出容器（文字/内容超出卡片/单元格/按钮边界） | ❌ 问题 | 设计稿短文案不溢、实现页长文案溢 = 未做溢出防护 |
| 遮挡邻元素（长文本压到其它区块/按钮/文字上） | ❌ 问题（升级 P1/P0） | 遮挡破坏可读与可操作 |
| 布局被撑崩（表格被撑破、栅格错位、卡片高度异常、弹性布局变形） | ❌ 问题 | 长文案破坏整体布局 |
| 换行错乱（中英文混排断行难看、词被拆断） | ⚠️ 依严重度 | 影响观感属 P2；遮挡/崩版升级 |
| 截断无省略号（`overflow:hidden` 但无 `text-overflow:ellipsis`，文字被腰斩） | ❌ 问题 | 应以省略号/工具提示/换行策略承接 |
| 可接受（两行内自然折行、排版仍整齐、按钮可换行且不挤压） | ✅ 通过 | 记录「已验证」 |

## 四、修改建议方向（写进问题清单）

按具体现象给「怎么改」，常见套路：

- 单行截断 + 省略号：`white-space:nowrap; overflow:hidden; text-overflow:ellipsis`（表格列/标题/导航）；
- 允许折行但限行数：`-webkit-line-clamp`（多行省略，卡片标题/摘要）；
- 容器防撑破：`table-layout:fixed` + `min-width:0` + `max-width`（表格）；flex 子项加 `min-width:0` 防溢出（布局挤压根因）；
- 长值自适应：按钮 `min-width:0`、`word-break`/`overflow-wrap:break-word`（长单词/URL）；
- 溢出承接：长文案以 tooltip / title 属性 / 气泡承接完整内容；
- 栅格/列表项：卡片内容区定高 + 省略，或允许卡片高度随文案自适应（与设计稿意图对齐）；
- 数字/金额/单号：等宽字体 + 单元格省略 + 悬浮全文；
- 响应式：在用户指定断点视口下再验一轮（长文案在小屏是否溢出）。

## 五、截图要求

- 每个文本位的每次替换 **前后各截一张**（替换前=原始实现、替换后=长文案表现），存 `screenshots/`，命名 `<页面>_<文本位>_长文案_<序号>.png`；
- 问题项必须截到「崩坏现场」；对照设计稿同位置（若设计稿有对应长文案示例）并排截。

## 六、常见错误对照

| 错误 | 纠正 |
|---|---|
| 只测主文案不测表格列/按钮/标签 | 所有动态文本位都测，尤其表格列与行操作按钮 |
| 极端文案自己编得太假（无业务来源） | 真实来源优先；压力用例标【设计假设】并在 Scope Gate 确认 |
| 看到换行就报 P0 | 按判定表：自然折行可接受；溢出/遮挡/崩版才高判级 |
| 只报现象不给改法 | 每条必附修改建议方向（§四套路） |
| 截图只截不崩的 | 问题项必须截到崩坏现场；通过项记录「已验证」即可 |
