# 交互还原走查清单（Interaction Fidelity Checklist）

> 用途：核对「实现页」的交互是否与设计稿/交互预期一致——该点能点、点了有反应、方式和设计稿一样。
> 范围：**全量 + 普适项**（D-04）——设计稿驱动的交互（可点性/反馈/跳转）逐元素走查 + Tab/弹层抽屉/表单校验等普适 UI 交互核对。
> 边界：只到「交互是否还原、是否可用」，**不验业务逻辑正确性**（点了后端是否成功、状态流转对不对归 Code-Review / Testing）。
> 交互问题若截图无法完全表现，必须附「点击操作步骤」文字证据。

---

## 一、可点性与反馈（Clickability & Feedback）

### 1.1 逐可点元素走查（全量）
- [ ] 盘点页面全部可点元素：按钮（主/次/文字/图标）、链接、输入框、下拉/选择器、开关、单选/复选、Tab、分页、卡片/列表项、表格行操作、图标按钮、面包屑、导航项；
- [ ] 逐一点击验证：「点了有反应」——视觉反馈（按压态/hover/loading）、行为反馈（跳转/开合/请求/状态更新）至少居其一；
- [ ] **死元素识别**：长得像按钮/链接（有样式暗示可点）但点击无任何反应 → P0/P1 问题（记页面+元素+步骤）；
- [ ] **禁用态**：设计稿中置灰禁用的按钮在实现页是否真的 disabled（点了无响应且样式正确）；不该禁用的被误禁也记问题。

### 1.2 交互方式一致性
- [ ] **触发方式**：悬停展示 vs 点击展示、单击 vs 双击、长按菜单等是否与设计稿/交互预期一致；
- [ ] **跳转链路**：设计稿中可推断的跳转（导航→页面、按钮→弹框/详情、行操作→确认）在实现页是否一一成立，目标是否对；
- [ ] **hover/active/focus 态**：链接与按钮是否有 hover 反馈，按压态是否存在，键盘 focus 环是否可见（与设计稿交互规范一致）。

## 二、普适交互核对（通用项，D-04 扩围）

### 2.1 Tab / 分段控件
- [ ] Tab 切换是否即时生效、内容区随之更新；
- [ ] 当前 Tab 选中态样式是否区分（高亮/下划线/背景）且可点击切换。

### 2.2 弹框 / 抽屉 / 下拉
- [ ] 打开入口 → 弹出 → 关闭（X/遮罩/取消/Esc）闭环是否通；
- [ ] 重复点击是否重复弹出或层叠异常；
- [ ] 弹层内部滚动/长内容表现是否正常。

### 2.3 表单校验反馈
- [ ] 必填/格式校验：为空/错误时是否有红框/错误提示文案/聚焦到错误项；
- [ ] 提交中按钮是否 loading/防重复提交；
- [ ] 校验通过/失败后的反馈是否清晰。

### 2.4 其它通用交互
- [ ] 分页/加载更多是否可点且状态正确；
- [ ] 搜索/筛选交互是否即时可用；
- [ ] 折叠面板/展开更多可点且有状态变化；
- [ ] 开关/勾选是否切换生效。

## 三、实现页交互 vs 设计稿差异记录

| 差异类型 | 判定 | 典型表现 |
|---|---|---|
| 缺失（该有交互没有） | 设计稿可推断可点，实现页点了没反应 | 提交按钮无 loading 也无跳转；导航项点了不动 |
| 走样（有交互但方式变了） | 交互方式与设计稿不同 | 设计稿 hover 展示 tooltip，实现页需点击才出；本应跳转改成了弹窗 |
| 多余（加了设计稿没有的交互） | 实现页擅自增加可点行为 | 多出的导出按钮、非设计稿的右键菜单 |
| 状态错（反馈不对） | 点击有反应但反馈错误 | hover 样式无、选中态不区分、禁用态点了还能提交 |

---

## 四、输出要求

- 每个交互差异记一行到报告：`页面 | 元素（DOM 路径/文案） | 设计稿预期交互 | 实现页实际表现 | 操作步骤 | 严重度 | 修改建议`；
- 死元素/跳转断/交互方式变 = 至少 P1（核心入口 P0）；
- 截图能表现的交互态（hover 态、禁用态、弹层开合、选中态）必须配截图；动态行为附操作步骤；
- 交互是否属「设计稿要求」拿不准时：回 `.spec/原型/布局清单` 或 PRD（若含 `PRD速查表.md`，先读它定位对应模块再回原文）判定该不该有，仍拿不准标【设计假设】交用户裁决，不臆断。
