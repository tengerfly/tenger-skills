# 设计稿基准获取与映射细则

> **视觉应然铁律**：有设计稿时，视觉维度只以设计稿判定；低保真原型仅作结构/存在性对照，**不得**充当视觉基准（无设计稿才回退，属降级）。

## 一、通道判定
- A（视觉唯一应然）：项目存在 `.spec/设计稿/`（README + design-system.md + 各页 HTML）→ 优先；页面与实现路由对不上时停下确认。
- B：A 缺失 → 向用户要外部稿，逐页确认映射；无 token，只能目测，报告标注「通道 B」。
- C（**降级**）：A/B 均无 → 回退 `.spec/原型/`；低保真原型只有中性色 + 单一主色 + 基础字号，**视觉质量口径降级**，报告与结论须显式标注「基准=低保真原型（降级）」，且**不得据此判「视觉还原达标」**，只能判「结构一致 + 视觉无硬伤」。

## 二、映射矩阵
每页记录：实现 URL ↔ 设计稿文件/图、载体、视口、通道、token 对账结果（通道 A）。
- 弹框/抽屉独立稿映射到宿主入口所在页。
- 实现页无设计稿对应 → 标「无基准页」，只做健壮性与普适交互。

## 三、辅助基准
设计稿无法判定「该不该有」时：布局清单 → PRD（先读速查表定位再回原文）；仍不定标【设计假设】交用户。

## 四、启动实现页
本地 README/package.json 取启动命令；起不来 → 停下反馈，不硬评。

## 五、常见错误
有 A 用 B、拿原型当视觉基准判达标、通道 B 称 token 一致、映射对不上硬评、漏弹框/抽屉、无基准页硬评、通道 A 未做 token 对账即判视觉达标记 → 均纠正。
