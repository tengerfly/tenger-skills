# Fidelity-Review —— 页面还原度评审

> 定位：对前端实现页对照 UI 设计稿做逐页还原度评审：视觉一致、交互一致、内容健壮。只审不改：截图必证、成因必写、方向必给。不评业务逻辑正确性（归 Testing/Code-Review）。

## 一、三大评审面

1. **视觉还原**：逐页核对布局、层级、颜色、字号字重、间距、圆角阴影、图标图片、状态（含 10 大 UI 状态）、暗色模式、窄屏视口。设计稿为应然，实现页为实然。对比度等可数值定义项（WCAG ≥ 4.5:1）用 axe-core 判定，不靠观感。
2. **交互还原**：核对可点元素能否点击、反馈是否正确、交互方式与设计稿一致（按钮/跳转/Tab/弹层/表单校验等）。边界：只到「是否按设计稿还原、是否可用」；业务逻辑与状态流转归 Code-Review/Testing。
3. **内容健壮性（超长文案专项）**：真实/极端长文案下不得溢出容器、遮挡邻元素、换行错乱、挤压布局、异常截断；设计稿排版正常而实现页崩 = 问题。

## 二、双通道设计稿基准

| 通道 | 来源 | 说明 |
|---|---|---|
| A（优先） | `.spec/设计稿/` | 高保真 HTML + design-system.md，可直接渲染并机械比对 token |
| B（缺失） | 用户指定外部稿 | Figma 导出/PNG/README/静态导出；无 token 只能目测 + 刻度换算 |

通道 B 报告须标注「基准=外部设计稿，按像素目测比对」。存在 A 用 A；A 缺失或用户明确给外部稿用 B 并确认。

## 三、输入与输出

- **输入**：设计稿基准；前端实现页（本地工程 + 启动命令 + URL，或部署 URL）；可选 PRD/布局清单辅助判断交互该不该有（读速查表建索引后按锚点回原文）。
- **独立模式输出** `.spec/页面还原评审/`：`页面还原度评审报告.md`（视觉+交互+长文案分组，每条含截图引用与修改建议）、`任务清单.md`、`screenshots/`。
- **Testing 场景**：不另建任务清单，按 `assets/mini-issue-template.md` 就地出轻量清单交 Testing 汇总。

## 四、严重度

| 级别 | 定义 | 处理 | 典型 |
|---|---|---|---|
| P0 | 整体结构/布局严重不符、主视觉走样、核心入口点不动或跳错、长文案大面积崩坏 | 阻断交付，修复并通过复核 | 列表页实现成卡片流且主按钮消失；整页配色脱离设计稿；按钮点了无反应 |
| P1 | 局部偏差明显、单元素不可点、交互方式不同、状态缺失、长文案破坏局部布局 | 必须进任务清单，原则上全修 | 弹框确认按钮点不动；卡片标题两行排版崩开 |
| P2 | 像素级微差、次要细节、轻微换行可接受 | 记录，由用户裁决 | 间距差 2px；图标色偏一档 |

## 五、六大铁律

1. **只审不改**：禁改实现页代码、设计稿、design-system；唯一产出为报告/清单/截图（或 Testing 轻量清单）。
2. **截图必证**：一切样式/视觉/溢出问题必须配浏览器截图（实现页截图，必要时并排设计稿），命名 `<页面>_<问题>_<序号>.png`；交互问题截图表现不了则附操作步骤。
3. **成因必写**：剖析成因（默认样式未对照稿、色值未走 token、容器未加省略/min-width、flex 溢出、真实文案更长）；推不出标「成因未明」。
4. **方向明确**：给具体修改建议（改哪个文件/哪类样式/加什么约束）和建议修改方——实现问题 → `Frontend-Dev`；设计稿自身缺陷 → `UI-UX-Design`；源于 PRD 口径变化 → 双方协商。
5. **浏览器工具硬前置**：检测 Playwright → browser-use → 其他可驱动浏览器工具；任一可用即截图+点击验证；全无 → 报错停止，产出为空，安装后重跑。
6. **只对还原度负责**：不评业务逻辑、接口契约、代码架构；页面起不来即阻塞。

## 六、评审流程（7 步）

1. **输入解析与预检**：读 `.spec/设计稿/` 或向用户要外部稿并记录通道；确认实现页目录/启动命令/逐页 URL（未提供必问，不猜测）；按铁律 5 预检浏览器工具。
2. **页面清单 × 基准对齐**：按 `references/design-source-guide.md` 建逐页映射 `实现页 URL ↔ 设计稿页面`，记录响应式断点；通道 A 摘 token 速查，通道 B 记录目测基准；生成比对范围清单交用户确认后再继续。
3. **双开截图 + 点击验证**：相同视口并排截图；逐元素点击记录有反应/无反应/反应对不对。独立走查纪律：只认渲染产物与基准，不参考实现者说明或自查结论；任务重可开独立会话/换模型交叉复查。
4. **视觉 + 交互还原走查**：视觉按 `references/visual-checklist.md`（含设计稿有而实现没有、实现多出的双向比对）；交互按 `references/interaction-checklist.md`（可点性/反馈/方式一致/跳转链路）。

   逐区块断言（页面级截图无法暴露的局部偏离必须单列）：标题字号体系一致、空态唯一且间距正确、弹框/Tab 方向与设计稿一致、Loading 居中、设计稿状态稿（空/错/禁用/断网等）与实现页逐态一致、错误/选择状态在切换时重置、文案逐字取自设计稿、待确认等入口位于设计稿指定的 icon 位。
5. **超长文案专项**：按 `references/overflow-guide.md`，识别动态文本位，用真实业务文案 + 更极端长文案替换后截图判定；给出 min-width/ellipsis/flex 收缩等修改方向。
6. **分级输出报告**：按 `assets/review-report-template.md` 生成报告；每条含编号/页面/基准出处/现象+截图/期望 vs 实际/成因/严重度/建议/修改方；分组统计 P0/P1/P2。
7. **双模式收尾**：
   - 独立模式：按 `assets/issue-list-template.md` 生成任务清单（自足可读 + 修复判据 + 修改方 + P0/P1 阻断 + 逐条确认裁决；要改 → `已确认`，不改 → `已忽略` + 理由；复核只验本轮清单）。
   - Testing 场景：按 `assets/mini-issue-template.md` 就地出轻量清单，不生成任务清单。

## 七、防评审死循环

1. 每条问题附**修复判据**：修到什么表现算完成。
2. **分级冻结**：P0/P1 未清零不放行；复核只验本轮已确认项，不无限新增同级问题。
3. **轮次上限 3**：同批超 3 轮不收敛 → 停下交用户裁决。

## 八、与上下游关系

| Skill | 关系 |
|---|---|
| UI-UX-Design | 通道 A 基准生产方；设计稿缺陷回改 |
| Frontend-Dev | 被审对象 + 主要修改方；fidelity-guide 是开发自查，本 skill 是第三方还原验收 |
| UI-UX-Review | 评「设计稿 vs PRD/布局清单」，本 skill 评「实现页 vs 设计稿」，不重叠 |
| Code-Review | 评代码层契约/架构，本 skill 只评样式/交互还原 |
| Testing | Testing 可调用本 skill 做 UI 还原检查（Testing 场景） |

## 十、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 无截图报样式问题 | 铁律二必配截图 |
| 把业务逻辑当还原度问题 | 归 Testing |
| 与 UI-UX-Review/Code-Review 混跑 | 按第八节边界 |
| 页面起不来仍评审 | 步骤 1 阻塞并提示 |
| 通道 B 声称 token 一致 | 只能目测，报告标注基准 |
| 长文案崩当不是 bug | P1 必录必给改法 |
| 只报现象无成因/改法 | 铁律三四 |
| 浏览器不可用仍开工 | 硬性预检报错等安装 |
| 漏查实现页多出的内容 | 双向比对 |

## 十一、运行问题埋点

收尾自查，将方法论问题、用户否定/认可信号、可复现产物问题（含协作侧）上报 `issue/Fidelity-Review/<日期>/<序号>-<标题>.md`，字段/等级/标签遵循 `Skill-Optimizer/references/instrumentation-guide.md`，模板用 `Skill-Optimizer/assets/issue-template.md`。不确定不记，不打断主流程。
