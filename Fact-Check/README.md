# Fact-Check（AI 回答辨伪核验）

AI 给的方案/结论/知识点，采纳前先过一道证据关：拆成原子断言 → 按证据层级取证（能跑就跑最小实验 > 官方文档原文 > 源码 > 多独立源交叉，每条必做反证搜索）→ 四值判定 + 证据链 + 修正版说法。

解决两个真实痛点：

- **方案坑时间**：照 AI 给的错误方案干了半天才发现不对——先验承重断言（错了整个方案就塌的那几条）再动手
- **知识坑脑子**：把 AI 的错误知识点当真记住了——先核验再入脑

## 快速开始

```
AI 说「Node 18 起 fs.promises.readFile 能直接读目录」，对吗？
帮我核验这个方案：<粘贴 AI 回答>（我的环境：Node 16 / Vue 3.4）
这个知识点是真的吗：<粘贴内容>
```

## 产出

- 轻量（几条断言）：对话内直接给判定
- 正式（整篇方案/长回答）：`.spec/事实核验/YYYY-MM-DD-<主题>.md` —— TL;DR（承重断言结论表）+ 逐条判定明细 + 未证实清单与后续动作

## 判定四值

| 判定 | 含义 |
|---|---|
| ✅ 证实 | 有正证且反证搜索未命中 |
| ⚠️ 条件成立 | 特定版本/环境/前提下方成立（AI 最常见的错误形态：条件正确被说成普适） |
| ❌ 证伪 | 有明确反证，附修正版说法 |
| ❓ 未证实 | 证据不足（不知道/搜不到/跑不了），附原因 + 「下一步怎么验」；宁 ❓ 不猜，**绝不编证据** |

## 命根子

没有证据不下判定（宁 ❓ 不猜）· **查不到就诚实说未证实并说明原因，绝不编证据（红线）** · 能跑的先跑（实验是金标准）· 拆原子断言逐条验（防半真半假）· 每条必做反证搜索 · 版本对齐用户环境 · 「再问一遍 AI」不算验证

## 边界

- 已写代码的验收 → `Testing` / `auto-test`；代码评审 → `Code-Review`；方案文档（TDD/FTDD）评审 → `Tech-Review`
- 本 skill 只管「断言对不对」，不审文档结构、不重写完整方案
