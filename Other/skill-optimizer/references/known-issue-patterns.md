# Skill-Optimizer · 编排与交互层已知问题模式清单

> 定位：**流程次序、资源投入、用户交互**类错误模式的沉淀池——历史上出现过、且换个载体就会再犯的一类问题。同类问题再次出现即判为问题。
> 与另两处分工：代码类错误模式在仓库根 `../../../bug-patterns/`；各评审节点（方案/设计/代码/还原度）的文档检出模式在该 skill 自己的 `references/known-issue-patterns.md`。本文件只收**编排器与需求交互层**的模式——`workflow`/`prd-workflow` 是编排器，没有上游评审方，其运行问题的检出由本 skill 的体检与综合分析承担。
> 边界：粒度 = **一类问题**（不是单点案例）；必须有可执行的「检出方法」，否则不予收录。
> 写入方：`issue/` 池 P0 问题的 B 方向落点（规则见仓库根 `../../../issue/README.md` 出口②与 `../../../shared/anti-deadloop.md` §4 Bidirectional learning · 检出侧）。

## 使用方式

- **模式④七维体检**：对 `workflow` 及各领域编排 skill 体检时，逐条对照本清单核对现行规则是否仍可被绕过（判据存在 ≠ 判据可达 ≠ 判据不可换形规避）。
- **综合分析问题日志**：新条目按「表层载体 → 共性实质」归纳，同一实质的多种载体合并为一条，不另立同族条目。
- **试跑复盘**：`../../../docs/task-scope-regression.md` 场景跑偏时，先比对是否命中本清单某条，命中即按该条检出方法取证。
