# 取源 Playbook（步骤① 执行时加载）

四类输入的文本获取与结构摸底方法。产出统一为：**可定位的全文/分块文本 + 结构地图 + 锚点体系选型**。

## 锚点体系选型（先定，②③ 全程沿用）

| 输入类型 | 锚点格式 | 说明 |
|---|---|---|
| 书（有页码/章节） | `第N章·pNN` / `第N章·节M` | 用原书目录 + 抽取文本的页标 |
| 长文本/转写（无页码） | `B<块号>` | 按自然段/转写段建 B1、B2… 块索引（块 = 一个完整语义段，通常 200~500 字），块索引存 `原文索引.md` 或文本头部 |
| GitHub 仓库 | `文件路径:行号` | 与 Source-Reading 同标准；机制锚点指到实现/定义处 |
| 网页/文章 | `小节标题` + URL(+访问日期) | URL 只写核实过的 |
| 资料集 | `文件名#小节` | 多文件先列清单 |

## 1. 书（PDF/EPUB/TXT）

- **TXT/Markdown**：直接读；超长先按章节切 B 块。
- **EPUB**：本质是 zip——解包取 `*.xhtml/*.html` 逐章转文本（`unzip book.epub -d book_src/`，或 python `ebooklib`）；目录即章节结构。
- **PDF（文本型）**：优先 `pdftotext -layout book.pdf book.txt`（poppler）或 python `pypdf` 抽取；抽取后检查页标是否保留（页码是锚点，丢了就按章重定锚）。
- **工具缺失**：抽取工具/库不可用时不硬转、不自造文本，先声明缺失并请用户提供可读文本；仍不可得则按铁律停在第⓪步，写明文本可得性结论。
- **PDF（扫描型）**：无文本层 → **停下来**向用户要文本版或确认走 OCR（本机无 OCR 能力时明说，绝不瞎编）。文本可得性结论写「扫描版，未取得文本，流程中止于①」。
- **多文档/分卷**：每卷独立 B 块索引，锚点带卷号（`卷2·B17`）。

## 2. GitHub 仓库

1. 元信息：`api.github.com/repos/<owner>/<repo>`（免认证）拿默认分支/主语言/规模。
2. 浅克隆到**工作区外临时目录**（绝不克隆进在研项目）：`git clone --depth 1`；大仓 `--depth 1 --filter=blob:none` + sparse-checkout 排除 tests/fixtures——**详细参数直接复用 `source-reading/references/clone-playbook.md`（逻辑引用）**（含网络故障重试序列），此处不重复。
3. 摸底顺序：README → docs/ → 核心目录文件树 → 关键入口文件。本 skill 的精读重心是**文档、注释、设计讨论（ADR/README）、关键实现的思想**，不是逐行走读（那是 Source-Reading）。

## 3. 单篇资料（文章/讲义/网页）

- 可直接读的本地文件：直接读。
- URL：用会话内的网页抓取工具取全文；抓不到（登录墙/反爬）→ 要用户提供文本或存档，不硬编。取到后 B 块化。
- 视频/播客：**先要转写文本**（平台字幕、用户手头转写稿、whisper 类本地转写均可），拿到后才进②；没有转写 = 无文本，流程停在第⓪步。时间戳可作辅助锚点（`B17@00:34:12`）。

## 4. 资料集（多文件/多来源）

1. 先列**文件清单**（名称/来源/规模/彼此关系），呈在结构地图里。
2. 问用户或按相关性排序：核心 N 份精读，其余快扫；未精读的不冒充精读。
3. 锚点 `文件名#小节`；跨来源对比时标注来源各自条件（冲突并存铁律）。

## 大文件分块策略

- 切块优先沿**自然边界**（章节、小节、空行段落），不硬按字数切；单块 200~500 字为宜。
- 超出单次上下文的材料：分块逐段处理，**每处理完一块立即记候选精华 + 锚点**（不攒到最后凭印象补）。
- 需要「全文感」时先读目录 + 各章首尾段（结构通读预算 ≤ 全文 10%），再定向深读高密度区。
- 分块进度随时留痕（处理到 B 块号），中断可续，不重头再来。
