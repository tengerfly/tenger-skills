# 进化台账条目模板

> 每次进化执行一条，追加进 `../../../evolution/进化台账.md`。只增不改；回滚靠 git，台账负责「为什么改」可追溯。
>
> 台账是**进化是否有效**的唯一凭据：没有效果证据条目的改动只能算"发生过的修改"，不算优化。

```markdown
### E-<序号> <日期> <目标 skill>（档位：<保守|标准|激进>）
- 触发信号：<偏好条目编号 P-x | issue 编号 | 信号月志定位 | 用户点名>
- 诊断结论：<轨迹原文说明了什么问题，定位到哪一层（触发/主流程/护栏/references）>
- 改动清单：
  - <文件:行区> old → new（一句话）
- 能力审计：old 清单 N 项 / new 清单 N 项，<无丢失|差异说明>
- 语义定位：改前「<一句话定位>」= 改后「<一句话定位>」（未漂移）
- 确认记录：<用户逐条确认日期 | 激进档 P2 免确认（事后报告编号）>
- 效果证据：`<命令>` → <指标> before <值> → after <值>（只接受 `tsr report` / `tsr score` / `validate_core` / `detection.json` 的可复算输出，叙述不算证据）
- 判定：<已验证 | 未验证>——**缺 before/after 只能写「未验证」，不得写「已优化」**；锚（skillRevision·casesVersion·engine·model·scoringVersion）任一变了就不许跟旧值比
- 回归用例：<L2 case id 或 issue 编号 | 待补（待补则本条不得标闭环）>
- 回滚方式：git revert <commit>；偏好条目已标「已反哺」，回滚时同步改回
- 同步状态：源仓库 ✅ / 安装副本 ✅（哈希校验 <日期>）
```
