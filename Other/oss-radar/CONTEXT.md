# OSS-Radar CONTEXT（决策日志）

## D-01 2026-09-18 初版创建
- 需求：用户要一个 skill——定时采集 GitHub 上优秀开源 skill/项目情报，提炼优秀点反哺自有 skill 与在研项目，支持被 Agent 自动化定时调用；不只搜 skill，也搜在研项目相关的开源项目。
- 关键决策：
  1. 定位「链外外部输入口」，与 Skill-Optimizer（内部迭代）互补；沿用本仓「只审不改」纪律——反哺改动只进任务清单，skill 类经确认交 Skill-Optimizer 模式③执行。
  2. 双泳道（A skill / B 项目）覆盖「不只搜 skill」诉求；项目泳道提炼重点对齐 AI 组件库方向（组件/模式/测试基建/工程化）。
  3. 数据目录 `.spec/开源情报/`（对齐全仓 .spec 约定）；watchlist 承载配置+台账，保证增量采集与无人值守自含（不依赖会话上下文）。
  4. 无人值守模式三差异：不停（默认值继续）/不改（只出三类文件）/可读（TL;DR 30 秒扫完）。
  5. 采集通道：gh → api.github.com 免认证 → WebSearch/web_reader 降级链；单轮配额自守（search ≤5、深读 ≤6）防跑飞。
  6. 命名 OSS-Radar；根 README 登记「链外」区（表格 + 目录树）。
- 依据：用户 2026-09-18 需求。

## D-02 2026-09-19 技术方案前置调研场景接入
- 需求：用户拍板——写技术方案（TDD/FTDD）之前，先用 OSS-Radar 去 GitHub 找对应同域项目看怎么做，再落方案。
- 关键决策：
  1. description 触发词补「写技术方案前先调研同类项目（TDD/FTDD 前置调研）」。
  2. B 泳道（项目泳道）反哺对象补：本轮报告（`.spec/开源情报/`）可直接作 Workflow ⑧⑨ 技术方案的前置调研输入。
  3. 主链接入方式：Workflow ⑧⑨ 前置调研步（非编号节点），快速档/用户确认可跳过留痕；Backend/Frontend-Tech-Design 输入表与 S1 已接收该报告。
- 依据：用户 2026-09-19 拍板。

## D-03 2026-10-18 反哺对象路径可移植化
- 需求：体系要能在其他机器 / 宿主 / 项目直接使用，watchlist 模板不能写死本机绝对路径。
- 关键决策：`assets/watchlist-template.md` A 泳道「反哺对象路径」由本机绝对路径改为说明性写法（skill 源仓库根——`bug-patterns/`、`issue/`、`evolution/` 同一根目录；安装副本 / 其它机器运行时填该仓实际本地路径或用户指定维护目录，不写死个人绝对路径）；B 泳道保留 `<!-- 在研项目绝对路径 -->` 占位，运行时由用户填。
- 依据：用户 2026-10-18 要求可移植 / 换机可用。
