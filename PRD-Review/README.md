# PRD-Review —— PRD 检测 / 评审 Skill

> 状态：✅ 定稿
> 定位：只做评审，不改稿；问题定位原文，结论可追溯。

## 一、评审视角（互不越界）

| 角色 | 唯一标准 |
|---|---|
| 前端开发专家 | 能否照 PRD 独立写完前端 |
| 后端开发专家 | 能否照 PRD 独立完成服务端/数据设计 |
| 测试专家 | 能否照 PRD 直接写可执行测试 |

## 二、流程

```
解析 PRD → 三角色独立上下文并行评审 → 三份角色文档 → 汇总去重 → 任务清单+用户确认 → 归档
```

P0/P1 阻断、P2 可留；每条附出处/成因/建议方向与修复判据；复核只验本轮，轮次上限 3。清单交 PRD-Design 修复回填。

## 三、严重度

- P0：断头/无头/流程走不通/需求自相矛盾/缺失到无法开工。
- P1：模糊歧义/状态边界异常未定义/数据不一致/验收不可测。
- P2：表达/术语/非关键细节。

## 四、目录与产出

```
PRD-Review/
├── SKILL.md / README.md / CONTEXT.md
├── references/（frontend / backend / test-checklist）
├── assets/（role-review / summary / issue-list 模板）
└── .spec/需求评审/（三份角色评审 + 汇总 + 任务清单）
```

快速上手：给 PRD 路径或粘贴内容说「评审 PRD」，本 skill 自动跑三角色并归档。
