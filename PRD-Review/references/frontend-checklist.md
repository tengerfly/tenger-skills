# 前端开发专家评审检查清单

> **角色立场**：以「能否照着这份 PRD 独立完成前端页面开发」为唯一标准。
> **只关心**：页面/入口、功能区块、交互闭环、状态覆盖、流程断点。
> **不关心**：数据库、接口、服务端逻辑、测试用例。

---

## 检查维度总览

| 编号 | 维度 | 一句话判定 |
|------|------|-----------|
| FE-1 | 页面与入口完整性 | 每个页面都知道"从哪进、进来看什么" |
| FE-2 | 功能区块清晰度 | 每页有哪些功能区，都说清了 |
| FE-3 | 交互闭环 | 每个操作都有明确的系统反馈和去向 |
| FE-4 | 状态覆盖 | 空态 / 加载 / 成功 / 失败 / 边界都定义了 |
| FE-5 | 交互细节 | 触发 / 禁用 / 反馈能直接开发 |
| FE-6 | 流程断点 | 无断头链路、无无头链路 |
| FE-7 | 越界提醒 | PRD 不该写控件名 / 技术选型 |

---

## FE-1 页面与入口完整性

**检查方法**：把 PRD 里提到的每个页面 / 视图列出来，逐个追问「用户从哪个入口进入这个页面？进入后能看到什么？」

**判定为"不通畅"的情形**：
- 出现一个页面 / 视图，但全文找不到从哪个导航、列表、按钮、上游业务进入（**无头页面**）；
- 页面职责不清：一个页面混杂了多个无关功能区块，边界模糊；
- 缺少一级入口说明：应用打开后第一屏是什么、有几个一级入口，PRD 没说。

**示例（问题表述）**：
> `01_订单管理.md §2` 提到"订单详情页"，但全文未定义从哪个列表项 / 入口点击进入 → 前端无法确定页面跳转关系。

---

## FE-2 功能区块清晰度

**检查方法**：对每个页面，追问「这一页由哪些功能区组成（信息区 / 操作区 / 列表区 / 表单区等）？每个区块里有什么？」

**判定为"不通畅"的情形**：
- 只写了页面名称，没写页面上有什么功能区块；
- 关键区块缺失（如"列表页只有列表，没有筛选 / 搜索 / 新增入口"）；
- 区块间关系不清（哪个区块在什么条件下显示 / 隐藏）。

---

## FE-3 交互闭环（触发 → 反馈 → 流向）

**检查方法**：对每个用户操作，按「① 用户做什么 → ② 系统给什么反馈 → ③ 反馈之后流向哪里」三段追问，缺任何一段即不通畅。

**判定为"不通畅"的情形**：
- 用户点了某个操作，PRD 没写系统给什么反馈（**做了没反应**）；
- 给了反馈，但没写反馈之后用户 / 页面流向哪里（**反馈后不知道去哪**）；
- 反馈文案缺失或含糊（如"提示用户成功"，但没说提示什么内容、停留还是跳转）。

---

## FE-4 状态覆盖

**检查方法**：对每个页面 / 列表 / 交互，逐一排查五类状态是否都定义：空态、加载态、成功态、失败态、边界态（0 条 / 超长 / 超限 / 无权限）。

**判定为"不通畅"的情形**：
- 空态缺失：列表无数据时显示什么没说；
- 加载态缺失：提交后、等待期间页面什么状态没说；
- 失败态缺失：操作失败时用户看到什么、能做什么没说；
- 边界态缺失：数据超长、超出上限、无权限时的表现没说。

---

## FE-5 交互细节

**检查方法**：对每个可交互元素，追问「触发条件是什么？什么条件下可用 / 禁用？反馈文案具体是什么？」

**判定为"不通畅"的情形**：
- 按钮 / 输入 / 选择的触发条件、可用 / 禁用条件未定义；
- 反馈文案含糊（"友好提示""适当展示"），无法直接开发；
- 校验规则（如输入格式、长度）未定义到前端能落地。

---

## FE-6 流程断点（断头 / 无头）

**检查方法**：把每条交互链路从头走到尾，检查"入口"与"出口"是否成对出现。

**判定为"不通畅"的情形**：
- **断头链路**：某链路走着走着断了，没有走到一个可见的业务出口；
- **无头链路**：某状态 / 页面出现了，但没有定义从哪个上游进入；
- 流程死循环：A → B → A，无终态。

> 这是前端视角最严重的问题类型，通常判 **P0**。

---

## FE-7 越界提醒（PRD 写了不该写的）

**检查方法**：扫描 PRD 是否出现前端实现细节。注意：这是"PRD 越界"而非"PRD 缺失"，要单独标注为「越界」，不要和「缺失」混为一谈。

**判定为"越界"的情形**：
- 出现具体控件名：Toast / Modal / Radio / Loading 态 / 抽屉 / 浮窗 / 浮层 / 弹窗；
- 出现技术选型：框架名、库名、协议名；
- 出现 DOM / CSS 选择器、布局实现细节。

> 越界项标注为「建议移除 / 改写为业务表述」，严重度通常 **P2**（不阻塞开发，但破坏 PRD 纯净性）。
