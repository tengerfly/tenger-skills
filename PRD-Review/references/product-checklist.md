# 产品专家总审检查清单

> 定位：**总审层 + 调度者**，不与前端 / 后端 / 测试平级。输入 = PRD 原文 + 三份角色评审。
> 标准：需求在**业务语义层**是否立得住、说得通、叫得统一、写得准。
> 只关心下表业务维度；不关心技术实现、数据建模细节、测试用例设计（归对应角色）。
> 术语与文案的**正确性**由本角色**唯一认领**（含调度时从 FE / BE 归并的同类问题）；FE / BE / TE 只判「有无 / 是否可开发 / 是否可测」，不判写法对错。

## 执行顺序

1. 先读三份角色评审，记下已命中区域与三角色均未覆盖的章节；
2. 再通读 PRD 原文，按本表独立复核（不被三角色结论带偏，也不刻意回避）；
3. 输出 = 自身发现（PM-xx）+ **调度结论**；三角色已编号的问题**标原编号 + 命中角色**，调度后不重复编号。

## 一、核心必查（每次评审全部执行）

| # | 维度 | 不通畅情形 |
|---|---|---|
| PM-1 | 目标与价值闭环 | 背景 / 问题定义不清；目标无可衡量指标；**无源需求**（无目标承接、无背景支撑 = 加戏）；需求与目标不匹配；成功指标上线后无法观测 |
| PM-2 | 业务逻辑闭环 | 背景→目标→需求→验收链路对不上；角色 / 场景缺失；主流程缺异常或逆向分支；孤儿需求（无验收）或孤儿验收（无需求） |
| PM-3 | 业务规则完整性 | 计算 / 判定规则缺失；生效条件、有效期、适用范围未定义；多规则并存时**冲突仲裁**未定（谁优先）；开关、灰度、可配置项是否需支持未说明 |
| PM-4 | 术语正确性 | 同义不同名；同名不同义；新概念未在术语表注册；跨模块 / 跨章节叫法不一致；中英混用无对照 |
| PM-5 | 文案正确性 | 错别字 / 病句 / 主语缺失；表述歧义（可推出两种规则）；面向用户的提示文案缺失或含糊；同一动作在不同章节描述不一致（**不审视觉与排版**） |
| PM-6 | 一致性与矛盾 | 需求内部自相矛盾；跨模块规则冲突；与既有产品 / 历史版本冲突且未说明变更点；编号与交叉引用对不上 |

## 二、扩展档（命中触发条件才查）

| # | 维度 | 触发条件 | 不通畅情形 |
|---|---|---|---|
| PM-7 | 异常与业务兜底 | 涉及资金 / 交易、审核审批、第三方对接、不可逆操作、存量数据处理之一 | 业务失败后流程无出路；无人工介入 / 客服路径；无补偿或纠偏机制；无降级方案（技术侧异常由 BE-4 覆盖，本条只管业务层兜底） |

- 未命中触发条件可不查，须在 `产品评审.md` §3 逐维度记录中标注「不适用（未触发）」，不得静默跳过。

## 三、调度三角色问题（总审必做）

| 动作 | 做什么 | 落点 |
|---|---|---|
| 归并去重 | 同一问题多角色命中 → 合并为一条，标命中角色（≥2 角色 = 系统性缺陷） | 合并条目 + 原编号 |
| 定级校准 | 同类问题三角色定级不一致 → 按仓库根 `shared/anti-deadloop.md` §二 统一口径并说明理由 | 校准后级别 |
| 冲突裁决 | 结论互斥（一说缺失、一说已定义）→ 回原文核对后收敛，给建议方向 | 裁决结论 |
| 归属指派 | 纯术语 / 文案类收归本角色 PM-4 / PM-5；技术类退回对应角色 | 改编号后的归属 |
| 补漏扫描 | 三角色均未覆盖的章节 → 复核是否存在明显缺口 | 补查发现 |

- 调度结果在 `产品评审.md` §4「调度处理记录」中**逐条列出**：原编号 / 命中角色 / 调度动作 / 结果；不静默合并、不原样照抄。

## 四、术语判定基准（PM-4 专用）

1. PRD 内术语表 / 词汇表 → 第一权威；
2. 无术语表 → 以 PRD 内首次定义处为准；
3. 仍无定义 → 记「建议补充术语表」，**不判错**；
4. 不引入 PRD 之外的术语标准，不臆造「正确叫法」。

## 五、输出要求

- 问题清单**逐条直接列出**，每条自足可读（含原文引用），不藏在段落里；
- 每条必给**修改方向**：改哪个概念 / 哪句话、往哪改；只给方向，不代写 PRD；
- 成因可考才写，推不出标「成因未明」。
