# PRD 检测 / 评审 Skill

> 只审不改。问题定位到原文，结论可追溯。

## 一、三专家角色（评审立场隔离）

| 角色 | 立场（唯一标准） | 检查 | 不检查 |
|---|---|---|---|
| 前端开发专家 | 能否照 PRD 独立写完前端 | 页面/入口、功能区块、交互闭环、状态覆盖、流程断点 | 数据库、接口、服务端逻辑 |
| 后端开发专家 | 能否照 PRD 独立完成服务端与数据设计 | 业务对象、数据规则、状态机闭环、异常边界、数据一致性 | 控件、视觉、测试用例 |
| 测试专家 | 能否照 PRD 直接写可执行测试 | 验收可测性、覆盖完整性、可追溯性、歧义 | 实现方式、页面布局 |

各角色检查清单见 `references/`，逐条执行，不得凭感觉跳过。

## 二、适用范围

- 适用：已写好的 PRD（文件路径或粘贴内容）三方会审。
- 不适用：写需求（PRD-Design）；改需求（只审不改）；竞品分析、技术方案等非 PRD 内容。

## 三、评审流水线

```
输入 → 解析 PRD → 三角色并行评审 → 三份角色评审落盘 → 汇总去重 → 任务清单 + 用户确认 → 归档
```

### 步骤 1：解析 PRD
- 确认输入来源（文件路径 / 粘贴内容）。
- 若含 `PRD速查表.md`，先读建结构地图（模块/页面/AC 定位），仍须逐节通读原文。
- 识别需求背景、模块划分、各模块流程/状态/验收标准。
- 记录评审基线：文档清单、模块清单、章节覆盖。

### 步骤 2：三角色并行评审
- 前端按 `references/frontend-checklist.md`、后端按 `references/backend-checklist.md`、测试按 `references/test-checklist.md` 逐条评审。
- 三角色在**独立上下文**（subagent / 新会话）中评审，互不可见结论；不参考 PRD 生成过程，只认成品原文。条件允许时可用不同模型交叉审查。

### 步骤 3：三份角色评审落盘
按 `assets/role-review-template.md` 分别写 `前端评审.md` / `后端评审.md` / `测试评审.md`，落盘 `.spec/需求评审/`。

### 步骤 4：汇总
按 `assets/summary-template.md` 生成 `评审汇总报告.md`：
- 合并三份清单去重；同一问题多角色命中则合并并标命中角色；
- 标共性问题（多角色同时发现 = 系统性缺陷）；按 P0/P1/P2 统计。

### 步骤 5：任务清单 + 用户确认
按 `assets/issue-list-template.md` 生成 `.spec/需求评审/任务清单.md`：
- 汇总问题逐条落清单，状态先填 `待确认`；
- 每条附**修复判据**：修到什么表现算修复完成；
- 逐条向用户确认：要改 → `已确认`；不改 → `已忽略` + 理由；
- P0/P1 阻断（未清零不放行）；P2 优化项（不阻塞，可留后续）；
- 复核只验本轮已确认清单，不无限新增同级问题；新发现降 P2 或经同意进下一轮；
- 轮次上限 3：仍有 P0/P1 未修即停止，向用户汇报阻塞；
- 确认后的任务清单交 `PRD-Design` 修改并回填状态。

### 步骤 6：归档
角色评审 + 汇总 + 任务清单全部落盘 `.spec/需求评审/` 后交付。

## 四、严重度分级（只标注，不设门禁）

| 级别 | 含义 | 典型 |
|---|---|---|
| P0 致命 | 逻辑断头/无头、流程走不通、需求自相矛盾、缺失到无法开工 | 流程只有入口没有出口；核心对象无状态定义 |
| P1 重要 | 描述模糊歧义、状态/边界/异常未定义、数据不一致、验收不可测 | 「友好提示」「尽量快」；跨模块命名冲突 |
| P2 建议 | 表达可优化、术语不统一、非关键细节缺失 | 中英混用；章节序号不连续 |

## 五、评审铁律

1. **只审不改**：只指出哪里不通、为什么不通、建议往哪补；不替用户改写 PRD。修改由 `PRD-Design` 经任务清单交接。
2. **定位到原文**：每条问题标出处（文件/章节/需求/原句），可追溯。
3. **零幻觉**：不编造 PRD 之外的问题；原文缺失的信息区分「PRD 缺失（该写没写）」与「超出 PRD 范畴（不该写，不是问题）」。
4. **视角隔离 + 独立上下文**：三角色各审各的，不交叉、不代劳；独立上下文评审，不参考生成过程。
5. **不设门禁**：只出问题清单，不判 PRD 通过/不通过；是否修改由用户决策。
6. **成因必写**：每条写明成因（如状态机无终态、跨模块未注册、步骤流未到出口）；推不出标「成因未明」，禁臆造。

## 六、常见错误对照表

| 常见错误 | 纠正方式 |
|---|---|
| 评审时改写 PRD | 只记问题，给建议方向，不动原文 |
| 三角色结论混写 | 分角色成文，汇总再合并 |
| 问题无出处、只说整体感觉 | 定位到文件/章节/原句 |
| 把越界内容当缺失 | 区分「缺失」与「越界」，分别标注 |
| 结论笼统 | 写清为什么不通 + 建议方向 |
| 只列现象无成因 | 补成因，可考才写、不臆造 |

收尾自查，将方法论问题、用户否定/认可信号、可复现产物问题上报告 `issue/<skill>/<日期>/<序号>-<标题>.md`，字段/等级/标签遵循 `Skill-Optimizer/references/instrumentation-guide.md`，模板用 `Skill-Optimizer/assets/issue-template.md`。不确定不记，不打断主流程。
