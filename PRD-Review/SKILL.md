# PRD 检测 / 评审 Skill

> 只审不改。问题定位到原文，结论可追溯。

## 一、评审角色与层级（评审立场隔离）

| 层级 | 角色 | 立场（唯一标准） | 检查 | 不检查 |
|---|---|---|---|---|
| 一审 | 前端开发专家 | 能否照 PRD 独立写完前端 | 页面/入口、功能区块、交互闭环、状态覆盖、流程断点 | 数据库、接口、服务端逻辑、文案写法 |
| 一审 | 后端开发专家 | 能否照 PRD 独立完成服务端与数据设计 | 业务对象、数据规则、状态机闭环、异常边界、数据口径一致性 | 控件、视觉、测试用例、命名术语 |
| 一审 | 测试专家 | 能否照 PRD 直接写可执行测试 | 验收可测性、覆盖完整性、可追溯性、可量化性 | 实现方式、页面布局、文案表述 |
| 总审 | 产品专家（**兼调度者**） | 需求在**业务语义层**是否立得住、说得通、叫得统一、写得准 | 审查：目标与价值闭环、业务逻辑闭环、业务规则完整性、术语、文案、一致性与矛盾（+ 异常与业务兜底，按需）；调度：归并、定级校准、冲突裁决、归属指派、补漏 | 技术实现、数据建模细节、测试用例设计 |

- 一审三角色**并行且互不可见**；产品专家为**总审层 + 调度者**，在三角色完成后启动，输入 = PRD 原文 + 三份角色评审。
- **术语与文案的「正确性」由产品专家唯一认领**（含调度时从 FE / BE 归并的同类问题）；FE / BE / TE 只从自身视角判「有无 / 是否可开发 / 是否可测」，**不判写法对错**（口径见 `references/product-checklist.md`）。

各角色检查清单见 `references/`，逐条执行，不得凭感觉跳过。

## 二、适用范围

- 适用：已写好的 PRD（文件路径或粘贴内容），三角色会审 + 产品专家总审。
- 不适用：写需求（PRD-Design）；改需求（只审不改）；竞品分析、技术方案等非 PRD 内容。

## 三、评审流水线

```
输入 → 解析 PRD → 三角色并行评审 → 三份角色评审落盘 → 产品专家总审（审查 + 调度）→ 汇总去重 → 任务清单 + 用户确认 → 归档
```

### 步骤 1：解析 PRD
- 确认输入来源（文件路径 / 粘贴内容）。
- 若含 `PRD速查表.md`，先读建结构地图（模块/页面/AC 定位），仍须逐节通读原文。
- 识别需求背景、模块划分、各模块流程/状态/验收标准。
- 记录评审基线：文档清单、模块清单、章节覆盖。

### 步骤 2：三角色并行评审
- 前端按 `references/frontend-checklist.md`、后端按 `references/backend-checklist.md`、测试按 `references/test-checklist.md` 逐条评审。
- 三角色在**独立上下文**（subagent / 新会话）中评审，互不可见结论；不参考 PRD 生成过程，只认成品原文。条件允许时可用不同模型交叉审查。

### 步骤 3：三份角色评审落盘
按 `assets/role-review-template.md` 分别写 `前端评审.md` / `后端评审.md` / `测试评审.md`，落盘 `.spec/需求评审/`。
- 问题**逐条直接列出**（含原文引用），每条自足可读，不藏在段落里。

### 步骤 4：产品专家总审（总审层 + 调度者）
- 按 `references/product-checklist.md` 执行：先读三份角色评审，记下命中区域与三角色均未覆盖的章节；再通读 PRD 原文独立复核。
- 输出 `产品评审.md`（同 `assets/role-review-template.md`，角色填「产品专家」）：
  - **核心必查**（每次全查）：PM-1 目标与价值闭环 / PM-2 业务逻辑闭环 / PM-3 业务规则完整性 / PM-4 术语 / PM-5 文案 / PM-6 一致性与矛盾；
  - **扩展档**（命中才查）：PM-7 异常与业务兜底，触发条件 = 涉及资金交易 / 审核审批 / 第三方对接 / 不可逆操作 / 存量数据之一；未触发在 `产品评审.md` §3 标「不适用（未触发）」；
  - **调度三角色问题**（总审必做）：① **归并去重**——同一问题多角色命中则合并，标命中角色；② **定级校准**——同类问题三角色定级不一致则统一口径；③ **冲突裁决**——结论互斥时收敛并给建议方向；④ **归属指派**——纯术语 / 文案类收归本角色 PM-4 / PM-5，技术类退回对应角色；⑤ **补漏扫描**——三角色均未覆盖的章节复核缺口。
- 术语判定基准：PRD 内术语表 → PRD 内首次定义处 → 记「建议补充术语表」不判错；不引入 PRD 之外的术语标准。
- 三角色已编号的问题标**原编号 + 命中角色**，调度后不重复编号；调度动作与结果写入 `产品评审.md` §4 调度处理记录。
- 每条问题必给**修改方向**（改哪个概念 / 哪句话、往哪改），只给方向不代写 PRD。

### 步骤 5：汇总
按 `assets/summary-template.md` 生成 `评审汇总报告.md`：
- 以 `产品评审.md` 的调度结果为准合并四份清单；已归并的不重复计入，定级以校准后为准；
- 标共性问题（多角色同时发现 = 系统性缺陷）与三角色结论冲突项（冲突以产品专家裁决为准）；按 P0/P1/P2 统计。

### 步骤 6：任务清单 + 用户确认
按 `assets/issue-list-template.md` 生成 `.spec/需求评审/任务清单.md`：
- 汇总问题逐条落清单，状态先填 `待确认`；
- 每条附**修复判据**：修到什么表现算修复完成；
- 逐条向用户确认：要改 → `已确认`；不改 → `已忽略` + 理由；
- P0/P1 阻断（未清零则评审-修复循环不退出，不进入收尾归档；节点放行由编排侧判定）；P2 不阻塞，可留后续；
- 复核只验本轮已确认清单，不无限新增同级问题；新发现降 P2 或经同意进下一轮；
- 轮次上限 3：仍有 P0/P1 未修即停止，向用户汇报阻塞；
- 编号：`FE/BE/TE/PM-xx` → 汇总去重 `SUM-xx` → 本清单沿用或重编 `REQ-xx`（见模板参数卡）；每条沿用来源问题的修改方向，直接列给用户逐条裁决。
- 确认后的任务清单交 `PRD-Design` 修改并回填状态。

> 防评审死循环三招（修复判据 / 分级冻结 / 轮次上限）与任务清单状态机的定义见仓库根 `shared/anti-deadloop.md`，本 skill 只保留上述流程参数，不重复定义。

### 步骤 7：归档
四份评审（前端 / 后端 / 测试 / 产品）+ 汇总 + 任务清单全部落盘 `.spec/需求评审/` 后交付。

## 四、严重度分级（只标注，不设门禁）

> P0/P1/P2 定义与处理口径见仓库根 `shared/anti-deadloop.md` §二；下表为本域典型示例。

| 级别 | 含义 | 典型 |
|---|---|---|
| P0 致命 | 逻辑断头/无头、流程走不通、需求自相矛盾、缺失到无法开工 | 流程只有入口没有出口；核心对象无状态定义 |
| P1 重要 | 描述模糊歧义、状态/边界/异常未定义、数据口径不一致、验收不可测、规则冲突无仲裁、需求无目标承接（无源需求） | 「友好提示」「尽量快」；同一称谓在两个模块指不同对象 |
| P2 建议 | 表达可优化、术语不统一、非关键细节缺失 | 中英混用；章节序号不连续 |

## 五、评审铁律

1. **只审不改**：只指出哪里不通、为什么不通、建议往哪补；不替用户改写 PRD。修改由 `PRD-Design` 经任务清单交接。
2. **定位到原文**：每条问题标出处（文件/章节/需求/原句），可追溯。
3. **零幻觉**：不编造 PRD 之外的问题；原文缺失的信息区分「PRD 缺失（该写没写）」与「超出 PRD 范畴（不该写，不是问题）」。
4. **视角隔离 + 独立上下文**：三角色各审各的，不交叉、不代劳；独立上下文评审，不参考生成过程。**产品专家为唯一例外**：可读三角色结论并做调度（归并 / 定级校准 / 冲突裁决 / 归属指派 / 补漏），但只标原编号 + 命中角色，不复述其结论充当新发现。
5. **不设门禁**：只出问题清单，不判 PRD 通过/不通过；是否修改由用户决策。
6. **成因必写**：每条写明成因（如状态机无终态、跨模块未注册、步骤流未到出口）；推不出标「成因未明」，禁臆造。
7. **问题直列 + 修改方向**：问题以清单表逐条列出（含原文引用，自足可读），不藏在段落里；每条必带**修改方向**（改哪个概念 / 哪句话、往哪改），只给方向不代写 PRD。

## 六、常见错误对照表

| 常见错误 | 纠正方式 |
|---|---|
| 评审时改写 PRD | 只记问题，给建议方向，不动原文 |
| 三角色结论混写 | 分角色成文，汇总再合并 |
| 问题无出处、只说整体感觉 | 定位到文件/章节/原句 |
| 把越界内容当缺失 | 区分「缺失」与「越界」，分别标注 |
| 结论笼统 | 写清为什么不通 + 建议方向 |
| 只列现象无成因 | 补成因，可考才写、不臆造 |
| 产品专家复述三角色结论当新发现 | 标原编号 + 命中角色，不重复编号 |
| 产品专家照抄三角色问题不调度 | 走调度五动作：归并 / 定级校准 / 冲突裁决 / 归属指派 / 补漏，结果入 `产品评审.md` §4，不重复计数 |
| 只给判断不给修改方向 | 每条补修改方向（改哪个概念 / 哪句话、往哪改） |
