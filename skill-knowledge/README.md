# skill-knowledge —— 跨项目业务组件资产池

> 定位：前端 / 后端开发中沉淀下来的**可复用业务组件**集中池，供后续开发直接检索复用，作为组件资产越攒越厚。
> 池属性：与 `issue/`、`bug-patterns/`、`evolution/` 同类——源仓库根集中池，只此一处，不随 skill 副本部署。
> 消费方：Frontend-Dev / Backend-Dev——S1 开工检索（命中即复用或适配复用，禁重复手写）；S10 交付沉淀判定（REQUIRED）。
> 关联计划：`AI组件库执行计划.md` 的 asset-library 若未来落地，本池组件按其 schema 收编迁移，届时一事一源不双库并存。

## 目录约定

```text
skill-knowledge/
└── 业务组件/
    ├── frontend/<组件名>/     # 前端业务组件（如 可配置查询表格、导入向导弹框）
    └── backend/<组件名>/      # 后端业务能力模块（如 通用导入导出、消息通知、支付对接）
```

组件名用业务语义命名，一个组件一个目录。

## 沉淀四件套（缺一不算沉淀完成）

| 件 | 要求 |
|---|---|
| ① README.md | 用途 / **不用途**（When not to use，禁「适合大多数场景」）/ 最小示例 / 来源项目与日期 |
| ② 接口契约 | 前端：props 逐字段（类型 / 默认值 / 边界）；后端：入参出参 / 错误语义 / 副作用（幂等 / 超时 / 失败语义） |
| ③ 实现 | 组件源码放本目录；体量大或强依赖工程环境时放来源项目路径 + 复制改造指引 |
| ④ 自测证据 | 怎么验证可用：跑通的测试 / 命令 / 结果（证据先于声明） |

## 质量判据（沉淀前自查）

1. **窄接口**：参数最少化、错误语义统一，不裸暴露底层实现；
2. **剥离项目特有依赖**：api / 配置 / 领域字段一律参数化——抽出来要带一堆 `if (本项目)` 特例的不合格；
3. **直白实现**：宁可重复直白，不做抽象表演（三层泛型 / 微妙重载 / 压缩式聪明一律不要）；
4. **真实使用**：只沉淀经真实项目使用验证的组件，不为凑资产预造。

## 项目特有组件不沉

强绑定本项目领域模型 / 数据结构 / 视觉规范的组件**不进本池**，避免污染资产池让检索失效（判据：换个项目还能不能直接用或小改就用）。

## 缺陷与退役

使用中发现缺陷：能修则修并回写来源标记；无法修复或已过时：在组件 README 顶部标 `> ⚠️ 已废弃（原因 / 日期）`，不直接删除，保留可溯源性。
