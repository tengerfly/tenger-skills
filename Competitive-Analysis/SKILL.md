# 竞品分析（Competitive Analysis）

## 概述

给定一个明确的产品想法，通过全球中英文数据驱动的调研，客观呈现其在五个层面的竞争全貌，输出一份规范的工业级竞品分析报告。

- **最终交付物料包（Artifact Spec）**：每次执行竞品分析，均在 `Competitive-Analysis/.output/` 下生成专属主题目录，包含且仅包含两个标准文档：
  - `Competitive-Analysis/.output/<主题>竞品分析/<主题>竞品分析报告.md`（包含 11 个模块的完整工业级竞品分析主文档）
  - `Competitive-Analysis/.output/<主题>竞品分析/验收结果详细说明.md`（依据 `assets/eval-template.md` 产出的三段式 Pass Gate 验收评测文档）

**核心纪律：一切结论有据可依，禁止编造，预测必须标注，多方口径并列呈现。**

## 何时使用

- 用户给出明确产品想法，要做竞品分析 / 调研 / 对比。
- 用户想了解某赛道（国内本土或海外出海）的竞品、市场趋势、用户痛点、商业模式、技术实现。
- 间接表达也触发：「这个赛道竞争怎么样？」「XX 产品强在哪？」

**何时不用**：产品想法已成熟、要直接写需求文档时，改用 PRD-Design。

## 工业级端到端交付流水线（End-to-End Pipeline）

本 Skill 采用严密的四阶段工业流水线：**「输入规范 ➔ 调研与草稿推演 ➔ 标准模板测试验收 (Pass Gate) ➔ 正式落盘与交付」**。

```
┌──────────────┐     ┌──────────────────┐     ┌────────────────────────┐     ┌────────────────────┐
│ 1. 结构化输入 │ ──► │ 2. 调研与草稿生成 │ ──► │ 3. 模板化测试验收 Gate │ ──► │ 4. 正式交付与归档   │
│ (Input Spec) │     │ (Draft Candidate)│     │ (assets/eval-template) │     │ (Final Output)     │
└──────────────┘     └──────────────────┘     └────────────────────────┘     └────────────────────┘
```

### 详细阶段规约

1. **输入阶段（Input Specification）**：
   - 解析用户原始 Prompt，锁定赛道类型（红海/内容/灰区/出海/数据稀缺）、目标市场与核心竞品预期对标项；
   - **派活四件套（缺一样先问，不脑补）**：目标（产品定位与调研方向）、边界（哪些不碰）、历史包袱（既有认知/材料）、验收标准（本次要回答哪些核心问题）——用户输入信息不全时，先补问再动手。
2. **调研与候选草稿推演（Candidate Drafting）**：
   - 执行全球双语检索（国内权威研报/裁判文书 + 海外 Statista/GVR/Reddit/Trustpilot）；
   - 按五层分析框架推演，严格执行数据红线（禁编造、多方口径并列、商业假设打标、优缺点强制建表），生成 11 模块候选草稿。
3. **模板化测试验收（Test & Evaluation Gate）**：
   - **强制依据 `assets/eval-template.md` 执行标准化三段式评估**（结果是什么 / 结果缺什么 / 需要优化什么）；
   - 执行 **Pass Gate 门禁裁决**：
     - **✅ PASS（P0=0 且 P1(Open)=0）**：准予进入最终交付阶段；
     - **⚠️ CONDITIONAL PASS（P0=0 但 P1(Open)>1）**：就地补齐 P1 缺陷，二次验证通过后方可输出；
     - **❌ FAIL（命中任一 P0 红线）**：严禁对外输出，立即阻断并重构草稿。
4. **正式交付与归档（Final Delivery）**：
   - 在 `Competitive-Analysis/.output/<主题>竞品分析/` 目录下完成双文档落盘交付：
     1. `<主题>竞品分析报告.md`（11 模块主文档）
     2. `验收结果详细说明.md`（三段式验收文档）
   - 在控制台同步呈现核心提炼与 Pass Gate 裁决摘要。

## 数据红线（最高优先级，不可违背）

1. **禁止编造**：某模块确实无公开数据时，如实标注「暂无公开数据 / 信息不足」，绝不虚构数字、案例或结论。
2. **数据可溯源**：每个核心数据、关键结论都要能追溯到来源（来源机构/平台 + 时间/版本）；无来源的数据不得写入。
3. **预测必须标示**：推测、估算、预测的数据，必须明确标示「此为预测 / 估算」，与已核实事实严格区分。
4. **多方口径并列**：当行业内各权威机构口径存在巨大分歧（如 18 亿 vs 43 亿 vs 50 亿）时，严禁随意挑选单个数字，必须并列呈现并说明口径差异。
5. **商业假设显式隔离**：报告中为目标产品提出的定价设计或抽佣模型，必须打上 `【平台设计假设值（非调研事实）】` 标签，严禁与竞品既有真实商业数据混淆。
6. **简洁不啰嗦**：一句话能说清的不写一段；能用表格 / 清单的不写长段落。
7. **具体优先**：能用具体数据、权威报告或海外社区（Reddit/Trustpilot）真实事例说明的，优先用具体内容，而非空泛描述。
8. **测试门禁前置（Pass Gate 强制验收）**：任何报告在正式交付或落盘前，**必须经过《竞品分析测试标准》的自检验收，达到 Pass 标准（P0=0 且 P1(Open)=0）后方可输出**；存在 P0 缺陷一票否决阻断。

**Red Flag（命中任一即停下自查）**：
- 想写一个数字却找不到来源（正要编造）；
- 想「选一个好看的数字」回避口径分歧（该并列却想单挑）；
- 把目标产品的定价/抽佣当成竞品真实数据写（假设没打标签）；
- 结论用「我觉得 / 应该是」开头（推测没标「此为预测」）。

## 赛道自适应策略（核心引导机制）

根据用户输入的产品所属赛道特征，自动调整调研与报告侧重点：

| 赛道特征 | 典型代表场景 | 重点分析维度与报告倾斜方向 |
|---|---|---|
| **大厂垄断 / 高度同质化红海** | 进销存记账、通用办公文档、云存储 | 重点分析**获客成本结构（CAC）**、**服务/渠道下沉度**及**价格带缝隙（中间空白）**。 |
| **内容平台蚕食型赛道** | 旅游攻略、美食菜谱、生活指南 | 重点对比**内容平台（小红书/抖音）UGC 碎片化缺陷** vs **结构化/交互式执行闭环**。 |
| **法律 / 监管敏感与灰区赛道** | 二奢改装再造、宠物殡葬、数字处方 | 重点穿透**知识产权（商标权利用尽边界）**、**前置资质审批与承揽合同合规链路**。 |
| **海外出海 / 全球高净值赛道** | 欧美 AI 健身、SaaS 出海、海外工具 | 重点调用 **Grand View Research / Statista** 研报，深挖 **Reddit / Trustpilot** 真实槽点与海外生态（GDPR/Stripe/Apple Watch）。 |
| **数据极度稀缺 / 新兴赛道** | 小众 O2O、前沿 AI 实验工具 | 严格执行**多方口径并列标注** + **自下而上单店/单点经济模型（Unit Economics）测算**。 |

## 五层分析框架

| 层 | 要回答的核心问题 |
|----|----------------|
| 市场趋势 | 这条赛道大盘多大、增速如何、值不值得进 |
| 竞品优缺点 | 对手是谁、强在哪弱在哪、横向对比差异化机会在哪 |
| 用户痛点 | 目标用户痛在哪、真实社媒中在抱怨什么、哪些需求未被满足 |
| 商业模式 | 竞品怎么赚钱、成本与客单价是多少、目标产品如何设计变现 |
| 技术可行性 | 能不能做出来、关键技术路径、数据与合规壁垒是什么 |

> 每层的具体子维度详见 `references/dimensions.md`。

## 调研与交付流程（七步闭环）

```
[1. 解析目标] ──► [2. 竞品界定] ──► [3. 匹配赛道策略] ──► [4. 全球双语检索] ──► [5. 五层交叉推演] ──► [6. 测试门禁验收 ⛔] ──► [7. 自动落盘交付]
```

1. **确认目标**：解析产品定位、目标市场（国内/出海）、目标人群与核心功能假设。
2. **竞品筛选与分类**：筛选 3–8 个竞品，划分「直接竞品 / 间接竞品 / 参照竞品」，标注对标维度。
3. **匹配赛道策略**：根据赛道自适应策略确定本次分析的重心（红海突围 / 合规防线 / 真实槽点）。
4. **信息收集（全球视野）**：
   - 国内源：艾瑞、IDC、易观、QuestMobile、裁判文书网、小红书、知乎。
   - 海外源：Grand View Research、Fortune Business Insights、Statista、Reddit、Trustpilot、G2、App Store。
5. **分层分析与矩阵构建**：产出个体画像、横向功能矩阵，且**必须单独产出竞品优缺点横向对比表**。
6. **测试标准前置验收（Pass Gate 强制执行）⛔ BLOCKING**：
   - 依据 `assets/eval-template.md` 执行 P0/P1/P2 自检；
   - **苏格拉底三问（分析质量自查）**：① 这个结论在什么情况下会失效？② 关键数据涨 10 倍 / 换个市场还成立吗？③ 漏掉了什么（隐性合规 / 履约盲区 / 真实槽点）？答不上来就回查补证，不硬下结论；
   - 检查是否命中 P0 违规（编造数据、未打假设标签、缺失优缺点表）；
   - 确认达到 **Pass（P0=0 且 P1(Open)=0）** 标准。若未通过，必须就地修复补齐，严禁将不合规报告输出给用户。
7. **输出报告并落盘交付**：
   - 按 11 模块组织报告，并在 `Competitive-Analysis/.output/<主题>竞品分析/` 下完成双文档落盘：
     - `<主题>竞品分析报告.md`
     - `验收结果详细说明.md`
   - 在控制台向用户呈现结构化提炼，并附带三段式测试评估摘要。

## 报告标准结构（11 模块）

1. **报告摘要**（一页读完：产品定义、主要竞品、3–5 条核心发现）
2. **调研背景与目标**（一句话产品定义 + 待回答核心问题）
3. **竞品界定**（竞品清单表格：名称/类型/选取理由/对标维度）
4. **市场趋势分析**（市场规模、增速、驱动因素、多方口径对比、监管信号）
5. **竞品个体画像与优缺点**
   - 5.1~5.N 各竞品详尽画像（定位/功能/定价/口碑）
   - **5.N+1 竞品核心优缺点横向对比汇总表（强制独立建表）**
6. **竞品横向对比（功能点矩阵）**（✓/✗/△ 矩阵 + 功能空白分析）
7. **用户痛点与社媒舆情分析**（用户画像、核心场景、真实槽点/差评、未满足需求）
8. **商业模式与定价分析**（竞品收入模式对比 + 目标产品设计建议【明确标示假设属性】）
9. **技术可行性与履约路径**（技术选型、核心算法/API、数据壁垒、合规风控）
10. **差异化与总结**（客观归纳五层 + 差异化空白与突破口 + 待核实风险）
11. **附录（数据来源与声明）**（全部中英文参考链接、发布时间与口径声明）

> 完整报告模板详见 `assets/report-template.md`。
