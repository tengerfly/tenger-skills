## 二、项目规则（开发前必读，见 SKILL 铁律）

```markdown
## 项目规则
1. 还原度优先：页面结构/间距/配色/字号/三态与原型一致，禁止自由发挥降级；
2. 模块化防重：组件模块内 ≥2 次复用 → features/<模块>/components/；跨模块 → src/components/；
3. 测试先行：先写测试（标注 TC-Mxx ↔ AC-Mxx）再写实现，五类覆盖；
4. 不确定即问：遇不确定停下问用户并给选项，不自己发挥；
5. 功能点即提交：每功能点一 commit，提交过 eslint + stylelint + commitlint，不绕过、不擅自 push；
6. 注释简单易懂 + 传参必注：每个参数写 @param 说明作用；
7. 共享类型单一来源：接口请求/响应/枚举只从共享包 import type，不重定义；
8. 仓库约定（{{monorepo 落位 / 根配置继承 / 提交信息约定等}}）。
```
