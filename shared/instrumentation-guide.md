# 埋点规范（运行事实与经验候选）

统一时机、路径、去重、恢复、写入失败及跨仓授权遵循仓库根 `shared/problem-recording.md`（本文件与其同目录）。全部活动 Skill 入口均显式接入；这是 Agent 执行规则，不是后台监听器。

## 一、何时记录

已观察到的失败、阻塞和用户纠正，在下一安全节点持久化最小事实；根因未知不妨碍记录。正常收尾补处理结果，并判断是否有可复用的方法论问题、真实正负反馈或重复产物问题。不要等顺利交付后才记录异常，也不要为提炼经验延误止损。

猜测不写成事实；不确定普遍性只标待分析。无需给预期负向测试和无影响的探索尝试逐条建 issue。正式评审放行不是事实记录的前置。

## 二、记什么

项目错误复用原报告/任务卡/轻量摘要，字段见共享规则；Skill 自身问题按 `templates/issue-template.md` 记录。字段未知标待确认，不编造归因。

来源为「埋点 / 挖掘 / 体检 / 用户 / 评审闭环」之一。来源=评审闭环时，补产出方 A 防复发与评审方 B 检出力落点；尚未确认目标时保留待分诊责任与下一步，不虚填已沉淀。

## 三、记到哪

确认真实 Skill 源仓根和授权后，写 `<源仓>/issue/<Skill目录名>/<YYYY-MM-DD>/<序号>-<标题>.md`，复用已有目录；序号在日期目录内递增，先查重再写，不覆盖已有文件。

项目错误先留项目本地详情并更新 `.spec/问题日志.md`；疑似 Skill 问题在无跨仓授权时标待反馈。之后的源仓条目只引用原问题和提炼依据，不复制原始敏感日志。不写安装缓存，不自动同步客户端。

## 四、分级与标签

- Skill 问题池等级：P0 方法论硬伤/必犯/阻塞；P1 明显影响/高频；P2 轻微/建议。未确认时标建议分级，不伪装已裁决。
- 标签：触发识别 / 流程缺陷 / 边界不清 / 术语文案 / 产物格式 / 接口契约 / 工具依赖 / 性能体积 / 正面参考 / 反面参考。
- 项目缺陷沿用其 P0/P1/P2/P3 等级，不因池口径转换自动改变项目严重度。

## 五、闭环

写后回读；写失败明确报告未落盘。恢复时核对未决记录；修复后补真实复核证据，不用「已修复」替代「已验证」。正面与负面信号均可作为候选，不从一次反馈擅自推导稳定偏好。反哺需保留来源、适用边界、验证与回退方式；权限不足就保持待反馈。无法保证在未观察到异常的宿主崩溃或强制终止后补写记录。
