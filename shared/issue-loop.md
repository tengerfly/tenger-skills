# 问题记录与反哺闭环（issue-loop 契约）

> 唯一事实源：问题卡字段、状态机、反哺规则只在本文件定义；各 Skill 引用本文件，不复述。
> 目标：开发中遇到的问题记录在案 → 小步反哺 Skill → 越用越好用。记录要轻，反哺要小。
> 新池从 0 开始：只记 v4 真实任务的问题；旧卡留在 `archive/issue-v3/`（只读），不迁移、不清理。

## 1. 记录时机（30 秒一张卡）

- 发现即记：评审、验收、测试、修复、用户纠正暴露的问题，在下一个安全节点落盘，不等收尾。
- 优先级：评审与验收发现的问题优先入池——它们是反哺最主要的来源。
- 只记有后续动作的问题：影响验收、导致阻塞或返工、需要改规则或跟进。不记预期内的负向测试、无影响的探索尝试。
- 根因与归属未明照样记，标「待确认」；先止损再记卡，事故不因填表延误；敏感信息脱敏后再写。
- 写后回读确认；无写权限时报告「未落盘」并给出待记录内容，不绕过权限。

## 2. 问题卡（`issue/NNN-slug.md`）

- 扁平池：`issue/` 下直接放卡，不按 skill / 日期建子目录；序号三位递增（从 001 起），模板 [000-template.md](../issue/000-template.md)。
- 一卡一件事：同现象先搜 `issue/`，已有则补证据、更新状态，不新建重复卡。
- 文件名 = 三位序号 + 短 slug；卡是索引不是报告，细节放任务产物。

frontmatter 七个字段全填（`verifiedBy` 可空）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | 三位序号 | 与文件名前缀一致 |
| `type` | `skill` / `project` / `env` / `process` | skill：Skill 自身问题；project：被开发项目问题；env：环境 / 工具；process：流程卡点 |
| `skill` | skill id 或 `none` | 归属 Skill（如 `auto-test`）；不属于任何 Skill 填 `none` |
| `severity` | `P0` / `P1` / `P2` | 与评审同一套分级：P0 阻断、P1 应修、P2 可排期 |
| `status` | `open` / `fixed` / `verified` / `closed` | 见 §3 |
| `found` | `YYYY-MM-DD` | 发现日期 |
| `verifiedBy` | 任务 id + 日期，可空 | 在哪个真实任务里验证有效 |

正文四节，各写几行：

- `## 现象`：期望 vs 实际，什么条件下必现。
- `## 证据`：命令与输出、日志行、文件 + 行号、截图 / 报告位置；没有就写「待补」。
- `## 影响`：阻断 / 返工 / 卡多久 / 范围 + 定级理由。
- `## 建议改动`：改哪个文件哪一处、怎么改（≤10 行）；判断不了写「待分析」。

## 3. 状态机

`open → fixed → verified → closed`

- `open`：事实已落盘，根因 / 归属可待确认。
- `fixed`：规则或产物已改；写清改了什么、改在哪。
- `verified`：后续真实任务验证有效，填 `verifiedBy`（任务 id + 日期 + 证据位置）。
- `closed`：不再跟进（重复 / 不成立 / 一次性特例），写理由。
- 已修复 ≠ 已验证：没有本次实测证据不得标 `verified`；无法验证的保持 `open`。
- 复发：同类问题再次出现，重开原卡（保留历史）或新建关联卡并互链。

## 4. 反哺触发（什么时候动 Skill）

触发任一即进待批改清单：

1. 同一问题第 2 次出现；
2. 单卡记录的工作时间 > 30 分钟（说明流程在拖人）。

- 一次性问题、环境特例：只记卡，不改规则。
- 先有卡才有改动：禁止「拍脑袋加规则」，改动必须回链卡号。
- 只改 `skills/` 与 `shared/` 四份规则；不改 `archive/`、不改别人范围、不新建治理层。
- 反哺落点二选一：流程缺陷 → 对应 SKILL.md 的判据 / 停等点；代码类错误模式 → [bug-patterns/](../bug-patterns/README.md)（评审检出清单）。

## 5. 批改窗口

- 频率：每 2 周一次；每次 ≤3 处；每处 ≤10 行。窗口外只记卡不动规则（阻断交付的紧急修复改完立即补卡）。
- 步骤：挑卡 → 最小改动 → 回填卡（`fixed` + 改动位置）→ 下个真实任务记 `verifiedBy` → 4 周未验证则回滚。
- 4 周回滚：从 `fixed` 起 4 周内没有真实任务验证 → 回退该处规则改动（git revert 或 diff 反向应用），卡回到 `open` 并写回滚原因。
- 改动后跑一次 `validate_lite`（≤5 秒）；超预算先删再交。

## 6. 度量（每月一次）

- 复发率 = 同类问题再次出现次数 / 已修复问题数。
- 反哺有效率 = 修复后该类问题减少条数 / 已修复问题数。
- 每任务一行记 [loop-log.md](../loop-log.md)（11 列）；验收类指标（一次验收通过率、缺陷逃逸率）在验收契约中定义，本文件不重复。

## 7. 防膨胀

- 卡可 `closed` 但保留；每半年审计：合并重复、关闭无效卡、超过 100 行的规则先删。
- 一张卡一屏内写完；写不完说明那是报告不是卡。
- 禁止：按 skill 分目录、新状态机、注册表、自动监听、多级模板。
- 删除优于冻结，冻结优于保留。
