# 问题日志（<项目名>）

> 位置：`<项目>/.spec/问题日志.md`。这是可发现索引，不是问题详情或正式 Gate。详情复用评审清单、测试任务卡、缺陷报告或轻量任务摘要；规则见仓库根 `shared/problem-recording.md`。
>
> 已观察到需追踪问题时，在下一安全节点写详情并更新索引；同一来源路径 + 问题 ID/锚点只保留一条当前索引，重复运行更新证据/状态，不重复追加。写后回读；恢复/交付前回查详情和未决项。无问题不建空记录。
>
> 状态以详情为准；更新时同步本索引，陈旧/不一致时回源核对。已修复不等于已复核；同报告可保留一行批次索引，但须列问题 ID 范围/锚点，不能将部分修复写为全批闭环。旧表兼容：在「问题产物」列补 `#问题ID`，不必全文迁移。
>
> 反哺只记来源/目标引用；跨仓未授权标「待授权反馈」。定期综合分析须读取索引指向的详情与证据，不能只读一行摘要。
