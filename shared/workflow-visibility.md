# 流程可见性与用户控制

适用于总编排、领域编排和原子 Skill 的交接。只增加可见性，不增加审批层或新的状态机。

## 何时告诉用户

- **开工/恢复**：展示本次目标、强度及原因、终点、拟走阶段、复用/跳过项与依据、当前步骤和下一动作；不能只说“开始处理”。
- **阶段开始与交接**：说明现在调用哪个 skill、为什么调用、输入/输出是什么；结束后说明完成内容、证据/文件位置、Gate 或剩余限制、下一步。
- **等待确认/阻塞/路线变化**：立即说明停在哪里、为什么、影响、谁需要提供什么、可选处理和恢复条件。不要把等待用户写成仍在执行。
- **长阶段**：完成有意义的子步骤时简报进度，不逐条播报工具调用，不虚构实时后台进度、百分比或预计完成时间。
- **结束/暂停**：列已完成、未执行/未验证、待决定事项和明确恢复入口。

## 状态卡（每次简短更新）

目标/终点：…
路径：接管 → 需求 → 设计 → 实现 → auto-test（本次不用的阶段标不适用并说明）
当前位置：阶段名称 / skill；已完成 …；待执行 …
状态：执行中 / 等待你确认 / 阻塞 / 已完成（人类可读展示，不是新增正式状态）
本步产物与证据：路径、版本、实测或研究引用
待你决定：具体问题、选项及影响；没有则写无
下一步：动作、执行方、前置条件

正式流程同时展示 workflow.yaml 的 state、gate、allowDownstream；中文状态不得冒充注册状态。“产物已写”不等于“已批准”，“未执行/不适用”不等于“通过”。

**状态卡是工作单元交付物（硬门禁）**：每完成一个可验收结果，必须输出一张状态卡（当前位置/本步产物/下一步/需你决定），**未输出不得开始下一个工作单元**。用户只回「继续」时，默认只做当前已声明单元的剩余部分，不得据此新开单元；任何一次静默的工作单元切换都视为流程偏离，应停下补卡并重新确认范围与终点。

## 持久化与单一事实源

正式当前状态只以 `.spec/workflow.yaml` 为准，沿用 executionId、currentSkill、state、gate、allowDownstream、artifactRefs、evidenceRefs、decisionRefs、nextAction、revision、updatedAt。每次交接按合法状态转移同步，历史原因及阶段计划保存在本次 execution 摘要中；展示是这些记录的视图，不再维护第二套状态。

轻量任务复用会话/已有任务摘要，不为看板补建正式文件。暂停或跨会话时按 execution-profiles.md 持久化；恢复先回读状态、相关产物、决策与未决问题。缺失/冲突时明确“状态未知/待核验”，不猜测完成。

用户问“到哪一步/完整流程/为什么跳过/还缺什么”时先回答再继续。用户要求暂停则保存进展后停止；调整范围须展示影响并在原决策处确认，不暗中扩展。确认聚焦定位、范围、风险、发布等决策，不要求每个确定的低风险动作都说“继续”。

可用 `python scripts/workflow_status.py --project-root <项目路径>` 只读查看持久状态；它不是调度器或 Gate 校验器。
