# 双基准术语（公共约定）

> 本文件是双基准术语的集中定义源（根 README 等处按此引用）。谈结构用「低保真原型」，谈视觉用「设计稿」；两词不得混用，旧称不得残留于现行正文（历史决策记录除外）。

| 术语 | 定义 | 边界 |
|---|---|---|
| 低保真原型 | Prototype-Design 产出，落 `.spec/原型/`；极简中性色 + 单一主色 + 基础字号层级，可点可交互；载体划分先经布局清单 Gate（产 `布局清单.md`） | **结构基线**：页面/载体结构、交互流转的唯一结构真相源；不是高保真稿，也不是纯灰白线框 |
| 设计稿 | UI-UX-Design 产出，归档 `.spec/设计稿/`（CLI 工作目录 `.superdesign/`）；以 design-system.md 为规范源 | **视觉基准**：色值/字号/间距等视觉值以 design-system token 为权威；⑥⑦ 为可选节点，缺失时视觉基准回退低保真原型 + 用户确认 |

## 引用规则

- 布局/结构/载体/流转 → 依据**低保真原型**（+ 布局清单）。
- 视觉值/组件样式/状态视觉 → 依据**设计稿**（+ design-system.md）；无设计稿时只能回退原型作视觉来源，且必须先有**用户批准的已登记例外 EXC**（规则见 `shared/product-workflow-contract.md` §5.1）：无 EXC 即 `BLOCKED`，不得以「明示降级」代替登记。
- 废弃旧称：`高保真原型`、`页面视图清单`、指 Prototype 产物时的`页面清单`/`wireframe`——现行术语一律用上表。

## 还原度定义（唯一口径）

**还原度 = 双基准同时达标**——两个维度各有对照物，任一维度不符即未完成：

| 维度 | 对照物 | 硬约束 |
|---|---|---|
| 结构 / 布局 / 载体 / 流转 | 低保真原型 + 布局清单 | 区块增删改即返工 |
| 视觉（色值 / 字号字重 / 间距 / 圆角阴影 / 图标 / 状态视觉） | **设计稿 + design-system.md token** | 每个视觉值必须在 design-system 有出处 |

**有设计稿时，设计稿是视觉维度的唯一应然**。低保真原型只有极简中性色 + 单一主色 + 基础字号层级，**不承载视觉基准**——拿它当视觉基准必然产出「结构与原型一致、视觉与设计稿差一截」的结果。

## 下游执行口径（防漂移，硬性）

各 skill 书写「还原 / 比对 / 校验 / 评审 / 验收」相关内容时，一律遵守：

1. **基准命名顺序**：有设计稿时，视觉比对的基准先写**设计稿**；原型只作结构对照与「该不该有」的存在性判定，**不得**把原型列为视觉基准，也不得写成「基准 = 原型，有设计稿时加开设计稿」这类把设计稿降为附加项的语气。
2. **禁止句式**：`色值 / 字号 / 间距 / 图标 / 配色…与原型一致`、`视觉值从原型提取`、`对照原型还原配色`——有设计稿时均属**口径错误**，改指设计稿。
3. **无设计稿时**：才回退原型作视觉来源，且必须同时具备已登记的视觉基线例外 EXC（`shared/product-workflow-contract.md` §5.1：例外 ID、用户批准出处、缺失原因、影响范围、补偿验证），并在产物 / 报告中**明示「视觉基准回退低保真原型」**；无 EXC 即 `BLOCKED`，不得静默降级。
4. **token 搬运对账**：设计稿是 HTML + Tailwind 类，实现是 CSS 变量，**载体不同必须逐条对账**——实现侧 `styles/variables` 与 `design-system.md` §7 Token 汇总核对条数 / 值 / 命名，对账记录留痕。
