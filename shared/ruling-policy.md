# 裁决优先（Ruling Policy）

> **解决的问题**：停等是默认动作，于是自主跑停成了人肉审批。本文件把它反过来——
> **能回退的决定自己下、记下来、继续走；只有五类别的事才停。**
>
> 适用范围：全执行强度（轻量/标准/完整）与全部 Skill。与 `gate-policy.md` 不冲突：
> 裁决回答"我现在怎么走"，Gate 回答"产物能不能进下游"。

## 0. 一句话判据

**这个决定做错了，用户能不能当场看出来并回退？能 → 自己裁；不能 → 停。**

## 1. 五类硬停（必须问用户，不得代裁）

| # | 类别 | 例 |
|---|---|---|
| 1 | **不可逆或破坏性** | 删除、覆盖已批准基线、数据库迁移、重置、不可回滚的批量改动 |
| 2 | **安全敏感** | 认证/授权边界、资金与计费、敏感数据、外部凭据 |
| 3 | **本仓之外的副作用** | `git push`、合并到共享分支、发布/部署、改外部仓、付费调用 |
| 4 | **关键产品决策** | 范围、定位、目标用户、MVP 取舍、验收口径的实质变更 |
| 5 | **无路可走** | 计划烂到每一步都是猜；缺关键输入且无法推断 |

**除这五类之外，一律裁决。** 包括但不限于：目录与命名、库的等价选择、文档详略、
评审发现的严重度归属、口径冲突的首次裁定、评审发现的修/延/弃（P0 除外）、
计划粒度与顺序、在已定验收判据内的用例选取。

## 2. 常见「该裁决却去问了」

- 一个工作单元内向用户问了 3 个以上非硬停问题；
- 把"要不要继续 / 是否往下做"当成确认；
- 把 AI 自己能查证的现状（代码、文档、依赖版本）做成用户的填空题；
- 让用户替 AI 决定评审里某条 P2 改不改；
- 在已批准范围内每换一个文件/页面就重新确认一次。

## 3. 裁决记录

```text
Ruling: <决定> — <理由> — <错了的代价> — <回退方式>
```

- 正式流程：追加到项目 `.spec/rulings.md`（一行一条，只增不改）；
- 轻量任务：写进任务摘要；
- **不写进 manifest、不占 Gate 字段、不算 DEC**。裁决是执行过程的记录，不是批准。

## 4. 裁决做不到的事（越权判据）

| 越权行为 | 判定 |
|---|---|
| 把 Gate 结果改成 PASS / 把 P0、P1 裁成"不阻断" | 越权，且致命 |
| 扩大修改范围、动到范围外的文件 | 越权 |
| 代用户批准关键产品决策 | 越权 |
| 撤销已登记的例外、阻塞或 `blockedBy` | 越权 |
| 覆盖已批准的基线版本 | 属第 1 类硬停，不得裁决 |
| 裁决后不记录 | 视同未裁决，不可追溯 |

用户可事后否决任何一条裁决；否决后回到该决定点重做，不回退已完成且已验收的工作。

## 5. 与 Gate 的关系

裁决不产生 `PASS`。产物能否进下游仍由 `gate-policy.md` 的判据决定；
裁决只决定"这一轮先做什么、先不做哪个"。

## 6. 与「继续」的关系

用户说"继续"时：在**已批准范围内**推进当前单元并可直接进入下一个单元，
每单元结束输出状态卡（状态卡是交付物，不是停等）；只有跨越范围边界才需要重新确认。

## 7. 失败对照

| 症状 | 判为 |
|---|---|
| 一个工作单元问了 3 次以上非硬停问题 | 过度请示 |
| 裁决没记录 | 不可追溯 |
| 裁决扩大了范围 | 越权 |
| P0 被裁成延后 | 越权且致命 |
| 把"继续"当成范围扩大的授权 | 越权 |
| 因等一个非硬停答案而空转 | 违反本文件 |
