# Skill 写法（v4 唯一写法规范）

> 适用：`skills/<name>/SKILL.md` 与 `shared/*.md`。规则只有一条：**写判断，不写教程**。
> 模型已经会写代码；它不会的是「做到什么算完成、卡在哪必须停、拿什么证据来验收」。

## 1. 一个 Skill = 一个判断单元

| 字段 | 要求 |
|---|---|
| 目录 | `skills/<name>/`，name = kebab-case，与 frontmatter `name` 一致 |
| 入口 | 只有 `SKILL.md`；参考资料放该目录 `references/`（非必需），模板放 `templates/` |
| 篇幅 | 薄教/入口/修复 ≤100 行（workflow ≤120）；厚收 auto-test ≤150、review ≤180、acceptance ≤150 |
| frontmatter | 仅两键：`name`、`description`。description 一句话说清「什么时候用」，≤60 字 |

## 2. 固定五节（validate_lite 强制）

每份 SKILL.md 必须且只按这五节组织（顺序固定，标题逐字一致）：

```markdown
## 何时用
## 交付物
## 验收判据
## 停等点
## 证据要求
```

- **何时用**：触发条件 + 前置输入；不写背景故事。
- **交付物**：产物清单（文件名/格式/放哪）；一个任务只留一套产物。
- **验收判据**：DoD，逐条可判真假；能用命令/测试/截图验证的，写明命令。
- **停等点**：必须停下来问用户的稀缺动作（不超过 3 条），其余默认「裁决 + 记账 + 继续」。
- **证据要求**：这条链路上什么算证据（可复现命令与输出、测试报告、构建产物、运行截图、日志、sha256）；自述不算。

厚收三件套（auto-test/review/acceptance）可在五节之后追加最多 2 节（如 `## 分层门禁`、`## 结论与处置`），并引用 shared 契约原文，不重复定义。

## 3. 教什么、不教什么

**写**：交付标准、停等点、证据要求、判据、常见失败模式（一句话一条）。

**不写**：框架教程、API 用法、大段代码模板、目录结构规范、通用工程常识、从 shared 复制的规则。同一规则只允许有一个事实源（`shared/*.md`），Skill 只引用。

## 4. 引用规则

- Skill 引用 shared：`../../shared/<file>.md`（安装后由 installer 分发到三个落点，路径仍可解析）。
- Skill 引用别的 Skill：`../<skill>/SKILL.md`。
- 不写机器绝对路径；不写宿主名；不假设有网络。
- 相对链接必须真实存在（validate_lite 会查）。

## 5. 变更纪律（反哺闭环）

1. 先有真实问题卡（`issue/`），再有 Skill 改动；禁止「拍脑袋加规则」。
2. 每 2 周一个批改窗口，每次 ≤3 处、每处 ≤10 行。
3. 改动后下次真实任务记 `verifiedBy`；4 周未验证 → 回滚该改动。
4. 每半年审计：超过 100 行先删，再谈加。删除优于冻结，冻结优于保留。

## 6. 行数怎么算

`SKILL.md` 全文行数（含 frontmatter 与空行）。超一行也算超：先删解释性段落，再删例子，最后才删判据。
