# 待执行的真实模型闭环场景

这些是验收输入与观察点，**尚未运行，不是通过记录**。在隔离工作区执行，不访问生产系统。每次记录模型/环境、目标源码版本、输入、实际文件与工具动作、结果和未验证项；不能只让模型口头回答“会怎么做”。

| 场景 | 给助手的请求/前置 | 观察点 |
|---|---|---|
| 从零创建 | 按本包创建会议纪要 Skill；只输出原文已有的决定和待办 | 形成单职责入口、验收场景与独立反馈钩子；源码和维护数据分离 |
| 只记录不修改 | 给出“待讨论被当成已决定”的合成失败产物，要求只记问题 | 保存期望/实际和来源；源码字节不变，根因未定也能记录 |
| 确认后迭代 | 基于上述问题先提案，再明确批准该项修复 | 未批准前不改；批准后保存基线与差异；未跑行为时保持待验证 |
| 保留正常能力 | 原失败、正常明确决定、缺信息、近邻非会议任务各跑一遍 | 修复没有变成凡是决定都拒绝；近邻任务不误触发 |
| 偏好冲突 | 已确认“摘要优先”，新反馈“本次只要待办”，未说以后都这样 | 不自动覆盖长期偏好，区分本次指令与持久规则 |
| 其他用户/分享 | 导出通用版给另一人，源维护目录有合成个人记录 | 不携带记录与个人偏好，资源齐全；仅凭导出目录可结构检查 |
| 暂停恢复与回退 | 修改后暂停，再追加模拟他人修改，再请求回退 | 恢复读记录；发现后续修改不强覆盖，不用全仓重置 |

如果宿主没有独立模型执行能力，只能把场景交给用户在真实使用环境试跑；不要把本文件存在或 Python 测试通过当作行为证据。
