# 可复制的 Skill 个性化迭代工具包

把本目录整体复制给别人即可；真正的 Skill 入口是 **skill-lifecycle/SKILL.md**。也可以只复制完整的 **skill-lifecycle/** 子目录（不能只复制入口文件）。无需本工程仓库、问题池、其他 Skill、Git 或外部知识库。

## 它解决什么

创建一个职责明确的 Skill → 在真实使用中记录问题和反馈 → 区分规则缺陷、环境问题与个人偏好 → 确认小步改进 → 修改并验证 → 得到更适合自己的 Skill。工具包是维护方法，最终交付的是你的目标 Skill，不是只得到一份优化报告。

## 第一次怎么用

在支持读取本地文件的 AI 编码助手中，告诉它：

> 请读取我复制过来的 skill-lifecycle/SKILL.md。帮我创建一个用于「会议纪要整理」的 Skill：输出决策、负责人、期限和待确认事项，不编造会议没有说过的结论。源码放在我指定的可写目录，维护记录与分享包分开。先明确用途与验收场景，再创建。

如果已经有 Skill：

> 请按 skill-lifecycle 接管这个已有 Skill：[源码路径]。不重写现有能力，先记录当前版本、职责和回归场景。维护记录存放在：[可写目录]。

后续使用：

- **只记录**：「这个 Skill 把待讨论事项当成已决定了。请记录问题，先不要修改。」
- **个性化**：「以后我的会议纪要先列待办，再列摘要；只适用于我的会议纪要 Skill。请记成待确认偏好。」
- **迭代**：「根据这个 Skill 的问题记录提出本轮改进、影响、验证与回退方式，等我确认再修改。」
- **复验**：「执行已确认方案；复跑原失败场景和已有正常场景，未执行的不要写通过。」
- **交付**：「导出我自己的版本，保留已确认偏好；不要带出聊天原文、问题池和私人路径。」

无需记命令，以上都可自然语言提出。新建 Skill 会带轻量问题记录规则；接管旧 Skill 时须经确认才植入。不具备文件写入能力时，AI 只能给待保存内容，不能声称已经记录。

## 复制边界

- 分享维护工具：只复制本目录；里面是通用规则与空白模板，没有本仓库的个人记录。执行 Python 后可能产生的 `__pycache__/`、`.pyc` 是缓存，不属于分享内容，复制时排除。
- 分享最终 Skill：复制目标 Skill 的入口及全部被引用资源，先按包内的分享检查去敏；通用版不带个人偏好，个人版只带本人明确选择的偏好。
- 运行数据：另存到用户选择的维护目录，按使用者和目标 Skill 隔离。不写入本工具包，不跨用户合并偏好，不默认修改安装缓存或同步设备。
- 工具能力：执行期由 AI 记录和迭代，不是后台监听器，不保证跨会话自动装载，也不承诺自动发现平台中的 Skill。未自动发现时直接提供入口路径。

## 可选的离线自检

规则与模板只需要助手能读写文件。结构检查脚本需要 **Python 3.10+，仅标准库**，不联网、不安装依赖、不修改被检查文件：

```text
python skill-lifecycle/scripts/check_bundle.py skill-lifecycle
python -B -m unittest discover -s skill-lifecycle/tests -v
```

检查通过仅表示结构、资源引用和脚本语法通过，不表示真实模型行为或宿主安装通过。

## 与原工程体系的关系

本包提炼了 Skill-Optimizer 的问题驱动改进、Skill-Evolver 的偏好确认与可回退迭代，以及创建/记录的必要规范；未搬运工程 Gate、固定磁盘路径、问题池内容或安装同步机制。原体系内部仍走原入口；独立维护闭环使用 skill-lifecycle，不要对同一问题同时跑两套记录。
