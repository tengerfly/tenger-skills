# Source-Reading（源码导读）

> IRON LAW：产出必须让「没读过这份源码的人」沿一条主线不回头地读懂——图给人全局感，文字把关键点用大白话讲透；每一处讲解必须带真实锚点（`文件路径:行号`）。
> 定位：学习加速器。不是文档搬运、不是 API 手册，是把源码的实现逻辑翻译成「流程图 + 说人话的关键点」。

## 一、四条命根子（所有产出逐关自检）

1. **通俗易懂**：大白话讲实现——每个关键点 = 它干了什么（≤2 句）+ 为什么这么设计（≤2 句，鼓励打比方）。术语首次出现必须一句话解释。禁止堆术语、禁止官话。
2. **不啰嗦**：单个关键点 ≤5 句话；单章正文 ≤300 行；代码摘录单处 ≤10 行（讲解为主，不搬代码）。
3. **逻辑清晰**：章节编号 = 推荐阅读顺序；每章只沿**一条真实执行主线**走读（一次请求 / 一次渲染 / 一次点击，从进到出），不并行铺开多个流程；图里每个主干节点在文字中必须有对应讲解，反之亦然。
4. **前置铺垫**：讲解要用到用户可能不懂的前置概念（语言特性 / 数据结构 / 协议 / 依赖库，如位运算、链表、AST、requestIdleCallback）时，**先铺垫再正题**——给 2~3 句简介 + 权威链接（官网文档 / GitHub / MDN），否则直接开讲用户必晕。链接必须核实过才给；拿不准**宁可不给**，改给精确搜索关键词——错误链接比没有链接害人（误导）。

## 二、流程（五步）

### ⓪ 输入确认
拿到仓库（`owner/repo` 或 URL）。可选输入：指定 tag/分支（默认默认分支）、聚焦模块（「只学响应式系统」）。缺分支/tag 用默认分支，不用问。

### ① 取源
1. `gh api repos/<owner>/<repo>`（或免认证 `api.github.com`）查元信息：默认分支、主语言、规模（size KB）、是否 monorepo。
2. 浅克隆到工作区外临时目录（**绝不克隆进在研项目、绝不改动源码**）：
   - 常规：`git clone --depth 1`
   - 大仓（size > 200MB 或包很多）：`--depth 1 --filter=blob:none` + `sparse-checkout` 排除 `tests / docs / examples / e2e / fixtures / benchmarks`
   - monorepo（react/vue3 级）：先只检出 `packages/` + 根配置，逐章需要时再扩
   - 详细参数与瘦身技巧见 `references/clone-playbook.md`（**此步加载**）。
3. 快速摸底：README、构建配置（vite/rollup/tsconfig）、包结构（monorepo 看 `packages/*/package.json`，单包看入口字段）。

### ② 侦察与定章
1. 识别：入口文件 → 核心 API 面（导出什么）→ 模块边界（目录职责）→ 依赖方向。
2. 规模分档定产出形态：

| 档 | 判据（取先命中者） | 产出形态 |
|---|---|---|
| 小 | 有效源码 ≤ 2 万行 且单包 | 单文档：总图 + 1~2 条主线 + 关键点 |
| 中 | 2~10 万行 或 2~4 个核心包 | 总览 + 3~5 章 |
| 大 | > 10 万行 或 ≥ 5 个核心包 或用户点名「react/vue3 这种」 | 总览 + 5~10 章，**必走章节规划确认** |

3. 大/中仓**先出《章节规划》呈用户确认再动笔**（对齐原型布局清单的确认习惯）：每章 = 章节名 + 一句话讲什么 + 依赖哪章 + 为什么排这个位置。用户说「不用确认直接写」则跳过。
4. 拆章原则：按**子系统/核心流程**拆，不按目录拆（学的是逻辑不是文件夹）；首章必是「总体架构与包结构」，尾章收「设计取舍总览」（这个仓库为什么这么设计，值 5 句话点睛）。

### ③ 深读（逐章）
1. 每章先定**核心问题**（「这章解决什么问题」，一句话，如「虚拟 DOM 怎么变成真实 DOM」）。
2. 沿一条真实执行路径走读源码：从入口跟到出口，记下经过的关键函数/数据结构，随手记锚点 `文件路径:行号`。
3. 提炼关键点：只挑「理解了它就理解了这章」的实现（核心数据结构、关键分支、巧妙处理、性能/设计取舍），宁缺毋滥，每章 5~10 个。
4. **REQUIRED 命题清点**（此步加载 `references/audit-checklist.md`）：九个通用命题逐仓过一遍——有机制就出关键点，没有就写「已核实不存在 + 检索证据」；侦察目录树里出现过、却不属于任何命题的模块，要么归进某命题，要么在总览显式标注「本次未覆盖」。禁止用总览里的一句口头词（如「有会话记忆」）代替机制章节。

### ④ 成文（按模板，**此步加载** `assets/chapter-template.md`）
每章固定骨架（保逻辑动线）：

```
## 本章在全局的位置（≤2 句，承接上一章、引出本章）
## 前置知识（可选：本章会用到、用户可能不懂的概念，每个 = 名称 + 2~3 句简介 + 权威链接或搜索词）
## 核心问题（一句话）
## 主线流程图（mermaid，一条主线，节点 ≤ 12）
## 关键点讲解（逐个：锚点 → 干什么 → 为什么；正文再遇新前置概念就地铺垫）
## 一句话收束 + 下一章预告（≤2 句）
```

mermaid 规范：
- 主图用 `flowchart TD`；跨模块调用链用 `sequenceDiagram`；包结构用 `flowchart LR` + subgraph 分组
- 单图节点 ≤ 12 个；主干实线、异常/分支虚线；节点名说人话（「打补丁 patch」而非 `p1()`）
- 图必须能在 GitHub/VSCode 直接渲染，成文后自检语法

### ⑤ 交付
1. 写/汇总 `00-总览.md`（**此步加载** `assets/overview-template.md`）：一张全仓架构总图 + 学习动线图（章节依赖顺序）+ 每章一句话 + 上手建议（先跑什么 demo、断点打在哪）。
2. 锚点核验：随机抽每章 ≥2 个 `文件:行号`，打开克隆的源码确认真实存在且内容对得上；对不上必须修。
3. 交互模式：把「总览 + 章节清单 + 从哪章开始读」呈给用户。

## 三、产物落盘

`<工作区>/.spec/源码学习/<owner>__<repo>/`：

| 文件 | 内容 |
|---|---|
| `00-总览.md` | 架构总图 + 学习动线 + 章节索引 |
| `01-<章节名>.md` … `NN-<章节名>.md` | 逐章（编号 = 阅读顺序） |
| `章节规划.md` | 大仓确认留档（章节 + 顺序理由） |

源码克隆目录在报告/总览中注明路径，学习完用户自行决定去留。

## 四、铁律

1. **只读不写**：对源码仓库零改动（克隆只作走读依据）。
2. **锚点真实**：所有 `文件路径:行号` 出自本次克隆源码；交付前抽查核验。
3. **一条主线**：每章一个流程从进到出讲完；两条主线就拆两章。
4. **图文一致**：图节点 ↔ 文字讲解一一对应，图文两张皮 = 重写。
5. **说人话 + 有节制**：四命根子（§一）逐章自检，超限即收敛。
6. **大仓必拆章、先规划后动笔**；单章超 300 行说明选题过大，拆。
7. **学源码不是抄源码**：摘录 ≤ 10 行/处，讲解永远为主。
8. **链接宁缺毋错**：前置知识只附核实过的权威链接（官方域名：react.dev / vuejs.org / developer.mozilla.org / github.com 等）；凭印象写 URL = 严重错误，拿不准改给精确搜索关键词（如「MDN Symbol」）。

## 五、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 关键点讲成 API 文档（参数列表式罗列） | 讲「干什么 + 为什么这么设计」，大白话 |
| 一章里并行讲渲染、事件、调度多条线 | 一章一条主线，其余开新章 |
| 图画得漂亮、文字另讲一套 | 图文逐节点对照，两张皮重写 |
| 全是文字没图 / 全是图没讲解 | 每章 ≥1 图；图后必有逐节点关键点讲解 |
| 讲了 20 个关键点，全是平铺 | 精选 5~10 个「懂了它就懂了这章」的点 |
| 直接拿 master 最新代码讲，行号对不上用户手上的 tag | ⓪ 拿到指定 tag/分支就按它克隆，锚点以它为准 |
| 大仓一章塞进「调度+协调+提交」 | 超规模就拆章，规划先行 |
| 摘 50 行代码让用户自己看 | ≤10 行摘录 + 讲透，超过就拆多个关键点或只讲结论 |
| 学完不知道下一步 | 总览给学习动线 + 断点建议，收尾章给取舍总览 |
| 正文用到 Symbol/位运算/AST 直接开讲，用户越看越晕 | 章首前置知识块 + 正文就地铺垫：先 2~3 句简介 + 权威链接，再进正题 |
| 前置知识链接凭印象写，点开 404 或驴唇不对马嘴 | 只给核实过的官方链接；不确定给「权威站点 + 精确关键词」（如 MDN Symbol），不给 URL |
| 深读按五域骨架走，骨架外的维度（错误降级/记忆/多代理）全漏 | ③ 步 REQUIRED 命题清点：九命题逐仓给结论，确认不存在也要写检索证据 |
| 侦察目录树里见过某模块（如 subagent/、tool-search）但没追 | 侦察发现的不明目录必须归属：某命题的关键点 / 「未覆盖」显式标注 |
| 总览口头词「有会话记忆/支持多代理」却没有对应章节 | 口头词 = 承诺，成文前逐个回源码补机制章节或删词 |
