# Tech-Review —— 技术方案评审 Skill

> **状态**：✅ 定稿
> **定位**：只做评审，不改稿。

## 一、这是什么

一个把已写好的后端技术文档（TDD）与前端技术文档（FTDD），对照需求文档（PRD）与原型文档，以 **后端技术方案评审 / 前端技术方案评审** 两个视角评审的 Skill。它不写方案、不改方案，只找出技术方案里"没有闭环"与"关联关系错误"的点，分视角记录，并汇总归档到 `.spec/技术方案评审/`。

**一句话原则**：审出问题，不改问题；问题定位到原文，结论可追溯到需求。

## 二、核心设计

| 项 | 决定 |
|----|------|
| 名称 | `Tech-Review` |
| 输入 | 用户指定 PRD + 原型 + TDD + FTDD 文件路径，或直接粘贴内容（优先读项目 `.spec/` 已有产出） |
| 输出 | 两份分视角评审文档 + 一份汇总报告 |
| 评审视角 | 后端技术方案评审 / 前端技术方案评审 |
| 评审重点 | 闭环（需求 / 流程 / 状态 / 数据）+ 关联关系（模块 / 接口 / 页面—原型） |
| 门禁 | 不设 Pass / Fail，只列问题清单 + 严重度（P0/P1/P2） |

## 三、两大评审视角（立场隔离）

| 视角 | 唯一评审标准 |
|------|-------------|
| 后端技术方案评审 | TDD 能否完整承接 PRD 且内部闭环 |
| 前端技术方案评审 | FTDD 能否完整承接 PRD + 原型 + TDD 且内部闭环 |

前后端"关联关系"由两个视角各自从己方立场核查，命中谁归谁，双方都命中则双方都记。

## 四、评审流水线

```
输入解析 ──► 双视角并行评审 ──► 前后端关联一致性专项核查 ──► 两份角色文档落盘 ──► 汇总去重 ──► 归档到 .spec/
```

1. **输入解析**：定位 PRD / 原型 / TDD / FTDD 四类文档，检测浏览器工具（Playwright → browser-use）；
2. **双视角并行评审**：后端按 `backend-checklist.md`、前端按 `frontend-checklist.md` 逐条找断点；
3. **前后端关联一致性专项核查**：按 `integration-checklist.md` 核查接口 / 数据 / 状态 / 权限一致性；
4. **两份角色文档**：`后端技术方案评审.md` / `前端技术方案评审.md`；
5. **汇总**：去重合并，标出「前后端关联错误」共性项，生成 `技术评审汇总报告.md`；
6. **归档**：全部落盘到 `.spec/技术方案评审/`。

## 五、目录结构

```

├── CONTEXT.md                      # 术语对齐源 + 决策日志

│   ├── frontend-checklist.md       # 前端技术方案评审检查清单
│   └── integration-checklist.md    # 前后端关联一致性检查清单
```

## 六、快速上手

1. 触发方式：把 PRD / 原型 / TDD / FTDD 的文件路径（或直接粘贴内容）发给我，说"帮我评审技术方案"；
2. Skill 会自动跑双视角并行评审 + 前后端关联一致性专项核查；
3. 产出三份文档：两份分视角评审 + 一份汇总报告；
4. 每个问题都标注了出处、严重度（P0/P1/P2）、问题类型（闭环 / 关联）和"建议补充方向"，但不改动你的原文。

## 七、严重度分级

| 严重度 | 含义 |
|--------|------|
| **P0 致命** | 需求无承接、流程 / 状态机断头、前后端接口对不上导致无法联调 |
| **P1 重要** | 关联关系不一致、数据字段命名冲突、异常边界缺失、数据流断链 |
| **P2 建议** | 表达可优化、术语不统一、越界内容、非关键细节缺失 |

> 注意：本 Skill **不做通过 / 不通过的裁决**，只输出问题清单。是否修改、由谁修改，交给用户决策。
