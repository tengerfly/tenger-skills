# 后端技术方案评审检查清单

> **评审视角**：以「TDD 能否完整承接 PRD 且内部闭环」为唯一标准。
> **评审基线**：需求文档（PRD，经 SKILL 步骤 1 先读 `PRD速查表.md` 建索引，逐字细节按锚点回原文）。
> **只关心**：需求承接、数据模型、状态机、流程、接口、模块关联、异常边界。
> **不关心**：前端页面 / 组件 / 交互 / 视觉。

---

## 检查维度总览

| 编号 | 维度 | 一句话判定 |
|------|------|-----------|
| BE-T1 | 需求承接完整性（需求闭环） | 每条 PRD 需求 / AC 都有技术方案承接，每个模块都能追溯到需求 |
| BE-T2 | 数据模型闭环 | 每个业务对象都有表，表字段完整承接 PRD 数据规则 |
| BE-T3 | 状态机闭环 | 状态有初始态、终态、无死循环，流转有触发条件 |
| BE-T4 | 流程闭环 | 核心流程有入口有出口，时序图有终态 |
| BE-T5 | 接口设计完整性 | 接口有入参 / 出参 / 错误处理，覆盖 PRD 隐含的全部服务能力 |
| BE-T6 | 模块边界与关联 | 「应做 / 不应做」清楚，关联图与模块文档一致 |
| BE-T7 | 异常与边界闭环 | 并发 / 幂等 / 越权 / 超限 / 空数据 / 失败恢复都定义 |
| BE-T8 | 越界提醒 | TDD 不该写前端控件 / 视觉 / 交互细节 |

---

## BE-T1 需求承接完整性（需求闭环）

**检查方法**：把 PRD 的每条需求 / 验收标准（AC）列出来，逐个追问「这条需求在 TDD 哪个模块 / 哪张表 / 哪个接口里被承接了？」

**判定为"没闭环"的情形**：
- PRD 有某条需求 / 功能，但 TDD 全文找不到对应模块 / 接口 / 表承接（**需求漏做**）；
- TDD 有某个模块 / 接口 / 表，但 PRD 里找不到对应需求来源（**凭空设计**，需确认是否越界）；
- PRD 的 AC 编号在 TDD 测试用例中找不到对应承接（测试用例与 AC 脱节）。

**示例（问题表述）**：
> `TDD overview.md §模块清单` 未包含 PRD `03_优惠券.md` 的"优惠券核销"功能 → 该需求无后端承接，P0。

---

## BE-T2 数据模型闭环

**检查方法**：把 PRD 的每个业务对象列出来，逐个追问「这个对象在 TDD 总文档表结构里有没有表？表字段是否完整承接了 PRD 的数据规则？」

**判定为"没闭环"的情形**：
- 业务对象无对应表（**缺表**）；
- 表字段缺失：PRD 有某字段 / 属性，但表里没有（**缺字段**）；
- 字段要素不完整：字段缺类型 / 可空 / 默认值 / 约束 / 索引 / 注释；
- 数据规则未承接：PRD 说"金额用分""时间用时间戳"，表结构与之一致吗；
- 跨模块同一业务对象被建了多张表，字段不一致。

---

## BE-T3 状态机闭环

**检查方法**：对每个有生命周期的对象，画状态流转图，检查四点：有初始态、有终态、无死循环、每个流转有触发条件。

**判定为"没闭环"的情形**：
- 状态机死循环（A → B → A，永远走不到终态）；
- 无终态（对象永远结束不了）；
- 状态流转无触发条件（什么条件下从 A 变 B 没说）；
- 非法逆向未定义（如"已取消"能否重新激活没说）；
- TDD 状态定义与 PRD 状态不一致（PRD 有 5 个状态，TDD 只设计 4 个）。

> 状态机不闭环通常判 **P0**，直接阻塞后端建模。

---

## BE-T4 流程闭环

**检查方法**：对每个核心业务流程，从头走到尾，检查入口与出口是否成对，流程图 / 时序图是否有终态。

**判定为"没闭环"的情形**：
- **断头流程**：流程走着走着断了，没有走到可见的业务出口；
- **无头流程**：某状态 / 数据出现了，但没有定义从哪个上游流程进入；
- 时序图 / 流程图中节点死循环、无终态；
- 跨模块流程在某个模块的边界处断了（模块 A 产出，模块 B 未消费）。

---

## BE-T5 接口设计完整性

**检查方法**：对每个接口，追问「入参、出参、错误处理是否定义清楚？PRD 隐含的服务能力是否都被接口覆盖？」

**判定为"没闭环"的情形**：
- 接口缺入参 / 出参定义（无法联调）；
- 接口缺错误码 / 异常返回定义；
- PRD 隐含需要服务端能力，但 TDD 没有对应接口（**能力缺失**）；
- 接口之间调用关系不清（谁调用谁、同步还是异步）。

> 注：本清单只要求接口要素完整，不要求 TDD 写前端如何调用（那是 FTDD 的职责）。

---

## BE-T6 模块边界与关联

**检查方法**：对照 TDD 总文档架构图 / 关联表 与 各模块文档「上下游依赖」章节。

**判定为"关联关系错误"的情形**：
- 总文档关联图有一条边，但某端模块文档「上下游依赖」没写（**有边无依赖**）；
- 模块文档写了依赖某个模块，但总文档关联图没画（**有依赖无边**）；
- 关联类型不明确：数据传递 / 调用依赖 / 事件触发没标注，或传递产物没说清；
- 关联方向错误（A → B 写成 B → A）；
- 模块「应做 / 不应做」边界缺失，导致模块间职责重叠或打架。

---

## BE-T7 异常与边界闭环

**检查方法**：从后端视角排查五类异常 + 本业务特有异常，逐条追问「系统如何处理」。

**判定为"没闭环"的情形**：
- **并发 / 重复提交**：幂等处理未定义；
- **越权访问**：谁有权限调用 / 访问未定义；
- **超限极值**：数据超上限、极值场景处理未定义；
- **空数据**：数据不存在时的返回未定义；
- **中断 / 失败**：流程中途失败、事务回滚、恢复方式未定义。

---

## BE-T8 越界提醒（TDD 写了不该写的）

**检查方法**：扫描 TDD 是否出现前端实现细节。这是"TDD 越界"而非"缺失"，单独标注为「越界」。

**判定为"越界"的情形**：
- 前端控件 / 组件名（Toast / Modal / 具体组件库组件）；
- 前端视觉 / 布局 / CSS 细节；
- 前端状态管理 / 路由实现细节。

> 越界项标注为「建议移除 / 改写为服务端职责」，严重度通常 **P2**。
