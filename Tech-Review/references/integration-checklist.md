# 前后端关联一致性检查清单

> **检查视角**：以「前后端方案能否无缝对接、数据流端到端闭环」为唯一标准。
> **基线**：后端技术文档（TDD）接口 / 数据模型 / 状态定义 ↔ 前端技术文档（FTDD）fetch / 数据类型 / 状态展示。
> **归因规则**：命中项归因到后端 / 前端 / 双方——接口未定义归后端，前端未消费或调错归前端，字段命名冲突归双方。

---

## 检查维度总览

| 编号 | 维度 | 一句话判定 |
|------|------|-----------|
| IT-1 | 接口契约一致性 | 前端每个 fetch 都能在后端找到一一对应的接口，方法 / 路径 / 参数一致 |
| IT-2 | 数据模型一致性 | 前端数据类型 / 字段名与后端表结构 / 返回字段一致 |
| IT-3 | 状态 / 枚举一致性 | 前端状态展示与后端状态定义一致 |
| IT-4 | 数据流端到端闭环 | 用户操作 → 前端请求 → 后端处理 → 响应 → 前端更新 → 反馈全链路无断点 |
| IT-5 | 权限 / 错误处理一致性 | 前端错误处理与后端错误码、权限控制前后端一致 |
| IT-6 | 接口覆盖双向 | 前端需要的接口后端都有，后端提供的接口前端都消费 |

---

## IT-1 接口契约一致性（最关键）

**检查方法**：列出 TDD 全部接口清单（方法 + 路径 + 入参 + 出参 + 错误码），再列出 FTDD 全部 fetch 接口，**逐条双向比对**。

**判定为"不一致"的情形**：
- 前端调用的接口后端未定义（**归因后端**：接口缺失，P0）；
- 方法不一致：后端 POST，前端 GET（**归因前端**：调错方法，P0）；
- 路径不一致：`/api/orders` vs `/api/order`（**归因前端或后端**，P0）；
- 入参字段不一致：前端传 `planId`，后端定义 `plan_id`（**归因双方**：命名未统一，P1）；
- 出参字段不一致：前端读 `data.list`，后端返回 `data.rows`（**归因双方**，P1）；
- 错误码 / 错误结构不一致（**归因双方**，P1）。

---

## IT-2 数据模型一致性

**检查方法**：对照 TDD 表结构 / 返回 DTO 字段 与 FTDD 的 TypeScript 类型定义。

**判定为"不一致"的情形**：
- 字段命名风格不一致：后端 snake_case（`created_at`），前端 camelCase（`createdAt`），但方案没写转换约定；
- 字段类型不一致：后端金额用整数（分），前端按浮点（元）处理；
- 必填 / 可空不一致：后端可空字段，前端按必填处理（或反之）；
- 枚举值不一致：后端 `0/1/2`，前端 `"pending"/"done"`，没写映射。

---

## IT-3 状态 / 枚举一致性

**检查方法**：对照 TDD 状态机定义 与 FTDD 状态展示 / 文案。

**判定为"不一致"的情形**：
- 后端定义 5 个状态，前端只展示 4 个（或反之）；
- 同一状态前后端叫法不同（后端 `processing`，前端展示"审核中"但枚举叫 `reviewing`）；
- 状态颜色 / 文案与后端状态值对不上。

---

## IT-4 数据流端到端闭环

**检查方法**：挑 1~2 条核心业务链路，从用户操作走到后端再走回前端，检查全程是否有断点。

**判定为"没闭环"的情形**：
- 前端发起了请求，后端流程走到某步没有返回（**后端无出口**）；
- 后端返回了数据，前端没有消费 / 展示（**前端无消费**）；
- 异步场景（轮询 / 推送 / 回调）前后端谁触发、谁接收没对齐；
- 长任务 / 文件上传等跨多步场景，中间态与终态通知前后端没对齐。

---

## IT-5 权限 / 错误处理一致性

**检查方法**：对照 TDD 权限 / 错误码定义 与 FTDD 权限路由 / 错误拦截。

**判定为"不一致"的情形**：
- 后端有权限校验，前端没有对应权限路由 / 按钮显隐（或反之）；
- 后端错误码，前端没写对应拦截 / 提示（或反之）；
- 登录态 / token 处理前后端不一致（过期 / 刷新策略）。

---

## IT-6 接口覆盖双向

**检查方法**：做两张"覆盖矩阵"——前端需要哪些接口、后端提供哪些接口，双向查漏。

**判定为"不一致"的情形**：
- 前端需要的接口后端没有（**归因后端**，P0）；
- 后端提供的接口前端没用（**归因前端**：漏做消费，或归因后端：多余设计，P1）；
- 同一业务操作前端拆成多个请求，后端只有一个接口（或反之），导致前端需要聚合 / 拆分，方案没写清。
