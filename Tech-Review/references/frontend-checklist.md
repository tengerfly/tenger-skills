# 前端技术方案评审检查清单

> **评审视角**：以「FTDD 能否完整承接 PRD + 原型 + TDD 且内部闭环」为唯一标准。
> **评审基线**：需求文档（PRD）+ 原型文档 + 后端技术文档（TDD）。
> **只关心**：页面承接、交互闭环、状态覆盖、hooks 数据流、fetch 对接、组件关联。
> **不关心**：数据库、表结构、服务端实现。

---

## 检查维度总览

| 编号 | 维度 | 一句话判定 |
|------|------|-----------|
| FE-T1 | 页面承接完整性（页面—原型闭环） | 每个原型页面都有前端方案承接，每个方案页面都能追溯到原型 |
| FE-T2 | 需求承接完整性（需求闭环） | 每条 PRD 前端需求都有前端方案承接，每个模块都能追溯到需求 |
| FE-T3 | 交互闭环 | 每个操作有触发 → 反馈 → 流向，无断头 / 无头链路 |
| FE-T4 | 状态覆盖 | 空态 / 加载 / 成功 / 失败 / 边界都定义 |
| FE-T5 | hooks 数据流闭环 | 数据从 fetch → state → 渲染全程闭环，无断链 |
| FE-T6 | fetch 接口对接一致性 | 每个 fetch 接口都能在 TDD 找到对应后端接口 |
| FE-T7 | 模块边界与关联 | 「应做 / 不应做」清楚，关联图与模块文档一致 |
| FE-T8 | 越界提醒 | FTDD 不该写数据库 / 表结构 / 服务端实现 |

---

## FE-T1 页面承接完整性（页面—原型闭环）

**检查方法**：把原型文档的每个页面列出来，逐个追问「这个页面在 FTDD 页面清单里有没有？路由、职责、所属模块是否对应？」

**判定为"没闭环"的情形**：
- 原型有某页面，FTDD 页面清单没有（**页面漏做**）；
- FTDD 页面清单有某页面，但原型找不到（**凭空页面**，需确认）；
- 页面职责与原形不符（原型是"订单列表"，方案写成"用户列表"）；
- 页面缺路由 / 职责 / 所属模块 / 对应原型文件标注。

---

## FE-T2 需求承接完整性（需求闭环）

**检查方法**：把 PRD 的前端相关需求 / AC 列出来，逐个追问「这条需求在 FTDD 哪个页面 / 组件 / hooks 里被承接了？」

**判定为"没闭环"的情形**：
- PRD 有某交互 / 功能，FTDD 找不到对应页面 / 组件 / hooks（**交互漏做**）；
- FTDD 有某组件 / hooks，但 PRD 找不到对应需求（**凭空设计**）；
- PRD 的 AC 编号在 FTDD 测试用例中找不到对应承接。

---

## FE-T3 交互闭环（触发 → 反馈 → 流向）

**检查方法**：对每个用户操作，按「① 用户做什么 → ② 系统给什么反馈 → ③ 反馈之后流向哪里」三段追问，缺任何一段即没闭环。

**判定为"没闭环"的情形**：
- 用户点了某操作，方案没写系统给什么反馈（**做了没反应**）；
- 给了反馈，但没写反馈之后页面 / 用户流向哪里（**反馈后不知道去哪**）；
- **断头链路**：链路走着走着断了，没走到业务出口；
- **无头链路**：某页面 / 状态出现了，但没定义从哪个入口进入。

---

## FE-T4 状态覆盖

**检查方法**：对每个页面 / 列表 / 交互，逐一排查五类状态：空态、加载态、成功态、失败态、边界态。

**判定为"没闭环"的情形**：
- 空态缺失：列表无数据时显示什么没说；
- 加载态缺失：请求等待期间页面状态没说；
- 失败态缺失：请求失败时用户看到什么、能做什么没说；
- 边界态缺失：数据超长、超限、无权限时的表现没说。

---

## FE-T5 hooks 数据流闭环

**检查方法**：对每个模块，追问「数据从哪来（fetch）→ 存哪（state）→ 怎么变（hooks）→ 渲染到哪（组件）」，四段是否成链。

**判定为"没闭环"的情形**：
- 某数据状态定义了，但没写从哪个接口 / hooks 获取（**数据无源**）；
- 某接口返回了数据，但没写存到哪个 state、渲染到哪个组件（**数据无消费**）；
- hooks 之间数据传递断链（hook A 产出，hook B 未消费）；
- 组件直接散落业务逻辑，未下沉到 hooks。

---

## FE-T6 fetch 接口对接一致性（前后端关联核心）

**检查方法**：把 FTDD 每个 fetch 接口与 TDD 接口清单**双向比对**。

**判定为"关联关系错误"的情形**：
- FTDD 调用了 TDD 未定义的接口（**前端调了后端没有的接口**，P0）；
- TDD 定义了接口，但 FTDD 没有对应消费（**后端接口前端没用**，孤儿接口，P1）；
- 方法不一致（后端 POST，前端写成 GET）；
- 路径不一致（`/api/orders` vs `/api/order`）；
- 入参 / 出参字段不一致（字段名、类型、必填性对不上）。

> 这是前后端最常出问题的点，也是联调阻塞的主因，通常判 **P0/P1**。

---

## FE-T7 模块边界与关联

**检查方法**：对照 FTDD 总文档关联图 与 各模块文档「上下游依赖 / fetch 接口对接」章节。

**判定为"关联关系错误"的情形**：
- 总文档关联图有一条边，但模块文档没写对应依赖（**有边无依赖**）；
- 模块文档写了依赖（路由跳转 / 共享组件 / 共享状态 / 接口依赖），但总文档没画（**有依赖无边**）；
- 关联类型不明确（路由跳转 / 共享组件 / 共享状态 / 接口依赖没标注）；
- 关联方向错误；
- 模块「应做 / 不应做」边界缺失，页面 / 组件归属打架。

---

## FE-T8 越界提醒（FTDD 写了不该写的）

**检查方法**：扫描 FTDD 是否出现后端实现细节。这是"FTDD 越界"而非"缺失"，单独标注为「越界」。

**判定为"越界"的情形**：
- 数据库 / 表结构 / 索引 / 存储设计；
- 服务端业务逻辑 / 中间件 / 缓存 / 消息队列实现；
- 服务端框架 / 语言选型细节。

> 越界项标注为「建议移除 / 改写为前端职责」，严重度通常 **P2**。
