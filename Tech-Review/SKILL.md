# 技术方案评审 Skill

> 只审不改；问题定位到原文，结论可追溯到需求。
> 术语：TDD = 后端技术方案文档；FTDD = 前端技术方案文档。

## 一、评审对象与输入基线

| 输入 | 角色 | 说明 |
|---|---|---|
| PRD | 评审基线 | 判断技术方案是否完整承接需求 |
| 原型 | 评审基线 | 判断前端方案是否覆盖页面/交互 |
| TDD | 评审对象 | 后端选型、架构、模块、表结构、接口、测试 |
| FTDD | 评审对象 | 前端选型、架构、页面、组件、hooks、fetch、测试 |

PRD 与原型是尺子，TDD/FTDD 是被量物。

## 二、双视角评审（立场隔离）

| 视角 | 标准 | 检查 | 不检查 |
|---|---|---|---|
| 后端技术方案评审 | TDD 完整承接 PRD 且内部闭环 | 需求承接、数据模型、状态机、流程、接口、模块关联、异常边界 | 前端页面/组件/交互/视觉 |
| 前端技术方案评审 | FTDD 完整承接 PRD + 原型 + TDD 且内部闭环 | 页面承接、交互闭环、状态覆盖、hooks 数据流、fetch 对接、组件关联 | 数据库、表结构、服务端实现 |

前后端关联问题由两视角各自从己方核查；命中谁归谁，双方命中则双方都记。

## 三、评审两大目标

### 找「没闭环」

| 闭环 | 含义 | 典型断点 |
|---|---|---|
| 需求 | 每条 PRD 需求有方案承接、每个设计可追溯需求 | 需求无人承接；设计无来源 |
| 流程 | 流程/交互链路有入口有出口 | 断头（只进不出）；无头（只出不进） |
| 状态 | 状态机有初态、终态、无死循环 | 无终态；死循环；流转无触发 |
| 数据 | 产生→传输→消费→反馈全闭环 | 返回字段未消费；请求字段后端未定义 |

### 找「关联关系错误」

| 关联 | 核查 | 典型错误 |
|---|---|---|
| 后端模块 | TDD 总文档关联图 ↔ 模块文档上下游 | 一边有边/依赖、另一边没写 |
| 前端模块 | FTDD 总文档关联图 ↔ 模块文档 | 同上 |
| 前后端接口 | FTDD fetch ↔ TDD 接口清单 | 调的没有、定义没用、方法/路径/参数不一致 |
| 页面—原型 | FTDD 页面清单 ↔ 原型页面 | 原型有方案没写；方案写了原型没有 |

## 四、适用范围

- 适用：已写好的 TDD/FTDD 评审、检测、审查、走查；需求与原型定稿后、开发前做闭环+关联会审。
- 不适用：写技术方案（Backend/Frontend-Tech-Design）；评审需求（PRD-Review）；改技术方案（只审不改）。

## 五、评审流水线（7 步）

```
输入 → 1 输入解析 → 2 浏览器检测 → 3 双视角并行评审 → 4 前后端关联专项
→ 5 两份角色文档 → 6 汇总 → 7 任务清单 + 确认 → 归档
```

1. **输入解析**：优先读 `.spec/`：PRD（先读速查表）、原型、`.spec/TDD/VN/`、`.spec/FTDD/VN/`；缺失回退用户路径/粘贴。
2. **浏览器工具检测**：本 skill 为软检测——检测顺序与两级行为见仓库根 `shared/browser-policy.md`；任一可用则核验选型版本、弃用 API、官方最佳实践；全无则跳过，不阻塞评审（核心是文档交叉比对）。
3. **双视角并行评审**：后端按 `references/backend-checklist.md`、前端按 `references/frontend-checklist.md` 逐条执行；独立上下文（subagent/新会话）互不可见、不参考生成过程；条件允许可用不同模型交叉审查。
4. **前后端关联专项**：按 `references/integration-checklist.md` 核查接口契约、数据模型、状态枚举、数据流、权限/错误处理；命中项归因后端/前端/双方。
5. **两份角色文档落盘**：按 `assets/role-review-template.md` 写 `后端技术方案评审.md` / `前端技术方案评审.md` 至 `.spec/技术方案评审/`。
6. **汇总**：按 `assets/summary-template.md` 合并去重，重点标前后端关联错误，按 P0/P1/P2 统计。
7. **任务清单 + 用户确认**：按 `assets/issue-list-template.md` 生成任务清单（状态 `待确认`）；每条附修复判据；逐条确认（要改 → `已确认`；不改 → `已忽略` + 理由）；P0/P1 阻断、P2 可留后续；复核只验本轮清单，不无限新增；轮次上限 3，不收敛即停止汇报。确认后交 Backend/Frontend-Tech-Design 修改并回填。

> 防评审死循环三招与任务清单状态机的定义见仓库根 `shared/anti-deadloop.md`，本 skill 只保留上述流程参数，不重复定义。

所有文档落盘 `.spec/技术方案评审/` 后交付。

## 六、严重度分级（只标注，不设门禁）

> P0/P1/P2 定义与处理口径见仓库根 `shared/anti-deadloop.md` §二；下表为本域典型示例。

| 级别 | 含义 | 典型 |
|---|---|---|
| P0 | 需求无承接、流程/状态机断头、前后端接口对不上无法联调 | 核心需求无方案；调用未定义接口；状态机无终态 |
| P1 | 关联不一致、字段命名冲突、异常边界缺失、数据流断链 | 总图与模块文档不一致；字段命名不一致；空/失败态缺失 |
| P2 | 表达可优化、术语不统一、越界内容、非关键细节缺失 | 方案写前端视觉/后端实现细节；命名风格不统一 |

## 七、评审铁律

1. **只审不改**：不改 TDD/FTDD 原文；修改由 Backend/Frontend-Tech-Design 经任务清单交接。
2. **定位到原文**：每条标文件/章节/接口/表，引用关键句。
3. **零幻觉**：结论基于 TDD/FTDD/PRD/原型；区分「方案缺失（该写没写）」与「越界（不该写）」。
4. **视角隔离 + 独立上下文**：各视角独立评审、互不可见、不参考生成过程；关联问题归因责任方。
5. **不设门禁**：只出问题清单，不判通过/不通过。
6. **成因必写**：写清为何没闭环/关联错（如方案未承接某状态、字段只定义单边）；推不出标「成因未明」，禁臆造。

## 八、常见错误对照表

| 错误 | 纠正 |
|---|---|
| 评审时改方案 | 只记问题，给建议方向 |
| 两视角混写 | 分视角成文，汇总合并 |
| 漏审一端 | 后端/前端两份都要出 |
| 漏接口一致性 | 步骤 4 专项双向比对 |
| 问题无出处 | 定位到文件/章节/接口/表 |
| 越界当缺失 | 区分两类标注 |
| 结论笼统 | 写清没闭环/错在哪 + 方向 |
| 无成因 | 补成因，可考才写 |
