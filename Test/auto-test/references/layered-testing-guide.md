# 分层测试执行指南（L0-L3）

> 执行各层前的操作细则。分层短路：上层失败不进下层，AI token 只花在 L2/L3。

## L0 确定性门禁（零 AI token，秒~分钟）

按成本升序执行，任一步失败即停并出证据：

| 步骤 | 命令模板 | 失败证据要求 |
|---|---|---|
| 依赖安装 | `npm ci` / `pnpm install --frozen-lockfile` | 完整报错输出 |
| 类型检查 | `npx tsc --noEmit`（或项目等价物） | 错误文件：行号清单 |
| Lint | `npx eslint .`（或项目等价物） | 错误清单（warning 不阻断） |
| 单元测试 | `npx vitest run` / `npm test` | 失败用例名 + 断言 diff |
| 构建 | `npm run build` | 构建错误输出 |

规则：
- 命令必须**完整跑完**（禁只跑改动文件、禁用上轮结果）；
- 输出全文保存到 `evidence/`（`l0-<步骤>.log`）；
- 项目缺任一环节（如无单测）：登记 P1「验收闭环缺失」，不虚构通过。

## L1 契约冒烟 + live 主链 E2E（分钟级）

**契约冒烟**：
- 输入：接口清单（来自接口文档 / OpenAPI / 路由提取）；
- 对每条关键接口发真实请求，断言：状态码、响应结构、关键字段存在与类型；
- 有 OpenAPI 契约时按契约校验（可用 schemathesis / dredd / 手写 curl+jq）；
- 启动被测服务后再跑；服务起不来 → 停，登记 P0（不可运行）；
- 证据：请求/响应原文存 `evidence/network/l1-<接口>.log`。

**live 主链 E2E（后端为主的项目在此层完成核心验收）**——按业务状态机顺序驱动真实 API，轮询异步任务至终态：
1. **先读后写**：每个轮询条件写之前，先 GET 一次目标资源，确认真实响应字段（禁凭文档/想象假定字段存在——实测中 `shots[].status`、`parseResult vs scenes`、触发接口返回 201 而非 200 都曾踩坑）；
2. **触发式接口**（返回 taskId 的）统一接受 200/201；轮询用查询端点判终态，失败信号用产品内建的 failure 字段（如 lastFailure / error）；
3. **轮询节奏**：间隔 ≥ 单任务典型时长的 1/5（真实 LLM 任务常 30-120s，间隔 5s 起步）；超时上限 ≥ 5×典型时长；
4. **重试判死只认新证据**：失败留痕字段（lastFailure 等）的**时间戳必须新于上次重试时刻**才能作为失败依据；重试触发后必须等任务走完一轮再评估；
5. **每步带幂等键**（Idempotency-Key 随机化），失败步骤可安全重发；
6. **多阶段断言从实时状态取值**：下一步需要的 ID/字段（如 sceneNos）必须来自上一步的**最新**响应，禁止引用更早阶段的快照；
7. 中断续跑：脚本支持从指定 workId/阶段恢复，避免重烧已通过阶段的 LLM token；
8. **环境特异性坑（Windows 实录）**：业务键含 `:` 的对象存储 key 在磁盘路径非法（编码磁盘路径、账本 key 不变）；ffmpeg/libass 滤镜参数里的盘符路径转义易错（用 ffmpeg 的 cwd + 相对文件名绕开）；此类缺陷只在真实产物落盘时暴露，mock 层永远测不到——**真实链路回归是唯一可靠的验收方式**。

## L2 视觉 E2E（主要 AI 成本层）

### 浏览器工具降级链

1. Playwright + **Midscene**（`aiAct/aiAssert/aiQuery`，视觉定位免 selector）——首选；
2. Playwright 原生（选择器 + `toHaveScreenshot`）——Midscene 不可用时降级，报告**明示降级**；
3. Playwright 协议 actionability 超时（点击/填充反复超时但元素存在）→ 页面脚本兜底（`evaluate` 内 `el.click()` / React 原生 setter+input 事件），**同时登记一条缺陷**（控件对自动化协议不可操作，人工正常）；
4. 全无浏览器工具 → 先按仓库根 `../../../shared/browser-policy.md` §五 获取（DSH 环境：MCP 插件 / Playwright 备选）；仍不可用 → **报错停止，不产出**（禁硬跑、禁凭想象写结果）。

### 执行规范

- 用例来源：`.spec/auto-test/用例库/`，按编号顺序执行，逐条回填结论；
- 全状态：每条用例的 `setup` 先注入前置状态，再验证该状态下页面展示与可操作项；
- 全点击：逐页盘点可交互元素（按钮/链接/输入/下拉/开关/卡片/行操作/分页），逐个触发并验证「有反应 → 反应对 → 无报错 → 无死链」；未点到的标原因；
- 三态必测：每页加载态 / 空态 / 错误态（错误态用路由拦截构造，见 case-authoring-guide）；
- 监听：全程挂 console 监听（error 级即记录）与网络监听（`page.on('response')`）；
- 慢接口阈值：>1000ms 慢 / >3000ms 很慢 / >5000ms 严重（【设计假设】可调），逐条记录路径+方法+耗时+场景；
- 样式断言：优先 `aiAssert` 对照设计稿自然语言描述；截图命名 `<页面>_<问题>_<序号>.png`；
- 失败用例：截图 + console + 网络 HAR 三件套齐活才算一条合格失败记录。

## L3 探索性测试（可选，按需）

- 形态：给 agent 一个目标（如「想办法让下单流程失败」）+ 完整的探索自由度，无预设脚本；
- 沙箱执行（Docker）：探索会乱点乱填乱提交，禁止对宿主环境直跑；
- 外部副作用先 mock（发短信/支付/邮件），否则跳过相关路径并声明；
- 产出：发现的异常进报告（按 P0-P3 分级），**不阻断**交付判定；
- 收获转化：探索发现的稳定缺陷 → 补一条正式用例进用例库（下次回归可重复）。

## 执行节奏

- 全量验收：L0→L1→计划确认→L2→（可选 L3）→汇总；
- 修复后回归：L0→L1→L2 全量（不是只跑失败项）；
- 日常冒烟：仅 L0（可挂 git hook / CI，见 fix-loop-guide）。
