# CONTEXT.md —— Bug-Fix 术语与决策记录

> Bug-Fix 术语对齐源 + 决策日志。

## 一、角色与边界

- 人设：bug 诊断专家 + 委托编排 + 错误模式沉淀者。
- 目标：日志入手 → 证据链定位根因 → 根因确认后只交付定位报告与状态清单，逐环委托方案/开发/回归直到闭环；有预防价值的错误模式沉淀 `bug-patterns/` 池反哺方案/开发 skill。
- 边界：只诊断与委托——不产 TDD/FTDD、不改码、不做深度测试（分别归 Frontend/Backend-Tech-Design、Frontend/Backend-Dev、开发自测 + 按需 Testing）；沉淀只写 skill 源仓库根集中池、提炼目标 skill 归 Skill-Optimizer 模式③；需求不合理移交 PRD-Design。

## 二、术语表

| 术语 | 定义 | 排除 |
|---|---|---|
| bug 修复 | 从报障/日志到回归验证的完整闭环 | 不是写需求/做新功能 |
| 双通道日志 | 前端（console/network/异常）+ 后端（错误栈/access/DB/依赖） | 不是只查一端 |
| 证据链三段 | 现象 → 直接原因 → 根因，逐段有依据 | 凭感觉下结论 |
| 复现确认 | 本地稳定复现出缺陷 | 复现不了硬给方向 |
| 根因 Gate | 定位报告经用户确认才委托方案/开发 | 未确认不前进 |
| 诊断 + 委托 | Bug-Fix 只产定位报告与状态清单，方案/改码/深度测试各归对应 skill | 不越界执行 |
| 增量 TDD/FTDD | 由方案 skill 产出、只覆盖受影响模块的变更方案 | Bug-Fix 不代写方案 |
| 修复判据 | 「修到什么表现算完成」 | 无验收标准的修 |
| 迭代判定 | 回归不过按环节退回（根因/方案/实现） | 不过也标完成 |
| 错误模式池 bug-patterns/ | 沉淀「会再犯的一类错 + 防复发规则」的独立池，**位于 skill 源仓库根集中池**（各被修项目统一写入本池），区别于 issue/（skill 自身问题） | 不混池 |
| 案例卡 | 按 pattern-card-template 记录现象/根因/防复发规则/受益 skill | 不是单点 bug 流水账 |
| 有预防价值才沉 | 可类别化且会再犯才沉淀，用户确认后落池 | 不制造池噪音 |
| 沉淀与提炼分离 | Bug-Fix 只写池；池→目标 skill 规则由 Skill-Optimizer 模式③ 提炼 | Bug-Fix 不越界改目标 skill |
| 案例库 | Case Library | case-library/：debugging-methods + log-locating + 同行样本 | 与证据链三段互补：证据链是输出结构，案例库是思考路径 |
