# 双通道日志识别与截取指南

> 用途：Bug-Fix 步骤 2「双通道日志解析」的落地细则。按日志来源选通道，两侧都涉及则都走、先按链路串接。
> 原则：日志是证据不是结论——先截全（含时间戳、堆栈、请求上下文），再解读，不凭一行报错拍板。

## A. 前端通道

### A1 日志种类与识别要点

| 种类 | 形态 | 提示的问题 |
|---|---|---|
| console 业务日志 | `console.error/warn` + 业务提示 | 业务逻辑分支错、参数不符预期 |
| 未捕获异常 | `Uncaught TypeError/ReferenceError…` + 堆栈 | 空值访问、未定义方法、异步回调异常 |
| React 渲染异常 | ErrorBoundary 报错页 / `componentDidCatch` | 组件渲染态崩溃（数据形状变化、null 渲染） |
| network 请求失败 | 4xx / 5xx / timeout / CORS / aborted | 接口报错、超时、跨域、token 失效、请求被取消 |
| 资源加载失败 | `Failed to load resource`（JS/CSS/IMG） | 静态资源 404、CDN、打包路径错 |
| Promise 拒绝 | `Unhandled promise rejection` | async 内异常未捕获、finally 未处理 |
| 路由/状态异常 | 白屏、跳错页、store 报错 | 路由守卫、状态初始化、持久化恢复 |

### A2 截取方法

- 打开浏览器 DevTools Console/Network，勾选「Preserve log」后重演操作路径，避免早期报错被清屏。
- Network 面板按请求筛选：**状态码、耗时、请求/响应体、发起方堆栈**（Initiator）四件套齐全再判定。
- 抓浏览器 console 全量：可在页面注入 `window.onerror` + `window.addEventListener('unhandledrejection')` 兜底采集，或从线上监控（Sentry/Arms 等）拉取。
- 记下复现时的**精确操作步骤 + 时间点 + 入参数据**，保证可直接复现。

## B. 后端通道

### B1 日志种类与识别要点

| 种类 | 形态 | 提示的问题 |
|---|---|---|
| 应用错误栈 | `ERROR … at Service.func (file.ts:42)` | 业务/服务层异常，直接定位文件行 |
| 请求/access 日志 | 方法 + 路径 + 状态码 + 耗时 | 哪个接口错、慢、被限流 |
| 参数校验失败 | 4xx + validation message | 入参不符合 DTO 约束（接口契约问题） |
| DB 异常 | SQL error、连接池耗尽、唯一键冲突、死锁 | 数据/表结构/事务问题 |
| 慢查询 | 单条 SQL 耗时超阈值 | 缺索引/全表扫/笛卡尔积 |
| 缓存/队列/依赖服务 | Redis/MQ/下游 timeout、retry 耗尽 | 依赖不可用、超时设置、网络分区 |
| 鉴权/权限 | 401/403 日志 | token/权限判断错 |
| 业务告警 | 自定义 error code + 上下文 | 业务规则命中失败 |

### B2 截取方法

- 先按**时间窗 + trace_id/requestId** 串：单条请求从前端 → 网关 → 服务 → DB 的全部日志，用同 ID 聚合，避免只看孤立的某条错误。
- 无 trace_id 时用 `时间 + 接口路径 + 特征入参（如 userId）` 三维粗筛后逐条对齐。
- 错误栈**完整截取**（含 Caused by 链、上一帧调用），不截首行。
- 附环境上下文：环境（dev/staging/prod）、版本/commit、实例、数据库/中间件版本、是否刚发版（对照最近变更）。

## C. 链路串接与初步归因

1. **归端**：报错形态 → 归属前端/后端/依赖三方（如 network 5xx + 后端错误栈同现 = 后端；network 成功但页面错 = 前端；超时 + 下游日志 = 依赖/网络）。
2. **串链**：有 trace_id 沿 ID 聚合全链；缺 ID 用时间窗对前端请求 ↔ 后端 access 日志。
3. **分离表面与根因**：前端报错可能是后端错误的上抛，后端 5xx 可能是 DB/依赖引起——日志解析只做「定位到第一异常点」，根因判断留给步骤 4。
4. **记录输出**：时间窗、触发操作、关键错误行（原文引用）、状态码、链路 ID、相关代码线索，写入定位报告素材。

> 反例（反面参考）：只看到「network 500」就断言后端 bug → 实际是前端传参非法被后端校验拒绝。正例：先串前端请求体 + 后端校验日志，确认入参结构，才判断责任端。
