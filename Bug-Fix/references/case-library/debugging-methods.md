# 调试方法学（Debugging Methods）

> 用途：收敛根因、生成假设时的方法参考。与 `root-cause-guide.md`（证据链三段）互补：证据链是「输出结构」，本文件是「思考路径」。

---

## 一、系统性 4 阶段调试

- **REPRODUCE**（复现）→ **ISOLATE**（二分/git bisect 缩小范围）→ **DIAGNOSE**（科学法 + 日志策略）→ **FIX&VERIFY**（先写失败测试再最小修复）。

## 二、假设驱动调试

- 生成 3–5 条可测假设 → 插桩收集证据 → 逐条确认/排除 → 最小修复。
- 核心：**不猜测、靠证据**（与本 Skill 证据链三段一致）。

## 三、铁律：先根因后修复

- `NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST`——绝不只修症状。

## 四、数据流回溯

- 从报错点沿调用链向上追溯，找到原始触发点，而非在症状处修。

## 五、5-Whys 根因分析

- 连问 5 个 why，直到可行动、可预防、根本的原因；输出 Why Chain 表。

## 六、三次修复上限（架构检查）

- 连续 3 次修复失败 → STOP，说明是架构问题，需讨论而非继续打补丁（防「打地鼠」）。

## 七、反模式（不要做）

- 瞎猜乱改 / 假设未经验证 / 信任注释胜过代码 / 生产环境 print / 只修症状。

## 八、常见根因速查表

| 现象 | 常见根因 |
|---|---|
| 本地 OK 线上挂 | 环境差异/时序/资源限制 |
| 间歇失败 | 竞态/资源争用 |
| 数据错 | 类型/编码/时区 |
