# 苏格拉底拷问协议（grill-me 式单步拷问）

> 执行范围：PRD-Design 澄清环节（S2 澄清① / S5 澄清② / V2 差异澄清）。吸收 grill-me、grill-with-docs 的决策树 + 单步提问法，内嵌执行，不依赖外部 skill。
> ⛔ BLOCKING：收敛点未过「收敛证明」前，禁止画图、成文或进入下一环节。

## 一、心智模型：决策树

- 每个收敛点是一棵决策树：答案会解开依赖它的下一层问题。
- 每轮只问「前置已定、现在就能答」的 frontier 问题；一次一问，答后消化再进下一轮。
- 用户回答冒出的新问题进下一轮；frontier 清空才算该点收敛。
- 未获用户拍板的推演默认（阈值/上限/文案/边界）标【设计假设】，且必须安排回访裁决，不得静默消化。

## 二、提问纪律

1. 每个问题写成「问题 + 推荐答案 + 理由」；无方向时给 2~3 个差异化选项 + 场景例子。
2. 推荐答案只是建议，最终仍须用户逐点拍板。
3. 一次一问：不连环轰炸、不提前抛出依赖未定的问题。
4. 回答质量门槛：抽象/口号回答（提升体验、尽快、适当、大概、后续再说）一律不放行，追问具体角色、场景、现状与变化，直到能举出一个真实例子。
5. 只给结论不给理由时追问：为何非做不可？不做会怎样？谁最受影响？

## 三、固定三问（每个收敛点至少各过一轮）

1. 什么情况下这个方案会失败/不成立？
2. 数据、用户或场景量涨 10 倍，这个假设还成立吗？
3. 你漏掉了什么？（换角色、入口、异常、时间段各看一遍）

## 四、边界拷问

- 这版明确「不做」的至少 3 条是什么？说不出 → 边界未想清。
- 哪些用户、角色、场景明确不进本期？
- 与现有系统/相邻模块的交界在哪？谁的数据、谁的页面、谁做判定？
- 输入在什么情况下算不合法？临界值是什么？
- 两条规则冲突时谁优先？
- 兜底/降级做到哪一步为止？

## 五、流程节点拷问

对主流程与每个模块流程：先拆节点序列（入口 → 步骤 → 分支 → 出口），再逐节点过问，禁止只走主干跳节点。

| 拷问维度 | 该问的问题 |
|---|---|
| 触发与前置 | 谁发起？什么条件触发？需要什么已就绪，没就绪会怎样？ |
| 动作与回应 | 用户做什么？系统回应什么（业务语言，不写控件）？ |
| 分支 | 下一步有几条路？每条路的判定条件是什么？ |
| 异常 | 失败/中断/超时/重复/反悔/无权时，用户看到什么、还能做什么？ |
| 终态与出口 | 节点有终态吗？从哪能离开？出口承接谁的下一跳？与入口成对吗？ |

逐节点记录「节点 / 触发 / 动作 / 产出 / 分支条件 / 异常出口」，全部节点闭环并经用户确认后，才进入模块图与成文。

## 六、收敛证明（一个澄清点何时算完）

同时满足四条才允许关闭：

1. 结论不是口号：可一句复述「做 X、面向 Y、解决 Z」，并有具体场景例子。
2. 已记录：决定 + 理由 + 已拷问的反方/边界/节点出口。
3. 【设计假设】有归属点与回访时机。
4. 用户对复述点头（V1 复述全貌；V2 复述差异点）。

## 七、雷区（出现即自查补问）

- 用户刚开口一两句，就开始画图/写正文 → 收敛证明未齐。
- 每个问题用户只回一两句，就当全确认 → 对每个抽象词继续挖场景。
- 只聊正常主链路，不问失败与边界 → 补边界拷问与异常节点。
- 把「推荐答案」直接当最终答案 → 仍要用户逐点裁决。
- 为少打扰用户，把未确认项一律标【设计假设】默认通过 → 假设须回访。
