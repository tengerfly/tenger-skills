# 竞品分析（Competitive Analysis）

## 交付物

每次执行在 `.spec/<主题>竞品分析/` 下生成两个文档：
- `<主题>竞品分析报告.md`（11 模块主文档）
- `验收结果详细说明.md`（按 `assets/eval-template.md` 的三段式验收）

核心纪律：一切结论有据可依；禁编造；预测必须标注；多方口径并列。

## 何时使用 / 不使用

- 使用：明确产品想法要做竞品分析/调研/对比；了解赛道竞品、市场趋势、用户痛点、商业模式、技术实现；间接表达（「这个赛道竞争怎么样？」）也触发。
- 不用：产品想法已成熟、要直接写需求文档 → PRD-Design。

## 四阶段流水线

```
1. 结构化输入 → 2. 调研与候选草稿 → 3. 模板化验收 Gate → 4. 正式交付归档
```

1. **输入**：解析赛道类型（红海/内容/灰区/出海/数据稀缺）、目标市场与对标项；派活四件套（目标/边界/历史包袱/验收标准）缺一先问，不脑补。
2. **调研与草稿**：全球双语检索；按五层框架推演；执行数据红线，产出 11 模块候选草稿。
3. **测试验收（强制）**：按 `assets/eval-template.md` 三段式评估；门禁：`PASS` = P0=0 且 P1(Open)=0；`CONDITIONAL` = P0=0 但 P1(Open)≥1 → 就地补齐再验（P1(Open)=1 不属 PASS，同样补齐）；命中 P0 即 `FAIL` → **阻断输出并回炉重构**。
4. **交付**：双文档落盘上述目录；控制台同步呈现核心提炼与 Gate 裁决摘要。

## 数据红线（最高优先级）

1. 禁编造：无公开数据如实标「暂无公开数据/信息不足」。
2. 可溯源：核心数据/结论能追溯到来源（机构/平台 + 时间/版本）。
3. 预测必标：推测/估算/预测明确标「预测/估算」，与事实区分。
4. 多方口径并列：机构口径分歧大（如 18 亿 vs 43 亿）禁止单挑，并列并说明差异。
5. 商业假设隔离：目标产品定价/抽佣模型标 `【平台设计假设值（非调研事实）】`，不与竞品真实数据混淆。
6. 简洁：一句话能说清不写一段；能列表不写长段。
7. 具体优先：优先具体数据、权威报告、海外社区真实事例。
8. Pass Gate 前置：未达 P0=0 且 P1(Open)=0 不得输出。

**Red Flag（命中即停查）**：数字无来源；想选好看数字回避口径分歧；假设未打标签；结论以「我觉得/应该是」开头。

## 赛道自适应策略

| 赛道 | 典型 | 侧重点 |
|---|---|---|
| 红海/高度同质化 | 进销存、办公文档、云存储 | CAC 结构、服务/渠道下沉度、价格带缝隙 |
| 内容平台蚕食 | 旅游攻略、菜谱、生活指南 | 内容平台 UGC 碎片化缺陷 vs 结构化/交互式闭环 |
| 监管敏感/灰区 | 二奢改装、宠物殡葬、数字处方 | 知识产权边界、前置资质、承揽合规链路 |
| 海外出海/高净值 | 欧美 AI 健身、SaaS 出海 | GVR/Statista 研报 + Reddit/Trustpilot 真实槽点 + 海外生态合规 |
| 数据稀缺/新兴 | 小众 O2O、前沿 AI 工具 | 多方口径并列 + 自下而上单位经济模型测算 |

## 五层分析框架

| 层 | 核心问题 |
|---|---|
| 市场趋势 | 大盘多大、增速如何、值不值得进 |
| 竞品优缺点 | 对手是谁、强在哪弱在哪、差异化机会 |
| 用户痛点 | 用户痛在哪、真实社媒抱怨什么、哪些需求未满足 |
| 商业模式 | 竞品怎么赚钱、成本/客单价、目标产品如何变现 |
| 技术可行性 | 能不能做出来、关键路径、数据与合规壁垒 |

子维度见 `references/dimensions.md`。

## 七步交付闭环

1. **确认目标**：产品定位、目标市场（国内/出海）、人群、核心功能假设。
2. **竞品界定**：筛选 3–8 个，分直接/间接/参照，标对标维度。
3. **匹配赛道策略**：定重心（红海突围/合规防线/真实槽点）。
4. **全球检索**：国内——艾瑞/IDC/易观/QuestMobile/裁判文书/小红书/知乎；海外——GVR/Fortune/Statista/Reddit/Trustpilot/G2/App Store。
5. **分层分析与矩阵**：个体画像 + 功能矩阵 + **强制独立产出优缺点横向对比表**。
6. **Pass Gate（⛔ BLOCKING）**：按 eval-template 自检；苏格拉底三问——结论什么情况下失效？数据涨 10 倍/换市场还成立吗？漏了什么（合规/履约/槽点）？未通过就地修复，禁止输出。
7. **落盘交付**：11 模块报告 + 验收说明，控制台给结构化提炼与测试摘要。

## 报告结构（11 模块）

1. 报告摘要（产品定义/主要竞品/3–5 核心发现）
2. 调研背景与目标
3. 竞品界定（名称/类型/选取理由/对标维度）
4. 市场趋势（规模/增速/驱动/口径对比/监管）
5. 竞品个体画像与优缺点（5.1~N 画像 + **5.N+1 强制独立横向对比表**）
6. 功能点矩阵（✓/✗/△ + 空白分析）
7. 用户痛点与社媒舆情（画像/场景/槽点/未满足需求）
8. 商业模式与定价（竞品对比 + 目标产品设计建议【标假设】）
9. 技术可行性与履约路径（选型/算法/API/壁垒/合规）
10. 差异化与总结
11. 附录（全部来源链接、发布时间、口径声明）

模板见 `assets/report-template.md`。
