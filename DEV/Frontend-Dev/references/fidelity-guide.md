# 页面还原度校验指南（还原验收）

> 用途：在编码完成后，核对「实现页」与「还原基准」的还原度，输出可验收结论。
> **基准口径（唯一）**：**结构 / 布局 / 载体 / 流转 → 低保真原型 + 布局清单；视觉（色值 / 字号字重 / 间距 / 圆角阴影 / 图标 / 状态视觉）→ 设计稿 + `design-system.md` token**。有设计稿时**设计稿是视觉维度的唯一应然**，原型不承载视觉基准（定义见仓库根 `../../../shared/baseline-terms.md`）。
> 状态口径：还原基线维度「三态」= 加载/空/错误，是 FTDD §9 适用状态（10 大 UI 状态，实现见 `ui-states-guide.md`）的子集——FTDD 声明的适用状态一并纳入还原基线与返工判定。
> 还原度是 Frontend-Dev 的第一原则之一——**还原基线不符 = 未完成**，必须返工到符合才交付。

---

## 一、还原基线的定义

步骤 4 已产出「页面 × 还原基线」清单。每一页的还原基线按维度分属两个基准（**对照列写明基准归属，不得混淆**）：

| 维度 | 说明 | 对照基准 | 不符示例 |
|------|------|---------|---------|
| 结构 | 区块顺序、层级、导航是否一致 | **原型 + 布局清单** | 漏区块 / 顺序颠倒 / 多出原型没有的模块 |
| 布局 | 对齐、栅格、间距、宽高比例 | 原型（骨架）+ **设计稿**（间距/尺寸值） | 卡片间距、表格列宽明显走样 |
| 配色 | 色值与 token 一致 | **设计稿 + design-system token** | 主按钮颜色、背景色与设计稿不同 |
| 字号/字重 | 字号字重与设计稿一致 | **设计稿 + design-system token** | 标题/正文层级模糊 |
| 圆角/阴影 | 与设计稿一致 | **设计稿 + design-system token** | 卡片圆角、弹层阴影不同 |
| 图标/图片 | 同一套资源、同尺寸 | **设计稿**（缺失才取原型） | 用错图标 / 占位图替代 |
| 文案 | 与设计稿/PRD 一致 | **设计稿**（源头 PRD） | 按钮文字、空态文案改动 |
| 三态/适用状态 | 加载/空/错误态 + FTDD §9 适用状态齐全且符合 PRD | **设计稿状态稿**（design-system §5.10） | 只做了成功态 |
| 交互细节 | hover/点击/禁用/表单反馈符合 PRD | 原型流转 + PRD | 点击无反馈、按钮无禁用态 |

> 还原基线在 Scope Gate 时已呈现给用户确认。若设计稿无某状态稿，按组件库标准态实现并在基线中注明；FTDD §9 声明的适用状态（10 大 UI 状态）一并纳入基线。
> **无设计稿时**：视觉维度回退原型基础值，基线中与交付结论里**明示「视觉基准回退低保真原型」**（口径降级，经用户确认）。

## 二、校验工具与硬门禁

```
Playwright 可用     ──► 自动截图比对（首选，推荐）
Playwright 异常     ──► browser-use 或其他浏览器工具（如 agent-browser）替代截图比对
全部不可用          ──► 不应发生（SKILL 步骤 1 已硬性预检并报错等安装）；
                        运行中全部异常 → 停止校验并报错，恢复后继续，禁止静默降级
```

> 浏览器工具是 Frontend-Dev 的**硬性前置**（SKILL 步骤 1 预检，均不可用即报错等安装）；web 端还原校验必须走自动截图比对，**不得以静态对照替代交付**（静态对照仅用于 §四 的限定场景）。

## 三、Playwright 截图比对流程（首选）

### 3.1 准备

```bash
# 项目内安装（未安装时）
pnpm add -D playwright
pnpm exec playwright install chromium
```

### 3.2 写比对脚本（临时脚本，校验后清理或归档进产物 README）

**有设计稿时 `BASE_URL` 指向设计稿、`IMPL_URL` 指向实现页；无设计稿才回退原型。**

```ts
// scripts/fidelity-check.ts
import { chromium } from 'playwright';

// 有设计稿：基准 = 设计稿 HTML（file:// 打开 .spec/设计稿/<页面>.html）
// 无设计稿：基准 = 低保真原型 HTML（并在结论中标注「视觉基准回退原型」）
const DESIGN_BASE = 'file:///abs/path/to/.spec/设计稿';   // 视觉主基准
const PROTOTYPE_BASE = 'file:///abs/path/to/prototype';   // 结构对照（可选）
const DEV_URL = 'http://localhost:5173/orders';            // 实现页

const cases = [
  {
    name: 'orders-list',
    design: `${DESIGN_BASE}/orders.html`,   // 视觉比对基准（必开）
    prototype: `${PROTOTYPE_BASE}/orders.html`, // 结构对照（可选）
    impl: `${DEV_URL}`,
  },
  // ... 页面 × 基准映射（来自还原基线清单）
];

async function shot(url: string, path: string) {
  const browser = await chromium.launch();
  const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });
  await page.goto(url, { waitUntil: 'networkidle' });
  await page.waitForTimeout(300);
  await page.screenshot({ path, fullPage: true });
  await browser.close();
}

for (const c of cases) {
  await shot(c.design, `shots/${c.name}.design.png`);       // 设计稿基准截图
  await shot(c.prototype, `shots/${c.name}.prototype.png`); // 结构对照截图（可选）
  await shot(c.impl, `shots/${c.name}.impl.png`);           // 实现页截图
}
```

> **同视口铁律**：设计稿截图与实现页截图必须**同视口宽高**，否则比对无意义。

### 3.3 比对与记录

- **先做「设计稿 ↔ 实现页」并排目视比对**（视觉维度），再做「原型 ↔ 实现页」结构比对（区块存在性与顺序）；两张截图并排（或脚本内像素相似度粗筛）；
- 逐项对照还原基线维度（按 §一 的「对照基准」列判定），输出结论表：

```
页面：订单列表（orders-list）
结构    ✅ 与原型一致（区块数量/顺序）
布局    ✅ 栅格与设计稿一致，间距取自 token
配色    ✅ computed style 与 design-system token 相符
字号    ✅ 与设计稿字号阶梯一致
圆角阴影 ✅ 与设计稿一致
图标    ✅ 同套同尺寸
三态    ⚠️ 错误态使用组件库标准文案（设计稿无该状态稿，已在基线注明）
交互    ✅ hover/点击有反馈
视觉基准：设计稿（A 通道）
结论：还原达标（1 项基线内差异）
```

- **差异两分**：
  - **可接受**：响应式断点行为、字体回退、动效实现方式、组件库标准交互细节（还原基线已注明）；
  - **必须修正**：区块缺失、间距/配色/字号偏差、三态/适用状态缺失、交互无反馈——进入返工清单，修完复验。
- **视觉维度以 token 机械判定**：对实现页取值（DevTools computed style / 脚本读 `getComputedStyle`）与 `design-system.md` §7 token 逐项断言，**不靠观感**。

### 3.4 小程序/移动端

- app/小程序端无法直接开浏览器页面时：用「设计稿刻度换算核对」替代截图（RN dp / Flutter 逻辑像素 / 小程序 rpx 按 750 换算），并核对各端真机/工具截图（若有）；
- 有 browser-use 时可用其对小程序开发者工具或预览截图辅助核对。

## 四、静态对照（辅助定位手段，不替代 web 端自动截图校验）

> 仅限两类场景：① app / 小程序等无法直接开浏览器页面的端（配合 §3.4 刻度换算）；② 自动比对发现差异后，用静态对照定位具体代码位置。web 端禁止只用静态对照交付。

1. 打开**设计稿 HTML**（有设计稿时）读取目标区块的结构 class / Tailwind 类 / 内联样式与 token 值；无设计稿才打开原型 HTML（同时读取原型结构）;
2. 打开实现页组件代码与对应 `.module.scss`；
3. 逐项核对：结构层级（DOM 树与原型相似）、布局方式（flex/grid 与设计稿视觉一致）、间距值（换算后相等）、色值（设计稿 token → variables token 值一致）、字号字重、文案；
4. 交互与三态/适用状态按 PRD + 代码审查确认；
5. 输出与 3.3 相同的结论表，并注明「静态对照」方式。

## 五、常见还原度问题

| 问题 | 纠正 |
|------|------|
| **有设计稿却只与原型比对视觉** | 设计稿是视觉唯一应然；原型只作结构对照 |
| 色值自由发挥 / 写死 | 全部引用 variables token，值从**设计稿 design-system** 提取 |
| 间距用「大约」「差不多」 | 与**设计稿**像素级核对（含换算），偏差即修 |
| 只做成功态 | 补全加载/空/错误三态及 FTDD §9 适用状态（见 `ui-states-guide.md`） |
| 用组件库默认布局顶替设计稿布局 | 布局基线必须匹配设计稿，不是「组件库长这样就行」 |
| 图标/图片用错 | 从**设计稿**提取同一套资源（缺失才取原型） |
| 文案改写 | 与设计稿/PRD 文案一致（除非 PRD 有修正并登记） |
| 跳过 token 搬运对账 | 逐条核对 design-system §7 ↔ 实现 variables（条数/值/命名） |
| 浏览器工具均不可用仍开工或声称已截图校验 | SKILL 步骤 1 硬性预检报错等安装；结论如实记录校验方式 |

## 七、防复发的失败模式（2026-09-07 学径项目案例）

下列模式会造成「页面能跑但整站与设计稿差异过大」，**出现任一项即回到本指南从头做该页**：

1. **先补功能后补视觉**：允许页面「功能骨架」批量合入、视觉统一后置 → 每页功能点提交前必须先完成该页视觉基线。
2. **只消费 AntD/浏览器默认样式**：design token 已定义但组件不引用，改用内联样式或默认色 → 每个样式值必须来自 variables token（variables.scss/less）/主题 token。
3. **只搭 DOM 不写样式层**：页面容器/导航只有 JSX/模板类名、没有对应样式文件（CSS Modules/scoped）→ 新增页面同时新增样式文件，不允许「未样式提交」。
4. **不做逐页同视口截图**：只在浏览器看个别组件，未对每页输出设计稿 vs 实现截图 → 每页交付前并存设计稿与实现页截图。
5. **把「截图看不了」当跳过理由**：模型无图像输入时改用 DOM/computed-style 提取设计稿与实现的 token/布局值逐项断言，仍不能跳过还原校验。
6. **把原型当视觉基准**（2026-09-15 全仓口径修复项）：只与低保真原型比对视觉 → 低保真原型只有中性色 + 单一主色 + 基础字号，比对必过但视觉与设计稿差一截。**有设计稿时视觉基准只能是设计稿**；只与原型比对视觉不算完成还原校验。
7. **token 搬运不对账**：设计稿是 Tailwind 类、实现是 CSS 变量，凭感觉抄值导致条数缺失 / 色值手抄错 / 间距网格走样 → S4 逐条对账（条数/值/命名）。
