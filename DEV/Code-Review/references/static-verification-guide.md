# 静态验证命令与取证规程

> 步骤 2 执行依据：能跑则跑，跑不了降级并明示「未取证」。失败是证据，未取证不是通过。

## 一、范围
前后端分别跑：install → build/tsc → test → lint（后端含 commitlint；前端加 stylelint）。命令以 package.json scripts 为准。

## 二、执行
1. 定位前后端各自 package.json 根目录。
2. install → build/tsc → test → lint，逐项分开记录。
3. 结果记 ✅/❌（附首个关键错误文件:行）/⚠️（原因）。
4. 失败只摘首个关键错误，不贴整屏日志。

## 三、降级
- 依赖无法安装 → 跳过 install 及后续，标「未取证：依赖未安装」。
- 无权限/被拦截 → 标「未取证：未授权执行」。
- 环境不符（Node 版本等）→ 标「未取证：环境不符」。
- 降级不阻塞评审，转静态读码并在报告注明未经命令验证。

## 五、边界
- 不做端到端联调冒烟（归测试）。
- test 全绿只说明可运行，不说明业务正确。
- build/tsc 失败 ≥P0；test/lint 失败 ≥P1；全部未取证须显著声明。
