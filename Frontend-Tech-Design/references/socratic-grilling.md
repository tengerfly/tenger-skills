# 前端选型拷问协议（grill-me 式单步拷问）

> 执行范围：FTDD 的选型澄清、Scope Gate、模块级组件拆分与数据流决策。协议通用核心（心智模型/提问纪律/固定三问框架/边界拷问框架/收敛证明/雷区）见仓库根 `shared/socratic-grilling-core.md`，本文件只保留前端领域专属内容，两者配合使用。
> ⛔ BLOCKING：决策点未过「收敛证明」前，禁止写入 overview 或模块文档。

## 一、前端决策点与默认处理

- 决策点类型：选型 / 组件拆分 / hooks 与状态归属 / fetch 边界 / 异常策略。
- 未获用户拍板的默认（组件库版本/兼容目标/状态归属/超时策略）标为待验证或【方案假设】，安排回访裁决，不得静默消化。

## 二、固定三问——前端失败场景与漏项清单

1. 这个方案在什么场景下会失败/不成立？（弱网、无权限、空数据、兼容旧浏览器、接口异常）
2. 页面、数据或交互量涨 10 倍，这套拆分/状态/渲染方案还成立吗？
3. 漏掉了什么？（换角色、入口、异常、重复点击、离开页面后再看一遍）

## 三、边界拷问——前端领域问题

- 这版明确不做/不支持的页面、设备、浏览器、交互是什么？说不出 → 边界未想清。
- 组件库与自研的适用边界在哪：哪些页面统一用库、哪些自研，为什么？
- 状态放哪层（本地/服务端/共享）？谁拥有并修改？
- 数据从哪来、由谁刷新？接口失败/超时由谁兜底？
- 权限、主题、i18n、空态等多规则冲突时谁优先？

## 四、数据流/交互节点拷问（前端专属）

关键链路（取数/表单提交/上传下载/权限路由/弱网/大列表）先拆节点序列（触发 → 取数 → 渲染 → 提交 → 反馈 → 跳转/刷新），再逐节点过问，禁止只走正常主链路。

| 拷问维度 | 该问的问题 |
|---|---|
| 触发与前置 | 什么动作触发？需要什么已就绪？没就绪/未授权会怎样？ |
| 数据 | 数据从哪个接口/缓存/本地来？空、旧、超时怎么办？ |
| 用户操作 | 用户做什么？过程中 loading/禁用/反馈是什么？ |
| 分支 | 下一步有几条路？成功/失败/取消/重复各走哪？ |
| 异常与恢复 | 弱网/离线/接口失败/重复提交/中途离开时，用户看到什么、还能做什么？ |
| 终态 | 完成后去哪？返回/刷新后与提交前状态一致吗？ |

逐节点记录「节点 / 触发 / 数据来源 / 用户动作 / 分支条件 / 异常恢复」，闭环并经用户确认后再写入模块文档。

## 五、收敛证明——前端落点

- 结论可落到具体页面、组件、版本或状态归属，不是「看情况/尽量」。
- 待验证项（浏览器兼容、组件库版本等）有验证动作与回退方案。

（其余两条通用条件见 `shared/socratic-grilling-core.md` §五。）

## 六、雷区——前端补充

- 关键数据流只画成功主链路 → 逐节点补异常、弱网、重复与失败恢复。

（其余通用雷区见 `shared/socratic-grilling-core.md` §六。）
