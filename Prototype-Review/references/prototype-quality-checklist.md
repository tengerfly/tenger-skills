# 原型自身实现质量检查清单（Prototype Quality Checklist）

> 目标：评审低保真原型 HTML/CSS/JS 代码与运行表现本身是否存在缺陷——这是「逻辑闭环、文案一致、防漏、防加戏」三个核心维度可被正确验证的实现前提（原型坏了就验证不了）。低保真原型不做视觉精修，本清单**只查实现质量与可验证性**，不查配色 / AI 模板感 / 字号网格 / 微动效等视觉精修项。

---

## 一、代码与运行稳定性

### 1.1 浏览器控制台健康度
- [ ] **无未捕获异常**：打开页面并执行常见点击时，控制台（Console）无报错（Uncaught TypeError / ReferenceError / 404 资源未找到）。
- [ ] **脚本逻辑健壮性**：DOM 事件监听器绑定前确保元素已挂载；同一事件多次点击不会产生叠加或死循环。

### 1.2 HTML/CSS 结构规范
- [ ] **样式布局错位排查**：在常见分辨率（1920×1080、1440×900 或移动端 375×812）下无元素重叠、无意外横向滚动条、无布局穿透。
- [ ] **弹框遮罩与层级（z-index）**：遮罩层 `z-index` 正确覆盖在页面内容之上；弹框内容处于最上层；下拉菜单不会被卡片 `overflow: hidden` 截断。
- [ ] **自包含性（Self-contained）**：所有 CSS/JS 资源若为本地相对引用必须存在；外链 CDN 资源地址可用且有本地兜底保障。

---

## 二、交互与载体可验证性

> 低保真原型评审聚焦「能不能正常跑、能不能点、能不能验证逻辑」，这是本维度的重点。

### 2.1 交互真实可用
- [ ] **无死按钮**：按钮点击有反馈（跳转或状态变化），不存在点击无响应的「死按钮」；
- [ ] **载体交互可用**：Tab 切换能真实切换面板；弹框/抽屉能正常打开与关闭；筛选下拉能展开选中；
- [ ] **数据展示正常**：表格/卡片等载体的数据能正常渲染（非空白、非全 0），动态内容无「静态正常但动态空白」的静默失效。

### 2.2 低保真可读性（最低要求）
- [ ] **区块结构清晰**：用户能一眼辨认「这是什么区块」（顶部导航 / 侧栏 / 主内容 / 列表 / 表单 / 操作区）；
- [ ] **基本层级区分**：标题 / 正文 / 辅助文字有基本层级区分，不要求字号网格精修。

> **明确不查（低保真铁律）**：配色是否真实、是否存在 AI 模板痕迹（紫蓝渐变/玻璃拟态）、字号间距网格节奏、按钮 hover 微动效、表格行悬停高亮——这些视觉精修项不属于低保真原型的评审范围。
