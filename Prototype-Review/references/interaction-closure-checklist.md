# 交互状态与流程闭环检查清单（Interaction Closure Checklist）

> 目标：验证原型链路可点击跳转、所有业务分支均有进出通道、异常与极限状态有直观承载，确保整个产品原型在逻辑上全线闭环。

---

## 一、链路通畅与进出闭环（No Dead Ends）

### 1.1 全链路出口与回退
- [ ] **死胡同页面排查**：任何一个页面都必须有返回上一级、返回首页或进入下一步的清晰出口，严禁出现只能靠浏览器后退键才能离开的孤岛页面。
- [ ] **弹框与抽屉闭环**：
  - **唤起通道**：点击触发元素（如「编辑」、「新增」、「查看」）能正常打开对应弹框/抽屉；
  - **关闭通道**：弹框必须包含右上角 `×`、底部「取消」按钮，点击能正常退出遮罩并恢复页面；
  - **确认通道**：点击「确定/保存」有交互反馈（如轻量 Toast 提示成功后自动关闭）。
- [ ] **跳转路径真实有效**：页面内所有超链接 `<a href="...">` 或 JS 跳转均能正确链接到对应的真实 HTML 文件或锚点，不得留空（`href="#"` 或无效锚点导致页面滚动突变）。

### 1.2 完整业务流程贯通
- [ ] **正向主流程贯通**：从起点页面开始（如发起创建 → 填写信息 → 提交审核 → 列表展示最新状态），主流程各环节原型可一路点击贯通。
- [ ] **逆向/分支流程闭环**：
  - 审核流分支：除「审核通过」外，「驳回/退回重填/终止」是否有对应的输入原因弹框及结果状态变化；
  - 撤回与取消：已提交但未处理前，是否有撤销入口及撤销后的界面表现。

---

## 二、状态机与全状态覆盖（Multi-State Coverage）

### 2.1 界面五态覆盖
- [ ] **空数据态（Empty State）**：首次使用、搜索无结果、列表清空时的占位图文指引是否展示，是否有「去添加」或「清空筛选」的引导操作。
- [ ] **加载中态（Loading State）**：数据加载或提交中的骨架屏（Skeleton）、Spinner 或按钮禁用态是否有所体现。
- [ ] **错误/异常态（Error State）**：网络异常、加载失败、操作超时的错误缺省页或局部报错卡片。
- [ ] **成功态（Success State）**：关键操作完成后的结果页（Result Page）或通知反馈。
- [ ] **极限/边界态（Boundary/Extreme State）**：超长文本省略（ellipsis + Tooltip）、超大数值格式化（千分位、万/亿缩写）。

### 2.2 表单验证与拦截反馈
- [ ] **前置校验提示**：必填项未填、格式不合法时是否有即时校验提示（如红色文字提示或高亮红框）。
- [ ] **按钮防重与禁用**：表单在不符合提交条件时，提交按钮是否置灰禁用（Disabled）。
