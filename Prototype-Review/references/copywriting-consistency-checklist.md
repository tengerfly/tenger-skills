# 文案与字段一致性检查清单（Copywriting & Field Consistency Checklist）

> 目标：确保原型中的文字、标签、提示语、表格列、表单项与 PRD 的业务定义完全对齐，杜绝错别字、表意偏差、模糊占位文案（Lorem Ipsum 等）。

---

## 一、文案严格对齐

### 1.1 标题与操作文案
- [ ] **页面与模块标题**：页面 Header、卡片 Card 标题、弹框 Modal 标题文案必须与 PRD 逐字一致，不可随意简写或扩写（例如：PRD 称「退款申请审核」，原型不得写成「退款详情」或「审核」）。
- [ ] **操作按钮文案（CTA）**：主要按钮、次要按钮文案必须严格遵照 PRD：
  - 区分操作动词语义：如「保存」vs「提交」vs「暂存」；「确认」vs「确定」；「通过」vs「驳回」；
  - 不得使用笼统模糊的「OK / 确定 / 点击」替代 PRD 中具体的动作意图（如「同意并签署」）。

### 1.2 提示、引导与反馈文案
- [ ] **占位引导文案（Placeholder）**：输入框、选择器中的 Placeholder 文案必须体现 PRD 中的格式规范或提示要求（如「请输入 11 位有效手机号码」），严禁出现无意义的 `input text here` 等英文或占位符。
- [ ] **反馈提示文案（Toast / Banner / Dialog）**：
  - 操作成功/失败的 Toast 提示文案是否与 PRD 一致；
  - 危险/破坏性操作（如删除、作废）的二次确认弹框提示文案是否完整表达后果与警告。

---

## 二、数据字段与表单项一致性

### 2.1 表单字段（Form Fields）
- [ ] **字段名称（Label）一致**：Label 名称与 PRD 业务信息清单严格一致（如 PRD 为「统一社会信用代码」，原型不得随意改为「纳税人识别号」或「税号」）。
- [ ] **必填与选填标识**：PRD 中规定的必填字段，原型必须带有清晰的必填标记（如红色星号 `*`）；选填字段不得误标为必填。
- [ ] **字段控件类型匹配**：
  - 单选/多选/下拉框：选项枚举项是否完整，文案是否逐一吻合 PRD 规格；
  - 日期范围：是单一日期选择器还是日期区间选择器；
  - 数字/金额：是否带有单位或货币符号后缀（如「元」、「%」、「个」）。

### 2.2 表格与数据呈现（Tables & Data Presentation）
- [ ] **表格列名与顺序**：表格列名（Header）与 PRD 定义一致，列顺序符合 PRD 描述。
- [ ] **状态标签文案与配色**：
  - 状态文案必须与 PRD 状态机枚举完全相同（如 PRD 为「待复核」，原型不得展示为「处理中」）；
  - 状态配色符合通用认知（成功/完成：绿；处理中/待审核：蓝/黄；失败/异常/拒绝：红；已废弃/关闭：灰）。
- [ ] **真实业务样例数据**：表格和卡片中的 Mock 数据必须符合真实业务场景，字段间逻辑自洽（如：创建时间不能晚于更新时间，总价必须等于单价×数量），严禁出现无语义字符。

---

## 三、冗余文案排查（防加戏）

> 反向核查：不仅查「PRD 要求的文案是否一致」，也查「PRD 没要求的文案是否被擅自加进来」。

### 3.1 无依据文案识别
- [ ] **无来源提示文案**：页面上的 Toast / Banner / 引导 / 说明文案，若 PRD 未定义且非必要交互反馈，记为冗余问题点（典型：「操作成功」「温馨提示：请确认信息无误」等通用话术）。
- [ ] **无依据 CTA 文案**：PRD 未定义的操作按钮（如列表页多出的「导出」「批量删除」「分享」），其按钮文案本身即无出处，一并记为问题点。
- [ ] **文案与 PRD 冲突**：原型自加的文案若与 PRD 语义矛盾（如 PRD 无删除功能，原型却出现「删除」按钮及其提示），升级为 P1。

### 3.2 分级建议
| 情形 | 严重度 |
|---|---|
| 冗余文案与 PRD 语义冲突 / 误导用户操作 | P1 |
| 纯多余、无冲突的提示 / 引导文案 | P2 |
