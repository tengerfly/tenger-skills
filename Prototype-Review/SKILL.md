# Prototype-Review —— 原型评审

> 定位：以 PRD 为基准审查已生成原型。只审不改；唯一产物是 `.spec/原型评审/` 下的报告与任务清单。

## 一、评审范围

1. **页面与载体完整性**：PRD 规定的页面、弹框、抽屉、页内区块必须落地；PRD 未要求的按钮、提示、区块、装饰元素不得出现。
2. **文案与字段一致性**：页面标题、CTA、提示文案、表格列名、表单标签与 PRD 逐字吻合；不得有多余提示/引导文案。
3. **交互与流程闭环**：页面出入口、正向/逆向分支、弹框打开与关闭、空/载/错/满多状态必须通畅闭环。
4. **原型自身实现质量（闭环验证前提）**：查控制台报错、样式穿透/错位、层级遮挡、死链、点击无响应。原型坏了，前三维度无法验证。不查视觉精修、配色、AI 模板感。

## 二、输入与输出

- **输入**：
  - PRD 目录（默认 `.spec/PRD/`）：存在 `PRD速查表.md` 则先读建六大索引，逐字比对按锚点回原文；
  - 原型工程（默认 `.spec/原型/`）：HTML、`布局清单.md`、`README.md`。
  - 任一方缺失 → 停下提示用户。
- **输出目录**：`.spec/原型评审/`
  - `页面与载体完整性评审.md`
  - `文案与字段一致性评审.md`
  - `交互与流程闭环评审.md`
  - `原型自身质量评审.md`
  - `原型评审汇总报告.md`
  - `任务清单.md`
  - `screenshots/`（硬性产出）

## 三、严重度分级

> P0/P1/P2 定义与处理口径见仓库根 `shared/anti-deadloop.md` §二；下表为本域典型示例。

| 级别 | 定义 | 处理 | 典型 |
|---|---|---|---|
| P0 致命 | 流程断头、核心页面/模态缺失、严重阻碍开发与演示 | 阻塞；修复并通过复核 | 核心审核弹框无入口也无代码；主流程死胡同 |
| P1 重要 | 字段/文案严重不符、关键状态缺失、弹框无法关闭 | 必须进任务清单，原则上全修 | 按钮文案写反；必填星号缺失；空/异常状态未设计 |
| P2 建议 | 非关键文案润色、次要体验优化 | 记录，由用户裁决 | 提示可精炼；次要入口可优化 |

## 四、五大铁律

1. **只审不改**：严禁改原型 HTML/CSS/JS 与 PRD；唯一产出为 `.spec/原型评审/` 下的报告与清单。
2. **成因必写**：每条问题结合 PRD 与原型代码给成因（如漏读章节、同名歧义、事件未监听、overflow 遮挡）；无法推导标「成因未明」，禁主观臆造。
3. **方向明确**：每条给修改方向和建议修改方——原型问题 → `Prototype-Design`；PRD 自相矛盾 → `PRD-Design`；双方口径不一 → `双方协同`。
4. **浏览器工具硬前置**：本 skill 为硬依赖——检测顺序、两级行为与报错文案见仓库根 `shared/browser-policy.md`；任一可用即用于截图存证（细则见 `references/browser-inspection-guide.md`）；全部不可用 → 报错停止，不产出任何评审文档。
5. **单一事实源任务清单**：全量问题去重后只收口到 `.spec/原型评审/任务清单.md`，初始状态均为 `待确认`。

## 五、评审流程（7 步）

### 步骤 1：资产解析与浏览器环境预检
- 读取 PRD（速查表/overview/NN_xxx）与原型（HTML/布局清单/README）；缺失即停。
- 按铁律 4 预检浏览器工具并记录走查工具；全不可用即报错停止。

### 步骤 2：建立映射基准
从速查表页面功能区块索引与各模块 §3.1 提取页面、交互路径、关键文案；读 `布局清单.md`；产出矩阵 `PRD 功能点 ↔ 原型页面/载体（文件/Modal ID）`。

### 步骤 3：截图走查 + 静态源码审查（双通道互证）
- **截图走查（硬性）**：逐页打开原型，对异常/缺失/不一致处局部截屏存入 `screenshots/`；
- **静态源码审查（并行）**：读 HTML 结构、CSS、JS 交互，以代码行与 DOM 路径为证据；
- 两通道独立完成、互不参考，最后合并比对；只认原型成品与 PRD 原文，不参考原型生成过程。

### 步骤 4：四维度对照评审
按四个参考清单逐项过筛（每份同时查漏 + 查多）：
`references/page-completeness-checklist.md`、`copywriting-consistency-checklist.md`、`interaction-closure-checklist.md`、`prototype-quality-checklist.md`。

### 步骤 5：产出四份维度报告
按 `assets/dimension-review-template.md` 落盘步骤 4 对应的四份报告。

### 步骤 6：汇总
按 `assets/summary-template.md` 聚合四份报告：合并同类、消除重复、归纳跨页面系统性问题、统计 P0/P1/P2，落盘汇总报告。

### 步骤 7：任务清单与归档
按 `assets/issue-list-template.md` 生成 `任务清单.md`：
- 每条自足可读：出处 + 现象 + 成因 + 修改方向，不依赖原型/PRD 原文；
- 每条附**修复判据**：修到什么表现算完成；
- 初始状态 `待确认`；标注建议修改方；
- P0/P1 阻断（未清零不放行）；P2 不阻塞，由用户裁决；
- 逐条向用户确认裁决：要改 → `已确认`；不改 → `已忽略` + 理由；不整体过目，不理解即展开说明；
- 复核只验本轮已确认清单，不无限新增同级问题；新发现降 P2 留后续或经同意进下一轮；
- 轮次上限 3：P0/P1 未收敛即停止循环，向用户汇报阻塞；
- 交付总结明确剩余待裁决项。

> 防评审死循环三招与任务清单状态机的定义见仓库根 `shared/anti-deadloop.md`，本 skill 只保留上述流程参数，不重复定义。

## 六、运行问题埋点

收尾按 `Skill-Optimizer/references/instrumentation-guide.md` 自查上报 `issue/Prototype-Review/<日期>/<序号>-<标题>.md`（来源=埋点；字段/等级/标签按其规范，模板 `Skill-Optimizer/assets/issue-template.md`）。不确定不记，不打断主流程。
