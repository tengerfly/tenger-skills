# 经典系统设计案例（System Design Cases）

> 用途：做高并发、容量规划时的参考范本。每题给「场景 → 技术挑战 → 架构决策 → 关键点」，可复用到同类型需求。参考：system-design-primer、karanpratapsingh/system-design。

---

## 一、短链系统（URL Shortener）

- **场景**：把长 URL 转成短链，跳转时 302 重定向。
- **技术挑战**：短码唯一性、高读写比（读远大于写）、跳转低延迟。
- **架构决策**：
  - 短码生成：Base62 编码自增 ID / 雪花 ID / 随机码（唯一索引兜底冲突）；
  - 存储：短码 → 长 URL，读多写少 → Redis 缓存 + DB 兜底；
  - 跳转：读 Redis → 命中 302，未命中查 DB 回填缓存。
- **关键点**：短码唯一索引；缓存 key 设 TTL；跳转接口限流（见 `decision-rules.md` §四）。

---

## 二、秒杀系统（Flash Sale）

- **场景**：限量商品，瞬时海量并发下单。
- **技术挑战**：超卖、瞬时流量击垮 DB、库存一致性。
- **架构决策**：
  - 削峰：请求先进 MQ，异步扣减；
  - 防超卖：Redis 预扣库存（原子 `DECR` + Lua），DB 最终落账；
  - 限流：令牌桶/滑动窗口，前端按钮置灰 + 后端限流双保险；
  - 幂等：用户 + 商品 唯一索引，防重复下单。
- **关键点**：库存扣减是最终一致（Redis 预扣 → MQ → DB 落账 → 对账补偿）；失败路径必须画（MQ 积压、库存回补、下单超时）。

## 三、消息推送 / 通知系统（Notification）

- **场景**：站内信 + 推送（App/短信/邮件），多通道、可异步。
- **技术挑战**：通道多样、失败重试、不丢不重、削峰。
- **架构决策**：
  - 入口：业务发「通知事件」进 MQ，通知服务消费；
  - 通道抽象：每个通道一个适配器（复用 Hexagonal 思想）；
  - 可靠投递：Outbox 保证业务变更与事件一致；消息带幂等键；
  - 重试：指数退避 + 死信队列兜底。
- **关键点**：用户偏好（免打扰/渠道开关）在发送前校验；推送失败不阻塞主流程。

## 四、可复用答题框架（做系统设计题的通用骨架）

1. **澄清**：问量级（DAU / QPS / 数据量）、读多还是写多、一致性要求；
2. **估量**：用 `decision-rules.md` §十 容量规划范式算实例/存储/带宽；
3. **定 API**：接口 + 入参出参 + 错误码；
4. **高层架构**：Mermaid 图（接入层/服务层/数据层）；
5. **深挖**：数据模型 + 缓存 + 队列 + 限流 + 幂等；
6. **瓶颈与权衡**：单点/热点/一致性，落到量化阈值与演进路径。
