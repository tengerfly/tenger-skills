# 表结构设计规范

> 用途：指导总文档「全局表结构设计」的编写——所有表、所有字段、完整要素。

---

## 一、字段要素（每列必填）

每张表用标准表结构列出，字段要素：

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 索引 | 注释 |
|--------|------|------|--------|------|------|------|
| id | BIGINT | 否 | 自增 | 主键 | PRIMARY | 主键 |
| user_id | BIGINT | 否 | — | 非空 | INDEX | 用户 ID |
| amount | BIGINT | 否 | 0 | 非空 | — | 金额（单位：分） |
| status | TINYINT | 否 | 0 | 非空 | — | 状态：0待支付 1已支付 2已取消 |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | 非空 | — | 创建时间 |
| updated_at | DATETIME | 否 | CURRENT_TIMESTAMP | 非空 | — | 更新时间 |

---

## 二、命名规范

- 表名、字段名统一 **snake_case**（如 `order_item`、`created_at`）；
- 表名用复数或单数全库统一（推荐复数，如 `orders` / `order_items`）；
- 索引命名：唯一索引 `uk_字段`，普通索引 `idx_字段`；
- 布尔字段用 `is_` 前缀（如 `is_deleted`）；状态字段用 `status` + 注释枚举。

---

## 三、必备字段约定

| 字段 | 说明 |
|------|------|
| `id` | 主键，BIGINT 自增或雪花 ID |
| `created_at` | 创建时间，默认 CURRENT_TIMESTAMP |
| `updated_at` | 更新时间，ON UPDATE CURRENT_TIMESTAMP |
| `deleted_at` | 软删除时间（可空，NULL 表示未删除） |

> 软删除策略：业务表默认软删除（`deleted_at`），日志/流水表物理删除。

---

## 四、索引规范

- 主键：`id`；
- 唯一索引：业务唯一键（如 `order_no`、`uk_user_email`）；
- 普通索引：高频查询字段（`user_id`、`status`、`created_at`）；
- 联合索引：遵循最左前缀（如 `idx_user_status(user_id, status)`）；
- 高频查询字段必建索引，避免全表扫描；索引不宜过多（写入开销）。

---

## 五、约束与类型约定

- **金额**：整数存储，单位「分」（避免浮点误差）；
- **时间**：DATETIME（业务可读）或 BIGINT 时间戳（跨时区）；
- **枚举/状态**：TINYINT + 注释写清每个值的含义；
- **外键**：推荐**逻辑外键**（应用层保证一致性），不强制物理外键；
- **字符集**：utf8mb4；**长度**：手机号/身份证等定长字段写明长度。

---

## 六、特殊字段约定

| 场景 | 约定 |
|------|------|
| 幂等键 | 业务唯一字段 + 唯一索引（如订单号、请求流水号） |
| 乐观锁 | `version` 字段（INT，更新时 +1 校验） |
| 分页游标 | 大表分页用 `id` 或时间游标，不用深 OFFSET |
| 冗余字段 | 高频读字段可冗余（如订单冗余商品名），注明同步机制 |

---
