# 后端选型拷问协议（grill-me 式单步拷问）

> 执行范围：TDD 的选型澄清、Scope Gate、服务拆分与数据模型决策。协议通用核心（心智模型/提问纪律/固定三问框架/边界拷问框架/收敛证明/雷区）见仓库根 `shared/socratic-grilling-core.md`，本文件只保留后端领域专属内容，两者配合使用。
> ⛔ BLOCKING：决策点未过「收敛证明」前，禁止写入 overview 或模块文档。

## 一、后端决策点与默认处理

- 决策点类型：选型 / 服务拆分 / 数据归属 / 一致性策略 / 接口契约。
- 未获用户拍板的默认（容量假设/保留策略/超时重试/一致性级别）标为待验证或【方案假设】，安排回访裁决，不得静默消化。

## 二、固定三问——后端失败场景与漏项清单

1. 这个方案在什么场景下会失败/不成立？（峰值、单点、慢调用、数据倾斜、误操作）
2. 数据量、并发或调用量涨 10 倍，这套选型/拆分/表结构还成立吗？
3. 漏掉了什么？（换调用方、失败重试、重复提交、幂等、回滚、监控告警各看一遍）

## 三、边界拷问——后端领域问题

- 每个模块的数据归属与写权限在哪？跨模块访问通过什么方式（同步/异步/事件）？
- 强一致与最终一致分别覆盖哪些场景？冲突时谁优先、怎么裁决？
- 鉴权、越权、敏感数据的安全边界到哪一层？
- 降级/兜底做到哪一步为止？哪些失败不自动恢复、需要告警给人？

## 四、链路节点拷问（后端专属）

关键链路（写库/缓存/异步/外部调用/幂等重试）先拆节点序列（入口 → 校验 → 读写 → 外部调用/消息 → 事务/响应 → 补偿/重试），再逐节点过问，禁止只走正常主路径。

| 拷问维度 | 该问的问题 |
|---|---|
| 触发与前置 | 谁调用？什么条件触发？前置校验/幂等键是什么？ |
| 副作用 | 这一步读写哪些数据？是否产生外部副作用？ |
| 分支 | 成功/失败/超时/重复/并发各走哪条路？判定条件是什么？ |
| 失败处理 | 失败回滚还是补偿？重试几次、什么间隔、是否幂等？ |
| 终态 | 链路有终态吗？失败后状态可恢复吗？补偿由谁触发？ |

逐节点记录「节点 / 触发 / 副作用 / 分支条件 / 失败处理 / 终态」，闭环并经用户确认后再写入模块文档。

## 五、收敛证明——后端落点

- 结论可落到具体组件、版本与量级承诺，不是「看情况/尽量」。
- 待验证项（容量、版本兼容、第三方能力）有验证动作与回退方案。

（其余两条通用条件见 `shared/socratic-grilling-core.md` §五。）

## 六、雷区——后端补充

- 关键链路只画成功主路径 → 逐节点补回滚、超时、重试、幂等与补偿。

（其余通用雷区见 `shared/socratic-grilling-core.md` §六。）
