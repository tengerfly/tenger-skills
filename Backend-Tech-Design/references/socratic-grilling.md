# 后端选型拷问协议（grill-me 式单步拷问）

> 执行范围：TDD 的选型澄清、Scope Gate、服务拆分与数据模型决策。吸收 grill-me / grill-with-docs 的决策树 + 单步提问法，内嵌执行，不依赖外部 skill。
> ⛔ BLOCKING：决策点未过「收敛证明」前，禁止写入 overview 或模块文档。

## 一、心智模型：决策树

- 每个决策点（选型/服务拆分/数据归属/一致性策略/接口契约）是一棵决策树：答案会解开依赖它的下一层问题。
- 每轮只问「前置已定、现在就能答」的 frontier 问题；一次一问，答后消化再进下一轮。
- 用户回答冒出的新问题进下一轮；frontier 清空才算该点收敛。
- 未获用户拍板的默认（容量假设/保留策略/超时重试/一致性级别）标为待验证或【方案假设】，安排回访裁决，不得静默消化。

## 二、提问纪律

1. 每个问题写成「问题 + 推荐答案 + 理由」；无方向时给 2~3 个差异化选项 + 场景例子。
2. 推荐答案只是建议，最终仍须用户逐点拍板。
3. 一次一问：不连环轰炸、不提前抛出依赖未定的问题。
4. 回答质量门槛：抽象/口号回答（看情况、尽量、后续优化、量大再说）一律不放行，追问到能落到具体组件、量级或规则。
5. 只给结论不给理由时追问：为什么现在就需要？不用会怎样？这条链路哪一步会先撑不住？

## 三、固定三问（每个决策点至少各过一轮）

1. 这个方案在什么场景下会失败/不成立？（峰值、单点、慢调用、数据倾斜、误操作）
2. 数据量、并发或调用量涨 10 倍，这套选型/拆分/表结构还成立吗？
3. 漏掉了什么？（换调用方、失败重试、重复提交、幂等、回滚、监控告警各看一遍）

## 四、边界拷问

- 这版明确不做/不引入的组件、能力与容量承诺是什么？说不出 → 边界未想清。
- 每个模块的数据归属与写权限在哪？跨模块访问通过什么方式（同步/异步/事件）？
- 强一致与最终一致分别覆盖哪些场景？冲突时谁优先、怎么裁决？
- 鉴权、越权、敏感数据的安全边界到哪一层？
- 降级/兜底做到哪一步为止？哪些失败不自动恢复、需要告警给人？

## 五、链路节点拷问

关键链路（写库/缓存/异步/外部调用/幂等重试）先拆节点序列（入口 → 校验 → 读写 → 外部调用/消息 → 事务/响应 → 补偿/重试），再逐节点过问，禁止只走正常主路径。

| 拷问维度 | 该问的问题 |
|---|---|
| 触发与前置 | 谁调用？什么条件触发？前置校验/幂等键是什么？ |
| 副作用 | 这一步读写哪些数据？是否产生外部副作用？ |
| 分支 | 成功/失败/超时/重复/并发各走哪条路？判定条件是什么？ |
| 失败处理 | 失败回滚还是补偿？重试几次、什么间隔、是否幂等？ |
| 终态 | 链路有终态吗？失败后状态可恢复吗？补偿由谁触发？ |

逐节点记录「节点 / 触发 / 副作用 / 分支条件 / 失败处理 / 终态」，闭环并经用户确认后再写入模块文档。

## 六、收敛证明（一个决策点何时算定稿）

同时满足四条才允许定稿：

1. 结论可落到具体组件、版本与量级承诺，不是「看情况/尽量」。
2. 已记录：方案 + 理由 + 备选 + 已拷问的失败/涨 10 倍/漏项。
3. 待验证项（容量、版本兼容、第三方能力）有验证动作与回退方案。
4. 用户对定稿复述点头。

## 七、雷区（出现即自查补问）

- 用户回答一两句，就开始写 overview/模块文档 → 收敛证明未齐。
- 把 PRD 没写、本方案新增的决策当“默认/继承”直接定稿 → 新增决策必须单独拷问。
- 只问选型正向，不逼失败/涨 10 倍/漏项 → 补固定三问。
- 关键链路只画成功主路径 → 逐节点补回滚、超时、重试、幂等与补偿。
- 把「推荐答案」当最终答案 → 仍要用户逐点拍板。
