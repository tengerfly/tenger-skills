# CONTEXT.md —— Backend-Tech-Design 术语与决策记录

> Backend-Tech-Design 的术语对齐源与决策日志。SKILL/assets/references 的概念必须与此一致；敲定概念即更新本文件。

## 一、角色与边界

- 人设：后端技术专家 / 技术架构师。
- 目标：依据 PRD + 原型产出可落地、可评审、可 TDD 开发的后端技术方案包。
- 边界：承接 PRD 域界的「技术方案」——PRD 不写的数据库/接口/选型在此落地；纯前端归 Frontend-Tech-Design。

## 二、术语表

| 术语 | Key | 定义 | 排除 |
|---|---|---|---|
| TDD | Technical Design Document | 方案包（overview + NN_xxx）落 `.spec/TDD/VN/` | 与测试驱动开发同缩写不同义；本 skill 两者都用（产 TDD 文档 + 全程先写测试用例） |
| 档位 | Tier | 企业级生产（集群/分库/监控/K8s，默认）/ 快速实现（单机/docker/MVP）；每次必问 | 不是项目规模 |
| 总技术文档 | overview.md | 选型总览+架构图+模块边界+关联图+全部表结构+可选章节 | 不是模块文档 |
| 模块技术方案 | Module Design | 边界+依赖+流程图+接口/服务+数据模型引用+TDD 用例 | 不重复定义总文档表结构 |
| Scope Gate | Scope Gate | 选型+边界+表结构预览，确认后才进模块方案 | 不是归档门禁 |
| 负向边界 | Negative Boundary | 每模块写不应做什么 | 不是功能清单 |
| 浏览器软检测 | Soft Browser Detection | 检测顺序（Playwright→browser-use→其他）；全无则跳过不阻塞 | 不是硬依赖；不是「三级」 |
| 评审任务回填 | Review Task Write-back | 消费 Tech-Review 清单，修完回填已修复 | 不产任务清单 |
| AC 追溯 | AC Traceability | 测试用例标 PRD AC 编号 | AC 单源在 PRD-Design |
| 选型一次定稿 | Selection Finalized at Design | 全部技术决策方案期敲定并经 Scope Gate 确认 | 不把选型留到开发期 |
| 苏格拉底拷问协议 | Socratic Grilling | TDD 澄清执行规范：决策树单步提问 + 边界/链路节点拷问 + 收敛证明 | 不是泛泛聊天；未过门槛不定稿 |
| 收敛证明 | Convergence Proof | 决策可定稿的四条件：结论含组件与量级 + 方案/理由/备选 + 失败/涨 10 倍/漏项已拷问 + 用户认可 | 缺一即 P0，退回补问 |
| 节点拷问 | Node Interrogation | 关键链路逐节点问触发/副作用/回滚/超时/幂等/终态 | 禁止只设计正常主路径 |
| 决策规则 | Decision Rules | `When+场景→动作+because/unless+量化阈值`的工程决策库（decision-rules.md） | 不是选型推荐表（那是 tech-stack-guide） |
| 量化阈值 | Scaling Thresholds | 单机能力/连接数/分片/限流等数字阈值与达到后的动作，方案期默认起点 | 写入前仍需过收敛证明校准量级 |
| 案例库 | Case Library | references/case-library/：模式解剖/经典题/可靠性/大厂案例，按需加载 | 借鉴决策，不照搬架构 |
| Anti-Happy-Path | Anti-Happy-Path | 每功能点至少三条失败场景（竞态/数据完整性/边界），拒绝只写 Happy Path | 不是五类覆盖的重复，是强约束底线 |
| 容量规划 | Capacity Planning | 实例数/存储/带宽的量化计算范式（decision-rules §十） | 不是只写「要做压测」 |
| 技术债登记 | Tech Debt Registry | 显式登记为赶进度妥协的设计 + 优化 TODO + 触发条件 | 不是静默妥协 |
| 上线与回滚 | Release & Rollback | 灰度/数据迁移/回滚步骤/验证清单 | 不是部署架构章节 |
