# 编排方单次并入新基类时，把「待裁的裁决说明」当 CSS 声明值写入，导致该声明被解析器整条丢弃（三重静默）

> 定级理由：缺陷**三重静默**（解析器丢弃声明不报错、`{`/`}` 计数不变、computed 静默回退到继承值），且三条既有护栏判据全部判绿；任何一次「把登记项合并进共享样式表」或「回填裁决」都会再犯，复发面 100%。产物已交付并被下游（`Frontend-Tech-Design`／`Frontend-Dev`）消费后才发现，纠正成本＝重绑批准摘要＋全站复扫。

## 现象

批次 3 六页交付后，编排方按 `newClassPolicy` 做「新基类单次并入」（2026-10-13T15:52:18+08:00，`assets/ui-kit.css` 追加「批次 3 并入块」40 条规则）。执行棒登记项 `b3a-new-classes.json` 的 `declared` 字段里，有两条把**待裁说明的散文**和声明值写在了同一串里：

```
.g-text    { fill: var(--color-text);       font-size: 12px→保持原型 12px 为 SVG 内部固有字号；font-family: inherit; }
.g-text--sm{ fill: var(--color-text-secondary); font-size: 11px（同上 ⚠️ 待裁）；font-family: inherit; }
```

合并动作**原样照抄**了这两串，于是 `ui-kit.css:945/947` 的 `font-size` 值里出现了中文、全角分号 `；` 和箭头 `→`。后果链：

1. CSS 解析器把 `font-size` **整条声明丢弃**（值非法），同规则内其余声明照常生效；
2. `graph.html` 内联 SVG 文本的 computed `font-size` 静默回退成 **14px** —— 既不是原型意图的 12/11px，也不是 `design-system.md` §2 字阶里的任何一档；
3. 三条可见信号全无：console 0 条、`{`/`}` 配平 215/215、页面无破版无横向溢出。

发现方式不是护栏，是编排方为「并入生效性」另写的量具在 **CSSOM 层**核对 `[...rule.style]` 时读到了 `decl` 与 computed 的矛盾（`orch_b3_class_probe.py` 报 `.g-text` computed＝14px），顺藤摸到样式表原文。

## 为什么既有护栏全漏（这是本条的核心）

`ui-ux-design` 现行自检口径（批次 1 P0 后由评审方写入汇总报告 §六-1 的四条）是：① §7 块外 hex 字面量＝0；② 页内 `<style>` 块＝0；③ 未声明 `var()` 引用＝0；④ `var()` 消费图全量对账。

本缺陷**同时不触碰这四条**：它没有新增色值、没有页内 style、引用的 `var()` 全部在 `:root` 有定义、消费图也完整。也就是说这四条查的是「**取值是否越界**」，而本缺陷是「**声明是否落位**」—— 属现有判据的空白维度，不是执行不严格。

同时「已交付真实渲染验收」（console／三视口溢出／逐态非空白／截图目视）**也查不出它**：字号回退到 14px 后页面依然完整、依然不溢出，只有拿登记值逐条对照才会发现。执行棒与评审方两轮都过了浏览器渲染，无人核对「这条声明到底进没进 CSSOM」。

## 根因

1. **登记字段语义不纯**：`b3a-new-classes.json` 的 `declared` 同时承担「声明值」与「待裁说明」（I-31/I-33 把裁决状态写进了值串）。合同只规定「逐条取值登记＋结构化清单」，没规定该字段必须是**可直接并入的合法 CSS 声明串**。
2. **合并动作无落位校验**：`newClassPolicy` 只写「编排方单次合并→重跑跨批回归→只对 ui-kit.css 重绑摘要」，跨批回归比的是**已批准页**的 computed 指纹（新页不在对照面），且没有任何一步要求「并入块每条声明在 CSSOM 里确实存在」。
3. **待裁项与执行动作没有隔离**：两条「⚠️ 待编排方裁」被以文本形式留在施工面（样式表），裁决完成时没有回头清扫占位串的强制步骤 ⇒ 说明文本天然会被当成值。
4. 同事件族的量具坑（不另建档，只回链，避免跨池复制同一原始问题）：`file://` 下直读外链样式表 `cssRules` 因 origin=null 抛 SecurityError，若被 `try` 吞掉会读空、把 40 条全判成「未并入」（须加 `--allow-file-access-from-files`）；组合选择器（`+ ~ > ,`）按基类首元素取样会读到未受该规则作用的兄弟；登记 `decl` 内嵌整条规则（`sel { … }`）时须先拆选择器，否则把 `sel { prop` 当属性名去查。

## 期望 vs 实际

- **期望**：并入后当场即知「两条声明没落位」，或根本不允许散文字符进入可并入的声明串；任何「待裁」状态都以注释或外部台账承载，样式表内只存在合法声明。
- **实际**：缺陷随交付落盘，经「执行棒自测 → 编排方类探测 → 独立复扫」三道之后才在 CSSOM 层被撞到；期间已生成并交付了 31＋72 张截图、两份汇总证据，且 `DEC-20261013-UIX-APPROVE` 的批准摘要已被并入动作失效，需二次重绑（摘要链 `760d8440→36d3120e→4786886194ff4daa→03f33f47`，四次变更其中两次源于本次事件族）。

## 检出方法（可直接实现，本轮已实证）

| 方法 | 成本 | 实证 |
|---|---|---|
| **静态**：剥离 `/* … */` 后扫描非注释区的 CJK 字符与全角标点（`；：（）、→`） | 极低（纯文本，无浏览器） | 本轮命中恰好 2 行＝该两条缺陷；修复后命中 0 |
| **CSSOM 层**：对每条登记项取 `rule.style.getPropertyValue(prop)`，断言非空 | 中（需浏览器，一次跑全站） | 能抓到「整条丢弃」，computed 层永远抓不到；须加 `--allow-file-access-from-files` |
| **computed 层**：把 `var(--token)` 用 `:root` 实值展开（hex→rgb）后与 computed 比 | 中 | 只能验「值对不对」，验不出「声明在不在」，且简写/长写需归一（否则假阳性成片——本轮实测 31 条假 DEFECT 全是表示法差异） |

## 修复方向（**本轮未改 skill 正文**，待用户统一优化时裁决）

1. **登记字段合法性约束（主修）**：`newClassPolicy` / self-write-sop 的新基类登记表加 REQUIRED——`declared` 必须是**可直接并入的合法 CSS 声明串**；待裁说明另起字段（如 `pending`／`note`），禁止与值串混写；合并方遇含非 ASCII 的声明串一律退回执行棒而不是照抄。
2. **并入后落位校验成为 REQUIRED**：单次合并的收尾步骤固定为「剥注释后非 ASCII 扫描＝0 ＋ 逐条 CSSOM 声明在位核对＝0 缺失」，两条都出数字才算合并完成；只跑跨批回归不构成并入完成证据。
3. **护栏新增一维**：把现有「取值是否越界」四条扩一条「**声明是否落位**」，并在 `ui-ux-review` 的 `references/known-issue-patterns.md` 立为新模式（建议名：**声明静默丢弃**：非法值／散文污染致 CSS 声明被解析器丢弃，computed 静默回退、规则数不变、console 无声，凡只看渲染只看 hex 的量具一律漏检）。
4. **裁决闭环扫占位**：凡「待裁／⚠️」类文本进入施工面（HTML／CSS／增量表）的，裁决动作必须附带「回头清扫该占位串」子步骤，并在交付检查里以 grep 该标记词命中 0 为判据。
5. **共享基准变更的摘要成本显式化**：并入共享样式表会让绑定它的所有批准记录失效——本条事件造成两次重绑。建议 `newClassPolicy` 要求合并前先在 DEC 里预告摘要演进链，避免下游读到过期绿灯。
