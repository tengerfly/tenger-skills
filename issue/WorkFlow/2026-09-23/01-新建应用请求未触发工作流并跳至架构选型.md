## 现象

用户开场请求：「我想做一个个人知识库的应用，就像 Obsidian 一样，先做 web 端 MVP，个人使用，功能有写入 / 查看知识库列表 / 知识库图谱（星球形状，点击弹框显示知识库）。」

这是 WorkFlow `Trigger` 段明确列举的「新建」类请求，但实际执行中：

1. **WorkFlow 未被调用**，因此 `Procedure §0` 的阶段路线与状态卡播报、`§1` 执行强度判定、`§2` 流程入口选择全部未发生；
2. 助手在**未做任何需求澄清**的前提下，直接探查兄弟项目工程栈，并一次性抛出 4 个技术决策问题：数据层级模型、存储真相源（Markdown 文件 / Postgres / 纯前端本地）、图谱渲染形态（3D 球面 / 3D 力导向 / 2D）、编辑器形态；
3. 用户中断并纠正：「为什么没有触发 WorkFlow 工作流？我明确说了我想做一个应用，接下来应该是澄清需求阶段而不是跟我讨论架构。」

后果：CREATE 链上本应先行的 `idea-intake` / `product-discovery` / `feature-decision` 全部被跳过，用户被迫在需求未定义时裁决架构，问题被拒绝。

**复发性**：`issue/WorkFlow/2026-09-22/01-流程可见性与产品需求入口纠正.md` 原始事实第 3 条即「创建对标应用时仅问搭建方式和用户，没有继续竞品功能盘点与范围确认」。上轮修复覆盖了「对标应用」路径（要求先交付有来源的功能全景），但**未覆盖「从零新建应用」路径**，同根因以新场景复发。

### 根因精确化（2026-09-23 本次会话内二次核查）

按指正调用 WorkFlow 后加载 `shared/execution-profiles.md`，发现 **`execution-profiles.md:15`「产品探索不能被误裁剪」已经逐字禁止了本次行为**：

> "做一个像某成熟产品一样的完整应用"……至少按标准产品探索处理。先研究并展示功能全景，再确认范围；**不能以"只问关键问题"缩成用户画像 + 自建/开源两问**。用户明确要求的竞品研究在任何强度下都不能静默省略。

即：**不是没有规则，而是规则不可达**。该规则位于 `shared/`，只有 WorkFlow 被触发、`Preconditions:32` 指示读取 `execution-profiles.md` 之后才会进入上下文；入口 `description:3` 不含用户原话触发词 ⇒ 技能从未被选中 ⇒ 下游全部规则（含本条）一次都读不到，错误必然发生。

据此修正根因优先级：**R1（触发词错层）是唯一致命项，R2/R4 属"规则已存在但缺跨层引用"** —— R2 的"澄清分层"其实已被 `execution-profiles.md:15` 覆盖，无需新写规则，只需在 `Trigger` 指向它；R4 同理，改为引用而非另立条款，避免两处规则漂移。归属仍为 WorkFlow 入口层，不改判。

## 期望 vs 实际

- **期望**：识别为新建应用请求 → 调用 WorkFlow → 播报阶段路线 → 判定完整档 → 进入需求澄清（原始想法登记、目标用户与任务、功能全景与 MVP 取舍），技术选型留到 Tech Design 节点
- **实际**：未调用 WorkFlow，无阶段播报，第一轮即输出 4 个架构层决策问题，需求定义被跳过

## 修复方向

1. **改 `WorkFlow/SKILL.md:3` description（R1，收益最大）**：前置用户原话触发词，例如加入「用户说想做一个应用/产品/网站/工具/MVP、有想法待落地时的总入口」。入口判据必须出现在技能列表可读到的那一行，正文里的 `Trigger` 不能替代它。
2. **在 `Trigger:20` 加澄清分层约束（R2）**：明确「第一轮澄清仅限业务范围、目标用户、使用场景、数据语义与验收预期；语言/框架/存储/渲染库/部署形态等技术决策一律延后至 Tech Design 节点，由该节点按 `shared/oss-research-policy.md` 展开」。同时删改「只澄清影响验收/安全的关键问题」这一句的宽泛解读空间。
3. **`§2:66` 增补首条判据（R3）**：目标目录为空 / 无 `.spec/` / 无已有实现，且请求含产品意图 ⇒ 直接判 CREATE 完整档并进入需求域，不得由助手自行决定起点。
4. **`§3:78` CREATE 行加禁止性说明（R4）**，并把它提升为跨生命周期通用门禁（与 09-22 已修的「对标应用先出功能全景」合并成同一条入口判据，避免再次分叉复发）。
5. **回归**：把「从零说想做一个 XX 应用」写入 `docs/task-scope-regression.md` 的场景清单，与 09-22 已登记的场景并列，要求 fresh-agent 试跑验证，不以规则改完即关闭。
