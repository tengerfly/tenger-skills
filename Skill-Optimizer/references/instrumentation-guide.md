# 埋点规范（各 skill 自查上报规则）

> 本规范是各专业 skill「监听」的实现：skill 无法后台常驻，运行期问题由各 skill 自己在执行收尾时自查上报。
> 各 skill 落地埋点时，在自身 SKILL.md 增加「运行问题埋点」一节并引用本规范（作为 Skill-Optimizer 上线后的第一批优化任务逐个落地）。

## 一、何时记录

skill 执行的**收尾阶段**（产物落盘 / 交付之后），自查本次运行：

1. **方法论问题**：本次执行中流程 / 规则设计暴露的问题（某 Gate 漏判、某步骤总返工等）；
2. **用户负面信号**：用户明确否定 / 纠正 / 质疑的点（「不对」「重来」「别乱发挥」类）→ 可加「反面参考」标签；
3. **用户正面信号**：用户明确认可的点（「好」「就这样」「以后都这样」类）→ 标签「正面参考」；
4. **明显复现的产物问题**：本次产物出现、且判断会再次出现的问题（一次性笔误不算）。

## 二、记什么（字段）

按 `Skill-Optimizer/assets/issue-template.md` 完整字段记录，来源填「埋点」。

## 三、记到哪

`issue/<本skill名称>/<当天日期 YYYY-MM-DD>/<序号>-<简短标题>.md`

序号在该日期目录内从 `01` 递增。

## 四、判定规则

- **等级**：P0 方法论硬伤/每次必犯/阻塞；P1 明显影响/高频；P2 轻微/建议
- **标签**：从 10 个预定义标签中选（触发识别 / 流程缺陷 / 边界不清 / 术语文案 / 产物格式 / 接口契约 / 工具依赖 / 性能体积 / 正面参考 / 反面参考）

## 五、红线

1. **不确定算不算问题 → 不记**，交用户判断（宁可漏记留给兜底通道，不可误记噪音）；
2. **不因记录打断主流程**——埋点是收尾动作，不是执行中动作；
3. **正负同等重要**——正面信号与负面信号都要记，正面是可复制的优化方法；
4. **零幻觉**——只记录本次运行真实发生的，禁止臆造。
