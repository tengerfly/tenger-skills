# 全方位优化检查清单（优化模式标准）

> 优化模式的固定标准：四维度逐项体检，先自优化（含修订标准）再优化目标 skill。**逐项走完，每项有结论（修 / 不修 + 理由），不凭感觉。**

## 使用前提

1. 优化对象 = 本 skill（Skill-Optimizer）时，先检查三份标准本身是否有 issue 待修 → **先修标准，再用修订后的标准执行本次优化**；
2. 优化对象 = 其他 skill 时，先确认本 skill 自身无 P0 未修项（有则先自优化）。

## 维度一：问题修复（issue 驱动）

- [ ] 读 `issue/<目标skill>/` 全部「待处理 / 处理中」项，按等级排序（P0 → P1 → P2）
- [ ] 逐条修复：改 SKILL.md / references / assets 对应位置
- [ ] 每条修复后回填：状态 → `已沉淀` + 沉淀目标 + 沉淀位置
- [ ] 不修的条目：状态 → `已忽略` + 理由（须向用户说明）

## 维度二：性能体积

| 检查项 | 判定 | 动作 |
|---|---|---|
| SKILL.md 篇幅 | 正文有明显冗余、重复表述、过度展开 | 删冗余不删规则 |
| 内容下沉 | 低频使用的细则占着主文件篇幅 | 下沉到 references（主文件留一句入口） |
| description | 过长（影响触发匹配效率与加载） | 压缩到触发语义清晰的最短表述 |
| assets 模板 | 重复字段、过度结构 | 合并精简 |

**精简原则**：删冗余不删规则；下沉不删除；每处精简可追溯到具体位置。

## 维度三：触发精准

- [ ] description 触发词与实际能力一致（不过度承诺、不遗漏）
- [ ] 与其他 skill 触发词不重叠（防误触发；重叠时写出差异化场景）
- [ ] 典型触发语句已覆盖（该触发的口语说法有没有写进去）

## 维度四：术语一致

- [ ] SKILL.md 与该 skill 的 CONTEXT.md 术语表无冲突
- [ ] 与仓库全局约定（根 README、跨 skill 机制如 issue 池 / 浏览器工具策略）无冲突

## 收尾动作（四维度全部完成后）

1. 目标 skill 的 CONTEXT.md 决策日志追加一条 `D-xx`（改了什么、依据哪条 issue / 体检发现）；
2. 回填 issue 状态（已沉淀 / 已忽略）；
3. 输出优化摘要：改了哪些文件、为什么、依据是什么，逐项可追溯。
