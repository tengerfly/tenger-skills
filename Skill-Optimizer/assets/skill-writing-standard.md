# Skill 编写规范（通用底座）

> optimize-checklist 维度二~六的判据来源。新写/优化 skill 时对照执行。
> 一句话：Skill 是给 AI 的操作手册——入口、省、准、稳 + 简洁不落俗。

## 一、入口：description
模型只靠 frontmatter description 决定是否使用。须同时说清：
1. 做什么（一句话能力）。
2. 何时用（用户自然语言：动词 + 场景 + 同义表达）。

检查：用户最可能说的 3~5 种说法，description 是否都能命中。

## 二、省：上下文是公共资源
硬红线：SKILL.md ≤ 500 行；超出拆走，正文只留入口。

**四级加载模型（渐进式披露，L1~L4）**：

| 层 | 内容 | 加载时机 |
|---|---|---|
| L1 元数据 | frontmatter（name + description） | 决定是否触发，最先加载 |
| L2 指令 | SKILL.md 正文（流程/铁律） | 触发后加载，常驻 |
| L3 引用 | references/ 知识 | 按需加载，不预载 |
| L4 脚本 | scripts/ 可执行代码 | 不加载，只调用 |

规则：references 只嵌套一层；反复写的代码进 scripts；反复读的知识进 references；只进产物的进 assets。四级各司其职，Token 按需消耗（省 60–80%）。

## 三、准：引导注意力
| 脾气 | 症状 | 对策 |
|---|---|---|
| 泛泛说废话 | 注意力不聚焦 | 写「该问的问题」，不写「该找的答案」 |
| 默认模式改不掉 | 每次都犯同一错 | 禁令清单逐条点名反面教材 |
| 压力下走捷径 | 改改试试 | 铁律 + Red Flag 放开头 |

写法：先想清最可能犯的错，防它的规则用斩钉截铁措辞放开头；再列症状清单让模型自己识别刹车。

引导式提问：确定型 skill 面对思路狭窄的用户要当思路放大器——竞品/参考引导、「问题+2~3 选项+例子」、专家视角纠偏，不照单全收。

## 四、稳：流程立稳
1. 工作流清单：关键步骤标 ⚠️ REQUIRED / ⛔ BLOCKING。
2. 确认节点 Gate：生成/修改类操作在决策点停下问用户；**需拍板点逐条编号列清单一次性呈现**，确认后记结论，未确认不推进。
3. Pre-Delivery Checklist：定义怎么算做完，每条具体可检查。
4. 优先级分级：P0-P3 让模型知道重点。

参数系统（可选）：$ARGUMENTS + argument-hint，支持只跑局部。

## 五、简洁不落俗
AI 写的 skill 天然臃肿，做完只做减法。

删除：空洞承诺（确保高质量/力求完美/无缝/赋能）；套话开场收尾过渡；冗余引导语；副词堆叠；emoji 滥用、加粗泛滥、无信息表格。

简洁判据：一句话能说清不用三句；删不承载信息的词；优先动词短语。

**禁口语化直接入 skill（硬标准）**：用户原话须提炼成简明准确可操作的专业表述再落笔；skill 全程简明扼要。
