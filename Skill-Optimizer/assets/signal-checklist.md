# 信号识别清单（挖掘模式标准）

> 挖掘模式的固定标准：对聊天记录逐类扫描四类信号，再按提炼规则聚合成问题。**逐类走完，不凭感觉。**

## 一、负面信号 🔴

用户否定、纠正、质疑的表达——skill 有问题的直接线索。

| 信号类型 | 识别特征（示例语句） | 提炼要点 |
|---|---|---|
| 直接否定 | 「不对」「重来」「不是我要的」「这不是我说的」 | 哪个环节的产出被否？根因在 skill 哪一步？ |
| 纠正指令 | 「别乱发挥」「别加戏」「按我说的来」「你理解错了」 | skill 是否缺「不确定即问」Gate / 约束规则？ |
| 质疑 | 「为什么又…」「怎么每次都…」「太啰嗦」「太慢」「太复杂」 | 高频质疑 = 方法论级缺陷信号 |
| 用户亲自下场 | 用户自己动手改 skill 的产出 / 大段重写 | 该环节 skill 产出能力不足，找差距 |

## 二、正面信号 🟢

用户明确认可的表达——可沉淀的优化方法。

| 信号类型 | 识别特征（示例语句） | 提炼要点 |
|---|---|---|
| 直接认可 | 「好」「不错」「就这样」「可以」 | 记下「好在哪」，提炼成可复制规则 |
| 定向认可 | 「这个思路对」「这版可以」「以后都这样」 | 明确指出哪一步 / 哪个做法好，标签「正面参考」 |

## 三、返工信号 🔁

同一处反复劳动——流程设计缺陷的强证据。

| 信号类型 | 识别特征 | 提炼要点 |
|---|---|---|
| 同任务重做 | 同一任务 ≥2 轮推倒重来 | 找第一轮失败的根因（信息不足？Gate 缺失？） |
| 评审循环 | 评审→改→再评审，问题清单不收敛 | 对照「修复判据 / 分级冻结」机制，记「评审死循环」类问题 |
| 用户反复调整 | 用户对同一处 ≥3 次微调 | skill 是否缺少中途确认点？ |

## 四、触发痕迹 🎯

skill 被调用的客观痕迹——判断触发是否精准。

| 检查项 | 说明 |
|---|---|
| 调起 skill | 哪个 skill 被调起、是否是用户想要的那个（误触发？） |
| 漏触发 | 用户诉求明明匹配某 skill 却没触发它 |
| 中断点 | skill 执行到哪一步被用户打断（打断 = 该步骤有问题） |
| 产出物 | 产出了什么、用户接不接受 |

## 五、提炼规则

1. **信号 ≠ 问题**：信号需聚合——同类信号 ≥2 次，或单次但足够明确，才提炼为问题；
2. **每条问题六要素齐备**：现象 + 期望 vs 实际 + 归属 skill + 等级 + 标签 + 修复方向；
3. **无归属不强行归属**：找不到对应 skill 的信号，单独列出交用户判断；
4. **先确认后落盘**：提取清单先给用户逐条过目（增删 / 改归属 / 改等级标签），确认后才写入 issue 池；
5. **零幻觉**：所有提炼必须能回溯到聊天记录原文，禁止臆造。
