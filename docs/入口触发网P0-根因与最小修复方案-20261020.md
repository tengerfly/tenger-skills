## 2. 根因判断

【事实】
- 入口判据唯一初始可见处是 `workflow/SKILL.md:3` 的 description；`Trigger:` 段、`§2` 与 `shared/ruling-policy.md`、`shared/workflow-visibility.md`、`shared/execution-profiles.md` 都在 skill 被选中后才加载（三份 shared 中无入口判据）。
- `scripts/validate_core.py` 对 skill 的 description 只校验非空（约 :284），`Other/skill-optimizer/assets/skill-writing-standard.md` 仍教「关键词轰炸」，没有「禁封闭枚举」规则。
- DSH 支持用户全局 `$DSH_HOME/AGENTS.md` 首请求注入（asar 内 README 说明），但本机 `~/.dsh/AGENTS.md` **不存在**；Qoder 有 guard（未复测）；zcode 已于 10-17 切到别的体系。
- 前两次修复都在 description 同层；没有任何机制在「未选中任何 skill」的时刻生效。

【推断】漏检发生在**选择层**（该轮零工具调用）；没有宿主级兜底时，改 description 只能提高概率、不能消除漏检。既有验收 n=1 / n=6 不足以证明「随机抖动」。
