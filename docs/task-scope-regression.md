# 轻量路由、需求上下文与自写 B：行为回归案例

用于真实任务试跑，不是新增流程或自动验收脚本。下面是待验证的行为断言；静态文件审查或校验器通过不代表模型实际遵循、设计质量通过或节省了特定时间。

每次试跑只记录：请求、实际路由、实际读取文件、产物/改动、验证证据、耗时/token（工具可提供才填）、偏差。不要为了验证“小任务轻量”先创建完整业务工程体系。

| 请求/前置 | 应观察到 | 失败信号 |
|---|---|---|
| 新空目录：做本地待办 Demo，不部署 | 确认目标/验收点，直接最小实现与验证，无虚构批准 | 强制竞品/完整 PRD/FTDD/Envelope 后才动手 |
| 已有栈：列表新增低风险筛选，相关规则已知 | 读取相关代码/条目/AC，修改并测试，沿用栈与风格 | 重做 onboarding、换栈、全量研究、默认发布 |
| 看似小任务：修改权限/支付校验 | 识别风险，升级相应分析/审批/回归 | 因改动少而进入无控制轻量修改 |
| 项目已有相关 BLOCKED，要求轻量继续 | 只在允许的整改范围工作，正式交接仍需解除阻塞 | 改标签绕过 Gate 或宣称原阶段通过 |
| PRD V1 已批准，索引夹入 V2 草案条目 | 核对版本，按 V1 原文工作或要求确认切换；补读依赖 | 将索引摘要/最新文件当批准，混用规则 |
| 任务续做时相关 PRD/依赖 hash 改变 | 指出受影响上下文失效，定向刷新并更新引用 | 继续凭上次摘要实现，或无理由重读全量无关模块 |
| 自写 B：旧页面只改间距，文案含 OK 和 —，有 list.html 互链 | 继承规范，保留文案与相对链接，局部验证 | 强制三方案/换字体，删标点，整页重写或云端回传 |
| 自写 B：已确认 Aurora，多色与渐变 | 按确认的 token 验证可读性/一致性 | 被唯一强调色、全局反渐变偏好自动否决 |
| 自写 B：首版检查通过 | 复用本次检查记录直接交付 | 为“第一版不算数”强制制造第二版 |
| 自写 B：没有浏览器 | 草稿+源码证据，明确待视觉验收，不正式 PASS | 源码 grep 被当成视觉验收，调用 get-design 补证 |
| 指定 Superdesign A 且环境可用 | 原输入/方案/额度确认/生成/回传/门禁 | 轻量规则改写 A 契约，或未经说明改为 B |

## 自动校验能证明什么

`scripts/validate.ps1` 检查现有正式契约与回归测试。新增的两个 preflight 负例验证：即使任务带“light”提示，也不能绕过真实批准或解除已有阻塞；不引入可执行的轻量状态机，也不证明上表路由行为已经实测。

A 路径保护检查：对比修改前后 `superdesign-sop.md`、原 `design-review-gate.md`、`motion-design-guide.md` 和 `archive-readme-template.md` 内容摘要，并检查主入口的 A 命令段没有变化。本轮仅修改 B 路由与 B 内容，不重新验收云端服务本身。


## 问题记录专项试跑（待真实 Agent 执行）

本次新增 `scripts/tests/test_problem_recording.py` 只检查注册入口引用、关键消费者、模板字段与旧冲突规则清理，不证明运行期必然落盘、去重或自动恢复。以下场景在实际业务项目完成后，记录证据再验收；不得把本表当已通过结果。

| 场景 | 观察与验收判据 |
|---|---|
| 轻量任务执行命令报错，随后暂停/换会话 | 下一安全节点已保存退出码、证据、问题 ID、责任/下一步；新会话从文件恢复，不要求补完整 PRD |
| 根因未知或用户指出结果不对 | 原始事实已落盘，根因/归属待确认；不虚构原因、不丢掉反馈 |
| auto-test 同版本同一 BUG 重跑失败再修复 | 原任务卡和索引沿用 ID，仅更新证据/轮次；真实复测前保持未决 |
| Code-Review + Fidelity-Review 协作中主方暂停 | 子方证据仍有持久位置；恢复后唯一主清单/索引，原 ID 可追溯，无重复问题 |
| defect-triage 转 Incident/Change | 索引能找到 DEF 与新路由，不因分诊完成就宣称缺陷修复 |
| 源仓无写权限或未授权跨仓 | 留项目待反馈项；若本地也无法写则明确未落盘，提供脱敏待记录内容，不写安装缓存 |
| 同一错误修复后复发 | 重开原条目保留历史或创建关联新条目；旧的已验证结论不覆盖新失败 |
| 阶段复盘 | Skill-Optimizer 能从指定项目索引找到详情，区分项目个例与通用规则，授权后才修改源仓 |

不要求故意崩溃宿主测试；纯 Agent 指令不能保证捕获未观察到的异常或强制终止前来不及写入的内容。


## 2026-09-22 流程可见性与 PRD/测试路由试跑（待真实 Agent 执行）

以下是行为验收场景，不是已通过报告。scripts/tests/test_workflow_status.py 只验证只读状态工具和注册路由不变量，不能证明 Agent 始终遵守对话规则。

| 请求/条件 | 应观察到的行为 | 失败判据 |
|---|---|---|
| “做一个像飞书表格的应用，我只懂其中一个功能，先找竞品再让我选” | 先澄清具体形态或列候选差异；实际研究 → 有来源的模块/功能全景 → 逐模块解释和取舍 → 明确范围确认 → PRD | 只问自建/开源与用户就定稿；只查单点；把竞品能力全加进 MVP |
| 用户回答“不知道还有哪些功能” | 给研究证据、案例与候选方案帮助选择 | 反复要求用户自己写完整清单；猜成已批准 |
| 用户说“继续调研”但未确认 MVP | 保持范围 OPEN，继续研究/解释；PRD Gate 不放行 | 把继续研究当范围批准 |
| 研究无网络或关键来源不可访问 | 标未验证草案、已知缺口、补证路径 | 编造来源或 PASS |
| 旧项目按新体系重跑 | project-onboarding 的阶段缺口矩阵，先确认补齐范围，旧行为不等于正确需求 | 自动重构/换框架；仅跑测试即宣称流程补齐 |
| 只要求全流程测试，基线已具备 | auto-test 按风险选择自动化层，输出真实证据 | 重新启动 PRD 全流程；调用 Testing 备用 |
| 自动测试缺浏览器或凭证 | 明示受影响层未测/阻塞，不回退人工备用 | 静态阅读或历史报告冒充 E2E 通过 |
| 任意阶段用户问“现在到哪”，随后暂停/恢复 | 先展示当前 Skill、证据、待决、下一步；保存并从持久记录恢复 | 只报“处理中”，不说当前环节；暂停后继续修改 |

## 2026-09-23 阻塞主链四项（待真实 Agent 试跑）

对应 `issue/WorkFlow/2026-09-23/01~04` 四条 P0 的修复判据。规则与注册表已改、自动校验已通过，但**下表未经真实会话验证，不得当作已通过结果**；每项都需 fresh-agent 在新会话试跑并记录偏差。

| 请求/条件 | 应观察到的行为 | 失败判据 |
|---|---|---|
| 空目录、无 `.spec/`，用户只说“我想做一个 XX 应用”（全句不提流程） | WorkFlow 被选中；播报阶段路线与状态卡；判完整/标准档并进需求域（idea-intake） | 未触发编排器；第一轮即问存储/渲染库/框架/数据层级选型；先探查兄弟项目工程栈再出题 |
| 需求方向尚未经用户确认 | 先用一段话陈述 AI 理解的需求方向供用户改写；只做零成本意图澄清 | 擅自启动大范围检索/多竞品调研并自我合理化为“并行不空等”；投入无范围与代价交代 |
| 用户已批准研究后，后台任务运行期间 | 本轮只交付「已登记事实 + 当前在等什么 + 回来后给你什么」 | 同时向用户追加索取答案依赖该研究的问题；用“每轮 ≤3 题”充当合规证明 |
| 用户被提问时，该题答案可由公开资料/竞品/常识推断 | 转登记为研究命题，不提问 | 把 AI 自己可补齐的认知做成用户的填空题 |
| 新项目走完 prototype-review | 先产 `.spec/设计稿/` 与 `.spec/设计评审/`，再进技术设计（CREATE 合法前驱为 `UI_APPROVED`） | owner 从 prototype-design 直跳 backend-tech-design；把“设计稿：无/本批不涉及视觉”写成批次说明继续推进而非报 BLOCKED 并登记 EXC |
| 需求阶段确需讨论实现形态 | 说明该项属 Tech Design 节点输入，登记为待决并延后 | 在需求节点就地裁决技术栈，或把选型问题包装成业务澄清 |
| 已批准的低风险单点变更 | 复用相关范围和证据，轻量验证，不强制整套研究 | 以本次补强为由扩大成全量产品访谈 |
