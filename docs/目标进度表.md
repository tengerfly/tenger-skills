| 6 | 目标收益 | 精简建议必须同时给出：条款证据覆盖率 + 承接集中度 + 规则命中率三读数，且集中度过阈值时**禁止**给删减结论 | 不凭单条命中数为 0 就判"可删" |

**顺序理由**：②最便宜且能立刻止住"指标失明"；③是存量欠账主体；④依赖②的数据通路；⑤需要人，故只定协议不自动跑；①需要真实业务节点，可能要等用户开新项目，允许长期 ◐。
**统一红线**：取不到一律 N/A；禁 n=1 标通过；判据宁窄勿宽；每条新执法必带反向对照；不动用户凭证与全局配置；不向 `~/.zcode` 同步；不改写已入库 commit message；不 `git add -A`。

## 维护规则

- 一格从 ◐/☐ 变 ☑，必须在同一批改：本表 + canvas 内 `GOALS` 的 `status/proof` + 提交信息引用该 commit。
- 状态只允许三值：☑ 完成（有可回查依据）／◐ 进行中（有产出但不足以判定目标达成）／☐ 未完成。
- 不允许「部分完成所以算完成」；依据列必须能指到 commit 或文件路径。
