## 1. 开工即发现的问题

### F-1 控制文件落后代码 40 轮，机械校验器看不出来（P1）

- **现象**：workflow.yaml 停在 `TECH_DESIGN_APPROVED` / currentSkill=frontend-tech-design，而代码已推进 40 轮；`validate_core.py gate` / `artifact` / `controldrift` 三条全部 passed。
- **证据**：
  - `python scripts/validate_core.py controldrift --project-root <KB>` ⇒ passed（2026-10-18 15:30）
  - `git log -1`（KB 仓，本轮新建）之前项目无 git；`.spec/manifest.yaml` 未登记任何代码面产物
- **根因**：controldrift 的对账面是「控制文件 ↔ 已登记产物」；代码实现进度既不进 manifest 也不进 trace，所以状态可以落后任意轮数而全绿。40 轮开发是在体系外执行的（无 tsr 事件、无 PROJECT/PLAN、无 git 提交），体系恢复时没有机械信号。
- **影响**：新会话接手时无法信任 workflow.yaml；正确状态要靠人读交接文档 + 抽查代码重建，属于「状态失真」类风险。
- **本次处置**：按 `shared/workflow-visibility.md` 换会话对账规则，人工重建为 DEV_IN_PROGRESS，并补 tsr node-start（backend-dev / frontend-dev，execution=EXEC-20261018-KB-DEV-R41）；补 PROJECT.md/PLAN.md；KB 仓 git init + 基线提交。
- **skill 修复候选**：① 开发类节点把「代码产出」纳入可对账面（至少 dev node-start/end + 每功能点 commit hash 写入 PLAN）；② controldrift 增加「state 已过技术设计但 dev trace 事件为 0 且工作区有代码」的告警档。待本轮结束按实测补判据。

### F-2 真实项目没有 git 仓库，backend-dev 铁律 6（一功能点一提交）无法执行

- **现象**：项目无 .git，此前 40 轮开发无提交记录；backend-dev S7 要求「每完成一功能点：更新 PLAN 状态（附 hash）→ eslint + commitlint → 自动提交」。
- **影响**：评审无法按 commit 定位改动；回滚无基线；trace 的 artifacts 只能绑文件 sha，无法绑提交。
- **本次处置**：开工前 git init + 基线提交（Lead 统一提交，agent 不执行 git）。
- **skill 修复候选**：backend-dev/frontend-dev S1 增加「无 git 先建仓并提交基线」的前置动作（当前只在「提交」步骤隐含要求）。

### F-3 项目缺 PROJECT.md / PLAN.md，续做只能靠交接文档

- **现象**：backend-dev S1 三路判定要求「续做（有 PROJECT.md + PLAN.md → 读后从进行中/待做续）」，项目两者皆无。
- **影响**：功能点状态只存在 .spec/auto-test 的交接文档里，跨会话易丢。
- **本次处置**：补 PROJECT.md/PLAN.md（Lead 维护）。
- **skill 修复候选**：可在 project-onboarding/接管判据里加「缺两文档 ⇒ 列入缺口矩阵」，当前 workflow 只说缺基线调 project-onboarding，未点明这两个文件。

### F-4 Agent Teams 共享任务写作用域无法表达工作区外路径

- **现象**：`team_task_create(write_scopes=["../knowledge-bases/..."])` 被拒（invalid workspace-relative write scope）；工作区根是 tenger-skills，被测项目在兄弟目录。
- **影响**：多 agent 并行时「写作用域」只是口头约定，无法登记为可核对的 scope，冲突只能靠 prompt 约束。
- **本次处置**：改用逻辑标签（kb/apps/...）登记，实际约束写进每个 agent 的 prompt。
- **skill 修复候选**：属 DSH 工具面，非 skill 文本；建议 Agent Teams 写作用域支持「工作区外路径（绝对/相对项目根）」或明确文档说明限制。
