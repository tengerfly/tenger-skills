# PRD-Design —— 工业级 PRD 生成 Skill

> **状态**：✅ 定稿
> **术语与决策基准**：[CONTEXT.md](CONTEXT.md)（术语表 + 决策日志 D-01~D-20）

---

## 一、这是什么

一个由 **Staff 级高级产品经理**人设驱动的标准流程 Skill：把用户的一句话想法，变成**需求边界清晰、模块划分合理、每个流程闭环、验收可直接转测试用例**的工业级 PRD 交付包。

**第一设计原则**：「先把需求考虑清楚、写清楚。」——效果度量、灰度发布、技术实现都是需求清楚之后的事。

## 二、核心特性

1. **两段式苏格拉底流水线**：
   - 阶段一总览期澄清 → 收敛 7 点（用户痛点/价值主张/主流程闭环/**入口与导航结构**/MVP 边界/**模块划分草案+每模块应做·不应做·产出物**/效果度量开关）→ **画流程图（泳道图 + 关联关系图）**→ 流程与范围确认 Gate；阶段二每模块澄清②后 → **画模块业务流程图 + 状态机图 → 逐模块确认** → 字段方案确认 → 成文。全程三段式：**询问 → 流程图确认 → 编写文档**。
2. **PRD 域界铁律（与技术方案彻底解耦）**：全文禁止数据库字段类型、API 接口、前端控件、技术选型；负面清单见 [references/tech-feasibility-guide.md](references/tech-feasibility-guide.md) §二。
3. **模块间关联关系图强制化**：总纲必含 Mermaid 关联图 + 双向核对注记表，逐边验证闭环。
4. **Gherkin 单源验收**：废除双轨制（原 Gherkin + UAT 表），每模块唯一权威验收章节 `AC-Mxx-nnn`——开发 TDD 先写测试用例的直接输入源。
5. **双 Gate + 回炉机制**：流程与范围确认 Gate / 用户终审 Gate；模块级内联自检 + 全局 Pass Gate；拆分错误随时回炉重切。
6. **页面归并下沉原型设计**：PRD 只在各模块 §3.1 描述页面功能区块；「页面→载体（独立页/弹框/抽屉…）」归并划分由 Prototype-Design 布局清单 Gate 承接，PRD 不产出页面清单（原页面视图清单已移除）。
7. **PRD 速查表（L0 速查入口）**：PRD 全部成文后汇总生成 `PRD速查表.md`——六大索引（术语/页面/模块/业务规则/业务信息/AC）+ 原文锚点，全链路下游 skill 的统一入口：先读速查表，逐字级细节再回原文；与 PRD 同源同版本归档，不失同步。

## 三、流水线全景

```
用户一句话 ──► 苏格拉底澄清①(7点收敛) ──► 画流程图(泳道图+关联图) ──► overview.md
                 （单步提问·推荐答案前置）                                   │
                                                            ◉ 流程与范围确认 Gate
                                                                          │
                        ┌─────────────────────────────────────────────────┘
                        ▼
            ┌──────────────────────────────────┐
            │ for each 模块:                    │
            │  澄清②流程闭环推演                │──► 发现拆错即回炉流程与范围 Gate
            │  画模块流程图+状态机（逐模块确认）  │
            │  字段方案用户确认（基于已确认流程图）│
            │  成文九章+内联自检                │
            └───────────┬─────────────────────┘
                        ▼
              全局 Pass Gate(三段式)
                        ▼
              ◉ 用户终审 Gate ──► 归档到 .spec/
```

## 五、快速上手

1. 触发方式：提出产品想法或说「帮我写 PRD」「需求升级到 V2」；
2. 你将被反复提问——每次只有一个带推荐答案的问题，做选择题即可；
3. 全程需要你拍板三次以上：7 点收敛确认 → **流程图 + Scope 范围**（一并确认）→ 每个模块的字段方案 → 终审归档；
4. 交付物中每个模块的「§9 验收标准」可直接交给开发按 TDD 先写测试。
