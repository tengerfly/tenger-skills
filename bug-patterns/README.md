# bug-patterns/：真实缺陷模式池（评审检出清单）

> 存「会再犯的一类错」+ 防复发规则：评审时当检出清单，开发 / 方案时当预防规则的来源。单点偶发、环境特例不入池。

## 与 issue/ 的分工

| 池 | 记什么 | 谁消费 |
|---|---|---|
| [`issue/`](../issue/README.md) | Skill 自身方法论 / 流程问题 | 批改窗口改 `skills/`、`shared/` |
| `bug-patterns/` | 各项目 bug 暴露的代码类错误模式 + 防复发规则 | 评审检出清单；方案 / 开发防复发 |

判归属：问题出在「Skill 怎么干活」→ `issue/`；问题出在「写出来的代码有哪类坑」→ 本池。

## 结构

```text
bug-patterns/
├── README.md
└── <YYYY-MM-DD>/
    └── <NN>-<错误模式简述>.md   # 一类错一张卡
```

模式卡字段：根因类型（数据 / 状态 / 竞态 / 契约 / 环境）、受益 skill、等级、现象、根因（证据链摘要）、防复发规则、建议落点、状态。
「依据」写原项目定位报告路径，可回查；状态机 `待提炼 → 已提炼（必填落点）/ 已忽略（理由）`。

## 怎么用（评审检出清单）

1. 评审开工先读本表：本任务改动命中哪类根因，就按对应卡的「防复发规则」逐条查。
2. 检出问题 → 进评审问题清单，标「模式 #NN」。
3. 新缺陷 → 收尾按卡模板沉一张新卡，状态 `待提炼`。
4. 每 2 周批改窗口挑高频模式，提炼进 `skills/`（规则见 [issue-loop.md](../shared/issue-loop.md)）。

## 写入规则

- 先有真实问题再沉淀；不预设、不批量造卡。
- 一张卡只写一类错；证据链摘要三行内，细则回链原报告。
- 有预防价值才沉：会再犯 + 可类别化；一次性 / 环境特殊不沉。
