# bug-patterns/ —— 错误模式池（集中池，位于本 skill 仓库根）

沉淀**各被修项目修复 bug 暴露的可类别化错误模式 + 防复发规则**。池固定在 `tenger-skills/bug-patterns/`（skill 源仓库根）——无论 bug 修在哪个项目，Bug-Fix 都**直接写入本池**；优化时也只需在**本仓库一处**定期提炼，不需要去各项目拉取。

## 为什么集中在本仓库

- 用户只需在本仓库「定期处理」：沉淀进来 → Skill-Optimizer 模式③ 提炼进方案/开发 skill，一处闭环。
- Bug-Fix 在任意被修项目执行时，沉淀写入路径 = 本池（skill 源仓库，即本目录）。若运行目录不是本仓库，写入前先确认本仓库路径可写；不可写则先告知用户。

## 与 issue/ 池的分工

| 池 | 在哪 | 记录什么 | 消费方 |
|---|---|---|---|
| `issue/` | 本仓库根 | skill 自身方法论问题 | Skill-Optimizer 优化 skill 自身 |
| `bug-patterns/` | 本仓库根 | 各项目 bug 暴露的错误模式 + 防复发规则 | Skill-Optimizer 提炼进方案/开发 skill |

> 判归属：问题出在「skill 怎么干活」→ `issue/`；问题出在「写出来的代码/方案有哪类坑」→ `bug-patterns/`。

## 结构

```
bug-patterns/
├── README.md              # 本说明
└── <YYYY-MM-DD>/
    └── <NN>-<错误模式简述>.md   # 案例卡（模板：Bug-Fix/assets/pattern-card-template.md）
```

- 案例卡字段：根因类型（数据/状态/竞态/契约/环境）、受益 skill、现象、根因（证据链摘要）、**防复发规则**、建议落点层级、状态。
- 来源可追溯：案例卡「依据」字段填原被修项目 `.spec/bug修复/<日期>-<简述>/问题定位报告.md` 路径（供需要时回查原始案例）。

## 写入方（Bug-Fix 收尾沉淀）

1. 仅**有预防价值**才沉：会再犯的「一类错」→ 沉；一次性/环境特殊 → 不沉。
2. 落盘前经用户确认：根因类型、受益 skill、防复发规则、等级。
3. 依据被修项目 `问题定位报告.md` 提炼，写入本池 `bug-patterns/<日期>/`。

## 提炼方（Skill-Optimizer 模式③）

定期读本池 `待提炼` 案例，翻译成方案/开发 skill 的防复发规则，按层级升级落点：
1. 目标 skill「常见错误对照表」加行；
2. 高频/跨项目模式 → references 防复发清单；
3. 重大模式 → 方案 skill 的 Gate/预检项。

提炼后回填：`已提炼`（落点 skill + 位置）/ `已忽略`（理由）。

## 状态机

`待提炼 → 已提炼（必填沉淀目标+位置）/ 已忽略`
